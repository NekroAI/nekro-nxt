# 社区接入

状态：implemented（2026-10-07 用户确认社区方向；NekroNXT 侧实施）

## 背景

NekroNXT 社区是为 NekroNXT 新建的独立平台（官网、扩展市场、自动审查与管理后台），部署在 Cloudflare，由独立仓库维护，与 Nekro Agent 旧社区不共享数据、接口或账号。本决定只记录 NekroNXT 一侧如何接入：登录社区、浏览与安装社区扩展、把扩展发布到社区。社区端的审查、额度与管理规则由社区方案负责。

## 用户已确认的取舍

1. 不再复制社区密钥：在 NekroNXT 实例内直接登录社区。
2. 任何登录用户都可以发布，社区自动审查并给出建议；尚未完成审查的发布也公开，标注「风险未知」。
3. 暂不做扩展进程隔离评估，以审查结论、风险标注和明确告知替代，见下文「对现有决定的调整」。

## 决定

### 登录

- 「社区 → 账号」发起登录。Host 生成 PKCE（S256）verifier 与一次性 state，只在内存保存 10 分钟；页面在新窗口打开社区授权页，Desktop 把新窗口交给系统浏览器。
- 回跳地址为浏览器当前访问本实例的来源加 `/community/callback`。这个页面由 Host 直接返回，无脚本、无外部资源；它在安全入口中免登录，因为从社区回来的往往是 Desktop 用户的系统浏览器，没有本实例的会话。它只能完成本实例发起、state 匹配的那次登录。
- 刷新令牌保存在本机凭据存储（`credentials/`），系统设置 `community.accounts` 按社区地址分别保存账号资料与凭据引用（旧的单账号 `community.account` 读取时迁移）。访问令牌只在内存中，过期前一分钟用刷新令牌轮换，并发请求共享一次刷新；社区拒绝刷新时本机退出登录并删除凭据，社区暂时不可达时保留登录。
- 退出登录删除本机凭据，并尽力在社区撤销授权。登录属于某一个社区地址，切换地址后使用该地址自己的登录，切回时原登录仍在。

### 「社区」一级入口

导航在「工坊」与「接线」之间设「社区」空间（路由 `/community`，Host 的 SPA 前缀白名单包含它），分为五节：

- **发现**：浏览、搜索、查看详情与安装（`/community/extensions/:id`，社区网站的「在我的 NekroNXT 中打开」指向这里）。
- **人设**：浏览、筛选与安装社区人设（`/community/personas/:id`），见下文「人设」。
- **已安装**：列出来自社区的扩展，与社区比对是否有新发布、所装发布是否已撤回、扩展是否被下架，以及新发布新增或升级的权限。
- **我的发布**：登录后列出自己发布的扩展与每次发布的审查结果、审查报告，以及自己分享的人设与审查状态；可对未完成或有风险的发布申请重新审查、撤回发布，也可把尚未发布的本地扩展发布出去。
- **账号**：登录、查看与退出。

旧的「工坊 → 社区扩展」路径重定向到 `/community`。

### 浏览与安装

- 「社区 → 发现」浏览、搜索与查看详情。Host 代理社区开放接口并归一到 `@nekro-nxt/contracts` 中的社区结构，社区新增字段不透传给页面；浏览与安装不需要登录。
- 详情先展示审查标签、审查摘要与权限说明。「风险未知」与「有风险」各有醒目提示；审查结论只描述审查发现，不做「安全」担保。
- 安装时 Host 先读取发布记录中的包摘要，下载后比对 SHA-256 与大小，不一致即停止；之后走与本地文件导入相同的检查与确认（`ExtensionImportStaging` 被两个入口共用），导入后不自动启用，启用仍按现有能力确认。
- 社区安装在导入提交时写入来源记录（表 `extension_revision_sources`：保存记录 → 社区地址、发布 ID、发布者），随扩展删除级联清除。工坊扩展详情显示「来自社区 @发布者」。

### 更新检查

- Host 以已安装来源批量调用社区 `POST /api/v1/updates`，结果缓存在内存；启动后与之后每 24 小时自动检查一次，「已安装」可手动检查。导航只显示有新发布的数量。
- 更新不自动安装：用户从「已安装」导入新发布，走同一导入确认，新增或升级的权限在确认中单列。

### 发布

- 扩展详情的「更多 → 发布到社区」导出所选保存记录并上传，附可选的更新说明。未登录时对话框引导登录。结果展示本次发布的审查状态与需要留意的检查项，并可打开社区上的审查报告。
- 同一扩展身份只能由首次发布者继续发布；官方扩展例外，由全体官方成员共同维护。这条规则由社区执行，NekroNXT 原样展示社区的说明。
- 官方扩展与官方成员只由社区管理员在后台认定，不按发布账号判断。官方扩展的发布者是社区保留的官方主页 `nekro-nxt`，NekroNXT 显示为「NekroNXT 官方」并标「官方」（`communityPublisherLabel`）。

### 人设

2026-10-08 用户确认把人设作为社区共享的资源（「人设也是我们社区共享的一大资源重点」）。人设只含名称、头像、一句话简介、作者介绍（Markdown）、标签与人设正文（对应智能体的设定，≤64 KiB），不含模型与扩展；与社区端共用的开放接口见社区方案。

- 「社区 → 人设」（`/community/personas`，深链 `/community/personas/:id` 供社区网站的「在我的 NekroNXT 中打开」使用）浏览、搜索与按标签筛选；宽窗口点卡片在右侧打开详情，窄窗口进入整页详情。详情先展示作者介绍，人设正文可展开，审查只做轻量标注。浏览与安装不需要登录。
- Host 宽松读取社区人设响应（个别条目格式不对时略过），头像改写为本机代理地址 `/api/community/personas/:id/avatar`，代理按 ID 与版本向当前社区读取并以文件头确认是 PNG、JPEG 或 WebP；页面不直接跨域读取社区图片。
- 安装为新智能体：显示名默认用人设名称，可改；模型默认与新建智能体相同，可在安装对话框中选择；设定正文同时写入纯文本与等价的结构化文档；头像下载后作为智能体头像。替换现有智能体的设定：为该智能体保存一次新配置，只换设定与可选的名称，模型、能力与图片策略不变，原来的设定可在「恢复之前的配置」里找回；头像不属于版本，替换头像是可选项。安装请求带上用户看过的人设修订，社区上已更新时拒绝；安装成功后尽力调用社区的安装计数。
- 智能体「更多 → 分享人设到社区」需要已登录社区：预填名称、设定与头像，填写简介、介绍与标签；头像在页面缩放后上传（≤512 KiB）。系统设置 `community.personaLinks` 按社区地址记录智能体最近一次发布的人设，再次分享时默认更新它，社区修改正文或头像会生成新修订并重新审查。「社区 → 我的发布」列出自己的人设与最新修订的审查状态。

### 共享的包格式

`.nxt-extension` 的结构校验、Manifest V6 与内容摘要由 [`@nekro-nxt/extension-format`](../../../packages/extension-format/README.md) 承载，NekroNXT 的保存、导入与社区发布前的校验执行同一份代码，社区接受的包一定能被安装。它与所依赖的 `@nekro-nxt/contracts` 以 MIT 发布到 npm（`packages-v*` 标签触发暂存发布，维护者以 2FA 批准）。为了让仓库外的扩展（包括官方种子扩展）能独立开发与类型检查，`@nekro-nxt/extension-sdk` 也以 MIT 发布，发布物内联同为 MIT 的 `adapter-sdk` 类型；NekroNXT 其余代码仍为 AGPL-3.0-only。

### 配置

- 社区地址优先级：在本实例保存的地址 > `NEKRO_COMMUNITY_URL` > 默认正式社区 `https://nxt.nekro.ai`。只有少数开发成员需要更改，入口是「社区 → 账号」底部的一行小字，点开后在对话框中测试连接、保存或恢复默认；不单独占设置分区，旧的 `/settings/community` 重定向到这里。
- 地址只接受 HTTPS 与本机 HTTP；局域网 HTTP（私有网段、无点主机名、`.local`、`.lan`）需在设置中明确确认，公网 HTTP 一律拒绝。
- 社区 `GET /api/v1/meta` 报告环境（production / staging / development），非正式环境在社区空间显示「测试站」「开发站」标记。
- 正式发布包含社区入口的 NekroNXT 前，正式社区必须已经上线，否则入口只能显示连接失败。

## 对现有决定的调整

- [未来扩展方向](../../02-未来扩展方向.md) §6 与 §10：社区市场、公开发布与社区账号按本决定推进；签名、SBOM、发布者等级、云构建与组织账号仍不做。
- [扩展宿主能力与生态移植](../accepted/2026-10-07-扩展宿主能力与生态移植.md) §11：扩展 Host 半边进程隔离不再是社区开放的前提，以审查、风险标注与明确告知替代；隔离仍是后续加固方向。

## 不在此决定内

- 设备授权短码、遥测、改编来源链、`nxt-ext` 命令行与模板仓库。

## 验证

Server 测试覆盖 PKCE 登录、state 一次性与过期、拒绝授权、令牌轮换与并发刷新、刷新被拒时退出、社区不可达、退出撤销、切换社区地址、目录归一化、包摘要校验与发布；安全入口测试覆盖回跳页免登录而其他社区接口仍需登录；另覆盖地址优先级与按地址登录、局域网地址确认、旧账号迁移、更新检查与我的发布、来源记录的写入与级联删除。生产构建以隔离数据根连接本机社区开发服务，实测登录授权、回跳、社区目录与详情、安装确认、发布与审查报告链接，以及真实导出的扩展包经社区发布后重新安装。人设另有 Server 测试覆盖目录宽松读取与头像代理、安装为新智能体与替换设定（含修订冲突）、发布与作者关联，浏览器用例覆盖浏览、详情、两种安装与发布。
