# 统一使用通信工具发送用户可见消息

状态：implemented

智能体自己的用户可见发言必须调用 `send_channel_message`。网页与外部平台同一规则。模型原始 `text`/`reasoning` 只进入内部运行轨迹，不自动投递。管理员可通过网页以机器人账号向外部频道发言，走 Adapter 出站并注入系统事实，不记为模型工具发送。

Host 按 Admission 顺序维护当前进程内的回应义务。Binding 真正触发智能体的 Admission 建立义务；观察型 Admission 不建立义务。确认 `sent`/`partially-sent` 的 `send_channel_message`，或成功执行 `finish_channel_turn`，只清除该动作之前的义务；因此 Turn 开头的发送不能覆盖后来注入的新 Mention、回复或命令。`failed` 和 `unknown` 不确认回复，其中 `unknown` 禁止盲目重发，必须由智能体显式结束收口。

`finish_channel_turn` 使用 DSH 公开的 `ToolRunContext.concludeTurn()`。它以 `response-complete`、`no-response-needed` 或 `cannot-respond` 说明结果，必填原因只进入后台轨迹，不创建频道消息。结束结果不会清空 Inbox；已经排队或竞态到达的新消息继续处理，并可重新建立义务。

守卫同时接入 DSH `agent/pre-step` 和 `agent/turn-stopping`。模型只生成普通文本时，Host 明确要求它调用发送工具或结束工具；每个最新义务最多纠正两次，第三次仍不执行时不再增加模型请求，Turn 在 Inbox 排空后投影为 `protocol-failed`。Host 不把模型原始文字兜底投递。

回应义务和纠正预算不是持久业务事实，只保存在当前 DSH Host 进程内。它们不进入 `AdmissionRecord`、Core/Runtime SQLite 或 DSH 消息 source；重启恢复 Admission 时由 Channel Runtime 使用当前 Binding 和原始 Channel Event 重新计算。

运行投影使用 `responseState: not-required | pending | sent | finished | protocol-failed | interrupted`。`producedReply` 只由确认发送设置；显式结束不等于已经发言。文字、Mention、图片、文件和音频使用有序 `MessagePart[]`。模型工具输入额外接受无歧义的 `{"text":"..."}` 简写，Host 规范化后仍进入严格 `MessagePart` 契约；其他无 `type` part 拒绝。详细契约以 `docs/03-消息内容与投递协议.md` 为唯一事实源；工具名分界见 `docs/decisions/implemented/2026-08-18-频道通信工具与DSH子智能体工具分名.md`。
