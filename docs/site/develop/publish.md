# 发布到社区

发布后，其他人能在「社区」里搜到并安装你的扩展。每次发布都会自动审查，审查结论和评分公开显示在扩展页上。

## 怎么发布

- **在 NekroNXT 里**（推荐）：登录社区后，在「工坊」打开扩展，选“更多 → 发布到社区”，填简介、介绍、标签、源码地址和更新说明。也可以让智能体起草，发布前要管理员确认。步骤见[版本、分支与发布](../extensions/versions.md#发布到社区)；
- **在社区网站上传**：在 [nxt.nekro.ai](https://nxt.nekro.ai) 用 GitHub 登录，上传 `.nxt-extension` 文件。

个人扩展不需要任何令牌。

## 版本规则

- 扩展的 `id` 由第一个发布它的人拥有，别人不能给它发新版本；想在别人的扩展上改，先在 NekroNXT 里从它创建分支，再发布分支。社区页面会标明分支自哪里；
- 新的发布要接在上一次发布之后。社区上已经有更新的发布时（比如你在另一台机器上发过），会提示先更新或合并再发；
- 完全相同的内容不能重复发布；
- 许可证、作者、版本说明这些属于社区页面的信息，在发布时填写，不写进清单。

## 审查

发布后先做自动检查，再由审查员“小澄”审查源码和权限，通常几分钟内完成。审查完成前扩展照常公开，标为“风险未知”。

自动检查发现这些问题时，发布**不公开**：源码里写着私钥、云服务密钥、GitHub 令牌、模型服务的 API Key 等凭据。这类拒绝不消耗审查额度。

这些写法会转为人工复审，标为“待复审”：`eval`、`new Function`、动态 `import()` 或 `require()`、访问宿主进程、访问云元数据地址、混淆或压缩过的代码、在用户设备上运行程序的 MCP 服务。

### 六项评分

每项 1–5 星，综合评分是六项的平均：

| 维度 | 看什么 |
| --- | --- |
| 安全 | 权限的实际用法和用途一致，凭据走配置字段，不把不可信内容直接塞进上下文，群里其他人不能越权触发 |
| 开放 | 源码可读，没有混淆、大段编码数据或远程加载的代码 |
| 稳定 | 出错返回看得懂的结果，外部调用有超时，副作用可以重复执行 |
| 轻量 | 占用的上下文小且稳定，轮询类工作用定时任务预检，模型调用有节制 |
| 易用 | 功能和介绍一致，工具和参数的描述写清格式、范围和默认值，错误提示面向用户 |
| 工艺 | 结构清楚、类型完整、没有重复和死代码，遵循 SDK 约定 |

5 星是范例，3 星合格但有明确的改进点。没有实际功能的扩展（不注册任何东西，或只返回固定文字）分数有上限。审查报告里每一项都会写“再拿一颗星要做什么”。

### 权限判断

审查员逐项判断每个权限：

- **必要且最小**：没有问题；
- **超出需要**：比如声明的域名和代码实际请求的不一致、固定接口却申请任意联网。安全最多 4 星；
- **使用可疑**：安全最多 2 星，并转人工复审。

宿主已经保证的事不用你自己做：`nxt.http.fetch` 已经拦截内网、回环和云元数据地址，跨域重定向时会去掉认证头，所以扩展不要自己实现私网过滤，也不要绕开它直接用全局 `fetch`。

## 发布前自查

- [ ] 只申请用得到的权限，联网限定域名；
- [ ] 凭据都通过配置字段，源码里没有任何密钥；
- [ ] 工具和参数的描述写清格式、范围、默认值；
- [ ] 出错返回 `{ ok: false, message }`，`message` 是给用户看的中文；
- [ ] 外部请求设了超时；
- [ ] 每个工具的 `verificationInput` 没有副作用；
- [ ] 有图标和介绍，填了公开的源码地址；
- [ ] 改了数据格式时提高了 `dataVersion` 并注册了迁移。

## 额度

| 项目 | 默认 |
| --- | --- |
| 单个包大小 | 5 MiB |
| 扩展数量 | 20 个 |
| 每个扩展每天发布 | 5 次 |
| 每天提交审查 | 10 次 |
| 每月审查 | 100 次 |

需要更多时，可以在社区网站申请提额。

## 发布之后

- 「社区 → 我的发布」里查看每次发布的审查报告，可以重新审查或撤回；
- 已安装的用户会在 NekroNXT 的“社区更新”里看到新版本，新增的权限要他们重新同意；
- 撤回后社区不再提供这次发布，已安装的用户会看到“作者已撤回”。
