# 内容寻址资源与当前图片投影

状态：implemented

## 结论

NekroNxt 用统一 Asset Service 保存图片、音频、视频、文档和其他文件。相同字节只保存一个规范 blob；入站消息中的授权来源由独立 `AssetOccurrence` 保留，模型生成内容中的授权来源由独立 Channel scoped grant 保留，内容去重不能扩大跨频道读取权限。

当前不实现图片增强器、OCR、标签、派生队列、驱逐/隔离状态或未来格式字段。图片能力只使用 DSH 当前公开的原生 ImageBlock 与按需查看工具。

## 当前数据模型

`assets` 只保存稳定 `assetId`、SHA-256 `contentDigest`、`byteSize`、按字节检测的 `mediaType` 和首次提交时间。Asset Service 不把模型或平台声明的 MIME 当作事实，也不把接收统计复制到 Asset 主记录。

`asset_occurrences` 使用 `(channelEventId, partIndex)` 作为主键，并保存该位置实际引用的 `assetId`。频道、连接、平台消息 ID 和接收时间都通过 Channel Event 关系获得，不重复存储。

`asset_channel_grants` 使用 `(assetId, channelId)` 作为幂等主键，保存 `source: 'agent-tool'` 与 `grantedAt`。它表示一次不产生消息事实的产品授权：`AssetService.prepare` 成功确保 Asset 后，当前 DSH Session 的 `asset_create` 工具写入当前 Channel grant。Grant 所有者是 Core SQLite Asset repository 的授权表；它不代表成员、机器人账号或其他频道权限。

MessagePart 只携带稳定 `assetId` 和必要显示元数据，不暴露宿主绝对路径、临时 URL、base64 或全局 digest。视频当前仍作为普通 `file` Part 入库，不宣称模型已经理解其二进制内容。

## 原子可见性

Asset Service 在私有临时目录完成流式摘要、大小和 MIME 验证，再以同文件系统原子发布内容寻址 blob，并确保 `assets` 行。入站消息随后由 Channel Runtime 在一个 `BEGIN IMMEDIATE` 数据库事务中提交 Channel Event 与全部 AssetOccurrence；事务完成后才能启动 Admission。模型生成 Asset 不启动 Admission，也不创建 Channel Event，而是在准备成功后持久化当前 Channel 的 grant。

文件系统与 SQLite 不伪装成跨介质事务。blob 发布失败时没有 Asset 行；Asset 行或 grant 提交失败、或进程崩溃留下的未引用 blob 可以安全忽略，当前不建立 `asset_operations` journal。重启恢复依赖 SQLite migration、Asset 行、Occurrence 和 grant 的持久事实；相同 digest 的并发准备得到同一规范 Asset，grant 写入是幂等的。grant 不会被自动复制到其他 Channel，当前也没有 grant 转移或撤销 API。

## 授权与 DSH 投影

读取资源必须证明当前频道存在引用该 Asset 的 Occurrence，或存在 `asset_channel_grants` 中匹配 `(assetId, channelId)` 的显式 grant。`canAccessAsset` 同时检查这两类事实；相同 digest 在其他频道出现、当前频道以外的 grant，或模型只知道某个 ID，都不会扩大当前读取范围。

当前模型和 Provider 明确支持图片输入时，触发消息中的受支持图片由 `dsh-compat` 映射为 DSH ImageBlock，底层仍读取同一 Asset blob，不复制第二份图片。图片能力可用时注册 `asset_view_image(assetId)` 供历史回看；通用资源元数据通过 `asset_inspect(assetId)` 读取。两个工具都必须执行频道授权检查。

不支持图片的模型只看到安全元数据和 `assetId`，不会得到伪造摘要，也不会隐式调用外部云服务。普通文件按元数据进入上下文，具体提取能力由已安装扩展提供。`asset_create` 只接受 UTF-8 或受限 base64 内容，模型输入解码后上限为 8 MiB；返回的 Asset 必须先取得当前 Channel grant，之后 `send_channel_message` 对每个 `image`、`file`、`audio` part 再次逐项检查当前 Channel 的 `canAccessAsset`。

动态 Cordis 插件使用同一智能体 Session 的工具面，因此可以按同一规则调用 `asset_create` 和 `send_channel_message`。Host 不额外暴露可由动态插件指定 Channel、路径或任意 Asset 的服务；若未来增加服务，仍必须携带并验证当前 Channel scope。

## 当前不做

本期不实现图片增强、OCR、向量索引、人物识别、视频转码/抽帧、资源驱逐、隔离恢复、跨设备资源同步或任意路径读取。出现真实消费者后再设计派生事实和生命周期。
