# 已实施：用户可见界面视觉验收

状态：implemented

## 问题

用户可见 UI 改动可以在类型检查、单测和产品旅程全部通过后，仍然出现挤压、重叠、选中态破坏行布局、导航抖动或对比不足。旅程证明页面能开、动作有外部结果、无整页崩溃；几何断言只覆盖已登记回归。两者都不证明画面看起来对。

此前完成条件把截图审查写成一句附属要求，没有覆盖范围、判定项、否决条件和取画面手段，实现者可以把“打开过页面”“元素可见”或测试日志当作视觉通过。

## 决定

- 用户可见的布局、样式、路由、客户端状态或渲染数据发生变化时，真实渲染画面的视觉验收与类型检查、相关测试、产品旅程同级，缺一不可；
- 验收对象是当前改动实际服务出来的产品画面。取画面手段不限：有内置可视化能力的实现者用该能力，没有时改用任何能得到真实帧的等价手段。不把某一种驱动方式写成唯一做法；
- 只要实现者能理解图像（包括多模态模型），就必须亲自阅读真实画面并按清单判定；不能阅读图像时，必须由能看见画面的人完成同一份清单，不能由源码审查代签；
- 清单覆盖布局、可见功能正确性、美观与工艺、合理性、可读性；任一项明显不合格即整轮失败，修完必须再看真实画面；
- 现行细则、覆盖范围、不构成证据的情形见 `docs/06-开发与测试规范.md` §5.1。观感目标仍以 `docs/05-桌面UI与动效规范.md` 为准。

本次明确不把 CI 自动化像素对比、全视口笛卡尔积或指定某一种页面驱动产品写成门禁。

## 验证

- 根 `AGENTS.md` §8 / §10、检查阶梯和 `06` §5.1 把视觉验收写成与旅程同级的完成条件；
- `05` §13、界面交互模型和一期整改面只保留指向，不复制第二份清单。
