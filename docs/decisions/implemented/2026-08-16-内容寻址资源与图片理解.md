# 内容寻址资源与原生图片多模态

状态：implemented

## 结论

NekroNXT 用统一 Asset Service 保存图片、音频、视频、文档和其他文件。相同字节只保存一个规范 blob；入站消息的授权来源由独立 `AssetOccurrence` 保留，模型生成内容的授权来源由 Channel scoped grant 保留，内容去重不扩大跨频道读取权限。

图片理解采用“视觉原文常驻 + 主动定向重看”：明确声明支持 `image` 的主模型按消息原顺序持续收到原图，同一 Session 当前 Surface 中相同 `contentDigest` 只驻留一份像素；文本或能力未声明的主模型不接收 ImageBlock，只能在 Revision 配置了明确支持图片的辅助模型后，通过同一个批量工具取得结构化二手证据。NekroNXT 不按模型名称建立视觉白名单。

## Asset 与授权

`assets` 保存稳定 `assetId`、SHA-256 `contentDigest`、`byteSize`、按字节检测的 `mediaType` 和首次提交时间。MessagePart 只携带 `assetId` 和必要显示元数据，不保存宿主路径、临时 URL 或 base64。`asset_occurrences` 以 `(channelEventId, partIndex)` 记录入站位置；`asset_channel_grants` 以 `(assetId, channelId)` 记录模型创建资源的显式频道授权。

Asset Service 在私有临时目录完成流式摘要、大小和 MIME 验证，再原子发布内容寻址 blob。Channel Runtime 随后在 Core SQLite 事务中提交 Channel Event 与全部 Occurrence，提交后才能启动 Admission。`canAccessAsset` 只接受当前频道的 Occurrence 或 grant；相同 digest 在其他频道出现、模型知道某个 ID 或其他频道存在授权都不能越权。

DSH ImageBlock 引用同一个 Asset blob。`NekroAssetAttachmentStore` 通过 DSH rc.2 的公开 `readImageRequest` 接缝和官方确定性图片投影器生成供应商请求版本；请求版本缓存属于 `/data/dsh/request-images`，不是新的 Asset、授权事实或 base64 持久副本。

## 不可变图片策略

每个 `AgentRevisionContent` 携带规范化 `imagePolicy`：

```ts
interface ImageUnderstandingPolicy {
  history: {
    mode: 'persistent-distinct'
    detail: 'low' | 'auto' | 'high'
    restoreAfterCompaction: {
      recentMessages: number
      maxImages: number
    }
  }
  textModel:
    | { mode: 'disabled' }
    | {
        mode: 'auxiliary'
        model: AgentModelSelection
        maxTokens: number
      }
}
```

默认值为 `detail: auto`、最近 32 条频道事实、最多恢复 20 张不同图片、文本模型辅助理解关闭。消息数范围 1–100，恢复图片数范围 1–50，辅助输出范围 256–8192 Token。辅助模型必须由 DSH 模型目录明确声明 `inputModalities` 包含 `image`；缺失声明按文本路径执行，但 UI 显示“输入能力未声明”，不伪装为明确不支持。

策略随人设和模型创建不可变 Revision。新 Revision 使用包含完整 `imagePolicy` 的 `v3:sha256` 内容摘要；迁移前的 `v2` 摘要保持原值。SQLite `agent_revisions.image_policy` 非空回填默认策略，旧客户端省略字段时由 Core 规范化，Snapshot 始终返回完整策略。

`low` 使用不高于 512×512 总像素的请求投影；`auto` 使用模型路由允许的普通投影；DSH rc.2 没有逐图片 `high` wire 等级，因此 `high` 映射到该路由最高可用的 `auto`。从驻留的 low 主动请求 auto/high 会以新的 detail 附件身份再注入一次并记录 `detail-upgraded`；相同或更低等级不会重复注入。

## 消息投影与视觉驻留

Channel Event、Episode handoff 和管理员网页出站事实都按 MessagePart 原顺序投影。`text → image → text` 在 DSH 内容块中保持同序；每张图片先出现含 Asset ID、alt 和来源的短标签，再在该位置出现 ImageBlock。`rich` 预览和转发条目图片在所属 rich Part 位置处理。

视觉驻留从当前 DSH Surface 重建，不依赖进程内 Set。索引以 `contentDigest` 去重，并从 detail 附件身份、图片检查审计和当前 Surface 恢复实际等级。重复出现仍保留各自文字引用；只有像素块仍在 Surface 时才跳过。NekroNXT 不主动 replace、删除或裁剪图片块；rc.2 Tool Result Pruner 只裁剪文本中段并原序保留 ImageBlock，兼容测试对此有直接断言。

文本或能力未声明的主模型只收到原位置 Asset 标签。有效辅助模型不存在时不注册图片检查工具，纯文本聊天仍可运行，系统提示和检查器明确报告图片理解不可用。

## 批量主动检查

模型可见工具统一为 `asset_inspect_images`，不再注册单图 `asset_view_image`：

```ts
interface InspectImagesInput {
  images: Array<{ assetId: string; focus?: string }>
  question?: string
  detail?: 'low' | 'auto' | 'high'
}
```

单图也传长度为 1 的数组。批次范围 1–20；`question` 去空白后最长 4000 字符，逐图 `focus` 最长 1000 字符。工具只接受 Asset ID，不接受路径、URL、base64 或 digest，不自动拆批。执行前完成整批 Schema、频道授权、Asset、`image/*` MIME 和附件可读性校验；任一项失败则整批失败，Tool Result 不含任何部分图片或证据。

视觉主模型走 direct 路径。Tool Result 依次包含批次问题、每图序号/Asset ID/focus，以及需要新注入或提升 detail 时紧跟的 ImageBlock；已驻留项返回 `resident`，批次内相同 digest 返回 `duplicateOf`。即使配置了辅助模型也不静默委派。

文本主模型走 delegated 路径。Host 通过 DSH LLM 公共接口发起一次独立请求，在同一 user message 中交替放置完整图片批次、编号和 focus，不启动第二个 Agent Loop。辅助模型只提取可见证据、区分观察与推断，并输出严格 JSON；Host 校验图片数量、顺序、index、Asset ID 和 comparison 引用。首次结果不合格只允许一次纯文本修复，修复不重发图片；再次失败则整个工具调用失败。

辅助结果缓存仅在同一 Session 生效，键包含频道、辅助模型与推理配置、有序 digest 和重复映射、question/focus/detail、提示词版本与 Schema 版本。缓存由成功的 DSH 审计事件重建；命中前仍重新执行完整授权和 Asset 校验。检查调用沿用 DSH exclusive 调度，同一 Session 串行，不同 Session 并行，取消信号贯穿附件读取与辅助模型请求。

每次调用写一条 log-only `nekro-nxt/image-inspection` terminal record，保存 call ID、模式、内部 Asset/digest 映射、问题摘要、模型、缓存、Token usage、结果或稳定错误码，不记录图片字节、路径、临时 URL 或凭据。主模型实际看到的 direct 图片块或 delegated 证据仍由 DSH Tool Result 持久化。

## 压缩后的视觉恢复

NekroNXT 继承 DSH `BasicCompactionEngine`，包装 `compactIfNeeded`、`compactNow` 和 `compactRegion`。DSH 仍决定阈值、保留尾部和摘要算法；重入深度保证一次外层成功提交只恢复一次，恢复失败不把已经提交的压缩伪装成回滚。

成功压缩后，从当前频道最近 `recentMessages` 条权威历史收集普通图片和 rich 预览，按 digest 合并并保留全部来源消息 ID。已经留在压缩后 Surface 的图片不重复恢复；其余候选取最新 `maxImages` 张，再按原消息时间顺序追加。DSH TokenMeter 在追加前按当前模型上下文阈值估算；若恢复会立即重新产生压力，则从最旧候选开始缩减。

恢复写入 durable DSH-only user message，source 为 `nekro-nxt-visual-restore`，包含 `compactionId`、`policyVersion: 1`、来源消息 ID 和 Asset/digest 映射。它不创建 Channel Event、Outbound、Occurrence 或授权，不显示为用户新消息，也不主动唤醒智能体。`compactionId + policyVersion` 保证幂等；重启发现成功压缩缺少终态恢复记录时，在下一次模型请求前补做。损坏或不可读图片被跳过并记入 `nekro-nxt/image-restoration`，不回滚压缩。

主动重看的窗口外图片不会被自动恢复，智能体仍可再次调用批量工具。视觉 Session 默认使用当前视觉主模型完成摘要；当前 Host 没有配置独立摘要模型，未来开放时必须先验证其明确支持图片，不能静默转成二手描述。

## DSH 与 DeepSeek 兼容边界

生产 DSH 版本统一为 `0.1.1-rc.2`，同时挂载通用 `dsh-llm-pi-ai` 和官方 `dsh-llm-deepseek` 路由。NekroNXT 只读取 DSH `inputModalities`，不复制 DeepSeek 请求协议或维护模型 ID 特例。

兼容探针覆盖普通 user message 多图顺序、Tool Result 多图顺序、Files API 失败后的 inline 回退、Tool Result Pruner 保留 ImageBlock、公开 compaction append 接缝和 Session 重放。无真实凭据时官方 DeepSeek 适配器标记为“可加载但未外部验证”；只有真实双图调用取得外部结果后才能升级为“已验证”。

## 当前不做

本期不实现 OCR、标签、向量索引、人物识别、视频转码/抽帧、跨频道派生缓存、任意路径读取或把文本主模型伪装成原生视觉。视频仍作为普通 file 入库，不宣称模型已经理解。
