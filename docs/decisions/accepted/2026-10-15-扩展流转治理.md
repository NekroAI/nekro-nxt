# 扩展流转治理

状态：accepted（2026-10-15 批准并实施；正式发布、npm 包与社区正式环境未上线）

扩展会在很多路径之间流转：智能体在频道里创造、过一段时间再修改、导入文件、从社区安装、发布到社区、别人改了再发布、作者在另一台机器上继续发布。此前每条路径各自处理，版本之间没有关系，修改任务和对话绑死，数据跟着扩展走却没有格式版本，智能体每做一步都要有人去后台点一下。本决定给扩展一套统一的版本、数据、权限和社区规则，并让智能体在授权范围内自己完成这些步骤。

## 1. 场景与目标

- 扩展像代码一样有版本历史：知道每个版本从哪个版本改来，本机和社区谁更新、有没有各自改过。
- 修改已保存的扩展和新建一样自然；对话结束后任务不丢，换个对话能接着做，验证过的候选可以直接保存。
- 长期积累数据的扩展（例如表情包）在升级、回滚、分支和换机器时数据不丢，迁移前能看到会改什么。
- 群里聊两句就能让智能体完成保存、启用、发布，管理员在聊天里确认即可，不必打开后台。
- 智能体和社区审查员都理解这套规则。

## 2. 决定

| # | 决定 |
| --- | --- |
| G1 | 版本谱系写在 Manifest：`lineage: { parent, ancestry, branchOf? }`（`ancestry` 从近到远，最多 256 个），计入内容摘要、不计入载荷摘要；需要 `requires.sdk >= 10`。传输包格式不变（v2）。没有谱系的旧包导入时接在本机已有版本之后 |
| G2 | 版本号就是谱系里的代数：`v1`、`v2`；同一代保存了第二次写作 `v2·2`。两台机器对同一条谱系给出相同的版本号 |
| G3 | 「分支」是从某个版本另起的新扩展，记录 `branchOf`，可以选择复制数据；分支可以继续分支。工坊用谱系图展示同一家族的全部扩展与版本 |
| G4 | 修改已保存的扩展走「修改任务」（`kind: revise`），基于指定版本（可附一个参考版本用于合并），保存时成为该扩展的下一个版本；一个扩展同时只有一个进行中的修改任务 |
| G5 | 任务所在的对话结束后任务暂停，不再失败或孤立；可以在任何对话里继续（重新绑定到新对话），30 天不继续自动归档。最新候选验证通过时，不需要对话也能保存（用账本里的源码和验证记录） |
| G6 | 数据有格式版本：Manifest `dataVersion`（默认 1）。版本提升时扩展注册 `harness.migrateData`，宿主在切换前留快照、迁移失败恢复快照并退回原版本；切回读不懂当前数据的旧版本会被拒绝，除非同时恢复一份旧格式快照。快照按扩展保留最近 3 份 |
| G7 | 显式数据迁移：从另一个扩展、快照或 `.nxt-extension-data` 数据文件迁入，「覆盖」（保留目标已有，同名以来源为准）或「替换」（先清空）；先算差异再执行，会覆盖或删除时要求输入扩展名确认，执行前留快照。可以连同配置一起迁移，凭据从不迁移 |
| G8 | 管理员是系统级配置：登录控制台的人始终是管理员，另在设置「管理员」里列出平台账号（从用户目录添加，或在聊天里用 `/admin claim 认领码`）。群主、群管理员不自动是管理员。命令权限分三级：普通用户 < 频道管理 < 管理员，管理员拥有每个频道的管理权限 |
| G9 | 智能体的扩展自主权按智能体设置：手动（只开发和试运行，查看相关扩展）、管理员确认（发现和管理本机扩展，每一步发出请求）、自主（发现和管理本机扩展，只影响自己的普通操作直接完成并留记录）。本机扩展不按创建者隔离；给自己启用或停用不授予操作其他智能体启用状态的权限。另可设置只有管理员能让它做扩展 |
| G10 | 每个操作按同一套风险分级判断：只能在后台做（新增高风险权限）、需要管理员确认（发布与撤回、数据迁移或复制、影响其他智能体、提升级权限，以及「管理员确认」档的全部操作）、直接执行。没有次数限制 |
| G11 | 请求在频道里以系统通知出现（不是智能体发言），管理员发送 `/ext approve 编号` 或 `/ext reject 编号` 处理，24 小时过期；结果以系统通知告诉智能体。自主完成的操作同样留记录和撤销方法。智能体发布到社区后，审查结果出来会通知回频道 |
| G12 | 社区按谱系要求快进发布：新发布必须接在最新一次发布之后，否则拒绝（先更新或合并）；同一版本不能重复发布；别人的扩展不能直接追加版本，要先分支；分支在社区上标明来源。审查对比上一次发布的权限、数据格式与源码差异 |
| G13 | 本机记录每个版本对应的社区发布（安装与发布都记），以及本机在每个社区上是发布者还是订阅者；「社区 → 同步」按谱系显示已同步、社区有更新、本机有修改、两边都改了，可以更新、保留本机或查看谱系 |
| G14 | 动态创造支持命令贡献（保存验证用宿主生成的参数样例真实执行一次）、带 import/export 的模块源码（修改从社区或源码包导入的扩展时原样带回）和数据迁移 |

## 3. 边界

- 谱系由保存它的机器写入，社区只检查它与已有发布是否连续，不验证它是否「真实」。伪造谱系最多让一次发布接到别人的历史后面，仍受发布者身份限制。
- 自主档下智能体能直接完成的只限它自己的、普通风险的操作；它仍可能被聊天内容诱导去发出请求，所以发布、迁移和影响他人的操作一律要人确认。
- 扩展代码属于本机共享能力，创建者不决定管理范围；[Issue #51](https://github.com/NekroAI/nekro-nxt/issues/51) 确认由管理员设置的扩展自主权决定该范围。任务、待确认请求、智能体配置与私有数据仍按智能体隔离；共享本机配置沿用现有权限。列表只返回启用前提和配置提示，不返回配置值或凭据；修改其他智能体尚未完成的任务需要等待其结束。
- 快照只覆盖扩展的存储、索引和素材，不覆盖扩展外发出去的数据和凭据。迁移后、恢复快照前扩展新写入的数据会在恢复时丢失。
- 配置迁移只写目标扩展声明过的非凭据字段；类型不合的值由目标的配置校验拒绝。

## 4. 备选

- **只记「来源」不记谱系**：判断不了本机和社区谁更新，也做不了快进检查。
- **谱系存在传输包而不是 Manifest**：版本内容与历史分离，导出再导入会丢失历史；写进 Manifest 后历史随版本走。
- **按次数限制智能体**：限制次数挡不住一次就造成的危害，又让正常使用到处碰壁；改为按操作的影响范围和风险判断。
- **在频道里授权管理员**：频道授权只管频道命令，与「管理整台机器的扩展」不在一个层级，两种权限会错位。

## 5. 契约入口

- 谱系、版本号与风险分级：`packages/extension-format/src/lineage.ts`、`risk.ts`；Manifest：`manifest.ts`。
- 数据迁移、快照与切换：`packages/extension-runtime/src/lifecycle.ts`、`data.ts`；服务端 `apps/server/src/extension-governance/`。
- 管理员、请求与自主权：`apps/server/src/extension-governance/`、`apps/server/src/commands/`；能力字段 `AgentCapabilities.extensionAutonomy`、`extensionRequesters`。
- 接口：`packages/contracts/src/host-api.ts` 的扩展谱系、分支、回滚、数据、请求、管理员与社区同步契约。
- 扩展作者：`packages/extension-sdk` 的 `harness.migrateData` 与开发技能「扩展治理」一节；用户说明：[使用扩展](../../guide/extensions.md)。
- 命令：[命令系统](../../10-命令系统.md)的 `/ext`、`/admin` 与管理员权限级。
