# 内置频道与实体删除语义

状态：implemented

## 1. 用户词汇与内部语义

NekroNXT 自带、无需外部平台账号的频道在所有用户界面统一称为“内置频道”，领域 kind 为 `internal`，通用 API 使用 `createInternalChannel`。具体 Adapter 的包名和 key 只属于 Adapter 包；Host 通过 `system-singleton + internal + localChannel` 发现唯一内置实现，不比较 key。管理员通过产品 Composer 向外部平台频道发言时显示“管理员从客户端发出”。

## 2. Channel tombstone

删除频道不物理级联数据。`channels.deleted_at` 让频道退出活动产品状态；仓储在同一事务中清除当前 Binding，并从工作树的已绑定和未绑定列表移除该频道。Channel Event、Outbound、Episode、DSH Session 历史、Asset Occurrence、资源授权和内容寻址 blob 均保留。

`ChannelRuntime.deleteChannel(channelId)` 与该频道的换绑和解绑共用频道级转换锁，并在锁内读取当前 `(channelId, agentId)` lane：先以 `channel-deleted` 取消 DSH Session并关闭活动 Episode，不生成 Handoff，再提交 Channel tombstone。频道页对内置频道显示“删除内置频道”，对外部频道显示“从 NekroNXT 移除”；后者不操作外部平台中的真实频道。

外部 Adapter 再次观察到同一 `(connectionId, platformChannelId)` 时，`ensureChannel()` 清除 `deleted_at`，复用原 Channel ID 和历史。重新发现仍需按当前入站事实重新建立成员与 Binding，不从 tombstone 自动恢复旧绑定。

## 3. 删除智能体的频道范围

`channels.auto_created_for_agent_id` 只记录创建智能体事务自动生成的内置频道来源。删除智能体确认框默认开启“同时删除自动创建的内置频道”，且只删除同时满足以下条件的频道：

- `kind: internal`；
- `auto_created_for_agent_id` 等于待删除智能体；
- 删除提交时仍绑定给该智能体。

已换绑频道、手工创建的内置频道和外部频道不会自动删除，只会立即停止运行并解除 Binding。用户关闭默认选项时，自动创建的内置频道也只解除绑定。删除先逐频道停止运行并完成删除或解绑，再 dispose 并删除该智能体的 NekroNXT Extension Activation 和 DSH Agent Plugin Activation；任一运行时无法静止时中止删除，不发布智能体 tombstone。最后写入 `agent_definitions.deleted_at` tombstone，活动查询、Snapshot 和工作树不再返回该智能体；历史 Revision、Episode、DSH Session 审计、频道消息、已保存扩展、Asset 和 `workspaces/<agentId>/` 保留，不使用数据库级联或目录删除清理这些共享或历史事实。它的创造任务同样保留为历史，但随智能体离开 Snapshot 与工坊，任务的测试凭据删除；它的定时任务在 tombstone 事务中删除，因为这些任务不再有可唤醒的对象（见[定时任务](2026-10-07-定时任务.md)）。

## 4. 并发与 API

`DELETE /api/channels/:channelId` 必须携带 `expectedBoundAgentId`，其中 `null` 明确表示客户端预期频道未绑定。Host 在提交前比较当前 Binding，不一致返回 `409 binding-conflict`，避免陈旧页面误删刚换绑的频道。

`DELETE /api/agents/:agentId` 除当前 Revision 和名称确认外，携带 `deleteAutoCreatedBuiltInChannels`，省略时默认 `true`。响应分别返回 `deletedChannelIds` 和 `unboundChannelIds`，调用方不能把删除与解绑混成同一结果。

## 5. 持久化与恢复

SQLite 迁移 `0008_channel_tombstone_and_builtin_origin` 增加频道来源、Channel tombstone 和 `channel-deleted` Episode 终态。活动频道查询统一过滤 tombstone；历史查询继续按既有稳定 ID 工作。迁移重建 Episode 表时保留全部被引用数据，并在完成后通过 SQLite foreign key check。

## 6. Connection 删除与恢复

系统单例 Connection 不能删除。用户创建的 Connection 删除确认包含“同时删除频道数据”：

- 关闭时，Host 先停止关联 Channel lane 和 Adapter Runtime，再写入 `connections.archived_at`。归档 Connection 及其 Channel 不进入活动查询，原 Connection ID、凭据引用、Channel、成员、Binding、消息、Connection Event 和运行历史保持；添加连接界面从明确的归档记录恢复，不比较 Adapter key 或配置内容猜测账号；
- 开启时，Host 在资源静止后按外键依赖顺序物理删除该 Connection 的 Channel、成员、Binding、Channel/Connection Event、Episode、Admission、Outbound、Adapter state 和 Connection 行，再删除凭据文件。共享的内容寻址 Asset 不因一个 Connection 被删除而误删。

恢复只清除原 Connection 的 `archived_at` 并重新挂载当前 Adapter；新消息创建新的 Episode，已关闭的历史 Episode 不复活。Adapter 未安装时保留归档项但拒绝恢复。`DELETE /api/connections/:connectionId` 必须显式提交 `deleteChannelData`，`POST /api/connections/:connectionId/restore` 只接受归档的用户 Connection。
