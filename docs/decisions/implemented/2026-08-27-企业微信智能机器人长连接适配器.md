# 企业微信智能机器人长连接适配器

状态：implemented

## 结论

NekroNXT 通过 `@nekro-nxt/adapter-wecom-ai-bot` 接入企业微信官方智能机器人长连接。Connection 使用 BotID 与只写 Secret 主动连接 `wss://openws.work.weixin.qq.com`。一个 Connection 对应一个智能机器人；同一 BotID 建立新连接时，收到 `disconnected_event` 的 Runtime 进入 `connection-conflict` 状态并停止重连。

实现基于仓库现有 `ws`。官方 `@wecom/aibot-node-sdk@1.0.7` 用于协议字段对照，不作为运行时依赖。该 SDK 的主动发送参数、类型声明、流式组合和日志行为与现行官方文档存在差异，无法直接满足显式 `chat_type`、零起始媒体分片和敏感字段日志边界。

Webhook 智能机器人、群机器人 Webhook 和自建应用使用不同凭据、权限和消息链路，不属于本 Adapter。

## Host 契约

成功 `AdapterDeliveryReceipt` 允许缺少 `platformMessageId`。企业微信发送回执只包含 `errcode` 与 `errmsg`；Host 持久化成功投递，但撤回和平台消息引用只处理实际存在平台消息 ID 的回执。

`AdapterConnectionInteractions` 的处理中反馈、撤回和戳一戳均为独立可选方法。企业微信只实现处理中反馈。`AdapterPhysicalPlan.consumesProcessingFeedback` 允许一个物理投递消费最新 Feedback Lease，PhysicalDelivery 持久化 Lease 关联；成功或写入后结果未知时清除 Lease，明确失败时由 Host 收束占位消息。

活动事件支持直接提供 `targetLogicalMessageId`。Core 提交时验证目标消息属于同一 Connection 和 Channel，非法关系拒绝入库。新增活动类型为进入会话、卡片操作以及正向、负向和撤销消息反馈。

Host 统一提供 `fetchRemoteBytes`：只接受 HTTPS，禁止重定向、私网和元数据地址；DNS 解析后固定已校验地址并保留原 Host 与 TLS SNI；Content-Length 和流式读取均执行字节上限。OneBot 11 复用同一服务。

## 传输与状态

连接后使用 `aibot_subscribe` 认证，`headers.req_id` 关联请求和回执。同一 req_id 严格串行，不同 req_id 可以并发。请求默认 15 秒超时；写入前失败为临时失败，写入后断线或超时为未知。网络断线持续重连，认证连续失败三次后等待凭据修正。心跳每 30 秒发送一次，连续两次缺少成功回执时重建连接。

一个 Connection 首次启动时锁定 BotID，避免已有频道静默切换至另一个机器人。单帧上限 2 MiB，只接受 JSON 文本帧。诊断不包含 Secret、消息正文、userid、临时 URL、aeskey、req_id、媒体 Base64 或完整帧。

## 消息、身份与媒体

群聊平台频道 ID 为 `group:<chatid>`，单聊为 `single:<userid>`。群消息只有提及机器人账号时才由企业微信推送，因此统一记录 `mentionedBot=true`。userid 直接作为 Connection 范围平台身份；显示名缺失时保持为空。

文本和图文混排按顺序映射公共 MessagePart。图片、文件和视频通过 Host 下载加密字节，严格解码 32 字节 AES Key，使用 AES-256-CBC 和 Key 前 16 字节 IV，并手工验证 1–32 字节 PKCS#7 填充。密文与明文均限制为 100 MiB。临时 URL、aeskey 和密文副本不进入 Asset、Channel 事实、日志或 Web API。语音只保存官方转写文本；引用缺少目标消息 ID，只保存 `quote-summary`。

普通发送使用 `aibot_send_msg` 并明确提供单聊 `chat_type: 1` 或群聊 `chat_type: 2`。Markdown 按 UTF-8 字节切分。媒体通过 `aibot_upload_media_init/chunk/finish` 上传，原始分片不超过 512 KiB、索引从 0 开始；只有幂等分片允许有限重试，最终用户可见发送写入后不重试。

图片支持 PNG、JPEG、GIF，语音支持 AMR，视频支持 MP4；普通文件上限 20 MiB。Adapter 不执行转码。

## 流式反馈与特殊事件

群消息实际触发智能体时，Adapter 使用原回调 req_id 创建“正在处理…”流式消息。智能体首条纯文本投递复用 req_id 与 stream.id，替换内容并设置 `finish=true`。没有文本发言时按 Session 结果结束；九分钟未消费时结束为“处理仍在继续，结果将另行发送。”，企业微信十分钟窗口之外不再更新。

活动流式状态持久化在 Connection 命名空间。重启后在有效窗口内尝试结束为“处理未完成。”。写入后结果未知时不重复更新。受控 `feedback.id` 使用逻辑消息 ID 或 Lease ID，反馈回调只在同一频道验证目标后建立关系。

`enter_chat` 可以在用户启用事件触发后使用五秒欢迎语窗口。`template_card_event` 记录卡片类型、event key、task ID 和受限选择摘要；首版不更新卡片。`feedback_event` 记录反馈类型、正文和负反馈原因。所有特殊事件默认入库但不触发智能体，只有 Binding 明确启用后才创建 Admission。

## 验证状态与边界

自动化覆盖订阅、认证失败上限、同 req_id 串行、媒体解密、UTF-8 切分、零起始上传分片、流式 Lease、欢迎语、卡片、反馈和连接冲突。当前未提供独立企业微信测试企业与专用机器人，因此状态为“自动化通过、未完成企业微信实机验证”。

首版不支持私有化 Endpoint、自签 CA、Webhook 模式、自建应用、模板卡片发送或更新、媒体转码、消息撤回、任意平台命令透传。
