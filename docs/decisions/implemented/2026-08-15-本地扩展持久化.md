# 本地扩展持久化

状态：implemented

## 结论

当前闭环只有三个独立动作：运行指定动态 Package、把指定 Package 保存为不可变本地 Extension Revision、给指定智能体启用指定 Revision。没有 Draft、导入、删除、市场兼容或 Activation 历史状态机。

## 当前领域事实

`LocalExtension` 只保存稳定 `id`、`slug`、`displayName`、`description`、可选 `createdByAgentId` 和 `createdAt`。

`ExtensionRevision` 只保存稳定 `id`、`extensionId`、扩展内递增 `revisionNumber`、规范化源码内容摘要和 `createdAt`。Revision 不可变；相同内容复用已有 Revision。

新 Revision 写入 Manifest V2：`schemaVersion: 2`、稳定身份、Host/Client entrypoints 和由运行时验证得到的 `tool`、`rpc`、`client-slot` Contributions。Builder 继续读取旧 V1，并把它规范化为没有 Contribution；旧不可变目录不重写。Builder key 使用 V2，避免复用旧构建缓存。

`extension_revision_verifications` 以 Revision 为主键持久保存 DSH/契约版本、Episode/Plugin/Package/Run 来源、构建结果、合成 Tool 调用、RPC 方法和实际渲染 Slot。验证输入输出限制为 16 KiB。源码发布后必须先完成构建与运行时验证，随后 Extension、Revision 和 Verification 在一个 SQLite immediate transaction 中可见；任何验证失败都不发布数据库 Revision。

`AgentActivation` 以 `(agentId, extensionId)` 为复合主键，只保存当前成功启用的 `extensionRevisionId`、配置和 `activatedAt`。它不保存 Activation ID、pending/waiting/failed/disabled 状态、默认 Revision、兼容范围、来源类型或单值 `runtimeKind`。

`extension_client_diagnostics` 以 `(agentId, extensionId)` 为主键，只保存当前 Activation 最近一次 `loaded` / `failed`、精确 Revision、可选错误和观察时间；停用 Activation 时级联删除。它是可诊断状态，不参与 Activation 事务，也不因 Client 失败回滚 Host。

## 文件与数据库提交顺序

保存 API 必须显式传入 `agentId + episodeId + pluginId + packageId + displayName + slug + description`。其他动态审批、Host half、Client 源码、调用、Guard 和渲染证据请求同样携带 `episodeId`。Web 不能按智能体寻找“第一个 Package”或 Session；创造工作台使用 `episodeId:pluginId:packageId` 作为稳定选择键。宿主校验 Agent、活动 Episode、DSH Session、Plugin 和 Package 完整归属，并且只接受等于 `currentPackageId`、当前仍在运行、最新 Run 已成功的精确 Package。含 Client 半边的 Run 还必须由浏览器在允许的产品 Slot 提交真实渲染证据。宿主随后在临时目录完成规范化和最小构建验证，再以原子 rename 发布完整源码目录，最后用一个数据库事务保存 Extension、Revision 与 Verification。

文件系统与 SQLite 不伪装成跨介质事务。源码发布失败时数据库不可见；数据库提交失败或进程在提交前崩溃时，已发布但无人引用的目录可以安全忽略。当前不建立 save operation journal、staging 恢复状态机或 quarantine 领域状态。

源码 Revision 是持久事实；构建 bundle 和 `build.json` 是可删除缓存，缺失或损坏时从源码重建。所有持久 JSON 和缓存清单读取都必须经过其 Zod Schema。

## 动态创造策略

每个 Episode 同时只维护一个动态 Plugin；创建后只能以 `kind:existing` 向同一 Plugin 追加不可变 Package，显式 `undefine` 后才允许创建另一个。策略按普通用户 Turn 计数：连续失败最多三次，相同 `phase + 规范化 message` 出现两次立即熔断。熔断只拒绝 define/run，仍允许 Inspect、Stop、Undefine 和频道通信；新的普通用户 Turn 重置失败预算但保留 Plugin。产品快照投影全部活动 Episode，并把 Package 历史和策略状态一起交给创造工作台。

## Activation

启用新 Revision 时先构建，在智能体的安全间隙挂载新版本；挂载成功后才事务 upsert 当前 Activation。失败时恢复旧挂载，数据库仍指向旧 Revision。停用删除当前 `(agentId, extensionId)` 关系；同一 Extension 可由多个智能体独立启停。

Server 重启只恢复数据库中的当前 Activation。运行期注册、Fiber、Tool、Slot 和监听器都是可撤销 effect；停用与 dispose 必须等待它们静止。

每个 Activation 只执行一次 Host factory；`harness.handle` 只能在 factory 阶段注册 RPC，handler 生命周期属于 Activation。factory 返回的 Cordis Plugin 按该智能体每个 DSH Session 挂载 Tool Fiber，Session dispose 只撤销自己的 Fiber。停用或 Revision 切换才撤销全部 Fiber 与 RPC。

Client Artifact 只通过精确 `extensionId + revisionId + buildKey + agentId` 提供。每个智能体拥有独立 SlotCore，当前只声明 `agent.workbench.sections`、`extension.details.panels`；动态预览与持久 Runtime 使用同一 Slot 名、Props 和稳定 Styles。Revision 更新先 dispose 旧 Client 再 mount 新 Client；Client 失败由单扩展 Error Boundary 隔离并写最近诊断，Host Activation 保持。

## 磁盘边界

源码归 `extension-data/extensions/<extensionId>/revisions/<revisionId>/`，临时发布目录归 `extension-data/staging/`，构建缓存归独立 `extension-cache/`。Extension 只能通过公开 SDK 和 Service/Contribution 接缝访问宿主，不能读取 Core 数据库或依赖宿主绝对路径作为身份。

## 当前不做

本期不实现 Extension Draft、导入/删除、社区市场、签名、兼容范围、迁移导出、Activation 历史、失败队列或未来 Runtime 类型预留。等真实消费者出现时再增加相应字段和生命周期。
