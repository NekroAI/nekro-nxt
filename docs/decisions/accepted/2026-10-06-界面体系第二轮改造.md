# 界面体系第二轮改造

状态：accepted（2026-10-06 用户确认；分阶段实施，进度见 §10）

本决定在[客户端体验重构与扩展界面统一](2026-10-04-客户端体验重构与扩展界面统一.md)的信息架构之上，建立统一的设计基础（Token、版式、交互语法、信息分层），重做全部页面，并只保留一套组件库。领域不变量不变：智能体与扩展仍以不可变 Revision 演进，运行中的会话只在安全点切换配置。

## 1. 理由

第一轮重构完成了空间划分与功能迁移，但没有建立设计基础，页面逐个拼接：所有页面套用同一限宽模板，配置与表格被挤压、宽屏留白；没有间距与尺寸档位，内外边距各写各的；同类对象的点击行为不统一；内部版本号、键名与错误码直接展示；旧组件与新组件并存，靠 Token 别名勉强统一配色；暗色主题下部分控件仍是亮色样式。验收只覆盖单一宽度与少量数据，未能发现这些问题。

## 2. 用户已确认的取舍

1. 默认密度为“标准”（行高 40），外观设置提供“紧凑”。
2. 智能体页为一页滚动加固定分节导航，不使用标签页。
3. **不向用户强化“版本”概念。** 智能体只是几个配置项的集合：界面上只有“保存”，不出现“发布新版本”、版本号或版本历史区。Revision 仍在后端生成，用于会话安全切换与审计；只在“更多”菜单保留一个低调的“恢复之前的配置”入口。扩展同样不展示版本序号，只在扩展详情的“版本”节以时间区分可切换的保存记录。
4. 智能体页先展示功能（模型、频道、能力、扩展），设定默认折叠为摘要，展开或编辑时才显示全文。
5. 扩展界面合约直接升级为 `ui-kit@2`，不兼容 `ui-kit@1`。
6. 暗色主题按独立主题设计，不能出现亮色样式的控件；颜色只能来自 Token。

## 3. Token

`apps/web/src/ui-kit/tokens.css` 是唯一 Token 来源：

- **间距** `--s-1`…`--s-9`：4/8/12/16/20/24/32/48/64。
- **尺寸**：控件高 28/32/40（紧凑/标准/大）；行高 32/40/56；图标 14/16/20；点击目标不小于 32。
- **密度**：根元素 `data-density="comfortable|compact"` 切换尺寸 Token，组件不写两套数值。
- **文字角色**：页标题、区块标题、正文、说明、标签、数字、等宽；组件使用角色，不直接使用字号。
- **颜色角色**：强调色拆为填充（`--accent-fill`、`--on-accent-fill`）、文字（`--accent-text`）、描边（`--accent-line`）、浅底（`--accent-soft`）；成功、警告、危险同样拆分。明暗两套各自取值，组件只引用角色。另设四档风险色 `--risk-0`…`--risk-3`。
- **身份色**按对象分配（智能体、频道各自稳定），同一画面内可区分。
- **断点** 1100 / 1280 / 1440 / 1920。

## 4. 页面版式

| 版式 | 用于 | 规则 |
|---|---|---|
| `ReaderPage` | 关于、外观、通知 | 正文限宽 720–880，居中 |
| `WorkbenchPage` | 模型、DSH 插件、适配器、工坊、接线、智能体、频道 | 铺满：可折叠列表栏（240–320）+ 主区 + 可收起详情栏（320–400） |
| `BoardPage` | 现场 | 响应式网格 |

每个空间入口必须声明版式；页面内不得再嵌套分栏。

## 5. 交互语法

- **选中与打开**：单击对象只选中并在详情栏显示；详情中的“打开”或双击才跳转到对象所属空间。列表行、接线节点、现场卡片一致。
- **保存**：智能体的名称、设定、模型、能力就地编辑，改动累积到底部保存栏“N 项未保存的修改 · 保存”，一次保存；频道触发、连接设置、外观、通知等即时生效并可撤销。不再有整页“编辑模式”。
- **长文本**（设定）在原位展开专用编辑面板，可全屏。
- **危险操作**写明后果；授权类按风险级别决定确认力度。

## 6. 信息分层

- 第一层只放名称、状态、后果和下一步。
- 键名、错误码、包名、命名空间、配置版本、内部 ID、Revision 编号进入默认收起的“诊断”区，可复制。
- 错误码映射为中文原因与建议操作，未映射时显示通用原因。
- 状态词典：连接、智能体、任务、扩展各有固定的状态、颜色与措辞，状态栏、列表、详情与现场共用。

## 7. 组件

`ui-kit/next` 改名为 `ui-kit`，删除旧组件库、`ui.module.css` 与 `--nxt-*` 别名。新增：版式组件、`DetailPane`、`PropertyList`/`PropertyRow`、`DataTable`、`RiskLadder`、`SaveBar`、`ObjectHeader`、`Diagnostics`、完整形式的 `EmptyState`、`InlineEdit`、`SearchField`、`Toolbar`、`KeyValueCopy`。模型设置、DSH 插件设置、设定引用编辑器、消息内容、反馈组件与扩展 `ui-kit@2` 全部改用新组件。

系统访问使用 `RiskLadder`：四级递进刻度，每级只写新增能力，风险色逐级加深；可展开“手动调整”直接控制文件读写、运行命令、完整访问，并维护依赖；不属于任何级别时显示“自定义”。

## 8. 页面

- **外壳**：顶栏不再重复页面标题；状态栏使用状态词典并可点击进入对应详情。
- **现场**：潮汐图按频道着色并可筛选；关注项按严重度排序合并；活动卡片收紧。
- **频道**：列表检索与筛选；检查器改为 `DetailPane` + `PropertyList`（响应、频道事件、上下文、来源、诊断），名称就地编辑。
- **智能体**：`ObjectHeader` 后依次为模型、频道、能力、扩展、设定（折叠摘要），保存栏统一保存；“更多”里有恢复之前的配置与删除。
- **工坊**：左栏为创造任务与扩展库；空状态说明扩展的作用与入口；任务页为紧凑阶段条、预览与当前待办；扩展详情为概览、使用、配置、版本（按时间）、诊断。
- **接线**：所有节点单击只选中；频道按账号分组可折叠，支持检索与“只看未接线”；详情改为统一组件，错误码映射为中文。
- **设置**：模型为供应商列表 + 详情（凭据、模型表、连接测试、高级）；DSH 插件以目录为主、安装进对话框、配置用统一表单并显示中文字段；适配器为列表；通知、外观、关于为阅读型。
- **命令面板**：分组、最近使用、动作类命令。

## 9. 门禁

- **布局审计**（Playwright）：1100/1280/1440/1920 × 明暗，检查横向溢出、截断、重叠、点击目标与空白画布。
- **样式门禁**（Stylelint）：CSS Module 中颜色、间距、圆角、阴影、字号只能使用 Token。
- **版式门禁**：空间入口使用三种版式之一。
- **信息门禁**：用户可见文案中禁止 rN 编号、错误码格式与配置键名。
- **真实数据样本**：40 个模型、200 名成员、30 个频道、两千字设定、长名称与 Emoji。
- **像素基线**：1280 与 1920，明暗各一套；保留逐帧动效审计。
