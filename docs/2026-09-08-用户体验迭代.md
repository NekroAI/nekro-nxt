# 用户体验迭代：从生成结果到持续使用

## 方案摘要

先让“验证通过、可以使用”对应安装后的真实结果，再缩短失败恢复路径，最后调整默认界面和上手流程。保留群聊、智能体与工具创造的产品方向；普通用户优先看到内容、结果和下一步，诊断与高级设置按需展开。

本轮以真实 Web 体验为输入。模型生成的采购页面在预览中可操作，首次保存安装后出现 `styles is not defined`；通过对话反馈、生成修复版并重新安装后可用，修改和勾选记录在刷新后保留。该案例证明修复路径存在，也暴露预览验证不能代表持久交付的缺口。它不代表所有扩展或 Desktop 路径都已验收。

## 实施顺序与状态

| 批次 | 目标 | 状态 | 完成边界 |
| --- | --- | --- | --- |
| 0 | 整理既有模型供应商移除改动 | 已完成 | 独立审查并补齐引用提交保护、启动配置限制与未知结果核对，已通过生产旅程并提交 |
| 1 | 预览与安装运行一致 | 已完成本次样式缺陷修复 | 页面物化绑定已修复；安装后样式、交互及刷新恢复有回归保护，完整模型创造链仍需后续扩充 |
| 2 | 失败后就地修复与更新 | 待实施 | 错误页可发起修复，保留结果身份及数据，修复后能更新并打开 |
| 3 | 对话与创造页面以结果为主 | 待实施 | 内容可读、诊断收起、预览优先、保存继承上下文 |
| 4 | 上手与导航简化 | 待实施 | 基础配置先行、连接向导明确、对象可查找、扩展按用途组织 |

每批次独立提交和记录实际验证。后续条目描述目标，不冒充当前已提供的行为；落地时修改现行契约中对应章节。没有真实平台验收的部分继续保留限制，不因前一轮工程检查通过而标为完成。

## 批次 1：先修复交付一致性

- 对照动态预览与持久页面的 Client factory、React、UI Kit、样式映射及资源装载，找到同一候选表现不同的原因；在实际所有者处修复，不针对体验样本硬编码。
- 用合成候选覆盖样式引用、页面交互、保存安装及重新打开；确认刷新后记录保持。重建或安装失败不得损害已安装版本及原数据。
- 保留权限范围、CSS 作用域与资源限制。运行环境一致不意味着扩大扩展可访问的宿主能力。
- 检查生成材料中的示例与实际运行协议是否一致；只有发现失真才改，避免把问题转嫁给模型提示词。
- 验证以正式页面入口为终点；后续完善“验证通过”的证据范围，区分候选预览、所保存版本和当前安装运行结果。

所有者：扩展构建与物化、Web 动态 Client 与持久 Host UI 加载器。验收：相关单元/浏览器回归和生产保存安装旅程通过；常驻开发页面和 API 可访问。

## 批次 2：失败恢复与版本更新

- 运行失败页提供“交给创建者修复”，携带扩展、修订、失败阶段和脱敏错误；发送前明确目标智能体与内容，不把修复发到外部群聊。
- 对来源已删除、智能体未授权创造、任务仍运行等情况提供具体下一步；不静默提升权限。
- 修复候选关联原扩展，保存默认更新该扩展。保留不可变版本及旧版本回退，权限变化单独说明。
- 提供“更新并打开”的连贯操作；分别记录保存和安装结果。保存已成功而安装失败时提示重试安装，不让用户重复生成等价版本。
- 明确工具数据保存位置和持续性。浏览器本地记录不能暗示跨设备同步；验证更新与刷新保持记录，不声称已经具备备份。

所有者：创造应用服务、扩展安装服务、Web 错误页与保存表单。验收覆盖成功、无创建者、明确失败、结果未知、安装失败重试、权限变化和数据保留。

## 批次 3：默认页面围绕结果

- 修复消息中的换行、列表与长内容阅读；保留结构化消息语义。普通对话不展示结束协议 JSON 或“未必发送消息”这类与已显示事实冲突的提示。
- 默认收起缓存/Token 诊断，保留按需查看和用户主动选择；真正需要处理的运行错误与等待确认仍在主路径提示。
- 创造页面先呈现可用预览和下一步动作，阶段条、运行协议及视觉建议移入详情。长任务有简明进度和可发现的停止入口。
- 保存继承候选名称、说明和原扩展关系。本地标识自动生成，必要时才手动编辑。
- 修复浅色主题中名称与背景对比不足，检查深色主题及减少动效下的反馈。

所有者：会话渲染、检查器、创造页面、保存表单与主题。验收：实际聊天、创建和更新旅程；浅深主题、窄窗、键盘和减少动效；错误不能因精简默认界面而不可见。

## 批次 4：上手与持续使用

- 创建智能体以名称、用途和模型为基础，图片恢复数量等高级选项按需展开；创造能力说明用途与边界，避免只显示等级。长表单保留可见的提交入口。
- 连接表单提供凭据获取指引和连接测试，将字符/字节等协议参数移入高级设置；未绑定频道直接提供绑定或创建智能体的下一步。
- 对象列提供搜索、折叠、最近使用与归档入口，保留现有排序和偏好。归档与删除明确区分，不清理历史消息来缩短列表。
- 扩展按“我的工具、平台接入、模型能力”等用户用途组织，底层格式与运行时信息进入详情。旧验证标注历史范围，“需要重建”与当前运行状态明确区分。

所有者：智能体表单、连接向导、导航、扩展和设置页面。验收：新用户可在不阅读开发文档的情况下进入首个对话；多智能体、多频道情况下能定位对象；既有偏好及配置保持。

## 验证与交付记录

2026-09-08 本轮交付：

- 既有供应商移除改动独立提交；引用检查移到宿主服务，并在引用持久化提交入口阻止删除期间的并发写入。固定接入及启动基础配置不假装移除成功；响应丢失后只读取核对，不自动重发删除。
- 页面物化器补充 `styles` 参数，动态预览和持久运行均可引用样式映射。旧修订保持不可变，缺少参数的旧源码需通过创造生成新修订；清理缓存或普通源码重建无效。
- 全 workspace 生产构建及 18 个产物入口检查通过；最终 Server 接线变动后补构建。相关存储、扩展运行、动态 Client、持久页面、供应商移除 Node 测试通过；新增测试夹具中的字段和类型问题已修正并重跑相关范围。
- 6 项生产旅程通过：浅深主题的供应商移除、引用与版本冲突、两种响应丢失恢复，以及扩展样式/交互/刷新恢复和未授权访问拒绝。扩展旅程使用真实物化的合成包，经导入保存、安装后访问真实产物；没有冒充模型生成、浏览器批准和工作台点击保存的完整旅程。
- 类型、ESLint、格式、静态安全、CSS 类型、workspace 和文档检查通过。已查看生产确认弹窗及安装刷新后的页面画面。ESLint 排除各包 `.local` 运行产物，避免把测试生成的扩展源码当作仓库源码检查；本次样式旅程结束后卸载并删除自己的合成扩展。

批次开始前保留原工作区改动，测试使用合成数据和隔离宿主。运行相关测试和类型检查，涉及 Web 则构建生产产物并验收受影响旅程；不重复执行与本批无关的整仓测试。最终确认原常驻宿主、API 与真实页面仍可访问。

本轮不执行正式发布，不修改真实聊天及凭据，不把产品体验中的个人数据写入仓库。提交完成不等于公开交付，平台分发验证仍需另行记录。
