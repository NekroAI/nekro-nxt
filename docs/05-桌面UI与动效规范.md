# NekroNXT 桌面 UI 与动效规范

> 文档编号：05
> 文档性质：基础视觉、桌面交互和动效的唯一事实源
> 状态：一期设计基线
> 适用范围：Web UI、Electron Renderer、System Client UI 和 Extension Client Contribution

## 0. 设计定位

NekroNXT 的界面目标是：**冷静、精密、有生命感；高级但不花哨，专业但不像企业后台。**

产品以鼠标、触控板和键盘操作的 PC 应用为主，不复制手机或平板交互。高级感来自准确的排版、克制的颜色、稳定的空间层级、低延迟反馈和一致行为，不来自大面积毛玻璃、持续光效、弹跳或卡片墙。

月潮靛是品牌主色，用于选择、连接、运行和少量品牌识别；流明蓝只标记焦点与能量端点，黄铜只标记校准节点和品牌签名。消息正文、代码、日志、配置表单等长期阅读区域保持高对比中性色实底。

视觉以实现中的 `--nxt-*` Token 和 ui-kit 为准。`prototype/` 用来确认对象标记、空位、工位和会话密度；概念图只作对象关系参考。

## 1. 基础原则

1. **内容优先**：频道消息、代码、配置和诊断信息始终比装饰更醒目；
2. **桌面效率**：优先键盘、Hover、右键菜单、精确拖动、分栏和高信息密度，不为触屏放大所有控件；
3. **即时反馈**：按下、选择、保存、执行和失败都在动作发生时反馈，不用无意义等待动画；
4. **空间一致**：面板从其所在方向出现并沿原路径退出；触发器与浮层的空间关系明确；
5. **克制动效**：默认无弹跳、无惯性投掷、无装饰循环；动效只解释状态或空间变化；
6. **用户掌控**：未保存 Draft、危险操作、运行中任务和失败恢复都给出明确结果与撤销/恢复路径；
7. **双主题平权**：浅色和深色都是完整主题，不把浅色主题作为反色补丁；
8. **扩展一致**：System UI 和 Extension UI 使用同一语义 Token、基础组件与动效等级。

### 2.4 使用比例与品牌签名

- 中性色承担至少 85% 的界面面积；
- 月潮靛、流明蓝和黄铜不承担成功、警告和错误语义，状态色独立定义；
- 主按钮使用纯色，不默认使用渐变；
- 品牌渐变只允许出现在 Logo、2px 活动状态环、运行轨迹线和创造状态的窄强调区域；
- 推荐品牌渐变：`linear-gradient(120deg, #466394, #3fb1ea)`，只在 Logo、2px 轨迹和窄强调区使用；
- Glow 只允许作为 1–2px 焦点或运行状态的低透明外环，不作为容器背景。

### 2.5 状态色

状态色需要浅色/深色主题各自校验，不能由品牌色自动推导：

- success：连接成功、验证通过；
- warning：即将失效、需要用户处理；
- danger：发送失败、不可恢复和危险动作；
- info：中性系统信息，可使用流明蓝；
- unknown：未知结果，使用中性灰紫，不能伪装成成功或失败。

### 2.6 平台品牌资产

- 项目标志采用水月荧侧脸头像章，保留银白短发、圆框眼镜、深蓝帽、金色圆环和水母头饰；16–32px 微型版只减少缩放噪声，不另画字母或抽象图形；
- Stable 使用主头像章；Preview 保留同一轮廓，只在右下角增加黄铜—流明蓝—黄铜三节点校准标记，不使用 Beta、Canary 或字母角标；
- Web 提供 SVG/ICO favicon、Apple Touch、PWA、maskable 和 pinned-tab；Desktop 的 Stable/Preview 分别拥有 ICNS、ICO、Linux PNG 图标组、DMG 背景和 NSIS 安装/卸载图；
- macOS DMG 使用 660×420、72 DPI 的珍珠底，不在背景预绘应用或 Applications 图标；Finder 图标中心位于 `(190, 220)` 和 `(470, 220)`。Windows assisted installer 使用 164×314 sidebar 与 150×57 header；
- 安装、升级、备份和恢复使用 `assets/brand/generated/process/` 与 `status/` 的 64px 装饰图标；日常按钮、菜单和运行状态继续使用 ui-kit 与 Lucide；
- 水月荧属于品牌角色，不自动成为产品中的智能体，也不作为默认头像、消息发送者或运行状态图标。人物只进入 README、安装、Release、欢迎、关于和少量大空态/完成页；
- `assets/brand/` 是可公开、可重建的唯一品牌母版，`pnpm brand:export` 同步平台消费物，`pnpm brand:check` 校验尺寸、格式、元数据、哈希和 Stable/Preview 差异。公开构建不得读取 `.local`。

## 3. 排版

### 3.1 字体

```css
--nxt-font-sans: Inter, ui-sans-serif, system-ui, -apple-system,
  BlinkMacSystemFont, 'Segoe UI', 'PingFang SC', 'Microsoft YaHei', sans-serif;
--nxt-font-mono: 'SFMono-Regular', 'Cascadia Code', 'Roboto Mono',
  ui-monospace, monospace;
```

首期不因品牌感引入装饰字体。中文不套用英文标题的强制负字距；混合文本按真实 Windows/macOS 渲染验证。数字、时间、Token 和日志可使用 `font-variant-numeric: tabular-nums`。

### 3.2 字号层级

| Token | 字号/行高 | 用途 |
|---|---|---|
| `caption` | 11/16 | 时间、次要元数据，不能承载关键操作说明 |
| `label` | 12/18 | 字段标签、表头、状态说明 |
| `body-sm` | 13/20 | 高密度列表、检查器、菜单 |
| `body` | 14/22 | 消息、表单和普通正文 |
| `subtitle` | 16/24 | Panel 标题、关键对象名 |
| `title` | 20/28 | 页面标题 |
| `display` | 28/36 | 首次引导和少量空状态，不用于管理页常规标题 |

正文默认 14px，不用 11–12px 灰字堆砌高级感。标题主要依靠层级、字重和间距，不依靠超大字号。

## 4. 间距、尺寸与密度

基础网格为 4px：

```css
--nxt-space-1: 4px;
--nxt-space-2: 8px;
--nxt-space-3: 12px;
--nxt-space-4: 16px;
--nxt-space-5: 20px;
--nxt-space-6: 24px;
--nxt-space-8: 32px;
--nxt-space-10: 40px;
--nxt-space-12: 48px;
```

- 默认按钮、输入框和 Select 高度：32px；
- 紧凑表格/工具栏控件：28px；
- 关键 Composer 和主操作：36px；
- 图标：14、16、18、20px 四档；
- 默认列表行：32–36px；包含两行文字时 48–56px；
- 鼠标目标通常不小于 28×28px；高频危险动作保留更大间距；
- 默认提供 Comfortable 密度，运行详情、文件树和日志可使用 Compact；
- 不使用移动端统一 44px 高度，也不通过巨大留白降低桌面信息效率。

## 5. 圆角、边框、阴影与材质

```css
--nxt-radius-sm: 4px;
--nxt-radius-md: 8px;
--nxt-radius-lg: 12px;
--nxt-radius-round: 999px;

--nxt-shadow-float: 0 8px 24px rgb(5 18 26 / 14%);
--nxt-shadow-dialog: 0 20px 60px rgb(3 14 22 / 24%);
```

- 小标签、代码块内部元素用 4px；按钮、输入和列表选择用 8px；Dialog、Popover 和独立浮层用 12px；
- 页面分组首先使用间距、标题和轻微背景差，不为每组内容增加 Card；
- Card 只用于可独立选择、拖动或拥有明确生命周期的对象；
- 工作区、消息、代码和表单使用实底；
- 半透明只允许用于标题栏、浮动工具栏和非阻塞浮层，且必须有不透明降级；
- 不叠加两层毛玻璃，不在正文下方持续显示复杂背景；
- 普通面板不使用悬浮阴影，层级主要由边框和背景明度表达；实验视觉中确需投影的独立表面，其内容列、页面过渡层和外层分组不得使用 `overflow: hidden/clip` 截断投影，内部装饰改由不越界的伪元素实现；
- Renderer 壳层面板在视口外沿保持方角、零外框和零外投影，窗口圆角与裁切由 Desktop 原生窗口负责；图标轨、对象列、主画布之间仍保留内部细分隔，不用四周高亮描边模拟窗口边缘；
- 页面标题可以保持左对齐，但窄于主内容列的设置组、空态和任务表面必须相对主画布内容区居中，不能贴在过渡层左侧；减少动效只关闭动画，不改变页面层级或中心轴。
- 用户、扩展和设置等领域页使用主画布全宽，不用 `max-width` 形成居中的网页正文列。页头、工具栏和底部操作属于稳定外壳；列表、表体或详情正文占用剩余高度并独立滚动。搜索、筛选、表头和分页不得随数据内容滚动或在筛选时改变位置；只有当前对象或数据区域参与切换动效。
- 空态占满所属列表、消息区或详情区的可用面积，空态图形、标题、说明和动作作为一个整体居中。空态容器保持透明、无边框、无圆角和无阴影；插画使用透明画布，不把空态重新包装成悬浮卡片。

### 5.1 容器连续性与视觉重量

页头、对象摘要、元数据、正文和操作区必须先确定属于哪个表面（Surface），再使用背景、边框和间距。不得把局部颜色、圆角或 `sticky` 当作临时修补；每一块可见底色都必须能说明它代表的容器、层级与边界。

常见失败范式：

- **孤立横幅**：只为一两行标题铺满宽高对比底色，但没有工具栏、状态转换或独立对象语义，看起来像遮罩、表头或外部页面被粘进当前界面；
- **容器拼接**：标题有底色、元数据落在画布、表单又进入另一张卡片，相关信息被边框、圆角和明度切成互不归属的孤岛；
- **重量倒挂**：装饰性背景的面积和对比度大于主内容，次要标题比表单、诊断或主操作更先吸引视线；
- **贴边与滚动条侵入**：标题、徽标、按钮或正文贴住容器外沿或滚动条，滚动槽被当成内容留白；
- **几何语言断裂**：同一对象的相邻区域混用直角、圆角、阴影、描边和不同明度，却没有层级变化；
- **粘性色块**：`position: sticky` 元素使用与所属内容不同的实底，滚动前就形成突兀的横向色带，滚动时又遮住或切断正文。

实现约束：

- 同一详情对象的页头和正文默认共用一个连续表面；需要分区时优先使用间距和一条低对比分隔线，不再添加一块满宽底色；
- 独立表面的内部边距使用 Space Token，默认不小于 16px；窄视口可收紧间距，但右侧控件与滚动条之间仍须保留明确安全区；
- 标题区只在确实需要在长内容中持续提供定位或操作时才使用 `sticky`；静止状态下不得因粘性实现出现额外横幅；
- 嵌套表面每深入一层只增加一种可解释的差异（背景、边框或间距之一），不同时叠加新底色、强描边、阴影和更大圆角；
- 修复局部观感时不允许直接新增硬编码颜色或随意像素值；必须先修正 DOM 归属、滚动边界和表面层级，再选择现有 Token。

视觉验收时，浅色与深色都要在页面顶部、中部滚动位置和接近底部的状态检查容器连续性。出现看似外部页面、遮罩、临时表头、悬空色条或被滚动条切掉的控件，即视为不通过。

## 6. PC 桌面布局

### 6.1 窗口基线

- 推荐最小窗口：1100×720；
- 主工作宽度针对 1280、1440、1920 三档验证；
- 不转换成底部导航或手机式页面栈；窗口不足时优先收起右侧检查器；
- 1100px 档的频道标题栏保持单行；次要动作可收敛为保留无障碍名称的图标按钮，不得把中文标签压成逐字竖排；
- Desktop 与 Web 外壳统一使用 48px 顶栏坐标系，拖动区域和交互控件不得重叠；
- Desktop 不显示系统标题栏，Renderer 自绘统一 48px 品牌顶栏；macOS 使用 `hiddenInset` 保留左侧 traffic lights，Windows/Linux 使用 `frame: false + titleBarOverlay` 保留右侧窗口控件；
- Desktop 原生窗口拥有最终圆角与裁切；Renderer 的顶栏、图标轨、对象列和主画布铺到视口边缘且使用方形外角，不在浅色或深色主题下叠加外沿边框、高光或阴影；
- macOS 左侧预留 84px，Windows/Linux 右侧预留 138px，Web 两侧安全区为 0；安全区只约束品牌与业务内容，顶栏底部装饰线从窗口左边缘开始。三端使用同一产品结构和顶栏几何，不把控件覆盖区当业务空间；
- 顶栏整体是窗口拖动区，任何进入顶栏的按钮、输入和浮层触发器必须显式标记为 no-drag；平台安全区由 Desktop 注入根 CSS 变量，页面不得按 user agent 猜平台。

### 6.2 应用外壳

```text
顶栏 48
└─ 主体
   ├─ 图标轨 56
   ├─ 对象列 240（可调 200–304，始终保留）
   ├─ 主画布 minmax(0, 1fr)
   └─ 检查器 360（可调 320–520，可收起）
```

- 图标轨顶部固定“工作、连接、用户、扩展、设置”系统组。至少存在一个可见扩展页面时显示轻量分界线，扩展入口组独立滚动；底部主题和服务实例入口固定。扩展页面图标来自受控 Host 图标目录或单色 SVG mask；系统组不可隐藏或排序；
- Desktop 图标轨底部依次放置主题与服务实例按钮；两者使用相同的 36px 尺寸、透明静止态、悬浮底色、圆角和焦点反馈。服务实例不是一级业务模式，普通浏览器不显示该按钮。Renderer 只以 `window.nekroDesktopShell` 是否存在判断 Desktop 能力，不依赖查询参数；因此入口在 `/work` 初始重定向和后续全部路由导航中持续存在。两项保留完整无障碍名称但不渲染悬浮文字 Tooltip，避免跨原生 View 的焦点与 Hover 时序造成文案闪回；服务实例用 7px 状态点表达正在连接、正常、不稳定、离线、需认证与不兼容；
- 服务实例 Sheet 由独立可信 `WebContentsView` 渲染。该 View 从 48px 顶栏下沿覆盖完整窗口正文，使用透明 scrim 明确遮挡关系并承接 Backdrop 点击；420px 宽、最大高 560px 的面板锚定图标轨右侧与窗口底部，标题与添加操作固定，实例列表独立滚动。列表项保持 4px 间距，当前项直接复用频道选择器的滑动选中底、左侧强调线与勾选，不给相邻条目拼接成一整块。本地实例固定第一项；普通打开先聚焦无描边的 Dialog 表面，不自动给面板或任何实例行绘制焦点框；键盘继续可用 Tab 或方向键进入列表。表单输入框使用 ui-kit 单层聚焦环，点击表单空白区域一次即取消输入焦点。Fallback 的“重新认证”直接打开当前实例的空密钥表单并聚焦，不要求再次从列表寻找；
- 服务实例按钮是开关而不是重复“打开”命令：再次点击或点击对应位置的 Backdrop 必须收起已打开 Sheet。Sheet 以按钮侧的左下角为变换原点，进入使用 160ms opacity + `scale(.98)` + 10px 向上位移，退出沿原路径使用 100ms，退出完成后才从原生 View 树移除。行内更多菜单绝对定位在列表上方，点击菜单、触发器和 Sheet 之外均关闭；整个行或按钮的可点击区域连续，不留下 pointer/default 指针死区；
- 本地连接状态页保留 48px 标题栏和平台安全区，正常切换显示“服务实例 / 正在切换”，不得显示“可信恢复”等内部术语。切换页先以透明 View 在旧实例上方完成预加载，再用 240ms 淡入覆盖旧实例；完全覆盖后才销毁旧 Product。整段切换从开始淡入起至少保持约 2 秒，新页面完成同源校验且最短时间满足后，切换页再用 240ms 淡出以露出新实例；加载超过该时长时不附加等待。连接失败时展示当前实例名称、地址、状态、可行动原因与恢复操作；远程失败以“返回本地实例”为唯一主动作，重试和管理服务实例为次级动作；不得在空白工程画布上再叠一个竞争主卡片；
- 生产 Web 旅程通过可信 preload bridge 替身验收 Renderer 中的服务实例入口、状态点、revision/legacy 顺序、重定向与导航持久性。现有 12 张浅色/深色、980×680/1360×880 的 Fallback、Sheet over Product 和 Sheet over Fallback 证据属于 Chromium 组合画面/DOM 验收；真实跨原生 View 导航阻断、最终命中测试与焦点交回仍待 macOS Electron 产品旅程验收；
- 顶栏只承担品牌、桌面拖动区和未来窗口级操作，不重复显示当前模式名称；当前模式已经由图标轨高亮表达。品牌与实验说明直接置于连续顶栏，不使用卡片底色、描边或内阴影；
- 对象列标题描述列内对象集合，例如“频道与智能体”“平台账号”“本地扩展”“设置分类”，并使用对应 Lucide 语义图标，不用所有模式共享的菱形或圆点；主画布标题描述当前对象或当前任务，连接、用户、扩展、设置页头分别使用 Cable、UsersRound、Boxes、Settings 图标；禁止让模式名在顶栏、对象列和主画布连续重复；
- macOS 左上角和 Windows/Linux 右上角窗口控制安全区不得进入品牌、业务控件或可拖动分隔条；Web 不伪造任何窗口按钮，但保持同一 48px 顶栏和主体几何；
- 对象列是当前模式的必要导航，不提供清空页面内容的收起功能；窄窗口仍保持对象列，通过调整宽度为主画布腾出空间；
- 分栏拖动时 1:1 跟随指针，不加 transition，不使用惯性；
- 分栏边界只占 1px 布局宽度，视觉线固定为居中的 1px；实际 9px 拖拽热区覆盖在边界两侧，不得靠扩大空白栏制造热区，也不得因不同分栏宽度把视觉线偏到一侧；
- 松开后持久化宽度；双击分隔条恢复默认宽度；
- 分隔条使用 Pointer Events 和 pointer capture，并提供 `separator`、当前值、最小值和最大值语义；键盘方向键逐像素调整，Shift 加速，Home / End 到边界，Enter / Space 恢复默认；
- 对象列宽度、检查器宽度和检查器默认显示状态只保存在当前浏览器的 `nekro-nxt.ui-preferences` 版本化对象中，不进入 Host snapshot、数据库或频道事实流；检查器默认宽度为 344px，读取时对宽度做 clamp，非法字段单独回退；
- 中央画布承担当前主要对象，右侧只检查或调整当前对象；
- 不把关键保存按钮藏进右侧检查器；
- 创造工作台可使用独立画布，但对象列仍留在工作模式；
- 频道会话不再内嵌第二套目录。

### 6.3 桌面能力

- 全局命令面板：`⌘/Ctrl + K`；
- 常用页面和操作提供可发现快捷键；
- 列表项可按领域需要提供 Hover 操作；工作树不使用行尾或右键操作菜单，绑定、换绑和解绑由管理页、检查器或拖放确认流程提供；
- Tooltip 只补充图标含义或快捷键，不承载必须阅读的说明；
- 鼠标与触控板环境中的可操作 Button、Link、Tab、MenuItem、Option、开关和可选行统一使用 `pointer`，其图标与文字子节点继承同一 cursor；加载态不临时切换为 `wait`。Web 与 Desktop Renderer 都按当前命中控件在文档根锁定 pointer、text、grab 或 resize 意图，控件重绘、替换子节点或切换 pending 状态时不得短暂回落为默认箭头。拖拽、缩放、文本输入和永久禁用控件保留各自语义 cursor，禁止同一可点击热区内部在 `pointer/default` 间变化；
- 拖放必须同时提供键盘拖动或位于对象管理页的等价路径；
- 双击只用于用户已有桌面预期的动作，例如恢复分栏或打开对象；
- 不使用“向左滑返回”“下拉刷新”“长按菜单”和 Bottom Sheet。
- 服务实例 Sheet 支持上下方向键、Enter、Escape 与封闭 Tab 焦点顺序；Backdrop 或 Escape 在表单/风险确认中返回列表并清除敏感 Draft，在列表中关闭 Sheet。鼠标关闭只恢复所属 View 的输入焦点，Escape 关闭再恢复触发控件焦点，避免程序化 focus 触发悬浮提示。后台 Snapshot 不得替换 add/edit/reauth/风险确认中的 DOM 节点、焦点、光标、选区或输入法组合态；列表状态原位更新。可信本地 View 始终位于 Product 或 Fallback 上层，远程页面不能遮挡或读取其内容；

## 7. 基础组件模式

### 7.1 Button

- `primary`：每个操作区最多一个，月潮靛实底；
- `secondary`：中性表面和边框；
- `ghost`：工具栏和低权重操作；
- `danger`：只用于真实破坏性动作；
- Hover 改变背景/边框，不让按钮整体漂浮；
- Pressed 可使用 `scale(0.985)`，文字密集或相邻按钮组只改变颜色；
- Disabled 必须同时给出不可执行原因，不能只降低透明度。

### 7.2 Input 与表单

- 默认实底、1px 边框，Focus 使用 2px 流明蓝外环；
- 标签常驻，不依赖 placeholder 代替；
- 校验优先在字段失焦或用户提交时显示，输入过程中不持续抖动；
- 错误信息靠近字段，说明如何修复；
- API Key、Token、Client Secret 等只写凭据使用统一 Secret Input：保留原生遮罩，但设置 `autocomplete="off"`、关闭拼写检查，并标记常见密码管理器忽略属性；不得用 `new-password` 把凭据误报为账号密码或触发随机密码生成；
- “测试连接”“获取模型”等针对表单内容的诊断必须读取当前页面 Draft，不能静默退回已保存值；诊断不提交表单，成功或失败后 Draft 原样保留；
- 桌面属性面板优先使用标签/控件双列或紧凑分组，不把全部字段拉成超宽单列。

### 7.3 Tabs 与导航

- 主导航使用稳定位置和月潮靛选择轨/背景，不用每项胶囊；
- Tabs 使用底部或侧边 2px 指示，不给每个 Tab 独立 Card；选中项变化时，同一指示滑块沿 Tab 轨道移动到目标项，不在目标项突然重绘；紧凑局部视图可以让同一滑块承载轻量选中底，但不得让每个 Trigger 各自生成选中卡片；
- 页面切换不做整页横向滑动，只对内容使用短淡入；
- 未读、失败和运行状态使用小型计数或状态点，避免大量 Badge。

### 7.4 Dialog、Popover 与菜单

- 使用 Radix 的焦点、键盘、ARIA 和 Portal；
- Dialog 只用于阻塞任务或需要明确提交/取消的操作；普通属性编辑优先检查器；
- Popover/Menu 从触发器方向出现，设置正确 `transform-origin`；
- 危险确认按钮写明对象和结果，例如“删除本地扩展”，不用“确定”；
- Escape、点击外部和窗口失焦行为由组件类型统一定义，业务页面不能各自发明。

### 7.5 消息与工作轨迹

- 左右消息车道都使用贴合内容宽度的同款轻量气泡：边框、圆角、内边距、段间距、正文色阶和 Markdown 排版完全一致，只用排列方向、头像和发送者信息区分归属，不扩成大面积卡片；只有单张图片或单个独立特殊渲染消息段时直接展示资源本身，不再套外层气泡，Mention 不属于该例外；
- 单张图片只展示图片本身，不在图片下重复显示文件名或替代文本；名称继续用于无障碍替代文本和应用内预览标题；
- 消息内容链路逐层设置 `min-width: 0`；长单词、长链接、行内代码与无空格字符串允许断行，代码块和表格只在自身横向滚动，禁止让消息列表或页面出现横向空白画布；
- 富卡片的封面图不是普通图片附件。有安全 HTTP(S) 导航目标时整张卡片跳转；封面不打开资源预览、不显示下载，没有目标时卡片不可点击；
- 中央消息列是唯一阅读主列：正文 `14/22`，发送者 `13/20`，时间用 `caption`；
- 对象列和工作轨迹台账使用 `12–13` 字号与更弱背景，不得与消息列同等抢视线；
- 工作模式对象列用 `@dnd-kit` 拖动排序：智能体标题行和频道整行都是 Pointer 拖动区域，保留 8px 激活阈值以区分点击；指针发生明确移动但没有激活拖动时不得触发页面导航。拖动激活后，源位置由后续条目连续补齐，预览通过页面根部 Portal 脱离对象列裁剪并按原抓取点跟随指针；同组条目围绕当前预计落点让位，形成与松手结果一致的空位。拖动智能体时预览包含名称和全部频道。绑定 / 换绑 / 解绑在投放处显示虚线指示，松手后确认，不直接改 Binding；
- 行尾移动图标是可拖动提示和键盘入口，不画按钮底色、边框或阴影；它绝对定位覆盖在行尾，常态不占标题宽度，只在 Hover、键盘聚焦或拖动时出现。键盘可通过该入口开始、上下移动、放下或取消，并由读屏播报结果；
- 绑定、换绑或解绑 Dialog 关闭后，焦点按频道 ID 回到频道的新位置；Host 拒绝保存顺序时恢复 Host 权威顺序并保留可见错误反馈；
- 目录里空闲智能体不挂状态；非空闲时在对应智能体或频道行尾显示一枚带中心光核的旋转弧光，不使用静态空心圈，也不叠加状态文字 Badge；弧光与拖拽入口共用行尾槽位，行 Hover、键盘聚焦或拖动时退出，移开后恢复；减少动态效果时固定为偏转弧光；频道未读仍使用小型计数；
- 会话流可穿插内部输出和工具行；工作轨迹是 30px 事件台账。切换这两种视图时，右侧检查器列保持；
- 当前频道状态只在频道名称前显示一个状态 Chip；标题栏操作区不追加状态环，检查器不重复状态。检查器在会话视图展示上下文占用、缓存分析、生成表现和绑定，在工作轨迹视图按选中记录类型叠放详情，不切换页签；上下文用紧凑环形图分别展示已用/剩余和系统/工具/对话/其他组成；缓存独立展示最近一次、最近窗口和本次会话的输入缓存覆盖，配合输入组成条、请求趋势、逐请求平均、请求命中、累计输入桶与数据覆盖率，不把未报告误写成 0%；缓存和生成表现的标题置于无描边内容表面之外，避免外层卡片、内层指标再叠一圈边框；环图 Tooltip 跟随指针且只淡入，Hover 扇区轻微放大并增亮，点击不留下 SVG 焦点框；内部输出、发出的内容和工具输入 / 输出分区限高并在区域内滚动；频道改名放在可折叠的次要区；
- 会话检查器使用“运行”和“绑定”两个紧凑面板。运行区没有 Episode、占用或缓存数据时显示带图标、标题和下一步说明的低噪声空态，不留下只有标题与分隔线的空白区；
- 会话检查器的绑定区统一容纳绑定/换绑智能体、管理智能体、频道来源、响应方式、频道显示名称和删除/移除频道；危险操作位于该模块底部并继续二次确认。频道顶栏不重复绑定或删除入口；
- 会话和工作轨迹首次进入默认直接落底，切换后恢复各自阅读位置；距底 80px 内才跟随新内容，离开底部时浮出「回到底部」。回到底部使用直接定位，避免平滑滚动的中间帧被误判为用户离开；
- 三车道时间轴（内部 / 工具 / 发送，高 50px）只出现在工作轨迹，不出现在会话页；点击片段选中并滚到对应行；轮次边界画竖线，点击落到该轮第一条记录；
- 新消息插入不推动整页做弹簧动画；
- 工作轨迹可使用 2px 月潮靛到流明蓝细线作为品牌签名，失败处切换为状态色。

会话消息按观察者视角排列：内置频道中智能体在左、客户端用户在右；外部频道中平台成员在左，智能体和管理员通过机器人账号发出的内容在右。消息车道占满主画布可用宽度，气泡按内容伸缩，不用固定窄列浪费空间。左右气泡共享完全相同的几何和表面样式，不按方向覆写背景、边框、圆角或正文间距。正常送达不显示“已发送”Chip，只在发送中、部分发送、失败或结果未知时显示投递状态。两侧所有 `text` part 使用同一个安全 Markdown 渲染内核；连续的 text 与 Mention 在同一行内联，Mention 使用名称 chip，不把提及机器人账号单独前置；图片、文件、音频和引用保持结构化顺序。

内部输出和工具使用内容宽度的 `ActivityDisclosureRow`：收起时状态灯、标题、实时工具摘要、工具数量和展开图标全部压在一行，并随当前调用工具更新；点击同一行双向展开或收起，详情使用 280ms 高度与透明度过渡。展开后的内部输出和工具仍形成固定左对齐轴，Hover 背景止于实际内容；收起完成后详情从可见性与焦点顺序中移除。

Composer 只存在于会话视图，视觉上是消息画布底部的浮动操作面；它作为画布的独立布局行参与尺寸计算，不覆盖消息滚动区。输入内容增长时由布局自动压缩滚动区，跟随底部时保持最新消息可见，用户已上滚时不抢夺阅读位置；不使用 JavaScript 测量高度再补偿留白。工作轨迹不渲染 Composer，也不为它保留底部净空。Composer 只有一个外框，文本区本身透明且无第二层边框；工具行从左到右是可聚焦信息图标、发送模式短标签、可选跳转和靠右的 30px 无文字发送图标，左右保留小幅内边距。长解释进入 Tooltip，阻塞原因保留一句可见说明。输入框最多增长到 8 行或视口高度 32%，之后内部滚动。

### 7.6 智能体编辑器

- 创建与编辑复用同一套页面骨架、字段、校验、双列布局和错误反馈；
- 人设使用共享结构化引用编辑器：默认可见 10 行，随输入自然增长到 20 行后内部滚动，不提供手动缩放；引用 Chip、候选浮层、失效警告和键盘行为在创建与编辑页保持一致；
- 合法位置输入 `@` 后，候选浮层锚定光标并提供全部、用户、频道、扩展分类。浮层使用 ui-kit 的 Popover 进入/退出动效，变换原点对齐光标；空间不足而向上翻转时，进入和退出都从下边缘发生。方向键移动，Enter 或 Tab 选择，Esc 关闭，边界 Backspace 整体删除 Chip；中文输入法组合期间不触发选择，外部粘贴的 `@名称` 保持普通文本；
- 创建位于完整页面，不使用四步 Dialog；创建模式显示草稿和“创建智能体”，编辑模式显示运行状态、未保存变化和“保存新配置”；
- 主编辑列不窄于 520px；辅助列只放当前状态、阻塞项和结果预览，不用大面积说明卡片挤压表单。
- 授权能力先按用户目标分组：系统访问使用四段拖动预设，动态创造作为扩展能力子区，子智能体与网页搜索后置到“更多能力”；禁止把六个开关平铺成同一层级；
- 系统访问四段分别使用中性、信息、警告、危险色阶，并显示 `Lv.0` 至 `Lv.3`；展开逐项设置后允许任意组合，组合不匹配预设时滑块位于最左端并写“自定义权限（Lv.C）”，不能只靠颜色表达；列表中的等级 Chip 只写等级码，悬浮提示再展示名称和权限说明；
- 动态创造开关放在该子区标题右侧；频道选择和主按钮按控件顶边对齐。文案描述用户将去哪里、做什么，不解释 Package、Revision、真实运行等内部过程；
- 工作树的智能体名称右侧显示紧凑权限 Chip，短标签只写“基础 / 读写 / 命令 / 系统 / 自定义”，Hover 再显示具体授权，不在树行写长说明。

### 7.7 领域页面

- 设置只使用对象列作为分类导航，主区采用无品牌竖线、无底部分隔线的安静页头；偏好组依靠标题和 28–36px 垂直间距组织，不再保留重复 Tabs 或连续切线；
- 用户、扩展和设置主画布占满对象列右侧的可用区域。页头、筛选工具栏、表头和分页操作留在固定工作面，长列表与详情只滚动正文区域；页面切换只替换发生变化的内容，不带动外壳、对象列或固定控件滚动；
- 连接以账号身份、连接健康、发现频道和绑定状态组织；收发测试只放在默认收起的可选诊断区，不计入连接或绑定步骤，也不阻塞日常使用；系统托管连接使用只读形态；
- 用户页使用安静页头和高密度表格。对象列显示全部用户与 Adapter 分类计数；名称、Adapter、平台连接筛选和分页只更新表体，不切换整页，也不对行做 layout animation。搜索与筛选工具栏、表头和分页固定，表体独立滚动；每行只展示名称、Adapter、平台连接和活动频道摘要，不展示内部 ID，也不提供编辑、权限或登录操作；
- 扩展以使用进度、当前版本、包含内容、检查结果和使用范围组织；使用范围用紧凑对象卡片展示所有智能体，卡片包含身份、版本状态和独立开关，不使用裸表单行或含糊的全局启用按钮。智能体工作台以同一对象卡片语言展示全部可用扩展，两处共享同一状态。已启用只用轻微强调描边、底色和状态文字表达，不把整个区域染成强状态色。标题和说明使用用户能直接理解的对象与结果，Host、Client、RPC、Slot、Contribution 等实现术语只可出现在次级技术信息或诊断中。页面优先使用留白和两列分区，避免嵌套卡片与 `sectionDivider` 连续切割；危险操作独立放在尾区；
- 扩展专属页面与宿主页面使用同一 UI Kit、语义 Token、4px 间距网格、控件高度和明暗主题。页面 Client 从 `ctx.ui` 使用 `PageHeader`、`Section`、`Stack`、`Grid`、`Button`、`Field`、`StatusBadge`、`DataTable` 等组件；不得直接渲染浏览器默认 `button/input/select/textarea/table`。语义容器和表格内部的 `thead/tbody/tr/th/td` 可以使用原生元素，但交互、表格外壳、状态、页头和反馈必须由 UI Kit 提供；
- 带声明式对象列的扩展页面由对象列标题说明整个应用，主画布 `PageHeader` 说明当前视图或当前对象；两处不得连续重复同一个标题。概览指标只在真实需要横向比较时使用 2–4 个紧凑区块，不把页面默认生成成指标卡片墙；
- 空态使用所在内容区域作为画布，图标、标题、说明和操作在可用空间内居中；不再为整块空态增加悬浮卡片、装饰背景、外框或阴影；
- 三类页面不能仅替换图标和标题后复用同一张详情大卡片。

#### 7.7.1 扩展专属页面责任契约

扩展专属页面和动态预览必须使用同一份责任契约。这里的“提供”表示该层由对应所有者统一渲染和验收；另一方不得再补一份相同职责。AI 开发上下文、SDK 示例和运行时错误都必须使用本节口径，不得只写“符合 NekroNXT 风格”“注意留白”等无法执行的要求。

| 层级 | 所有者 | 提供内容 | 另一方不得做的事 |
|---|---|---|---|
| 产品外壳 | Host | 顶栏、图标轨、对象列、分隔条和主画布边界 | 扩展不得遮挡、替换或模拟第二套外壳 |
| 页面视口 | Host | 尺寸、`--nxt-bg-canvas` 背景、唯一纵向滚动根、稳定滚动条槽和错误边界 | 扩展不得设置 `100vw/100vh`、接管根滚动、覆盖整幅画布或把固定定位元素挂到产品根 |
| 页面内容框 | Host | 顶部、左右和底部安全边距，以及标题和正文共享的内容轴 | 扩展不得在页面根重复设置 `padding`、使用负边距越界或根据宿主绝对尺寸补偿 |
| 声明式对象列 | Host | 背景、宽度、滚动、当前项、Hover、Focus、键盘操作和错误态 | 扩展只提供分组、项目和相对路径数据，不渲染任意对象列 React 或选中样式 |
| 当前视图内容 | Extension | 当前视图标题、说明、业务数据、业务操作和区块顺序 | 不重复应用标题，不创建第二个页面根、对象列或导航外壳 |
| 内容表面 | UI Kit 与 Extension | `PageHeader`、Section、Toolbar、表格、反馈和局部业务布局 | 不复制基础组件状态机，不用任意背景、边框、圆角和阴影制造卡片墙 |
| 局部样式 | Extension CSS | 当前组件边界内的排版、网格和受作用域装饰 | 不修改页面根背景/边距、Host Token、`html/body/:root`、其他页面或 Portal 容器 |

Host 页面内容框使用共享 Page Inset Token，而不是由每个页面复制数值：

- `--nxt-page-inset-block-start: 24px`；
- `--nxt-page-inset-block-end: 40px`；
- 内容容器宽度不大于 `960px` 时，`--nxt-page-inset-inline: 24px`；大于 `960px` 且不大于 `1440px` 时为 `32px`；大于 `1440px` 时为 `40px`；
- 断点按主画布内容容器计算，不按整个窗口计算；浏览器缩放后的 CSS 像素仍使用同一规则；
- `objectPane: hidden` 只撤销对象列和分隔条，页面内容框继续使用上述边距。“全宽主画布”不等于内容贴边；首版不开放扩展声明 edge-to-edge 页面。

背景与滚动所有权固定如下：

- 页面视口背景只由 Host 提供。Extension 页面根必须透明，不能铺满视口渐变、图片、伪元素或另一种 `--nxt-bg-*`；
- Section 默认依靠标题、间距和轻微层次组织。只有可独立选择、拖动、拥有明确生命周期或必须与相邻内容区分的对象，才使用 UI Kit 提供的 Surface 背景；
- 页面只有一个 Host 纵向滚动根。代码、日志、表格和资源预览可以在明确边界内使用 UI Kit 的局部滚动，不得形成整页滚动套整页滚动；
- PageHeader、Toolbar、正文首区和主要表格共享同一左右内容轴。组件自己的内部 padding 不得改变这个外部轴；PageHeader 与外层 Stack 只能由一方提供相邻区块间距，不能同时叠加 `margin-bottom` 和 `gap`；
- Portal、Dialog、Popover、Tooltip、Toast 的挂载层、遮罩、焦点和 z-index 由 UI Kit 提供，不受页面内容框裁切。

信息结构的最低要求：

- 对象列标题表示整个应用，主画布 PageHeader 表示当前视图或当前对象；两者相同即不通过；
- 对象列已有的视图切换不得再作为主画布主按钮重复出现。主按钮必须产生业务结果，不以“查看、返回”包装重复导航；
- 概览默认使用紧凑摘要、列表或表格。只有指标确实需要横向比较时使用 2–4 个 UI Kit `Metric`，由 `MetricStrip` 组合成无卡片背景的紧凑数字带；不用等宽大卡片填满首屏；
- StatusBadge 贴合文字内容，不拉伸成无进度语义的横条；同一状态在摘要、表格、筛选和详情中使用同一名称与归类；
- 示例和真实数据都必须内部一致。日期与星期、汇总数量与表格行、筛选结果与状态计数互相矛盾时，视觉链路即使可运行也不通过。

### 7.8 操作反馈

- 保存、测试、发送、启用、停用等操作的瞬时成功、警告和失败统一使用页面顶部居中的 Toast；
- Toast 最多同时显示四条，成功和普通信息约 3 秒自动关闭，警告和错误保留更久，并提供手动关闭；
- 字段校验继续靠近字段显示；连接中断、缺少前置条件、空态和持续诊断仍保留在对应页面，不迁移为短暂 Toast；
- 同一操作不得同时在页面正文和 Toast 重复显示相同结果。

## 8. 智能体状态视觉

智能体的“生命感”来自状态准确，不来自持续动画：

- 空闲：静态中性状态点；
- 思考中：月潮靛状态环做低振幅明度变化；
- 使用工具：状态环沿固定方向缓慢推进，Tool 区显示真实步骤；
- 等待输入：月潮靛描边保持静态，并突出待处理操作；
- 已暂停：中性图标和明确文字；
- 不可用：错误状态色和可操作说明。

创造状态使用月潮靛到流明蓝的 2px 渐变边或轨迹线，不改变整个应用主题，不把同一智能体画成另一个实体。所有动态状态必须能被文字和图标独立识别。

## 9. 动效系统

### 9.1 Motion Token

```css
:root {
  --nxt-motion-instant: 80ms;
  --nxt-motion-fast: 120ms;
  --nxt-motion-standard: 180ms;
  --nxt-motion-spatial: 280ms;
  --nxt-motion-emphasis: 340ms;

  --nxt-ease-standard: cubic-bezier(0.2, 0.7, 0.2, 1);
  --nxt-ease-enter: cubic-bezier(0.16, 1, 0.3, 1);
  --nxt-ease-exit: cubic-bezier(0.4, 0, 1, 1);
}
```

持续时间按变化的空间距离和视觉面积选择，不按组件名称死记。空间性进入、退出、开合和路由切换由 ui-kit 封装的 `motion/react` 执行，默认 tween，使用上表 easing，不使用 spring。业务页面不得手写 `@keyframes`，也不得直接导入 `motion`。颜色 Hover/Focus、Switch 滑块、无限 Spinner 旋转和主题语义色插值继续使用 CSS。

导航衔接必须同时交代三件事：选中从哪一项移到哪一项、旧画面如何离开、新画面如何到达。禁止「旧界面瞬间消失，再对空白做一次短缓入」。

### 9.2 标准模式

| 场景 | 模式 | 时间 |
|---|---|---|
| Hover、Pressed、Focus | 颜色/边框；主按钮 Pressed `scale(0.985)` | 80–120ms |
| Tooltip、Menu | opacity + 2–4px 位移 | enter 120ms / exit 80ms |
| Popover | opacity + `scale(.98)`，源点对齐触发器 | enter 160ms / exit 100ms |
| Dialog | opacity + `scale(.985)`，背景只淡入 | enter 180ms / exit 120ms |
| 检查器开合 | opacity + 12px 同方向位移 | 220–280ms |
| 列表/图标轨选中 | 唯一选中底在 `NavMarkGroup` 内滑到目标行，不让列表项做 layout projection；列表本身不重挂。Hover 只用颜色，不用实心底盖住选中标 | 280ms |
| Tabs/局部视图 | 选中滑块沿轨道移动到目标项；内容使用 `StageCrossfade`，旧层叠在新层之上淡出，新层在下同时就位；只用 opacity 与少量位移，不做 scale。动画层本身保持透明，由所属页面或面板提供连续表面，禁止在画布中露出居中的硬切矩形色块 | 滑块 280ms，内容 180–280ms |
| 一级模式切换 | 外壳不动；支持 View Transition 时画布旧层在上淡出、新层在下就位；不支持时直接替换主列，禁止用两份可交互 DOM 模拟交叠；对象列只做短 opacity 交叠，不位移；图标轨选中块滑移 | 画布 180–280ms，对象列 120ms |
| 同类型对象切换 | 选中块滑行；支持 View Transition 时主列交叠淡入，不支持时直接替换；不得保留失去事件所有权的退出层 | 180–280ms |
| Disclosure 展开/收起 | 高度 + opacity，双向且收起后移出焦点顺序 | 280ms |
| 主题切换 | 语义 Token 颜色过渡；主题图标短旋转/缩放 | 180ms |
| 数据图表 Tooltip | 跟随指针，只做 opacity 淡入，不做方向位移 | 180ms |
| Toast | 8px 位移 + opacity；同位置堆叠 | 180ms |
| 已知进度 | 连续 Progress，不伪造完成速度 | 与任务同步 |
| 未知等待 | 延迟出现的 Spinner；切换时先交叠旧内容，数据到达后就地更新新层 | 最早 300ms 后显示 |

进入和退出沿相同空间路径；退出通常更快，但必须与进入重叠，不能先卸掉旧层，也不能让新层先完全出现再把旧层残影淡掉。旧层在上、新层在下：先看见旧画面离开，再露出已经在下方就位的新画面。动画开始后不锁住与当前动作无冲突的输入。测量型选中底首次取得有效几何时立即定位；此后包括首次用户交互在内的每次选中项变化都由同一个 DOM 指示器执行 280ms 滑移。当前选中项因窗口 resize、字体或内容变化发生重排时取消移动并立即对齐；减少动态效果时同样立即对齐。布局拖动、窗口 resize、文本输入和滚动不加 transition。`NavMarkGroup` 内的行 Hover 不得使用会盖住选中底的实心背景。

### 9.3 动效禁区

- 不使用惯性投掷、速度投影、Rubber-banding、滑动返回和下拉刷新；
- 不让按钮、菜单和普通 Card 弹跳；
- 不循环漂浮头像、背景粒子、渐变光斑或呼吸边框；
- 不对聊天历史、对象列和可排序列表使用 Motion layout projection 或整列重挂动画；`@dnd-kit` 在一次拖动期间用 `transform` 表达相邻条目让位，不属于整列重挂；
- 不对聊天历史做大范围 layout animation；
- 不用 Skeleton shimmer 长时间扫过大面积页面；
- 不用动画延迟真实状态更新；
- 不因切换页面移动整个应用外壳；
- 不用声音、振动或亮度闪烁作为必要反馈。

### 9.4 Reduced Motion 与透明度降级

```css
@media (prefers-reduced-motion: reduce) {
  html {
    scroll-behavior: auto;
  }
}

:root[data-reduced-motion='true'] *,
:root[data-reduced-motion='true'] *::before,
:root[data-reduced-motion='true'] *::after {
  scroll-behavior: auto !important;
  animation-duration: 1ms !important;
  animation-iteration-count: 1 !important;
  transition-duration: 1ms !important;
}

@media (prefers-contrast: more) {
  :root {
    --nxt-border-default: var(--nxt-border-strong);
  }
}
```

应用设置提供“减少动态效果”和“减少透明效果”。打开「减少动态效果」后，页面切换、对话框和 CSS 过渡都会压到 1ms。系统 `prefers-reduced-motion` 只关闭平滑滚动，不再把全部动画打成硬切。减少透明后所有材质使用实底和明确边框。
对比度可选择跟随系统、标准或更高对比度；跟随系统时消费 `prefers-contrast: more`，显式选择优先于系统。减少动态效果跨刷新持久化；减少透明和对比度与分栏一起写入 `nekro-nxt.ui-preferences`。

## 10. 性能与实现约束

- 空间动画只优先使用 `transform` 和 `opacity`；Disclosure 允许 height；
- 空间动画由 `apps/web/src/ui-kit/presence.tsx` 输出，业务组件只使用 `Enter`、`Presence`、`Disclosure`、`RouteTransition`、`StageCrossfade`、`NavMark`、`NavGlyph`、`SidePane`、`Spinner`、`AgentStateRing`；
- 业务代码不得直接导入 `motion`、`motion/react` 或 `framer-motion`；
- 高频 streaming 更新不能触发整个页面重渲染；聊天历史本身不做 layout animation，仅新插入的消息短淡入；频道之间的切换交叠标题与主列，不重挂对话页；
- 面板尺寸拖动使用 Pointer Events 和 pointer capture，但不计算手势速度、不加 Motion；
- 动效不得推迟 Channel Event、发送回执、Tool 状态等真实数据展示；
- 所有浮层和可拖动布局在 Windows/macOS、100%/125%/150% 缩放下验证；
- 主题 Token、Motion Token 和 Radix state selector 统一由 `ui-kit` 输出，业务组件不复制数值。

## 11. DSH 与 Extension UI

- `ui-kit` 提供 NekroNXT 组件和 `--nxt-*` Token；
- 单一兼容层将必要 `--dsw-*` 语义别名映射到 NekroNXT Token，业务包不散落映射；
- Extension Client UI 使用公开 Slot、基础组件和语义 Token，不读取全局 DOM 结构；
- Extension 不声明 Tailwind class、宿主绝对尺寸和主题特有颜色作为公共契约；
- DSH 原生界面必须位于明确标记的兼容岛：外壳、状态、错误和 fallback 使用 NekroNXT 组件，岛内允许保留上游术语和交互差异；
- DSH Client bundle 经过开发与发布门禁后，只通过公开 `--dsw-*` Token 映射融入当前主题，不加载会修改 `body`、根滚动条或全局主题的完整 DSH Theme；验证结果不转换成内置扩展的用户可见评级；
- 不覆盖 DSH CSS Modules 哈希类、私有 DOM 层级或组件内部 selector；原生界面无法加载时显示真实错误并切回通用 Settings 表单，不改变扩展的“内置”来源标签；
- 启用的官方 Client bundle 所引用的 `--dsw-*` 必须自动扫描并由兼容层完整提供；第三方未知 Token 记录为样式兼容风险，不通过私有 selector 强行修补；
- 动态 UI 的加载、渲染、卸载和 Reduced Motion 都进入验证场景。
- 动态开发上下文必须从 §7.7.1 生成简短、版本化、机器可读的页面责任说明，逐项写明 `owner / provided / forbidden`，并给出使用同一页面骨架的合格示例。上下文必须明确告知智能体“Host 已提供背景、外边距和根滚动，扩展从透明内容区开始”，不得让普通用户在需求中补充内部组件名、CSS 数值或实现步骤；
- SDK 示例、Inspect 结果、预检错误和浏览器验证使用同一责任说明。示例不得默认采用后台指标卡片墙；错误必须指出实际对象、测得值、契约要求和修复方向，不能只返回“样式不符合规范”。

## 13. 验收清单

实现改动后的像素级验收流程、覆盖范围和否决条件见 `06` §5.1。本清单只规定设计语言必须覆盖的状态组合。

每个基础组件和代表页面至少验证：

1. 浅色、深色和系统主题切换；
2. 键盘操作、Focus visible、Escape 和 Tab 顺序；
3. Hover、Pressed、Disabled、Loading、Error 状态；
4. 100%、125%、150% 缩放；
5. 1100×720、1440×900、1920×1080；
6. Reduced Motion、减少透明和高对比；
7. 中文、英文、长名称、空内容和错误内容；
8. Slot 动态注册与卸载后无残留；
9. 动画期间状态更新不丢失、不锁输入；
10. 月潮靛主按钮、正文和状态色达到目标对比度。

首轮用 Channel Conversation、创造工作台和 Connection 配置三个页面验证设计语言。三者分别覆盖长时间阅读、高密度生产力和属性配置；只有三类页面都成立，Token 和组件才进入稳定 API。

## 14. 明确拒绝

- 不复制 macOS 系统设置、iOS 导航和手机手势；
- 不把 Apple 风格等同于毛玻璃、超大圆角和低对比灰字；
- 不使用 shadcn 默认模板、后台卡片墙和全屏指标面板形成产品身份；
- 不让月潮靛或流明蓝吞没内容层级；
- 不把创造状态表现成另一个智能体；
- 不为了视觉效果隐藏真实运行、发送和失败状态。

参考 Apple 设计资料中的即时反馈、空间一致、克制、可访问性和工艺原则；拒绝移动端触屏手势、惯性物理和平台外观照搬。技术实现遵循 `decisions/accepted/2026-08-16-一期技术栈与UI基础设施.md`。

外部参考输入：`https://github.com/emilkowalski/skills/tree/main/skills/apple-design`。本文只吸收适用于 PC Web/Electron 的原则，不继承其触屏交互和示例参数作为项目 API。
