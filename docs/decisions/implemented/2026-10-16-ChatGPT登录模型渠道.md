# 已实施：ChatGPT 登录模型渠道

状态：implemented

## 决定与理由

NekroNXT 通过 OpenAI 面向开源应用的 Sign in with ChatGPT 注册流程，提供独立的 `chatgpt` 模型路由。用户在“设置 → 模型 → 添加模型供应商”选择 ChatGPT，完成浏览器授权后获取此账号的模型列表，再为智能体选择模型。首次授权确认使用 ChatGPT 套餐，设置和频道输入区提供使用量管理入口。

ChatGPT 注册、身份校验和凭据刷新由 Server 的 `chatgpt-auth.ts` 拥有；`chatgpt-models.ts` 是本机 Cordis 插件，通过公开 `PiAiAdapter`、pi-ai Provider 和 Responses 协议组合接入，复用 DSH 的消息、图片、工具、回放与流式转换。普通 OpenAI API 密钥接入继续由 DSH 通用供应商拥有，没有改动或复制 DSH 内核。

模型目录从所选账号的公开模型接口读取，只展示 `visibility=list`，保留服务端顺序、名称和模型标识。能力元数据复用当前 pi-ai 目录，未知模型采用文本输入和保守容量缺省值；目录条目不表示额度或调用一定成功，连接测试执行完整的模型请求。产品供应商页为该登录型路由投影单独入口，不将令牌伪装成可编辑 API 密钥，也不提供自定义端点。

## 授权、存储与生命周期

- 首次使用 `dynamic_agent_client`、固定应用名 NekroNXT 和每个宿主持久不变的随机 `ext_agent_host_id`；每次生成独立 state、nonce 和 PKCE，只监听 `127.0.0.1` 的 `/auth/callback`。端口可以变化，同一次尝试的回调 URI 在授权与交换中完全一致。
- 收到签发的 client ID 后先保存，再交换代码。重试和重新登录复用该 ID。通过 OpenAI JWKS 验证签名、issuer、audience、过期时间和 nonce；重新登录还检查原账号 subject，成功后才替换凭据。邮箱相同的不同注册保持分离，账号标签保持稳定。
- 以令牌响应的实际授权范围判断套餐使用权。只有身份授权的账号可以保存，但不能推理。接近过期时串行刷新，原子替换 access token、轮换的 refresh token、授权范围和过期时间；主要数据根的独占宿主租约阻止多个运行实例竞争刷新。
- 文件位于数据根 `dsh/chatgpt/accounts.json`，POSIX 目录为 0700、文件为 0600，Windows 继承数据根 ACL。宿主拥有该格式及恢复；损坏时保留文件并拒绝启动，恢复备份后重试。Core、浏览器存储、产品快照和测试报告不保存令牌；日志脱敏器登记正在使用的令牌。
- 每次 DSH 调用准备时形成账号与模型快照，已准备或执行中的调用保持原账号，后续调用使用新选择。退出清除该账号的令牌与模型，保留注册映射；尝试撤销可续期会话，未确认远端撤销时提示到 ChatGPT 设置断开授权。
- 登录等待五分钟后过期；取消或插件 dispose 关闭监听，dispose 等待代码交换和凭据写入静止。

远程宿主按 OpenAI 自托管流程接收受保护账号文件，具体传输与恢复步骤由 [Server README](../../../apps/server/README.md#chatgpt-登录渠道) 维护。传入不替换接收宿主的 host ID。

## 推理边界

只请求公开模型与 Responses API，发送 OAuth bearer，固定 `store=false`、`stream=true`，完整传递所需上下文，不使用服务端会话续接。system 消息转 developer，函数工具归入命名空间，移除预览不支持的采样、输出上限等字段。仅 `response.completed` 成功；失败、不完整响应和提前断流均返回失败。使用限制需要在 ChatGPT 使用量设置中处理。

## 验证入口

- `apps/server/tests/chatgpt-auth.spec.ts`：虚构凭据、签名 ID token、真实本机回调、注册恢复、state/nonce/PKCE、范围校验、刷新、退出、远程导入，以及公开 Responses 线请求和完整/失败/不完整/中断流。
- `apps/web/e2e/chatgpt-login.spec.ts`：生产构建下添加供应商、启动和取消登录、授权拒绝、账号与模型状态、浅深主题和刷新恢复。外部授权与推理使用合成数据，不授予真实账号权限。
