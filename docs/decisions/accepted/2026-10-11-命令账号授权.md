# 命令账号授权

状态：accepted（2026-10-11 批准并实施；宿主侧受控 gh 未实施）

命令的读取范围收紧后，智能体的命令读不到用户主目录里的 `gh` 登录，也拿不到宿主环境里的 token。本决定新增一层按智能体授权的账号，让指定智能体的命令以指定的 GitHub 账号工作，其余智能体不受影响。

## 1. 场景与目标

- 让智能体自己提 issue、查 PR、推送分支，不需要把用户主目录交给命令。
- 授权对象是账号，不是文件。`gh` 的凭据可能在 `hosts.yml` 里，也可能在系统钥匙串里，一个文件里还可能同时登录多个账号。
- 不需要账号的智能体不应该拥有它。

## 2. 决定

| # | 决定 |
| --- | --- |
| A1 | 授权只发生在智能体上：`AgentCapabilities.commandAccounts`，随修订保存，默认为空。账号库只保管账号，不授予任何权限；社区人设安装不带授权 |
| A2 | 每个服务只授权一个账号；整个智能体生效，不分频道；子智能体沿用父智能体的授权 |
| A3 | 账号库在设置的「账号与服务」：添加、更换 token（只能换成同一个 GitHub 账号的）、移除、查看被哪些智能体使用。移除立即生效，已挂载的会话在下一条命令起拿不到 token |
| A4 | 添加账号有两种来源：填写 token；使用本机 `gh` 已登录的账号（添加时取一次，之后不跟随 `gh` 同步）。默认引导创建只开所需权限的专用 token |
| A5 | token 保存在现有的本机凭据库里，账号库只存账号名、来源、权限范围和凭据引用。界面和接口都不回显 token |
| A6 | 命令通过环境变量拿到账号：`GH_TOKEN`，以及让 `git` 走 https 时读取同一个 token 的内存凭据助手。DSH 会清除宿主环境里名字含 `TOKEN`、`KEY`、`SECRET`、`PASSWORD` 的变量，所以只有这里显式转发的变量会到达命令 |
| A7 | 授权上可以勾选「使用提示」（查看内容、处理 issue、处理 PR、推送代码）。它只写进提示词，界面明说不限制智能体能做的事；真正的限制只来自 token 本身的权限 |
| A8 | 命令环境里的 `gh` 配置目录指向临时目录，不碰用户的 `gh` 配置 |
| A9 | `gh` 不存在时，智能体的提示词说明这台设备没有 `gh`，改用 `curl` 调 REST 接口。授权页和设置页提供下载：固定版本、校验 SHA-256、解压到数据目录的 `runtimes/gh`，沿用 `run_code` 的 Node 下载机制 |
| A10 | 完整访问的智能体不显示授权项：它的命令本来就读得到用户主目录 |

## 3. 边界

- 授权后，该智能体的任意命令都能用这个 token 做 token 允许的一切。被提示词注入诱导的智能体可以把它发到外面。缓解来自三处：用权限收窄的专用 token；「命令联网」开关；结果入库前的脱敏尚未做。
- 「使用提示」不是限制。把全功能 token 配成「处理 issue」，智能体仍然能用它做别的事。
- 编排模式里程序自己派生的进程不带账号；通过 bash 工具执行的命令带。

## 4. 备选

- **放行 `~/.config/gh`**：一并交出文件里的所有账号，且对钥匙串存储无效。
- **宿主侧受控 `gh`**：token 不进沙箱，宿主只放行 `gh issue *` 之类的子命令。这是唯一能在应用层真正限制用途的做法，代价是宿主与沙箱之间的通道和对 `gh` 行为面的梳理，留作后续。
- **自己实现 GitHub 扩展**：`gh` 的功能面太大，不现实复刻。

## 5. 契约入口

- 能力字段与摘要：`packages/core/src/index.ts` 的 `CommandAccountGrantSchema`。
- 接口：`packages/contracts/src/host-api.ts` 的 `getCommandAccounts`、`addCommandAccount`、`replaceCommandAccountToken`、`removeCommandAccount`、`downloadGithubCli`、`removeGithubCli`。
- 账号库：`apps/server/src/command-accounts.ts`；命令环境与提示词：`apps/server/src/command-account-env.ts`；`gh` 运行环境：`apps/server/src/github-cli.ts`。
