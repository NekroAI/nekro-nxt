# 微信 iLink 实验通道适配器

状态：implemented

## 结论

NekroNXT 通过 `@nekro-nxt/adapter-wechat-ilink` 接入实验性微信 iLink 私聊通道。Connection 由宿主扫码登录会话创建：用户只扫描二维码并确认，账号 ID、访问令牌、API 地址和 CDN 地址不进入用户可见表单。访问令牌写入 Host-owned Credential；连接详情只暴露入站媒体接收开关。

该通道基于非官方 `wechat-ilink-client`。协议稳定性、账号风控和合规风险不由 NekroNXT 保证，建议只使用专用机器人账号。首版不开放群聊、Mention、引用、撤回、主动发送或出站媒体。

## Host 契约

Adapter descriptor 声明 `creation.mode = qr-login`。产品连接向导读取该字段后进入宿主登录会话，不按 `adapterKey` 分叉独立页面。Schema 表单仍是默认创建方式。

微信 Adapter 拥有 iLink 登录协议，Host 拥有通用登录会话、凭据与 Connection 提交：

- `POST /api/connection-logins` 按 `adapterKey` 开始会话并返回二维码；携带 `connectionId` 则重新认证原连接；
- `GET /api/connection-logins/:loginId` 读取 pending / scanned / confirmed 等状态；
- `DELETE /api/connection-logins/:loginId` 取消尚未完成的会话。

确认登录后，Host 用 Adapter 返回的稳定 `accountKey`、私有配置和原始凭据创建或更新 Connection。重新认证必须得到与原连接一致的 `accountKey`；新 Runtime 挂载成功后才删除旧凭据，失败或取消时先停止新 Runtime，再回滚并恢复原 Runtime。重新认证保留原连接的公开用户设置，包括已关闭的入站媒体接收。`POST /api/connections/:connectionId/configuration` 按公开 schema 修改入站媒体开关。

出站只支持已发现私聊的纯文本回复，且必须持有该会话最近的 `context_token`。`context_token` 只作为投递凭据保存在 Connection scoped state，不进入消息 facts、日志或用户可见响应。

## 传输与状态

Runtime 使用长轮询接收私聊。`syncBuf` 只在该批每条消息都被 Host 接纳后提交；接纳失败或入库前取消保留旧游标，重放时依靠既有幂等键去重。停止 Runtime 会等待所有已分派的入站任务收敛。会话过期后发布认证失败诊断，连接详情可对原 Connection 重新扫码认证。

群消息中的 `group_id` 被忽略并记录诊断，不创建群频道。入站媒体默认开启；SDK 下载每个 Connection 串行执行，独立 30 秒超时，并按实际流式读取的字节在 20 MiB 上限处中止。关闭后图片和文件只记录可解释占位内容，不下载明文。

## 验证

- Adapter 包测试覆盖 descriptor、入站映射、媒体占位、context_token 回复和会话过期；
- Server 组装测试用 Fake login/transport 覆盖通用扫码创建、保留 Connection/Channel 身份的重新认证、入站媒体开关、私聊发现和收发诊断；
- Web 产品测试覆盖扫码弹窗、Host 刷新后登录态保留，以及连接详情中的入站媒体开关。

当前实现尚未完成独立真实账号验收。完成真实扫码、私聊文本、入站媒体和会话过期测试后，才能标记为“已验证支持”。

## 未来方向与参考取舍

关联方向：更多聊天平台 Adapter、宿主登录会话协议。

保留接缝：第一方 Adapter 进入 `adapter-builtin-roster`，产品 UI 只消费 descriptor 的 `creation` 与通用 `connectionLogin`，Host 拥有登录会话、凭据和原子提交。明确不把微信 iLink 协议字段暴露给 Server/Web 或通用 Schema 表单，也不提前建设 OAuth、群聊或出站媒体。
