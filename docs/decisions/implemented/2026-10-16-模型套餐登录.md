# 模型套餐登录

状态：implemented

## 决定与理由

供应商除 API 密钥外，可以登录账号、使用账号的订阅套餐额度。首个开放的是 ChatGPT：OpenAI 为第三方应用提供了 Sign in with ChatGPT 授权方案。pi-ai 自带的其他登录（Anthropic 订阅、Codex 的 backend-api 路线等）的条款不允许第三方应用使用，暂不开放；以后逐个评估后加入 `subscription-login.ts` 的允许名单。

套餐登录不另建模型渠道。登录得到的凭据就是 pi-ai 自己的 OAuth 凭据，写进 DSH 凭据存储中 `llm-pi-ai/<供应商>` 这条记录，请求、令牌刷新、预览协议的字段裁剪都由 DSH 的 `llm-pi-ai` 路线和 pi-ai 完成，和 API 密钥接入的供应商走同一条路。模型列表、连接测试、移除配置也沿用现有供应商页面。

NXT 只补 DSH 没有的部分：

- **ChatGPT 登录流程**：DSH 的 `llm-pi-ai` 不提供 OpenAI 的网页登录，因为登录要求应用提供一个固定的安装 ID，而 DSH 没有。NXT 调用 pi-ai 自带的登录，传入本机安装 ID 和应用名 NekroNXT。若以后 DSH 自己提供了这个供应商的网页登录，NXT 改走 DSH 的流程。
- **同一供应商的多个账号**：DSH 每个供应商只有一个凭据位置。正在使用的账号放在这个位置；其他账号的凭据由 NXT 原样保存在 `nekro-nxt/subscription-<供应商>` 记录里，切换时在 DSH 的凭据锁内交换，令牌刷新不会写错账号。同一时间每个供应商只有一个账号在用，切换对使用该供应商的所有智能体生效；已经开始的请求不受影响。
- **登录过程的状态**：登录在宿主上运行，页面轮询进度、打开授权页面、回答提问。

## 接入方式与模型

供应商的“凭据”区分 API 密钥和套餐两种接入方式。DSH 的规则是路线配置了 API 密钥引用（`apiKeyEnv`）就使用密钥，因此改用套餐时移除这个引用；已保存的密钥留在凭据存储里，可以随时改回。同一个 OpenAI 路线不能同时用两种方式，这是 pi-ai 只在路线名为 `openai` 时识别 ChatGPT 令牌所决定的。

pi-ai 的 OpenAI 目录列出全部模型，不代表账号的套餐可用。首次登录时，如果模型列表没有改过，换成账号可用的模型（OpenAI 模型接口中 `visibility=list` 的项）；之后“获取可用模型”也读取账号的模型。路线固定使用 `openai-responses` 协议，以便保存目录里没有的新模型。

## 远程访问

授权完成后 OpenAI 回调 `http://127.0.0.1:1455/auth/callback`，只有运行 NekroNXT 的机器能接收。从其他设备打开网页、或 Server 运行在容器里时，浏览器会跳到一个打不开的页面，把它地址栏里的网址粘贴回登录框即可完成。这是 pi-ai 登录本身支持的方式，不需要在机器之间复制凭据文件。端口 1455 被其他登录（例如 Codex 命令行）占用时，登录会提示先结束那个登录。

## 退出与安全

退出账号时向 OpenAI 撤销刷新令牌，未能确认撤销时提示用户到 ChatGPT 使用量设置中断开。日志会登记凭据记录中的令牌并脱敏。凭据随 DSH 凭据文件 `dsh/.credentials.yaml` 保存和备份，接口与页面不返回令牌。

## 尚未验证

- 没有用真实账号完成授权与推理；测试使用虚构账号和模拟的 OpenAI 接口。
- OpenAI 预览文档要求函数工具放进命名空间，pi-ai（至 1.3.0）仍按普通工具发送。若真实账号拒绝，可在供应商配置的 `compat` 中打开 `supportsAdditionalTools`，不需要改代码。
