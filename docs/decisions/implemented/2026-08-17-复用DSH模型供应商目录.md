# 已实施：复用 DSH 模型供应商目录

状态：implemented

## 问题

Server 生产入口此前只挂载 `LlmRuntime`，没有注册任何真实 LLM Adapter；Web 创建智能体又把展示文案硬编码成 `deepseek` provider 下的模型 ID。页面看似允许选择模型，实际既没有可用供应商，也没有权威模型目录，真实对话必然失败且错误会被页面异步动作吞掉。

## 决定

- 直接挂载锁定版本的 `@deepseek-ai/dsh-llm-pi-ai`，复用其 provider catalog、端点、协议转换、模型能力、推理档位、错误语义和凭据解析；
- Server 挂载 DSH 文件 settings、只写 credentials 和休眠态 `dsh-llm-pi-ai`；Web 设置页从 DSH 可配置目录新增或编辑 provider，经 DSH settings 激活路由，不在 NekroNxt 代码中复制供应商 endpoint 或模型清单；
- API 快照从 DSH `ctx.llm.listProviders()` 与 `listModels()` 读取实时目录，Web 直接显示并提交确切 `{provider, model}`；
- AgentRevision 继续固定 provider/model，运行中的会话不因目录变化热换模型；
- API Key 不进入 AgentRevision、Core、快照或 Git，只通过 DSH credentials `set` 写入主要数据目录下权限为 `0600` 的凭据文档；页面只读取 configured/source/writable 状态，不读取或回显值。环境凭据只作为可选部署层。

## 验证

- Server parser 测试覆盖显式 provider allowlist、去重和非法路由拒绝；
- 真实组装测试覆盖页面协议保存 provider、响应不泄漏密钥、凭据文件权限、Runtime 完全销毁后的 provider/凭据/模型目录恢复；
- 设置页连接测试经 DSH 发起最小真实模型请求，不把本地 catalog 读取误当作凭据可用，并只返回脱敏错误；
- Server/Web 类型检查与局部测试覆盖模型目录投影、真实模型选择和创建请求；
- 智能体管理页从同一实时目录选择模型，通过带 expectedCurrentRevisionId 的 API 保存新 Revision；频道发送等待真实请求提交，失败时保留草稿并显示错误；
- 使用 DSH 内置 `opencode-go` 路由及其 catalog 模型完成一次真实 Web Channel 对话；外部回复只在模型调用统一通信工具并形成 `sent` 回执后出现在频道快照。
- 使用 DSH 内置 `deepseek` 路由保存官方凭据，冷重启且不加载模型环境变量后仍恢复为 `configured/active`、凭据来源为文件；`deepseek-v4-flash` 连接测试通过，并由新建智能体经真实 Web 页面形成 `sent` 回复。

## 未来方向与参考取舍

关联方向：更多模型供应商、多设备、Desktop/Server 双宿主与模型多模态。

保留接缝：DSH provider route、实时模型目录、provider-native Credential Reference、不可变 AgentRevision 和模型能力元数据。没有把单个供应商写进 Core，也没有把本地密钥路径变成模型身份，因此不会锁死未来 settings UI、系统钥匙串或远程凭据服务。

本次明确不实现：自研 OpenAI-compatible Adapter、第二份模型 catalog、云凭据服务、计费平台、供应商账号同步和运行中会话热换模型。NekroNxt 设置页只承载产品布局，目录、协议选项、profile 校验、模型发现与凭据生命周期均调用 DSH 公开服务。

参考 DSH rc.6 的 `dsh-llm-pi-ai` 公开包与当前锁定 pi-ai catalog；借鉴其注册、目录、协议和凭据引用边界，拒绝复制上游 endpoint/model 常量或读取 DSH 私有存储。
