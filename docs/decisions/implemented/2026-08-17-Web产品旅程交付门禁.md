# 已实施：Web 产品旅程交付门禁

状态：implemented

## 问题

一期 Web 测试主要使用 `renderToStaticMarkup` 和 `MemoryRouter`。它们能检查静态文案，却不会执行 React Effect、DOM 事件、浏览器路由、SSE、Zustand 外部 Store 订阅或生产 bundle。频道页把 `messages.filter(...)` 直接放进 Zustand selector；selector 每次读取都返回新数组，在 Zustand 5 的外部 Store 订阅中触发无限更新和整页白屏，但原有单测、API、类型检查和构建全部可以通过。

流程同时把浏览器控制不可用当作可备注的验证缺口，而不是交付阻断条件，最终把“各层命令成功”错误等同为“用户旅程可用”。

## 决定

- 增加 Playwright 生产产品旅程，由隔离的 Server 和忽略提交的数据目录加载真实 `apps/web/dist`；
- 一级路由必须显示关键主内容且根节点非空，任何 `pageerror` 或 `console.error` 都使旅程失败；
- 设置页必须经过真实供应商选择和跨路由点击，不以 API 响应代替 UI 行为；
- `pnpm test:journey` 是用户可见 Web 改动的最低门禁，`pnpm verify:product` 串联静态检查、单元/契约测试、构建和产品旅程；
- Codex Browser 不可用时仍运行仓库 Playwright；若两者都不可用，不得宣称 Web 改动完成；
- 根级 Error Boundary 只负责避免不可恢复的纯黑屏并提供重新加载/返回入口，不能替代修复和无错误旅程。

## 验证

- 回归旅程会直接打开 `/channels/regression-smoke`。修复前不稳定 selector 会产生 React 最大更新深度错误并触发 `pageerror`/`console.error`，修复后频道显示可恢复空态；
- 同一生产构建依次覆盖 `/`、智能体、频道、连接、本地扩展、创造工作台、运行诊断和设置；
- 设置旅程确认 DSH 内置供应商编辑器、密码输入类型和跨路由返回后仍可用；它还会提交隔离测试凭据，确认保存反馈、输入框清空，以及页面刷新后的“已启用 · 密钥已保存”状态；
- 测试使用 `.local/playwright-data` 与 `4970`，不读取或改写常驻 `data/`。

## 未来方向与参考取舍

关联方向：Desktop/Server 复用同一 Web 产物、动态 Client Slot 与智能体自开发的结构化验证证据。

保留接缝：生产 bundle、真实 Host API、浏览器路由和运行时错误门禁；以后可以增量加入 Desktop packaged renderer、扩展 Slot 和真实账号旅程。没有引入第二套 UI Runtime，也没有让测试读取 DSH 私有数据，因此不锁死未来宿主。

本次明确不实现：全浏览器矩阵、像素级视觉回归、真实平台账号常驻 CI、社区扩展供应链和 Desktop 安装包矩阵。

参考一期技术栈 Decision 中已确认的 Playwright Web 真实组装方案；借鉴真实入口与外部结果验证，拒绝继续把 SSR 文案快照当作交互验收，也拒绝用 Error Boundary 掩盖运行时错误。
