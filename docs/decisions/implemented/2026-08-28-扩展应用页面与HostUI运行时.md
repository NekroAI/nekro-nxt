# 扩展应用页面与 Host UI 运行时

状态：implemented

## 结论

NekroNXT 允许本机 `host-ui` 扩展、带页面的 Host Adapter Revision，以及显式声明 `nekroNxt.hostUi` 的 DSH Host 入口贡献顶级页面。系统外壳仍由产品拥有：扩展只能声明页面入口、图标、起始相对路径和对象列模式，不能替换图标轨、系统对象列、页头、Composer 或整条会话画布。

页面路由使用 Host 分配的 `/apps/:pageInstanceId/*`。`pageInstanceId` 不包含 Extension、Revision 或 DSH 包身份；Revision 更新按稳定 `entryId` 复用页面实例、显隐和顺序。新入口默认可见并追加到扩展区末尾。`host_ui_page_preferences` 的单调 Revision 与完整入口列表一起提交，多客户端写入冲突时以 Host 状态为准。

## 外壳与 Runtime

图标轨分为固定系统组、条件分界线、独立滚动的扩展页面组和固定底部工具组。所有可见扩展入口直接显示。入口选择 `objectPane: navigation` 时使用声明式 Navigation Provider；选择 `hidden` 时对象列和分隔拖动条一起撤销，主画布占据剩余宽度。

Host UI Client 在独立浏览器 Runtime 中运行，不复用智能体 SlotCore、Adapter SlotCore 或 DSH 原生 Client Runtime。Runtime 提供 React Hooks 子集、NXT UI Kit、页面注册表、页面内相对导航、`host.call()` 和 `host.subscribe()`。同一 Client Artifact 的多个入口共享模块实例，每个页面主画布和 Navigation Provider 分别隔离错误；Navigation 的 snapshot、订阅或 Schema 失败只替换对象列并写 `navigation-failed`，Client 加载失败写 `load-failed`，两者都不撤销已成功的 Server Installation 或 DSH Loader Activation。页面被隐藏、关闭或删除后，Shell 按原顺序进入它后面的下一个可见扩展页面并通知用户；没有可见入口时进入对应 Extension 或 DSH 详情。

Client Artifact 只通过当前 Installation 或 DSH Host Activation 的精确 Artifact 摘要提供。DSH 的 `dsh.client`、官方 root、侧栏、Composer 和页面 Slot 不加载；只有包内显式 `nekroNxt.hostUi` 自包含 ESM 进入本 Runtime。

## 权限与持久事实

`host_extension_installations` 是 `host-adapter` 与 `host-ui` 的共同安装事实源。`host_ui_page_entries` 保存页面实例，`host_ui_permission_grants` 保存绑定精确 Artifact 摘要的整组批准，`host_ui_diagnostics` 只保存运行诊断。Installation、权限批准和页面目录在同一 SQLite 事务中发布或撤销；页面写入或权限写入失败不会留下半份新安装。安装或升级增加权限时，协调器在停止旧 Runtime 前返回 `permission-approval-required`；用户提交匹配摘要后才挂载并发布新页面。

页面不能调用通用 Host API。`host.call()` 公开权限绑定的产品读取、非破坏性写入和扩展自己的 Host RPC：读取智能体、频道、连接、扩展、DSH 插件、运行状态、消息和受频道授权的 Asset；写入智能体 Revision/能力、内置频道/绑定、Connection、管理员消息和受限产品通知。Credential 使用五分钟、owner 与 Adapter 绑定的一次性写入 token，明文不返回 Client 或进入 SQLite。删除产品对象、卸载、发布、数据库、宿主路径、其他扩展状态和内部 DSH 对象均不进入 Client 环境。

扩展命名空间状态默认可用，按 owner 摘要写入受管设置，使用 `expectedRevision` 并限制为 128 项、64 KiB。事件订阅在 Server 确认 topic 权限后复用产品共享 SSE；页面完成智能体、频道、Binding 或 Connection 写入后统一发布产品失效信号，让所有客户端刷新 Host 权威状态。`network.request` 要求 Manifest 声明 HTTP(S) origin，逐次请求和每一跳重定向都重新解析地址；校验全部地址为公网后，将选中地址固定到实际 socket，拒绝 IPv4/IPv6 loopback、私网、链路本地、ULA、site-local、multicast、文档/转换前缀、`.local` 和 DNS 重绑定。

Client CSS 必须由 Manifest 声明为 CSS Module 并进入 Artifact 摘要。PostCSS 拒绝 `:global`、产品根和裸全局选择器、外部 URL、`@import`、`@font-face` 及未批准 at-rule；Server 在返回 Extension 或 DSH CSS 时再给每个选择器添加精确 Artifact 的 `data-host-ui-owner` 页面根边界，避免样式影响产品和其他页面。SVG 限制大小、`viewBox`、元素和属性，作为单色 mask 渲染；脚本、样式、事件属性、`foreignObject`、`image`、`use`、实体和外部引用均拒绝。扩展代码与 DSH 插件仍是受信任进程内代码，权限服务和资源约束不是安全沙箱。

## 生命周期

Host UI Installation 支持安装、更新、回滚、卸载和冷启动恢复。Host mount 或 dispose 失败会阻止 Installation 事实提交；恢复期间页面目录重建失败会同步 dispose 候选 Runtime 并显示 `restore-failed`。浏览器加载失败不会回滚 Server。DSH 页面只随匹配 `entryKey` 的 Host Activation 发布，关闭或移除对应入口时撤销；智能体作用域 Activation 不贡献全局页面。

导入 Host UI Revision 时，目标 Host 不采用分享包携带的来源证据。受控 Builder 完成后，本机验证器执行 Host factory、全部 RPC、Client factory、页面注册、组件调用、Navigation snapshot/subscribe 和 dispose，并核对页面与权限 Manifest；本机证据成功后才提交 Revision，且不自动安装或显示侧栏入口。

本地 `.nxt-extension` 可携带 Manifest V4 页面 Revision。导入进行路径、大小、文件清单、摘要、本机构建和 V4 契约校验，提交后保持未安装。来源验证证据只用于追溯，不覆盖本机生成的构建证据。

## 产品 Slot Catalog

共享 Catalog 把智能体 Slot、Adapter Slot 和 Host Page 分成三个类型集合。智能体当前开放工作台区块、Activation 面板、频道检查器和 keyed Tool 卡片；Adapter 当前开放富消息、连接 setup/status/test 和频道检查器。未知名称、错误 key 和跨作用域注册立即失败，动态预览与持久 Runtime 使用同一 Props 和验证规则。图标轨、系统对象列、系统页头、Composer 输入框和整条会话画布不接受任意 React Slot；命令、通知和页头动作在出现真实消费者时使用类型化 Contribution。
