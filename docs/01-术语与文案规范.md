# NekroNXT 术语与文案规范

## 1. 品牌

| 场景 | 唯一写法 |
|---|---|
| 产品名 | NekroNXT |
| 根包名/仓库名 | `nekro-nxt` |
| 所属品牌 | NekroAI |
| 不再使用 | Nekro Harness、Nekro 新平台、Nekro Agent 2 |

## 2. 用户实体称呼

产品面对用户时只使用“智能体”。同一个对象不得根据页面随意改称 Agent、AI 成员、机器人、Bot 或助手。

正确示例：

- 创建智能体；
- 管理智能体；
- 小奈正在使用工具；
- 将此频道交给小奈响应；
- 为小奈启用“网页摘要”扩展；
- 2 个智能体正在使用此扩展。

错误示例：

- 创建 Agent；
- 管理 AI 成员；
- 当前 Bot 在线；
- Agent 配置；
- 给助手安装插件。

“助手”可以出现在具体名称中，例如“开发助手”，但不能作为实体类型。

## 3. 用户术语与内部类型映射

| 用户界面 | 内部 TypeScript 类型建议 | 说明 |
|---|---|---|
| 智能体 | `AgentDefinition` | 长期存在的身份和配置实体 |
| （不向用户展示） | `AgentRevision` | 不可变配置快照；界面只写“保存”“恢复之前的配置” |
| 会话 | `AgentSession` | 某配置版本在频道上下文中的运行实例 |
| 频道 | `Channel` | 单一消息事实流 |
| 频道绑定 | `ChannelBinding` | 指定谁响应及触发规则 |
| 平台连接 | `Connection` | 已登录的平台账号连接 |
| 平台用户 | `PlatformIdentity` | 某个平台连接内观测到的稳定用户身份；不同连接不合并 |
| 扩展 | `Extension` | 统一能力包 |
| 扩展版本 | `ExtensionRevision` | 不可变扩展版本；以保存时间区分，不展示序号 |
| 为智能体启用 / 智能体启用关系 | `AgentActivation` | 智能体对指定扩展版本的引用 |
| 动态包 | `DynamicPackage` | 创造会话中的临时可运行产物 |
| 工具 | `ToolContribution` | 扩展提供的一种贡献 |
| 适配器 | `AdapterContribution` | 扩展提供的消息平台贡献 |

内部类型使用 Agent 是为了与 DSH、生态 API 和英文代码保持一致，不构成产品文案例外。

### 3.1 界面空间与交互术语

| 用户界面 | 含义 | 不使用 |
|---|---|---|
| 概览 | 默认进入的页面：需要关注的事项、活动中的频道和近期活动 | 首页、仪表盘、Dashboard、现场 |
| 频道 | 单个频道的消息时间线及其检查器 | 会话页、对话框 |
| 智能体 | 智能体资料：模型、频道、能力、扩展、设定 | 工作台（作为页面名） |
| 工坊 | 创造任务与本地扩展 | 创造工作台、扩展库 |
| 接线 | 平台账号 → 频道 → 智能体的绑定关系 | 连接页、绑定向导 |
| 设置 | 模型、平台适配器、DSH 插件、通知、外观、关于 | 系统设置 |
| 透视 | 频道时间线中展开思考、工具输入输出与用量的显示方式 | 工作轨迹、调试模式 |
| 排队 | 已收录、尚未注入智能体上下文的新消息 | 待处理、缓冲 |
| 停止当前任务 | 中止当前模型或工具调用，不清空上下文，排队消息保留 | 取消、重置 |
| 需要关注 | 未确认投递、失败轮次、等待确认的创造任务、异常账号等需要用户处理的事项 | 通知中心、告警 |
| 搜索（命令面板） | `⌘K` 打开的统一查找与跳转入口，包含频道、智能体、成员、扩展页面和操作 | 全局搜索页 |
| 平台账号 | 接线中的一条 Connection，展示名为 `alias ?? 适配器名` | 机器人后台 |
| 成员 | 平台连接内观测到的用户身份；在账号详情和命令面板中查找 | 用户（作为一级页面） |

“工坊”中的一次动态创造称“创造任务”，其生命周期按“生成候选 → 确认运行 → 启动 → 界面验证 → 保存 → 启用”书写；保存与启用是两个独立动作。

NekroNXT 不加载 DSH 的 `dsh.client`、原生 WebUI、侧栏、Composer 和页面 Slot，也不设置允许上游术语泄漏的“兼容岛”。DSH 包只有显式声明 `nekroNxt.hostUi` 才能贡献 NXT 页面，用户可见文案遵守本规范。加载边界见[扩展应用页面与 Host UI 运行时](decisions/implemented/2026-08-28-扩展应用页面与HostUI运行时.md)。

## 4. 写作

这一节约束所有中文：界面、报错、通知、给智能体的提示词与工具说明、用户指南和开发文档。判断标准只有一个：读的人能不能一眼明白发生了什么、自己该做什么。

### 4.1 界面文字

- **只说对象、动作和结果。** 用户需要知道点了会怎样，不需要知道系统怎样做到。“已保存”好于“配置已写入并在下一个安全点生效”。
- **能删就删。** 标题、按钮和当前状态已经说明白的，不再加说明。说明文字只留每次都影响判断的内容：不可用的原因、费用、风险、不可撤销的后果。其余放进问号提示，或者干脆不写。
- **不替系统辩解。** 不写“不会……”“并不……”“不影响……”去回应没人提出的担心。只有在用户确实会误解、而且误解代价大时（删除、计费、外发内容），才说明边界。
- **不补理由。** “以免……”“为了……”“避免……”引出的从句默认删掉。用户要的是结果，不是设计动机。
- **同一件事在同一页面只说一次。** 同一个时间、同一句提醒、同一个状态，不在标题、副标题和列表里重复出现。
- **用界面上看得到的词。** 不出现 Host、Session、Turn、Revision、Episode、Package、Runner、注入、投影、安全间隙、静止、熔断、闭环、链路这类内部词。
- **按钮用动词。** “保存”“切换到这个版本”“重新连接”；不写“确定”“提交操作”。
- **短句，口语但不随意。** 像成熟的中文桌面软件；不卖萌、不喊口号、不用感叹号，也不用“哦”“啦”装亲切。

| 改前 | 改后 |
|---|---|
| “X”包含只写 Secret，无法安全拆分编辑；已禁止整体替换，避免清除或回显已保存的值。 | “X”含有密钥，不能在这里编辑。 |
| 密钥保留在本机凭据存储，不会删除，以免影响共用密钥的其他供应商或功能。 | 已保存的密钥会保留。 |
| 恢复后，名称、设定、模型和能力回到当时的样子；进行中的对话在当前这一步结束后使用。 | 名称、设定、模型和能力会回到当时的样子。 |

要保留的提醒长这样：“频道草稿会在刷新后恢复；其他表单里未保存的输入会丢失，需要的话请先复制。”它说的是真实后果和应对办法。

### 4.2 报错

- 报错写两件事：发生了什么，用户能做什么。“这个候选还没有试运行成功，暂时不能保存。”
- 用户的操作不可能触发的检查（内部状态不一致、协议违例、路由不存在）用英文写给开发者，界面显示“操作失败”，原文放进诊断区。
- 不把错误码、配置键名、HTTP 方法写进中文报错。

### 4.3 给智能体看的文字

提示词、工具说明和系统通知决定了智能体怎么说话。写的时候把它当成给一位能干的同事交代工作：

- 讲清处境和目标，再讲少数必须遵守的事，每条附上原因。不用“必须”“不得”“严禁”堆规章，不用感叹号和加粗强调。
- 只讲它行动需要知道的机制。它需要知道“群里只看得到 send_channel_message 发出的内容”，不需要知道 Turn、轨迹、义务、权威事实。
- 不规定说话的格式和流程。不要求它“先说明理解再同步进展、风险和阻塞”，这会让它在群里像写周报；说话方式交给人设和群里的习惯。
- 系统通知写成一句通知加一句要做的事，例如“〔系统通知〕「天气查询」试运行失败：……。接着修，不用等用户催。”
- 工具说明写这个工具做什么、什么时候用、参数怎么填，不复述别处已经讲过的规则。

### 4.4 文档

- 先写结论，再写理由。不用“不是 X，而是 Y”开头，不写“以下只是建议，不是硬性规则”这类自我说明。
- 用户指南只写用户能看到和能操作的东西，用词与界面一致。

### 4.5 具体约定

- 智能体没有版本概念。修改智能体写“保存”，回到以前的配置写“恢复之前的配置”。
- 扩展的每次保存或导入称为一个“版本”，用时间区分（如“10月1日 20:26”“正在使用”），不写 `r12` 这类序号。
- `Activation` 写“为小奈启用”；`Binding` 写“频道绑定”；`Connection` 写“平台连接”或具体账号。
- “成员”只指平台消息里出现过的身份，不是 NekroNXT 的登录账号；界面不设一级“用户”页。
- NekroNXT 自带的频道写“内置频道”。
- `Extension` 写“扩展”，不混用插件、Skill、能力包。
- `Agent Loop` 在界面上写“思考与工具执行过程”。
- 状态要说明对象：智能体空闲、平台已连接、频道监听中、工具执行中；不用一个“在线”概括所有状态。
- 不在产品界面写死 QQ、Discord 等平台名，平台名来自适配器。
- 管理员从客户端发到外部频道的消息标为“管理员从客户端发出”。
- 错误码、配置键名、内部编号只出现在默认收起的“诊断”区。

### 4.6 状态措辞

状态措辞以[界面交互模型](NekroNxt界面交互模型.md) §2 的状态词典为准：

- 本机：正在连接、运行正常、连接不稳定、无法连接；
- 平台账号：已连接、正在连接、已配置、认证过期、已断开、异常；“已配置”要同时说明还没连上的原因和下一步；
- 智能体：空闲、思考中、使用工具、等待输入、不可用；
- 创造任务：正在开发、等待确认、正在验证、可以保存、正在修复、需要处理、已停止、已保存；
- 扩展：未启用、N 个智能体使用、运行异常；未安装、已安装。

### 4.7 自动检查与精确例外

`pnpm check:docs` 运行 `scripts/check-terminology.mjs`，拦截产品界面中的内部术语、写死的平台名和用技术 ID 充当显示名的写法。它只查术语，不查文风；文风靠本节人工审稿。

确实需要保留被拦截的文字时，在 `scripts/baselines/user-visible-copy-exceptions.json` 按 `file + rule + text` 登记精确例外并写明原因，例如：

```json
{
  "file": "apps/web/src/example.tsx",
  "rule": "term:Adapter",
  "text": "/wiring/new?adapter=",
  "reason": "内部 URL 查询参数，不显示给用户。"
}
```

文字改掉或不再命中后，过期的例外会让检查失败，需要一起删除。

## 5. 创造状态

- “创造”是智能体打开动态创造能力后的状态，不是另一种实体；不出现“创造助手”“创造智能体”。
- 工坊中的创造任务直接显示发起它的智能体，例如任务标题旁的“小奈”和头像。
- 系统访问分四级：“基础权限 → 文件读写 → 运行命令 → 完整访问”，在智能体资料的“能力”中按风险从低到高排列，每级只写比上一级多出的能力；“运行命令”及以上需要确认。展开“手动调整”可以单独控制各项，组合不对应任何一级时显示“自定义”。
- 系统访问、子智能体、网页搜索和动态创造是“能力”中并列的独立项。
