# 备用模型

状态：implemented（2026-10-22，issue #50）

## 决定与理由

主模型额度用完、持续限流或服务不可用时，智能体按配置换到备用模型，而不是直接停止回复。

| # | 决定 |
| --- | --- |
| F1 | 每个智能体在配置版本中保存有序的备用模型（`fallbackModels`，最多 3 个，不与主模型重复）。默认为空，即不开启；只会换到这里列出的模型 |
| F2 | 触发：`QUOTA` / `ACCOUNT_QUOTA` 立即换；`RATE_LIMIT`、`SERVER`、`TIMEOUT`、`TRANSPORT`、`EMPTY_RESPONSE` 在 DSH 自带重试放弃后再换；凭据错误、上下文超限、参数错误等换模型解决不了，不换，以免掩盖配置问题 |
| F3 | 实现位置：宿主在 `agent/request-error` 上决定是否换，在 `agent/request` 上改用对应的模型与思考强度。DSH 每次重试都会重新经过 `agent/request`，并把请求头的变更写进会话日志；失败的请求只记为模型看不到的 `assistant/attempt`，工具要等模型完整回复后才执行，所以重试这一步不会重复任何副作用。不需要修改 DSH |
| F4 | 作用范围：换过去后整段对话沿用备用模型，只在开始处理新消息（一轮的第一步）时检查主模型是否已过冷却，过了就换回。一轮中途不切回，每次切换最多重建一次缓存 |
| F5 | 冷却按模型路线记录，整个宿主共用、只存在内存中：一个模型额度用完后，所有智能体都直接跳过它，重启后重新尝试。冷却时长在“设置 → 模型”中调整（`llm.modelFallback`：限流或出错后默认 10 分钟，额度用完后默认 1 小时）|
| F6 | 所有模型都在冷却时继续用当前模型；一步内每个模型最多失败一次，全部失败后照常报错结束，不会无限重试 |
| F7 | 频道对话和跟随主模型的子对话会换；子对话单独选的模型（子对话 C10）、压缩和视觉模型不受影响。修改备用模型从下一次请求起生效，不参与会话兼容判断 |
| F8 | 可见性：频道运行状态带 `modelFallback`（模型、原因、开始时间、何时再试主模型），页头显示“备用模型”；每次换和换回写一条警告级运行日志，不含密钥 |

## 契约入口

- `packages/contracts/src/host-api.ts`：`AgentFallbackModelsSchema`、`ModelFallbackSettingsSchema`、`getModelFallbackSettings` / `updateModelFallbackSettings`、频道运行状态的 `modelFallback`；
- `apps/server/src/model-fallback.ts`：错误分类、冷却与路线选择；
- 迁移 `0055_agent_fallback_models`。
