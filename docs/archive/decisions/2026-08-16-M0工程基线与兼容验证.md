## DSH Client 边界

M0 实测确认：

- `@deepseek-ai/dsh-client-runtime` 根入口是 Host 侧空插件；
- `@deepseek-ai/dsh-client-runtime/client` 是交给 DSH Client ModuleLoader 的模块产物，不是普通 Vite ESM；
- `@deepseek-ai/dsh-client-ui-slots` 的 `SlotCore` 是可直接复用的标准 ESM 公共入口；
- NekroNxt 当前生产 Client facade 因此只直接导出纯 SlotCore；完整 Client Runtime 等 Server Host roster 建立后通过官方 ModuleLoader 链装配。

这条边界防止用空 `apply()` 冒充 Runtime，也不使用浏览器 polyfill 掩盖 Host/Client 打包错误。

## 依赖边界

完整 DSH Base/Web Bundle 和代表性 Host 包只作为开发期兼容面，不属于当前 Client facade 的生产依赖。未来 `apps/server` 组合根必须声明并断言自己实际使用的 Host package set，不能让 `dsh-compat` 的版本表无条件拖入完整产品闭包。

> 后续基线说明：本段记录 M0 当时的 Spike 结论。当前 Core 已改为 `better-sqlite3 + Drizzle` typed Repository，旧迁移历史合并为唯一 `0000_initial`，并删除 FTS5 与业务手写 SQL。DSH Session SQLite 的所有权不变。
