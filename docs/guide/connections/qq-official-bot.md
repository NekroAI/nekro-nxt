# 接入 QQ 官方机器人

本文介绍如何通过 QQ 开放平台的 OpenClaw 入口创建官方机器人，并将其接入 NekroNXT。QQ 官方机器人使用平台分配的 `AppID`、`AppSecret` 和 OpenID 身份体系，由 NekroNXT 主动连接 QQ Gateway。

```text
QQ OpenClaw 入口
  → 创建官方机器人并取得 AppID / AppSecret
  → NekroNXT 连接 QQ Gateway
  → 发现私聊或平台开放的群聊
  → 绑定智能体
```

该方案由 QQ 开放平台托管机器人身份，无需部署 QQ 协议端。使用普通 QQ 账号和第三方协议端的接入方式见 [OneBot V11 接入教程](onebot-11.md)。

## 开始前准备

准备以下环境与信息：

- 一个用于登录 QQ OpenClaw 入口的手机 QQ 账号；
- 已完成模型配置且至少创建一个智能体的 NekroNXT；
- NekroNXT 运行环境能够访问 QQ 开放平台的 HTTPS 与 WebSocket Gateway；
- 用于验收私聊或平台开放群聊的 QQ 客户端。

QQ 官方机器人受开放平台的使用范围、频率限制和审核规则约束。正式使用前应完成独立测试，并核对 [QQ 机器人官方文档](https://bot.q.qq.com/wiki/)中的当前规则。

## 创建机器人并获取凭据

1. 使用手机 QQ 打开 [QQ OpenClaw 机器人入口](https://q.qq.com/qqbot/openclaw/index.html)；
2. 登录并点击「创建机器人」；
3. 按页面要求设置机器人名称、头像和介绍；
4. 创建完成后复制 `AppID` 与 `AppSecret`，并保存到受控的凭据管理位置；
5. 使用页面提供的「发起聊天」或「扫码聊天」建立测试私聊。

`AppSecret` 只在创建或重置后明文显示。当前官方入口在二次查看时会重置 `AppSecret`，原值随即失效；重置后需要使用新值重新创建 NekroNXT 连接。

当前 OpenClaw 入口将机器人使用范围限定为创建者，并标注普通群聊暂未开放。页面显示「创建私人 BOT 群」时，可以创建平台提供的测试群聊。NekroNXT 支持 QQ Gateway 上报的私聊与群聊事件，实际可用范围由 QQ 开放平台为该机器人开放的场景决定。

## 网络要求

NekroNXT 使用 `AppID` 和 `AppSecret` 向 `https://bots.qq.com` 获取访问令牌，再通过 `https://api.sgroup.qq.com` 获取 Gateway 地址并调用消息接口。运行环境需要允许出站 HTTPS 和 WSS 连接。

该接入方式采用出站 Gateway 连接，无需为 NekroNXT 配置公网回调地址或开放入站端口。部署了出站代理、防火墙或域名白名单时，应允许上述官方域名及其返回的 Gateway 地址。

## 在 NekroNXT 添加连接

1. 前往「连接」，点击「添加平台连接」或「再添加一个账号」；
2. 选择「QQ 官方机器人」；
3. 填写 QQ OpenClaw 入口显示的 `AppID`；
4. 在「Client Secret」填写对应的 `AppSecret`；
5. 初次接入保留其余字段默认值，可填写连接别名用于区分多个机器人；
6. 点击「创建连接」，等待状态变为「已连接」。

Client Secret 是只写凭据，保存后页面仅显示“已保存”。提交前应核对内容，并从截图和问题报告中移除真实凭据。

连接配置字段如下：

| 字段 | 默认值 | 说明 |
|---|---:|---|
| App ID | 必填 | QQ OpenClaw 入口生成的机器人应用 ID |
| Client Secret | 必填 | 与 App ID 对应的 AppSecret，只写保存 |
| 允许主动发送 | 关闭 | 允许在有效被动回复上下文之外调用主动消息接口 |
| 使用 Markdown | 开启 | 使用 QQ 官方 Markdown 消息格式发送文字和 Mention |
| 单条字符上限 | `1800` | 超长文字按此限制分片 |
| 单条 UTF-8 字节上限 | `7200` | 单条消息的 UTF-8 字节限制 |

默认关闭「允许主动发送」，以被动回复路径完成初次验收。QQ 平台为入站消息提供有限的被动回复时间和次数；一次投递的分片数量超过剩余额度时，完整投递需要主动发送能力。启用前应确认机器人具备对应权限，并评估平台额度。

字符与字节上限已经按当前适配器行为设置。仅在 QQ 平台规则或实际回执要求调整时修改，且两个数值都必须为正整数。

## 发现频道并绑定智能体

1. 在 QQ OpenClaw 入口点击「发起聊天」，或扫描机器人聊天二维码；
2. 向机器人发送一条文字消息；
3. 回到 NekroNXT 连接页面，确认「最近收到消息」已更新且「已发现频道」不再为零；
4. 展开「收发测试」，点击「测试接收」；
5. 选择已发现的私聊或群聊，点击「发送测试消息」；
6. 点击「绑定智能体」，选择频道、响应智能体和响应方式；
7. 前往已绑定频道，再次发送消息验证智能体响应。

私聊消息可以直接触发绑定。群聊初次验收建议使用「被提及或回复时」，通过 Mention 或回复机器人消息触发智能体；「仅观察」用于记录频道事实，消息不触发智能体。

## 消息能力

当前适配器覆盖：

- 私聊 `C2C_MESSAGE_CREATE`；
- 群聊 Mention 消息 `GROUP_AT_MESSAGE_CREATE`；
- 平台开放时的普通群消息 `GROUP_MESSAGE_CREATE`；
- 文字、结构化 Mention、图片、音频、文件和引用；
- Markdown 文字分片和媒体分片上传；
- Gateway 会话恢复与断线重连。

QQ 平台将卡片、小程序和合并转发等内容拍扁后上报。NekroNXT 将可识别内容转换为富消息摘要，并按平台提供的信息导入预览图或附件。

## 最小验收清单

接入完成后，至少确认：

- 正确凭据使连接进入「已连接」，错误凭据显示认证失败；
- 测试私聊能够被 NekroNXT 接收；
- 私聊能够收到 NekroNXT 的发送测试消息；
- 文字、Mention、图片和引用各完成一次接收与发送；
- 平台开放私人 BOT 群或其他群场景时，完成群聊 Mention 与回复测试；
- QQ Gateway 中断并恢复后，连接能够自动重建；
- NekroNXT 重启后，连接能够恢复并继续接收新消息。

真实账号的通知高亮、被动回复额度、媒体上传和平台回执仍需要按发布环境验收。当前实现状态以 [QQ 官方机器人 Adapter Decision](../../decisions/accepted/2026-08-15-首个QQ-OpenClaw-Adapter.md)为准。

## 按症状排障

### 连接显示认证失败

- 核对 `AppID` 与 `AppSecret` 是否来自同一个机器人；
- 确认填写的是 `AppSecret`，而非 QQ 开放平台其他页面中的 Token；
- 在官方入口重置过 `AppSecret` 时，使用重置后的新值创建连接；
- 检查运行环境对 `bots.qq.com` 和 `api.sgroup.qq.com` 的出站访问。

### 连接持续显示正在连接或重连

- 检查运行环境的 HTTPS、WSS、DNS 和系统时间；
- 确认防火墙或代理允许 QQ API 域名以及 API 返回的 Gateway 地址；
- 查看连接页面的最近错误，区分认证、限流和临时网络故障；
- 检查 QQ 开放平台中的机器人状态。

### 已连接但未发现频道

- 通过官方入口的「发起聊天」或「扫码聊天」进入机器人会话；
- 使用创建机器人的 QQ 账号发送一条新消息；
- 群聊场景以官方入口实际显示的「私人 BOT 群」或开放范围为准；
- 发送后运行「测试接收」，并检查连接页面的最近接收时间。

### 接收正常但发送失败

- 在发送测试前选择已发现的目标频道；
- 使用入站消息建立有效的被动回复上下文；
- 多段文字或媒体投递超过被动回复额度时，检查「允许主动发送」及平台权限；
- 图片、音频或文件失败时检查 QQ 平台回执和媒体上传状态。

## 与 OneBot V11 的区别

| 项目 | QQ 官方机器人 | OneBot V11 |
|---|---|---|
| 账号身份 | QQ 开放平台分配的机器人应用和 OpenID | 协议端登录的 QQ 账号 |
| 接入凭据 | AppID + AppSecret | WebSocket Endpoint + 可选 Access Token |
| 外部运行组件 | QQ 开放平台 | SnowLuma、NapCat、LLBot 等协议端 |
| 网络连接 | NekroNXT 连接官方 Gateway 和 HTTP API | NekroNXT 连接协议端 Universal WebSocket Server |
| 使用范围 | 由 QQ 开放平台为机器人开放 | 由登录账号、协议端和平台规则决定 |
