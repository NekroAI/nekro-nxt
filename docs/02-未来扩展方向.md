# NekroNXT 未来扩展方向

> 文档性质：方向约束，不是版本承诺或首版需求清单
>
> 用途：设计新功能、公共契约和持久格式时，检查当前方案是否把已知未来路径锁死
>
> 当前范围以根 `AGENTS.md`、《NekroNXT项目共识》和一期计划为准

## 0. 使用原则

未来规划用于防止架构被锁死，不要求首版提前实现未来能力。

开发者或 AI 只有在修改领域模型、公共 API、持久格式、DSH 集成、Extension、Adapter、消息协议、Runtime、部署或社区能力时才需要查阅本文。普通文案和局部修复不必读取全部规划。

每次相关设计至少回答：

1. 本次改动关联哪些未来方向？
2. 现在必须保留的稳定接缝是什么？
3. 是否出现只能靠破坏性迁移才能扩展的锁死方案？
4. 哪些未来能力明确没有在本次提前实现？

“保留接缝”通常意味着稳定 ID、明确边界、可扩展联合类型、Revision 或 Adapter capability；不意味着先建空服务、空表、假状态机和无人使用的抽象层。

DSH 是 NekroNXT 的核心引擎，生态兼容不以插件作者专门适配 NekroNXT 为前提。面向 DSH 能力面的插件应优先通过上游公开接缝零适配运行；NekroNXT 元数据、中文文案、专用表单和产品 Slot 只提供增强体验。现行安装、Loader 和支持识别契约见 `decisions/implemented/2026-08-18-DSH能力插件优先兼容与支持识别.md`。

## 1. 更多聊天平台 Adapter

- 用户价值：让同一个智能体进入更多群聊、私聊和业务消息渠道。
- 当前不做：同时实现所有主流平台、统一抹平全部平台差异，或由 NekroNXT 捆绑和管理第三方协议端。
- 现在保留：`AdapterContribution`、`Connection`、`Channel`、`Binding` 分离；统一入站事件、特殊活动关系、受限 Host Service、出站消息和语义互动协议；Adapter 显式声明文本、Mention、图片、文件、回复、混合消息和尺寸限制，并贡献稳定平台目录与版本化 Connection 配置 schema。OneBot 11 与企业微信智能机器人已使用这些接缝，现行契约见 `decisions/implemented/2026-08-26-OneBot11正向WebSocket适配器.md` 和 `decisions/implemented/2026-08-27-企业微信智能机器人长连接适配器.md`。扫码/OAuth 继续走宿主登录会话与可选 `connection.adapter.setup` Slot，不在壳内按 `adapterKey` 分叉。
- 禁止锁死：在 Core 中写具体平台逻辑；假设所有平台都支持相同媒体与回执；用平台展示名代替稳定成员 ID；把创建/挂载/测试写成某个平台的特权函数。
- 下一启动条件：出现新的高需求平台后，继续复用同一 Host Service、活动关系与互动意图，并以平台官方链路和实际回执能力决定消息映射。

## 2. 频道解绑与批量管理

现行绑定规则见根 `AGENTS.md` 与 `NekroNxt界面交互模型.md`：一个智能体可以同时绑定多个频道，一个频道同一时间只由一个智能体响应。

- 用户价值：明确解绑、查看换绑后的频道历史，以及批量调整多个绑定。
- 当前：对象列可拖绑定 / 换绑 / 解绑；解绑先停止该频道正在工作的智能体。
- 当前不做：批量解绑、自动迁移消息、隐式选择发送目标、跨频道短期上下文混合、通信工具按 `channelId` 向其他频道发言。
- 现在保留：稳定 Binding 身份、独立频道事实流、显式 `agentId` 与 `channelId`；现行发送只允许 `target: current`。
- 禁止锁死：把智能体永久等同于某个 Channel Session；换绑时删除历史消息；让跨频道发送依赖含糊的“当前频道”。
- 启动条件：出现真实的解绑、批量管理或跨频道发送需求。

## 3. 长期记忆与知识

- 用户价值：跨会话保留偏好、关系和可引用知识，同时不混合不同频道的短期事实流。
- 当前不做：大型向量基础设施、自动实体图谱、默认读取所有频道历史。
- 现在保留：Channel Event Log、DSH Session Log、长期 Memory/Knowledge Provider 三者边界独立；记忆内容保留来源与作用域；通过工具或 Context Provider 按需读取。
- 禁止锁死：直接把所有频道记录拼进 Prompt；把向量数据库当领域事实源；丢失来源和可删除性。
- 启动条件：基础会话与消息协议稳定，并能用真实任务评估召回质量。

## 4. Process 与 Remote Runtime

- 用户价值：为陌生插件、重型任务、远程算力和不同设备提供独立运行位置。
- 当前不做：首版强隔离沙箱、远程调度集群、复杂 capability token。
- 现在保留：Extension Revision 与 Activation 分离；插件只通过公开 Service/Contribution 契约访问宿主；Core 数据库不是插件 API。当前不持久化无人消费的 `RuntimeKind` 预留字段。
- 禁止锁死：把宿主对象、数据库连接和绝对路径写进公开插件契约；宣称 in-process Realm 是安全沙箱。
- 启动条件：本地 in-process 生命周期稳定，且第三方代码风险或资源隔离需求真实出现。

## 5. 多设备与同步

- 用户价值：Desktop 与 Server 之间同步智能体配置、扩展和可选择的数据。
- 当前不做：云端账号强依赖、透明同步全部消息和 Secret、冲突自由复制系统。
- 现在保留：核心对象使用稳定 ID 和不可变 Revision；本地数据格式版本化；Secret 使用引用而不是嵌入业务对象。
- 禁止锁死：使用机器路径作为资源身份；原地覆盖不可追溯配置；把 Desktop 与 Server 做成两套领域实现。
- 启动条件：单机备份恢复成熟，用户明确需要跨设备连续使用。

## 6. 社区市场、发布与供应链

- 用户价值：搜索、分享、安装和更新社区扩展。
- 当前不做：社区市场、公开发布、云构建、签名、SBOM、发布者等级和复杂审核。
- 现在保留：Extension 有稳定 ID、固定 scope、不可变 Revision 和跨身份 `payloadDigest`；本地保存、Agent Activation 与 Host Installation 独立，构建产物可重建。单 Revision `.nxt-extension` 支持小范围手动分享；DSH 分享包携带根 tgz 和锁元数据，在目标机器联网重装依赖。Manifest V3 和 `AdapterHostContributionV1` 固定当前 Host Adapter API；来源、签名和市场兼容范围仍等到远程分发出现时再引入。
- 禁止锁死：把本地路径当全局插件 ID；安装即对所有智能体生效；要求未来社区插件重写首版本地插件格式；为市场另做一套适配器模型。
- 启动条件：本地插件模型稳定、已有真实分享需求、升级和回滚可用。

## 7. 智能体自开发与自迭代

- 用户价值：绝大多数用户只描述需求，智能体即可创建、运行、调试、验证并保存扩展。
- 当前不做：智能体无人监管地修改 NekroNXT Core、自动发布公共插件、用“自称成功”代替验证。
- 现在保留：创造是一套可配置 Preset；Inspect、Define、Run、Stop、Build、Validate、Save、Activate 是可观察的独立动作；动态 Package、本地 Revision 和 Activation 分离；验证输出结构化证据。
- 禁止锁死：把创造状态写成系统内核里的特殊智能体或不可替换模式；把 Bash、文件访问和创造权限合成一个开关；绕过 Extension 契约直接改数据库。
- 启动条件：首版本地动态创造闭环本身就是 Alpha 主目标；更高级的自动修复、回归和迭代在基础闭环稳定后增加。

## 8. 长期 Jobs 与主动行为

- 用户价值：定时总结、提醒、轮询、异步长任务和主动群聊互动。
- 当前不做：复杂分布式调度、多节点故障转移、无限后台自主循环。
- 现在保留：Job 作为 Extension Contribution 的可能类型；触发身份、目标频道、智能体 Revision 和权限上下文可追溯；发送仍使用统一通信工具。
- 禁止锁死：用前端定时器承担可靠任务；让后台任务绕过 Channel Runtime 直接调用平台 SDK。
- 启动条件：Runtime 具备长期运行、恢复和基础幂等能力。

## 9. 多媒体与交互式消息

- 用户价值：发送 Mention、图片、文件、音频、引用，未来扩展按钮、卡片和平台原生交互。
- 当前不做：首版穷举所有平台卡片协议、视频理解/转码和富媒体编辑器。视频原件仍作为普通文件入库。
- 现在保留：有序 `MessagePart[]`、稳定 `assetId`、内容 digest、AssetOccurrence、版本化派生结果、Adapter capability 与降级策略；一个逻辑消息可以对应多个平台消息 ID。平台卡片走公共 `rich` 块（必填 summary + 可选 extension）和产品 Slot `conversation.message.rich`，不把平台对象写入 Core。现行契约见 `decisions/implemented/2026-08-20-适配器Host贡献与产品Slot.md`。
- 禁止锁死：把媒体当宿主绝对路径；把 Mention 当裸文本；假设混合内容必定能作为一条平台消息发送；让适配器 React 成为历史消息的唯一真相。
- 启动条件：文本、Mention、图片和文件的最小协议完成后按真实平台增量扩展。

## 10. 云资源、账号与远程管理

- 用户价值：资源分发、更新、远程管理 Server、可选同步和社区账号。
- 当前不做：本地智能体强依赖云端、企业多租户控制面、计费和复杂 RBAC。
- 现在保留：云服务通过公开 API 与版本化 contracts 接入；本地 Runtime 离线可运行；更新资源与用户数据分离。
- 禁止锁死：把云端租户概念渗入本地核心领域；无法关闭的遥测；把登录作为创建本地智能体的前提。
- 启动条件：本地产品成立，且远程管理或社区分发有明确需求。

## 11. DSH 能力插件兼容与支持识别

- 用户价值：直接使用为 DSH 能力体系开发的 Tool、Provider、Service、Settings、Scope、Bundle 和 Preset，不等待插件作者维护 NekroNXT 专用版本。
- 当前不做：承诺兼容所有 DSH 官方 Web 页面、接入 DSH 原生 WebUI、为每个插件手写适配器和产品页面。
- 现在保留：受管 npm/tgz 安装、Host 与智能体 Loader、Bundle 展开、DSH Settings/Schemastery 通用配置投影、Cordis Config Schema/高级 JSON、Credential Reference、可逆 Cordis 生命周期和真实 Inventory 诊断；插件专用 NekroNXT Contribution 只覆盖展示和高级产品流程。
- 禁止锁死：把 NekroNXT 元数据作为 DSH 能力插件的加载前提；复制上游 Plugin/Provider 目录；用硬编码包名白名单代替能力识别；把“能 import”或“能启动”冒充完整支持。
- 启动条件：每次引入新的 DSH 插件类别或安装入口时，先实现该类别的通用识别、最小真实组装验证、来源展示和 Loader 错误投影，再开放用户入口；验证结果属于开发门禁，不生成用户可见支持评级。

## 12. 变更检查结论模板

相关任务在设计或交付说明中用几句话记录即可：

```text
关联方向：多媒体消息、更多 Adapter
保留接缝：有序 MessagePart、Adapter capability、逻辑消息 ID
本次不做：交互式卡片、专用视频理解/转码、跨设备资源同步
避免的锁死：不暴露宿主路径，不把 Mention 编码成裸文本
```
