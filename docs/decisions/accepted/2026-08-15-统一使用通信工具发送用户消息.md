# 决策：统一使用通信工具发送用户可见消息

状态：accepted

## 问题

DSH 模型既可以输出普通 `text/reasoning` 内容块，也可以调用 Tool。如果普通文字自动成为聊天回复，同时图片、文件、Mention 和主动消息又通过 Tool 发送，智能体需要理解两套发言规则，运行中的分析和调试文本也可能被误投递到真实群聊。

## 决定

所有用户可见消息必须由智能体调用 NekroNxt 通信工具产生。Web Channel 与外部聊天平台使用同一规则。

DSH 模型原始 `text`、供应商实际提供的 `reasoning` 和其他非通信工具内容只进入内部 Session Log 与后台运行观察，不自动投递到 Channel。工具先持久化逻辑出站意图，再由 Channel Runtime 和 Adapter 发送；只有真实回执可以标记为已发送。

文字、Mention、图片、文件和音频使用统一的有序 `MessagePart[]`。媒体通过 `assetId` 引用，Mention 通过成员 ID 表达。详细契约以 `../../03-消息内容与投递协议.md` 为唯一事实源。

## 备选方案

1. 模型最终文字自动发送，媒体再用 Tool：规则割裂，容易重复发送或泄漏分析文本，拒绝。
2. 解析模型文字中的特殊标记生成媒体：协议脆弱、无法可靠校验回执，拒绝。
3. 每种内容提供独立发送工具：工具数量和组合规则膨胀，首版拒绝；平台特有动作仍可作为独立 Adapter Tool。

## 影响

- Prompt 只要求智能体在需要发言时调用通信工具；
- 应答型 Turn 如果没有成功通信工具调用，显示“未产生回复”，不得兜底发送原始文字；
- Channel Conversation 只展示 Channel Event 和通信工具产生的出站事实；
- 运行详情必须区分内部输出、Tool 和已发送消息；
- 通信工具成为消息幂等、媒体、回执、失败和审计的统一入口。

## 验证

- Web 与外部 Adapter 的端到端测试断言原始模型文字不会自动出现；
- 文本、Mention、图片和文件的混合发送经过同一 Tool；
- 失败或部分成功不会显示成完整成功；
- 零发送的观察型 Turn 合法，应答型 Turn 可被标记并提醒一次。

## 参考证据

- DSH 的统一 `send()` 与非唤醒 `inject()` 消息设计；
- DSH 可扩展 Content Block 和 attachment/provider capability 实现；
- Nekro Agent 的公开多媒体、平台发送与群聊实践。
