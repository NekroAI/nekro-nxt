# Desktop 多实例与设备鉴权

状态：implemented

## 问题

Server 适合在 VPS、NAS 或家庭服务器上持续运行，Desktop 适合提供本机窗口、通知和操作系统适配。单一 BrowserWindow 固定加载本地 Host 时，用户无法用一个客户端管理多台独立服务器；直接把管理密钥交给远程产品页面，又会让 Extension Client 与普通页面脚本进入本机可信边界。

## 决定

Desktop 是本地实例与多个远程服务实例的切换宿主。每个实例拥有独立的数据、智能体、频道、扩展、凭据和运行状态；切换只替换当前管理界面，不停止任何实例中的 Runtime。

远程实例加载该 Server 同包托管的 Web UI。Desktop 接受 `desktopChromeProtocol = 1`，并按 transport 协商 management protocol：`loopback-http` 与 `auto-tls-pinned-v1` 使用兼容既有 Desktop 的 `managementProtocol = 1`，`explicit-http-v1` 使用 `managementProtocol = 2`。wire descriptor 允许未来增加字段并读取未知的数字协议与 transport 字符串；只有当前支持的组合才进入 operational schema。未知协议或 transport 显示版本不兼容，只有已知 transport 与地址 scheme 不一致时显示传输配置错误。Desktop 不维护跨任意历史业务 API 的兼容层；实例版本不兼容时进入可信错误页，不加载产品页面。

BrowserWindow 的 Content View 下维护：

- 当前实例的 `Product WebContentsView`，使用 Profile 专属持久 partition；
- 安装包内的 `Instance Overlay WebContentsView`，负责实例列表、配对、编辑、重认证和移除；
- 本地 `Trusted Fallback WebContentsView`，负责连接、认证与不兼容状态。

切换实例时先在旧 Product View 上方预加载背景透明、正文隐藏且与当前明暗主题一致的 Trusted Fallback；过渡页就绪后用 240ms 淡入覆盖旧实例，完全覆盖后才关闭旧 Product View 并为目标 partition 创建新 View。可见窗口中的正常切换从淡入开始至少约 2 秒，界面只显示“服务实例 / 正在切换”，新页面完成同源校验且最短时间满足后，Fallback 再用 240ms 淡出以露出新实例；首次启动窗口尚未显示时不人为延迟。旧 View 的 Zustand、SSE、动态 Client、Extension Client 和请求随 WebContents 一起销毁。每个 Profile 保存自己的最近产品路由。页面通过统一未保存草稿注册器声明编辑状态；跨实例切换或编辑当前实例的连接参数前由主进程显示确认。

## Desktop 信任边界

远程 Product View 使用 `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`。它只获得：当前实例展示信息、订阅当前状态和请求打开实例浮层。Bridge 不返回 Profile 列表、地址、设备凭据或固定公钥，不提供文件、Shell、通知和通用 IPC。

实例浮层使用独立本地 preload。Profile 与设备 Secret 分离：Profile 使用版本信封和原子替换文件；损坏或未来版本原文件改名保留为 recovery 文件。设备 Secret 通过 Electron `safeStorage` 加密；Linux 选择 `basic_text` 或安全存储不可用时只保留进程内凭据，应用重启后要求重新认证。

Profile Store 拒绝重复的规范化 Origin 与重复实例身份。远程 Profile 的实例身份创建后不可变；编辑名称且地址不变、管理密钥留空时只更新名称，不发起网络请求。编辑地址或填写管理密钥时重新 inspection 与 enrollment：目标仍是同一实例身份才原子提交连接参数，地址变化时保留 Profile id 并轮换持久 partition；目标属于另一实例时拒绝覆盖并要求新增 Profile。管理密钥只参与本次认证，不持久化。提交新连接前的失败补偿新凭据并尽力撤销新设备；提交成功后旧设备、旧凭据与旧 partition 尽力清理。重试只连接已保存 Origin；重新认证不覆盖实例身份。

添加远程实例先规范化地址。无协议输入固定使用 HTTPS，不探测 HTTP 或静默降级；显式 `:443` / `:80` 使用对应标准端口，只有 authority 真正省略端口时才补 4960。显式非回环 HTTP 在任何 descriptor、challenge、enrollment、管理密钥或设备凭据网络 I/O 前进入可信确认页，明确显示：“HTTP 连接未加密。管理密钥和设备凭据可能在传输途中被截获或篡改。”取消确认返回原表单并保留草稿；地址编辑使旧确认失效；继续只授权当前添加流程中的同一规范化 Origin，主进程再次核对确认值后才开始 inspection。loopback HTTP 不显示该确认。

inspection 读取实例描述和协议版本，并在产生设备副作用前拒绝已知 Origin 或实例身份。Server 对 loopback HTTP 与固定 SPKI HTTPS 继续发布 protocol 1 descriptor，使只理解 protocol 1 的旧 Desktop 仍能解析并连接；protocol 2 只用于 `explicit-http-v1`，旧 Desktop 会按不兼容安全拒绝。HTTPS 首次观察 TLS/SPKI 后，descriptor、challenge、enrollment、session 与 revoke 的每个独立 HTTPS socket 都必须在发送请求正文或接受响应数据前验证同一 SPKI，不能把一次观察结果用于放行未验证的新连接。配置管理密钥的实例确认唯一后才完成 HMAC challenge 与设备 enrollment。未配置管理密钥的 loopback HTTP 实例只提交 Profile，不伪造密钥、设备或 TLS 身份。显式非回环 HTTP 使用 `transport = explicit-http-v1` 与 `managementProtocol = 2`，挑战使用独立 proof domain；该协议只做身份与重放结构化，不提供机密性、完整性或抗中间人保证。enrollment 后才提交本地 Credential Vault 和 Profile；任一阶段失败时不发布新 Profile，并在当前进程内清理已写入的新凭据、尽力用新设备凭据撤销远端 enrollment。实例变更 IPC 串行执行，Profile Store 与 Credential Vault 的 durable write 也各自串行并在写入失败时回滚内存状态。该补偿不构成跨进程事务日志；进程在 enrollment 后立即崩溃时仍可能留下可由服务器设备管理清理的孤立设备。

每个 HTTPS 远程 partition 固定服务器 SPKI SHA-256。首次配对由主进程临时读取实际 TLS 证书并完成 HMAC 证明；后续 Chromium 证书回调只接受相同 host 与固定 SPKI。公钥变化要求针对原地址和原实例身份重新认证；实例身份变化拒绝重新认证并要求添加新实例，二者都不会静默覆盖。所有远程 `Session.fetch` 都使用 `redirect: error` 并校验响应最终 URL 等于请求 URL；设备 Secret、Cookie 和 CSRF 不跟随 3xx。Product View 同时拦截跨 Origin `will-navigate` 与 `will-redirect`，并在 `loadURL` 后复核最终 Origin。Overlay View 只允许安装包内精确 renderer file URL，Fallback View 只允许当前 data 恢复页和被主进程拦截消费的固定 `nxt-desktop` 动作；加载后再次核对精确 URL。每次 Fallback load 的 token 同时绑定 URL、Profile id 与 action map，只有最新 token 能断言成功、处理失败或执行动作；导航 guard 在动作前还要求当前 WebContents 与 mainFrame URL 都等于该 token URL。Overlay 每次 main-frame document navigation 递增 document generation，`dom-ready`、`did-finish-load` 与首次 load Promise 共享幂等门：可信同页 reload 在打开时恢复一次当前 intent，关闭时不发送，其他 URL 直接丢弃 View。Overlay IPC 在 sender id 之外还要求 `senderFrame === sender.mainFrame`，且 frame 与 WebContents URL 都等于可信 renderer URL。loopback HTTP Profile 不设置证书回调或设备会话，只接受 Server 声明的 `loopback-http` transport。显式远程 HTTP Profile 在列表中显示 `http://`，切换继续使用已确认并保存的 Origin；重新认证再次显示同一未加密风险确认。

本地 Profile 健康状态只由 Host 生命周期提交：相同 `releaseId` 的初始就绪和恢复写入 `ready`，自动重启窗口写入 `unstable`，恢复预算耗尽写入 `offline`；成功 Product 导航或手工重试也可重新确认 `ready`。Host 回调先写入主进程 relay，再由 relay 向已经构造且未 dispose 的实例管理器投递，因此构造与销毁窗口中的事件不会丢失或访问失效对象。通知轮询不得写本地健康。

远程 Profile 使用单一串行监视循环。一轮依次完成远程健康与设备会话检查，再按通知开关读取通知；整轮结束后才安排下一次 5 秒调度，不存在重叠 `setInterval`。monitor 取消和单轮总超时贯穿 health、TLS/SPKI、descriptor、management session GET/POST；stop 后当前轮能够 settle，单个挂起请求超时后继续后续 Profile。轮次顶层捕获 getTargets、commit 等意外 callback throw，诊断回调本身也被隔离；除 stop/abort 外仍安排下一轮，不产生 unhandled rejection。每个目标携带 Profile generation；切换、修改、重新认证、移除和 dispose 都使旧 generation 失效，迟到健康或通知结果不能提交。当前切换中的 Profile 不进入后台检查，成功 `loadURL` 与同源复核是当前页面的较新提交点。健康状态和通知流是两个独立结果：通知 endpoint、HTTP、JSON、游标或授权失败只丢弃通知游标并记录诊断，不覆盖已经提交的健康状态。新 Desktop 的 Profile 列表 Snapshot 与 Product 当前实例展示共享单调 revision，内容未改变时不发事件；frozen desktop chrome protocol 1 的旧桥允许省略 revision，legacy subscription 按到达顺序提交，任何迟到 initial Promise 都不能覆盖已经接受的订阅事件。

服务离线、恢复和设备会话失效由 Desktop 根据远程健康生成；产品功能通知由 Server 写入短暂的脱敏客户端通知流。Desktop 第一次连通时只建立当前游标，之后通过该 Profile 的 Session 读取新事件并生成系统通知；断线或通知读取失败会丢弃游标，因此服务器部署实例没有在线远程 Desktop 时不积压系统通知。远程读取复用已配对设备 Session 和同源代理，不新增管理密钥、跨域接口或 Product View 通知权限。点击通知只打开协议白名单内产品相对路由。Bark 等 Server 直推渠道不依赖 Desktop 在线。

## Server 安全入口

开发与 Desktop 自带本地 Host 继续使用随机 loopback HTTP，并公开无凭据的实例描述，使同一设备上的 Desktop 可将其作为无管理密钥实例添加。Server 在创建数据目录和 Runtime 前按实际监听 host 检查 loopback；`0.0.0.0`、`::`、LAN IP 和其他非回环 host 缺少管理密钥时均拒绝启动，不能只依赖 CLI 的精确字符串分支。公开监听必须提供至少 32 个字符的 `NEKRO_MANAGEMENT_KEY`。配置后的管理密钥只保留在进程与配对 HMAC 计算中，数据库只保存带域分隔的摘要，用于识别密钥轮换。轮换会撤销全部旧设备。Desktop 支持显式远程 HTTP 不改变 Server 的安全默认监听门禁；需要该 transport 的部署必须由明确声明 protocol 2 的兼容安全入口提供。

安全入口在同一进程中监听外部 TLS，并把已认证请求代理到随机 loopback DSH WebServer。首次启动在 `/data/host/tls/` 生成 EC P-256 自签名证书和私钥；容器重启复用同一身份。Desktop 表单接受 `host[:port]`、`https://host[:port]` 和显式 `http://host[:port]`；省略协议时使用 HTTPS，不进行静默协议降级。管理密钥是可选输入，只有实例描述要求配对认证时才参与配对。

配对协议使用一次性 60 秒 challenge：Server nonce、Client nonce、实例 ID 与实际 SPKI 进入 `HMAC-SHA-256` proof。管理密钥不进入请求正文。安全入口最多保留 256 个未过期 challenge，同一来源地址每分钟最多请求 10 个，超限返回 `429 pairing_rate_limited`。验证成功后 Server 签发随机设备 Secret，只保存带域分隔的 Secret 摘要。Desktop 用设备 Secret 换取 12 小时 Secure、HttpOnly、SameSite=Strict Session Cookie 与独立 CSRF Token。

匿名入口只有：

- `GET|HEAD /health/live`；
- `GET|HEAD /health/ready`；
- `GET|HEAD /.well-known/nekro-nxt`；
- `POST /api/management/pairing/challenge`；
- `POST /api/management/devices/enroll`；
- `POST /api/management/session`。

其余静态资源、SPA、REST、SSE、Asset、Extension Client 模块与 RPC 默认要求有效设备 Session。非安全方法同时校验 Session、同源 `Origin`/`Host`、CSRF Cookie 与 `X-Nxt-Csrf`。安全入口不发布通用 CORS。

反向代理同时拥有下游请求、上游请求和外部 socket：浏览器断开时立即销毁对应上游，SSE 上游中断时关闭下游；Server 关闭时拒绝新代理、取消全部上游、关闭空闲连接，并在五秒边界后强制销毁剩余 socket。重复调用 `stop()` 等待同一个关闭 Promise，活跃事件流不能让进程关机永久等待。

实例身份、管理密钥摘要和配对设备保存在 `core.sqlite`；证书属于 `/data/host/tls/`。移除 Desktop Profile 会清除对应 partition 与本机 Secret，并尽力撤销 Server 设备；远程 establish、management GET 与 DELETE 使用同一个总时限 AbortSignal，任何 timeout/abort/网络错误都被撤销边界吸收并继续本地清理，不能长期占用实例变更串行队列。远程实例的数据不属于 Desktop Profile 删除范围。

## 界面

Desktop 模式在左侧图标轨底部把“服务实例”放在主题按钮下方。主题与服务实例按钮显示完整无障碍名称但不渲染文字 Tooltip；服务实例按钮同时显示当前实例状态，普通浏览器不渲染该入口。打开后，独立可信 Overlay View 覆盖 48px 顶栏以下的完整窗口正文，透明 scrim 明确遮挡关系并承接外部点击；左下角 Sheet 宽 420px、最大高 560px，与图标轨右边缘对齐。本地实例固定第一项，远程实例按添加顺序排列，标题和底部添加操作固定，列表独立滚动。普通打开只聚焦无描边 Dialog 表面，当前实例的选中底与勾选是唯一初始行状态。Trusted Fallback 本身是带相同 48px 安全区、NekroNXT 身份、实例名称/地址/状态、失败原因和恢复动作的完整本地页面；正常切换不显示“可信恢复”等内部术语，远程失败把“返回本地实例”作为主动作，重试和管理服务实例保持次级，不再同时显示空工程画布与独立小卡片。

实例行显示名称、此设备或带显式 `http://` 的未加密地址、明确状态与当前勾选。主实例按钮与更多操作按钮是相邻的原生按钮，不嵌套可聚焦控件；实例列表使用 `ul/li` 语义，操作菜单绝对定位于列表上层，声明 `aria-haspopup`、`aria-expanded` 与 menu 关系，点击菜单外立即关闭，并支持原生 Enter/Space、菜单方向键、Escape 与封闭 Tab 顺序。Fallback 的“重新认证”携带当前 Profile intent，可信 Overlay 打开后直接进入该 Profile 的空密钥表单并聚焦输入框；关闭或返回清除密钥，不经过通用列表二次选择。Backdrop 或 Escape 在表单/风险确认中返回列表并清除敏感草稿，在列表中关闭 Sheet；鼠标关闭只恢复所属 View 的输入焦点，Escape 关闭再把控件焦点还给 Product 服务实例按钮或 Fallback 对应操作，避免错误触发 Tooltip。可信 Sheet 以按钮侧左下角为变换原点，进入使用 160ms opacity/scale/位移，退出沿原路径使用 100ms；退出结束后主进程才摘除 View，减少动效时降为 1ms。窗口在 `close` 阶段先幂等注销该 manager 记录的全部 IPC handle 与精确 event listener，再清空解密运行时凭据及 cursor/availability/status/generation 等内存状态，最后释放 View；不得移除其他模块的同通道 listener，同进程重建 manager 不得发生 handle 冲突。所有 detach/close 都检查已销毁状态，`before-quit` 与窗口事件重复调用不会访问已销毁对象。远程实例提供重新连接、编辑名称与地址、系统通知开关、重新认证和移除；编辑连接表单包含显示名称、完整服务器地址和可选管理密钥，拒绝未知 scheme、账号密码、路径、query 与 fragment。只改名称且密钥留空时不联网；地址或认证字段变化时执行同身份迁移。Snapshot 更新在 add/edit/reauth/HTTP 风险表单中只更新内存，目标仍存在时不得替换 DOM 节点、焦点、选区、光标或输入法组合态；列表状态使用原位 patch，结构变化时按控件身份恢复焦点。提交期间主按钮禁用；duplicate、地址校验、认证和网络错误都保留显示名称、地址与管理密钥草稿。pending 期间取消、Backdrop 或 Escape 会递增请求代际、清空 busy 与本地 Secret，并忽略迟到的 resolve/reject，不能复活已丢弃草稿。实例操作错误在主进程可信 IPC 边界序列化为稳定错误码与简洁用户原因；协议版本、transport、实例身份和 TLS 身份使用稳定可行动码，未知输入使用安全通用原因，Electron channel、method、重复 `Error:` 与堆栈不进入 Sheet。

Desktop 在每次 Product View `dom-ready` 后注入当前平台窗口安全区：macOS 左侧 84px，Windows/Linux 右侧 138px。远程与本地页面使用同一 48px 顶栏和导航外壳，页面不按 user agent 推测窗口控件位置。

## 不在此决定内

- 跨实例数据同步或统一智能体/频道列表；
- 自动故障转移；
- 本地目录绑定、文件传输、远程挂载或通用系统能力 Bridge；
- 社区账号与中心控制面；
- Extension Client 直接调用系统通知。

## 验证

Server 测试覆盖匿名拒绝、HMAC 配对、challenge 重放与限流、Session、CSRF、代理业务请求、下游断开取消 SSE 上游、有活跃事件流的有界关闭、设备撤销、keyless 非回环启动前拒绝，以及真实 loopback/TLS descriptor 继续通过冻结的旧 Desktop protocol-1 严格 schema。Desktop 单元测试覆盖地址与标准端口规范化、重复 Origin/实例身份、同身份迁址、不同身份拒绝、partition 轮换、连接编辑补偿、不可变身份、双证书切换、重定向不转发凭据、可信 Overlay/Fallback navigation guard、顶层 frame/精确 URL IPC 校验、远程探测取消与挂起超时、全部 generation 变更原因、Host 生命周期映射、串行远程检查、stale generation 拒绝、通知失败不改健康、单调及 legacy revision 顺序、真实生产 bring-to-front helper、Trusted Fallback 错误码、主题与动作。真实 Chromium DOM 测试覆盖 add/edit/reauth 输入节点、光标、选区和组合态跨 Snapshot 保持，编辑连接 payload、`saved:false`、菜单外关闭与 viewport 定位、连续指针区域、紧凑高度、Fallback reauth intent 直达与密钥清理、列表状态原位更新、Backdrop/Escape/Tab、HTTP 风险确认和 pending 取消/迟到结果代际。静态运行时契约要求 Electron 精确锁定 `42.9.0`、lockfile 一致且不出现在依赖年龄排除项中。

生产 Web 旅程继续证明普通浏览器不显示 Desktop 实例入口，并覆盖 revision 与 protocol-1 legacy shape 的 initial/subscription 顺序。现有 12 张证据只是 Chromium 组合画面/DOM 验收：覆盖浅色/深色、980×680/1360×880 的 Fallback 单独显示、Sheet over Product 与 Sheet over Fallback，不代表真实跨 View 自动化。尚未完成的原生 Electron 产品旅程必须在真实打包 macOS BrowserWindow 中，以真实指针验证跨 `WebContentsView` 的最终导航阻断、命中测试、原生焦点回交、多 partition 与完整 View 替换、平台窗口控件安全区及通知回跳；另需验证添加重复实例不会产生设备、原实例身份变化时重新认证提示新增实例且旧 Profile 重启后仍可选。跨进程 enrollment 崩溃恢复不属于当前承诺，也没有事务日志。
