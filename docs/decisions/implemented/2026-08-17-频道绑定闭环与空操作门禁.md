# 已实施：频道绑定闭环与空操作门禁

状态：implemented

## 问题

智能体管理页的“新增频道绑定”曾是没有 `onClick` 的占位按钮。Server 快照同时只枚举本地 Web Connection 的频道，即使 QQ Gateway 已发现频道，页面也无法建立 Binding。原有产品旅程只确认路由和主要文案可见，没有点击该按钮或验证数据库外部结果。

进一步验证还发现 Radix Select 弹层层级低于 Dialog 遮罩，选项虽然存在但无法点击。项目中另有多处外观看似可用、实际没有处理器的按钮，说明这是空操作缺少门禁，而不是单点遗漏。

## 决定

- Server 快照枚举所有 Connection 的 Channel，并为每个 Channel 投影完整 Binding 列表，不再只保留第一个智能体关系；
- 新增 `POST /api/bindings`，保存 `{agentId, channelId, triggerPolicy}`，继续使用 Core 已有的唯一 `(channelId, agentId)` 和多智能体 Binding 语义；
- 智能体频道页展示当前 Binding，新增流程选择已发现频道与四种触发策略；外部连接没有已发现频道时明确说明先让机器人账号收到消息；
- Select/Tooltip Portal 层级高于 Dialog 遮罩，保证对话框内下拉可操作；
- 未实现入口永久禁用并标注“尚未开放”；新增 `check:ui-actions`，拒绝没有处理器、submit 语义或永久禁用的产品按钮。

## 验证

- Server 真实 HTTP 测试创建第二个智能体并给同一频道增加 `observe-only` Binding，再从快照核对智能体频道列表和 Channel Binding 列表；
- Web Host 测试断言 `bindings.create` 的真实请求体与刷新；
- 生产 Playwright 旅程经 UI 创建两个智能体，打开频道 Tab，选择另一个频道与“仅观察”，提交后重新读取 `/api/snapshot` 证明 Binding 已持久化；
- 旅程实际打开 Radix Select 并点击 Portal 选项，覆盖此前遮罩拦截问题；
- 常驻数据中 QQ Connection 尚无 Channel 时，页面会显示可操作弹窗和频道发现说明。

## 未来方向与参考取舍

关联方向：同频道多个智能体、更多 Adapter 和 Binding 触发策略。

保留接缝：Channel/Binding 分离、显式 `agentId`、每条 Binding 独立触发策略、全量 Connection Channel 目录。没有把 QQ 群号写进 Binding，也没有恢复一频道一智能体限制，因此不锁死未来多智能体仲裁。

本次明确不实现：Binding 编辑/删除、多智能体仲裁 UI、手工伪造尚未被平台发现的 Channel、后台主动拉取 QQ 群目录。QQ Channel 仍由真实 Gateway 事件发现。

参考本仓 Channel Runtime Decision 与 Core 已实现的多 Binding 调度；借鉴稳定 Channel ID 和触发策略归属，拒绝前端假绑定、直接输入平台群号或用可点击占位按钮冒充完成。
