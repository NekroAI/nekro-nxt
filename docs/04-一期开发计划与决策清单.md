# NekroNxt 一期开发计划与决策清单

> 文档编号：04
> 性质：一期进度与现行技术选择
> 目标：用两条真实闭环验收一期，不按页面数量或 Adapter 数量验收

## 1. 一期闭环

### 闭环 A：智能体、Web Channel 与本地扩展

```text
创建智能体和首个配置版本
→ 自动创建 Web Channel 与 Binding
→ 通过 DSH 运行并只用通信工具回复
→ 同一智能体启用创造能力
→ 定义、运行、验证动态 Tool/Client UI
→ 保存为本地 Extension Revision
→ 明确启用给该智能体
→ 重启恢复、停用和回退
```

### 闭环 B：QQ OpenClaw 群聊

```text
创建 QQ Connection
→ 发现/产生 QQ Channel
→ 建立 Binding
→ 分别测试接收和发送
→ 群消息可靠入库
→ @、引用或策略触发智能体
→ Tool 运行期间新消息安全注入
→ 通信工具发送文字、Mention、媒体和引用
→ 展示真实平台回执与失败
```

Desktop 安装包和 Server 单容器在核心 Runtime 稳定后作为 M7 交付，不阻塞这两条闭环的产品验收。

## 3. 现行技术选择

| 主题 | 现行选择 |
|---|---|
| DSH | lockfile 冻结的精确 npm 包，当前 `0.1.1-rc.1` |
| Node / pnpm | `^22.19 \|\| >=24`，pnpm `11.7.0` |
| 前端 | React 18.3.1 singleton、React Router 7、Radix + CSS Modules + `--nxt-*` Token、空间动效 `motion/react`（仅 ui-kit 导入） |
| API Host | 复用 DSH WebServer / SSE / 静态托管，领域 API 由 NekroNxt 定义 |
| 数据库 | Core：`better-sqlite3` + Drizzle；DSH Session：DSH 自有 SQLite |
| Revision | ULID 身份 + 内容 digest |
| 扩展持久化 | 不可变源码 Revision + 可重建构建缓存；只允许 SDK 与宿主内置依赖 |
| 动态作用域 | 目标智能体独立 Scope |
| 会话 | 连续活动 Session；长时间空闲、不兼容变化、人工或不可恢复时交接 |
| 检索 | 频道分页 + `search_text` 字面子串匹配 |
| 图片 | 内容寻址原件 + 按模型能力原生投影；`asset_inspect` / `asset_view_image` |
| QQ | Connection 单账号、WebSocket；通信工具只用 `memberId`；视频作为普通 file |
| Adapter 配置 | 版本化 JSON Schema 子集 + 可选 Slot |

## 4. 一期完成标准

- 两条闭环均可从产品界面完成，普通用户不需要终端；
- 智能体自己的用户可见发言只来自 `send_channel_message`；管理员从网页以机器人账号发到外部频道会记入频道事实并注入系统来源；
- Channel、Session、内部模型输出和平台发送事实分离；
- 工具期间新消息不取消当前 Tool；
- 动态创造、开发 Shell、完整文件访问分别授权；
- 动态运行、保存 Revision、启用 Activation 分离；
- QQ Mention、引用、媒体、重放和失败状态有真实平台证据；
- 相同媒体只保存一个物理 blob；视频作为普通文件不丢失；
- Desktop 与 Server 共用 Runtime 和数据格式；
- 坏扩展和失败迁移可恢复启动；
- 根 `pnpm check` / `pnpm test` / `pnpm build` 覆盖相关路径。

## 5. UI 整改执行契约

当前 UI 已具备四个一级模式、对象列、频道会话、智能体工作台、连接任务、扩展与创造页面，并有生产构建浏览器旅程。整改按风险和依赖顺序推进，目标不是重做页面，而是让现有界面满足交互、文案、可访问性和交付证据要求。

| 顺序 | 当前整改面 | 完成条件 |
|---|---|---|
| 1 | 全仓交付门禁与危险操作 | 根类型检查恢复；清除 DSH 凭据必须经过明确危险确认，覆盖 pending、防连点、失败恢复、成功反馈和焦点返回 |
| 2 | 频道会话与工作轨迹 | 运行中工具行不存在空操作；会话 / 工作轨迹使用完整 Tab 语义；轨迹记录可由键盘选择；管理员从网页向外部频道发言时校验绑定与主动发送授权，明确标记来源并展示真实回执和失败 |
| 3 | 工作树桌面操作 | 排序、绑定、换绑和解绑具备键盘路径，并为拖放提供按钮或菜单替代；失败后恢复 Host 权威顺序 |
| 4 | 桌面外壳与辅助显示 | 对象列和检查器按规范可调整、持久化和恢复默认；窄窗口优先收起检查器；提供减少透明效果和高对比降级；所有禁用操作说明缺少的前置条件 |
| 5 | 文案、默认值与静态门禁 | 普通产品外壳只使用“智能体”“扩展”“动态包”等现行术语；创建智能体的所有入口生成同一份默认 Draft；术语和空操作门禁覆盖本轮发现的间接漏检 |
| 6 | 生产旅程与视觉验收 | 生产构建覆盖关键 mutation 的 pending / 成功 / 失败、外部频道管理员发言、键盘操作、1100 / 1440 / 1920 三档视口、双主题、125% / 150% 缩放、Reduced Motion、减少透明、高对比、长文案、空态和错误态 |

当前执行状态：第 1–6 项均已完成对应窄测试、生产构建旅程和截图视觉复核；本节末尾四条根命令全部通过。

每个整改面在同一提交中维护对应权威文档。实现期间优先运行最窄测试；进入下一整改面前，当前范围的类型检查和真实浏览器旅程必须通过。全部完成时统一运行：

```text
pnpm check
pnpm test
pnpm build
pnpm test:journey
```

最后确认现有开发服务的 Web 首页和 Server `/api/snapshot` 均返回 200，并按 `06` §5.1 对本轮真实产品画面做源码之外的独立视觉验收。任何一项失败都保持本节对应整改面未完成，不以其余测试通过替代。

## 6. 范围

关联尚未启动的方向：更多 Adapter、频道解绑与批量管理、Process/Remote Runtime、社区市场、多设备同步、长期 Job。

当前不提前实现：社区市场、签名、SBOM、任意 npm 供应链、Process/Remote Runtime、多智能体仲裁、Webhook、跨频道发送、原生音频/视频理解、向量记忆、基于上下文压力的 rollover。
