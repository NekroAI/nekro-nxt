# 适配器 Host 贡献、产品 Slot 与富消息

状态：implemented

本文是当前 Adapter Host Revision、Registry、安装生命周期、富消息 Slot 和可选 Host Page 的现行契约。扫码/OAuth 与登录会话尚未开放。

## 0. 目标

让新聊天平台（含扫码登录、卡片消息）只需安装或更新适配器包即可工作；应用本体只保留领域、通用向导、Slot 宿主和凭据。市场是同一套本地扩展的分发层，首期不建设。

艾特已按公共 `mention` 切分并内联，不纳入本改造。

## 1. 当前实现复核

当前实现由统一 Adapter Registry 和 Host Installation 协调器拥有。

### 1.1 已经成立

- 公共 `MessagePart` 闭集：`text` / `mention` / `image` / `file` / `audio` / `quote`。
- QQ 入站按原文位置切 `mention`，机器人账号写入 `mention` part，并保留 `facts.mentionedBot`。
- 频道页把连续 `text`+`mention` 内联；`mentionedConnectionAccount` 不再画成前缀。
- 连接创建向导先选平台，再按 `configSchema` 渲染字符串、数字、布尔和凭据槽。
- 扩展有 Host/Client 两半、不可变 Revision、智能体 Activation；Client 使用 DSH `SlotCore`。
- DSH 设置与动态创造使用**独立** SlotRegistry，因为 Host 只能直接 `renderSlot('root')`。

### 1.2 当前边界

| 位置 | 现状 |
|---|---|
| Adapter 安装来源 | 内置 Web、QQ OpenClaw、OneBot 11、企业微信由组合根注册；已验证的本地 Manifest V3 Revision 可安装、更新、回滚和卸载 |
| 连接扩展区 | `connection.adapter.setup/status/test` 已开放类型化 keyed Slot；Schema 表单和通用诊断始终保留 fallback |
| 频道扩展区 | `channel.inspector.adapter.sections` 位于运行与绑定信息之间 |
| setup / 登录会话 | 仍使用 schema 表单；扫码、OAuth 登录会话 API 尚未实现 |
| QQ Adapter Host Service | QQ 已获得通用 Context，但其旧协议实现仍保留产品桥接层，尚未完全改写为 SDK Host Service |
| 产品壳 | `conversation.message.rich`、连接和频道检查器使用全局 Adapter Slot Runtime；Composer 和顶栏不接受任意 React Slot |

### 1.3 保留但未开放的接缝

- 尚无登录会话 Host API，扫码和 OAuth 不进入当前创建路径。
- 登录会话仍由未来的类型化 Contribution 承载；当前 setup Slot 可以增强 Schema 创建流程，但不能移除宿主 fallback 或直接读取 Credential。
- 内置 QQ 仍保留协议桥接实现，但创建、恢复、测试、停止和目录投影不再拥有平台分支。

## 2. 目标契约

### 2.1 两层分离

| 层 | 所有者 | 卸载适配器之后 |
|---|---|---|
| Channel `parts`（含必填兜底字段） | Core，持久化 | 历史仍可读，宿主 fallback 仍能画 |
| 产品 Slot 上的 React 贡献 | Web Client，可撤销 | 槽空了，自动 fallback |

Slot 名和 React 不进 `ChannelEvent`。智能体上下文和 `search_text` 不读取 Slot，不倾倒 `extension` JSON。

### 2.2 富消息公共块

在 `MessagePart` 联合上增加（名称以落地 schema 为准）：

```ts
{
  type: 'rich'
  adapterKey: string
  kind: string              // 适配器短名，Core 不当枚举
  summary: string           // 必填：UI / 模型 / 检索 / 卸载后的兜底
  title?: string
  source?: string
  targetUrl?: string       // 只允许 HTTP(S) 用户导航目标
  previewAssetId?: string
  extension?: JsonValue     // 可选、限大小；只给适配器渲染器
}
```

规则：

- 预览图 / logo 必须先导入 Asset，禁止把媒体临时 URL 写入 parts 或 `<img src>`；平台明确提供的卡片导航目标可以写入 `targetUrl`，但只接受 HTTP(S)，不得用封面 URL 猜测。
- `extension` 只允许 JSON，设字节上限；禁止持久化完整 Gateway 事件。
- 入站 Adapter 按原文位置把 Mention 编进 `parts`（已落地）；卡片/小程序/转发编成 `rich`，不得再压成字段流水账 `text`。
- `facts` 只保留触发与策略（`mentionedBot`、`replyToBot`、`targetKind`），不放展示载荷。
- 模型投影使用 `summary`（及 title/source）；`search_text` 纳入 `text` 与 `rich.summary`。
- 出站仍走现有 `send_channel_message` 词汇。平台特有发送用适配器额外工具，不在本计划展开交互式卡片。

转发聊天记录首期只做 `kind: 'forward'` + summary（条数、首条）。嵌套整棵消息树另立项。

### 2.3 产品 Slot：复用 DSH 机制，不复用 DSH 页面坑位

使用 DSH `SlotCore` 的声明、kind、fallback、可撤销注册。产品壳是**自己的** root 贡献者。不把 DSH 官方应用的侧栏 / Composer 槽接到本产品。

产品 SlotCore 与 DSH 设置岛、动态创造岛分离，避免抢同一个 `root`。

当前 Adapter Catalog 声明以下真实宿主槽；未声明的名称和 id 不匹配会失败：

| 槽 | kind | owner 要点 | fallback |
|---|---|---|---|
| `conversation.message.rich` | keyed，`entryKey = adapterKey:kind` | `part`、`channelId`、`messageId` | 宿主小卡片（summary/title/source/preview） |
| `connection.adapter.setup` | keyed，`id = adapterKey` | 创建草稿、受控字段更新和 Schema fallback 状态 | 宿主 Schema 表单 |
| `connection.adapter.status` | keyed，`id = adapterKey` | Connection 摘要和裁剪诊断 | 通用状态区 |
| `connection.adapter.test` | keyed，`id = adapterKey` | 收发测试投影和受控动作 | 通用测试区 |
| `channel.inspector.adapter.sections` | keyed，`id = adapterKey` | 频道、Connection 和 Adapter 状态投影 | 不追加 Adapter 专属区块 |

Host Adapter Client 在全局运行时注册这些 key。加载失败、组件异常、卸载或没有贡献时恢复对应宿主 fallback。组件使用 `--nxt-*` Token，禁止 raw HTML、全局 DOM、Secret 和平台原始事件。

智能体扩展已经声明并拥有真实消费者：

```text
agent.workbench.sections      list
extension.activation.panels  list
channel.inspector.agent.sections list
conversation.tool.card       keyed by Tool name
```

`agent.workbench.sections` 位于“可用扩展”之后、“危险操作”之前；`extension.activation.panels` 位于扩展详情“使用范围”之后且在用户选定 active Activation 后显示；旧 `extension.details.panels` 作为兼容映射。频道检查器 Slot 位于“运行”和“绑定”之间，Tool 卡片同时用于会话工作流和工作轨迹。Props、生命周期和 fallback 以 `packages/extension-sdk/README.md` 与 `NEKRO_NXT_EXTENSION_AUTHORING_REFERENCE` 为现行契约。

仍保留但不打洞（无消费者不声明）：

```text
channel.binding.hints           list
conversation.composer.trailing list
conversation.header.actions     list
```

扩展不能向图标轨注册任意 React。带 `host-page` 的已安装 Adapter Revision 由 Host UI 页面目录生成独立侧栏入口，并使用声明式对象列或全宽画布。系统对象列、顶栏、整页 `connection.page`、整条会话画布和 `single` 替换 Composer 不开放。

对齐用**槽位名字**表达（`shell.topbar.end`、`conversation.composer.trailing`），不发明通用 `align` 参数。

### 2.4 连接管理页仍是宿主页

页面对象是 Connection，不是 Adapter 包。

宿主拥有：对象列、标题、状态、添加连接、产品进度（连接账号 → 发现频道 → 绑定智能体）、别名、绑定智能体、空态、向导外壳（选平台、别名）。

消灭 `adapterKey === 'web' | 'qq-openclaw'` 的页面/API 特权。改为描述符能力，例如：

- `userCreatable`
- 是否系统托管
- 是否有凭据槽 / 是否允许别名
- 是否提供收发诊断
- 创建方式：`schema`（默认）或 `slot`（扫码/OAuth）

内置频道：系统托管、不可创建、无凭据、无平台诊断。用标记关掉对应区块，不注册管理 Slot。

层级保持：

1. 无 `AdapterContribution` → 不出现在添加连接；
2. 有 schema → 通用表单覆盖完整配置闭环；
3. 可选 Client 槽增强 setup/status/test，**不能**取消 schema 闭环，也不能改变 Connection / Channel / Binding / Credential 语义。

### 2.5 登录会话是宿主协议

扫码、OAuth 对壳只是登录会话，不是新页面类型。

```text
adapter.login.start   → { loginId, display: 'qr' | 'oauth' | 'other', payload }
adapter.login.poll    → pending | succeeded | failed | expired
adapter.login.cancel
成功 → 凭据 API 写入 → 通用 create Connection
```

Client 只通过 `host.call` 调上述方法。适配器 Host 运行时对接平台。禁止适配器私开任意 HTTP 作为创建入口。

### 2.6 适配器作用域与加载

| 贡献 | 作用域 | 装上之后 |
|---|---|---|
| `AdapterContribution` + 适配器 Client | **宿主** | 本机多一个可创建平台；频道页/连接页能画它的 Slot |
| Tool / 智能体 Client | **智能体 Activation** | 只有启用了的智能体才有 |

创建、挂载、恢复、测试按已安装贡献的 `key` 分派到 `create(context, config)`，不再 `#mountQQ`。

内置 `web` 与首个 `qq-openclaw` 仍可打进宿主包，但必须走同一目录与同一分派，不能保留特权分支。第三方适配器以扩展 Revision 的 Host/Client 入口加载。

适配器 Client 随已安装 Adapter 挂载，**不**跟 Binding 走。未绑定智能体时，连接诊断和群内卡片仍要能看。

### 2.7 市场

首期不建设市场、签名、SBOM、任意 npm 供应链。保留接缝：

- 适配器是带 `AdapterContribution` 的扩展 Revision，与本地保存格式相同；
- 市场只增加「把 Revision 装进本机」的来源；
- 安装适配器 ≠ 给所有智能体启用工具；
- 需要 Host 适配器 API 版本或能力清单；旧壳装新包必须明确失败；
- 适配器在 Desktop/Server 进程内运行，市场包视为受信任本地代码。隔离是未来 Process Runtime，不是 Slot。

验收「只更新适配器就能用」：

1. 安装或更新该扩展 Revision；
2. 「添加连接」出现其 `displayName`；
3. schema 或 setup Slot 完成创建；
4. 不改 `apps/web` / `apps/server` 的平台分支；
5. 卸载后目录消失；已有频道历史仍在，Slot 退回 fallback。

## 3. 明确不做

- 穷举 QQ Ark/小程序/转发的全部协议；
- 交互式按钮卡片、嵌套转发树；
- 把 DSH 官方壳槽接到对象列或 Composer；
- 为顶栏、系统对象列或 Composer 预打空洞；
- 给每个 `text`/`mention`/`image` 挂扩展袋；
- 在 `facts` 或 Slot 名里存展示内容；
- 本计划内做社区市场与扫码微信（或任一第二平台）的完整实现；第二平台只作为接缝验收的假想消费者。

## 4. 阶段与完成条件

每阶段必须：相关测试、用户可见则生产旅程、现行文档现在时回写、已有 `pnpm dev` 则确认 4961 与 `/api/snapshot` 仍为 200。不在子目录建 Git 仓库。阶段内不引入无消费者的空槽。

### 阶段 A — 富消息事实（可独立入库）

范围：`contracts`、`core` search_text、快照、QQ 入站识别、频道页宿主卡片、模型投影。

完成条件：

- `MessagePart` 含 `rich`；未知 `kind` 仍能持久化。
- QQ 将可解析的小程序/卡片/转发编成 `rich`（至少 summary；能进口的预览进 Asset）；不再把字段名写入 `text`。
- 无 Client 渲染器时后台画宿主卡片；智能体看到 summary。
- 空消息 fallback 不再硬编码「QQ」。
- 契约与 QQ inbound 测试；频道页视觉复核。

### 阶段 B — 产品 Slot 宿主 + 消息 keyed 槽

范围：产品 SlotMap / 独立 SlotCore；壳 root 声明 Catalog 中的 Adapter Slot；`MessageContent` 对 `rich` 走 keyed `renderSlot`，连接页和频道检查器消费对应 Adapter key。

完成条件：

- 无注册时与阶段 A 外观一致（fallback）。
- 测试：注册、keyed 命中、未知 key、dispose 后无残留。
- 不把 DSH 设置/创造 SlotCore 与产品壳合并。

### 阶段 C — QQ 消息 Client 渲染器

范围：QQ 适配器 Client 注册 `qq-openclaw:miniapp` 等 key；随已安装 Adapter 挂载。

完成条件：

- 有结构的小程序/转发在频道页用适配器卡片；卸载或未知 kind 退回宿主卡片。
- 生产旅程覆盖有/无渲染器两条路径。
- 内置 QQ 的 Client 也走同一注册表，不在 `message-content.tsx` 写 `qq-openclaw` 分支。

### 阶段 D — 宿主去平台特权

范围：`bootstrap` 创建/挂载/恢复/测试；连接快照；连接页。

完成条件：

- 目录、创建、挂载、测试只消费已安装 `AdapterContribution` + 描述符能力。
- 连接页与快照不再用 `adapterKey === 'web'|'qq-openclaw'` 决定区块；`appId` 不再作为通用快照字段（改为 schema/status 投影）。
- 内置 web/QQ 行为对用户不变，但走同一分派。
- 添加连接仍先选平台再出表单。

### 阶段 E — 连接 status / test 槽

范围：声明 `connection.adapter.status`、`connection.adapter.test`；QQ 把 Gateway/额度/测试细节迁入贡献；宿主保留通用测试 fallback。

完成条件：

- 内置频道因能力关闭测试与账号行，不靠 key 分支。
- QQ 诊断不再散落在宿主特判里。

### 阶段 F — setup 槽 + 登录会话 API

范围：`connection.adapter.setup`；`adapter.login.start|poll|cancel`；向导配置步可被 Slot 替换。

完成条件：

- 契约测试用假适配器完成「选平台 → Slot 登录会话 → 凭据写入 → Connection」。
- 不实现真实第三方扫码平台；QQ 继续 schema，不强制改扫码。
- 无 setup 贡献时创建路径与现在一致。

### 阶段 G — 适配器作为 Host 级扩展贡献

范围：已安装扩展若声明 `AdapterContribution`，进入平台目录并加载 Host/Client；与智能体 Activation 解耦。

完成条件：

- 用夹具扩展（非改本体）增加一个假平台，通过阶段 F 的创建路径。
- 卸载夹具后目录与 Slot 消失，历史频道仍在。
- 不建设市场 UI、签名、远程安装。

市场若后续实现，只增加 Revision 来源，不改变本文的安装和 Host 生命周期。

## 5. 建议实现顺序与依赖

```text
A 富消息事实
 → B 产品 Slot（消息）
    → C QQ 渲染器
D 去特权（可与 A 并行，但勿再增加 adapterKey 分支）
 → E 连接 status/test
    → F setup + 登录会话
       → G Host 级扩展装配
```

A 与 D 都禁止新增平台特权分支。C 依赖 B。F 依赖 D 的通用创建。G 依赖 F。

## 7. 风险

- **进程内适配器**：市场前也要把贡献当可执行代码；文档不承诺沙箱。
- **快照形状**：去掉通用 `appId` 是破坏性投影，须同步 Web 与旅程测试。
- **Slot root**：产品壳必须自己声明子槽；漏声明等于插件无法注册。
- **历史消息**：旧卡片仍是 `text` 流水账，不迁移；只保证新入库走 `rich`。
- **并行改 UI**：连接页与 `product-pages.module.css` 正被其他工作改动；阶段 D/E 需避开或先合并。
