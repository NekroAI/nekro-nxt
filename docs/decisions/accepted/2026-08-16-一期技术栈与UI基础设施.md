# 决定：一期技术栈与 UI 基础设施

状态：accepted（当前设计基线，代码按里程碑落地）

## 目标

为 M0-M7 选择一套同时服务 Web、Electron Desktop、Server 和 Extension Client UI 的技术栈。选择必须优先满足 DSH 公共包兼容、单仓纯 TypeScript、双宿主复用、可测试和安装即用，不为了追逐新版本同时维护两套 React、状态层或 HTTP 框架。

## 当前证据

- DSH 当前要求 Node `^22.19.0 || >=24.0.0`、pnpm `11.7.0`，仓库使用 TypeScript `^6.0.3`、ESM、Vitest 4 和 tsdown；
- DSH Web 当前使用 React `^18.2.0`、Vite 6、Zustand 4、Immer、CSS Modules、`clsx`、语义 CSS Token 和 Client Slot；
- DSH UI 插件的 React peer range 是 `^18.2.0`，直接选择 React 19 会使公开包依赖契约失配；
- DSH Host 已提供基于 `node:http` 的 WebServer、FetchHandler、Typert RPC、SSE 和静态前端服务接缝；
- DSH SQLite Provider 使用 Node 内置 `node:sqlite`，无需额外 native SQLite 包；
- React/Vite/Electron/electron-builder、Radix UI、Zustand 和共享 UI Kit 均有成熟公开生态，可满足双宿主和自有设计系统需求。
- M0 实测确认 `@deepseek-ai/dsh-client-runtime` 根入口只是 Host 侧空插件，`./client` 是 DSH Client ModuleLoader 产物而非普通 Vite ESM；纯 `dsh-client-ui-slots` 可以标准导入，完整 Client Runtime 必须通过 Host roster 和官方模块加载链装配。

## 确定组合

### 工程与语言

- Node：`22.23.x`，`engines` 保持 `^22.19.0 || >=24.0.0`；
- pnpm：`11.7.x`，通过 `packageManager` 和 Corepack 固定；
- TypeScript：与验证后的 DSH package set 对齐，首选 `^6.0.3`；
- 模块：全仓 ESM，严格 TypeScript，不引入第二主力后端语言；
- Monorepo：pnpm workspace；暂不加入 Nx/Turborepo，先用 pnpm filter 和 TypeScript project references；
- 库构建：tsdown；Web 构建：Vite 6；动态 Extension 缓存构建：esbuild Spike 后固定。

理由：减少与 DSH 的编译面和消费方式差异。任务编排规模尚小，当前不需要额外 Monorepo 调度层。

### Web 与 UI

- React：`18.3.1`，全仓和动态 Client Extension 共用一个 React/ReactDOM singleton；
- 路由：React Router 7，使用普通 SPA/Data Router，不引入 SSR；
- 无障碍交互原语：Radix UI 按需安装，首批只引入实际使用的 Dialog、Alert Dialog、Dropdown Menu、Popover、Select、Tabs、Tooltip、Switch、Checkbox 和 Slot；
- 样式：CSS Modules + `clsx` + CSS Custom Properties；复杂 variants 使用 `class-variance-authority`；
- 图标：Lucide React；
- NekroNxt 自建小型 `ui-kit`，不采用完整视觉组件库；
- DSH `ui-theme/ui-primitives` 作为兼容和复用层，NekroNxt 维护 `--nxt-*` 语义 Token，并提供一处 `--dsw-*` Token 映射；
- 不使用 Tailwind/shadcn 作为一期基础，不引入 MUI、Mantine 或 Ant Design。

确定采用“Radix 交互原语 + 自有视觉层”，而不是手写 Dialog、Popover、Menu、Select 等复杂无障碍行为。CSS Modules 与 DSH 当前样式体系一致；自有 Token 则避免 NekroNxt 产品视觉被 DSH 默认界面锁死。

青蓝主题、桌面布局、基础组件状态和 Motion Token 的唯一规范见 `../../05-桌面UI与动效规范.md`。

### Client 状态与数据流

- DSH Session、Connection 和 streaming frame 在 Host roster 接通后使用 DSH Client Runtime 的对象层与 framework hooks；NekroNxt Shell 当前直接复用纯 SlotCore，不从根入口伪造 Runtime；
- Zustand 4 只保存跨组件且需要跨 remount 的 UI 状态，例如选中项、面板宽度和未提交草稿；
- React local state 保存组件私有交互；
- Core 业务事实不复制进 Zustand，不引入 Redux；
- 一期不默认加入 TanStack Query，CRUD 和实时数据优先通过 Typert Remote、SSE 和领域 Client Service 暴露；若后续出现明确的请求缓存、失效和分页复杂度，再针对非 Session 管理页引入。

这样可以避免同一份 Session/Channel 状态同时存在 DSH Runtime、Query Cache 和 Zustand 三份副本。

### 表单、Schema 与契约

- Wire、持久输入和工具参数：Zod 4；
- 普通产品表单：React Hook Form + Zod resolver；
- Adapter/Extension 声明式配置：版本化 NekroNxt JSON Schema 子集；
- JSON Schema 运行时校验：Ajv 8；UI Kit 提供受控字段 renderer，不承诺渲染任意 JSON Schema；
- Schemastery 转换器只作为开发/导入辅助，不成为持久格式或 UI 运行时依赖；
- API 优先复用 DSH Typert Remote 描述符和 Connection carrier，不额外维护一套手写 REST DTO。

Zod 与 JSON Schema 有不同所有权：Zod 负责 NekroNxt 自身 TypeScript 边界，JSON Schema 是 Extension 可序列化公共契约。两者不要求对所有高级特性双向无损转换。

### Host、API 与实时通信

- Runtime 以 Cordis/DSH Bundle 为组合根；
- HTTP 使用 DSH Host WebServer 的 route/FetchHandler 接缝和 Node 标准 Request/Response；
- RPC 使用 DSH Typert Gateway；实时事件和模型运行流使用现有 SSE/Connection carrier；
- 文件上传下载和平台 Gateway 使用各自明确路由或 Service；
- 一期 Core 不再叠加 Fastify、Hono 或 Express。未来社区后端是独立部署面，可以按其需求使用 Hono/OpenAPI。

只有 DSH WebServer 被证明无法表达 NekroNxt 必要的认证、上传或生命周期要求时，才重新评估独立 HTTP 框架；不能仅为熟悉的路由语法引入第二个服务器所有者。

### 数据库与搜索

- Core：SQLite + Drizzle ORM；
- 驱动：优先 Node 内置 `node:sqlite`，与 DSH SQLite Provider 对齐并减少 Electron native rebuild；
- Session：继续使用 DSH Session Persistence SQLite，Core 不访问其私有表；
- 搜索：SQLite FTS5 + 来源精确回读；
- 迁移：Drizzle schema 生成 migration，应用启动时受控执行；
- 首期不支持 PostgreSQL/MySQL 多方言，不加入 Redis、Qdrant 或外部搜索服务。

M0 必须先做 Drizzle `node:sqlite`、FTS5、WAL、备份和 Electron packaged runtime 的兼容 Spike；若 Drizzle 当前适配存在阻断，再降级为对 `node:sqlite` 的窄 Repository 层，而不是立刻换成 `better-sqlite3`。

### Desktop 与 Server

- Desktop：Electron，main/preload/renderer 严格分层；
- 打包：electron-builder；renderer 复用同一个 Vite Web 产物；
- IPC：只承载窗口、文件选择、Keychain、安全更新等本地宿主能力，业务调用仍走版本化 Client Service；
- Server：同一 Runtime + Web dist，Linux 单容器和一个主要 `/data`；
- 不选 Tauri：产品 Runtime 本身依赖 Node/DSH，Tauri 不会消除 Node，只会新增 Rust 宿主和双构建链。

### 测试与质量

- 单元/领域/组件：Vitest 4；
- React 组件：Testing Library + jsdom；
- Web 真实组装：Playwright；
- Adapter：Fake Gateway + Virtual Clock + 契约场景；
- 类型与 lint：TypeScript strict + ESLint flat config；
- 格式化：Prettier，只负责机械格式，不承担 lint 规则；
- 根命令收敛为 `pnpm dev/check/test/build`，按 package filter 提供窄检查。

## UI 基础方案比较

| 方案 | 组成 | 优点 | 主要问题 | 结论 |
|---|---|---|---|---|
| A | 完全沿用 DSH primitives + CSS Modules | DSH 兼容最高、依赖最少 | 产品组件覆盖有限，NekroNxt Shell 容易受上游视觉结构约束 | 作为兼容层，不作为完整产品 UI Kit |
| B | Radix primitives + CSS Modules + 自有 Token | 无障碍基础成熟、视觉可完全定制、与 DSH 样式方式一致 | 需要维护一套小型 UI Kit | 已采用 |
| C | shadcn/ui + Tailwind | 搭建页面快、生态大 | Tailwind 与 DSH CSS Modules 双体系并存，动态 Slot 样式治理复杂 | 不推荐一期 |
| D | MUI/Mantine/Ant Design | 完整组件丰富、后台页面快 | 视觉同质化、主题覆盖重、bundle 和插件 UI 协调成本高 | 不推荐 |

## 已确认的关键选择

1. UI 基础采用 Radix primitives + CSS Modules + NekroNxt 自有 Token；
2. 为兼容 DSH 公开 Client packages，一期固定 React 18.3.1，不使用 React 19；
3. Core API 首期直接扩展 DSH WebServer、Typert 和 SSE，不增加 Fastify/Hono；
4. Core 数据层采用 `node:sqlite + Drizzle`；M0 兼容 Spike 若发现 Drizzle 适配阻断，则保持 schema/repository 接口并降级为窄 `node:sqlite` Repository，不更换数据库；
5. 路由采用 React Router 7，统一 Web、Desktop deep-link、嵌套路由和未保存 Draft 离开保护。

M0 的 Client 接入边界进一步固定：NekroNxt 不直接导入 `dsh-client-web` 根 Shell，也不把 `dsh-client-runtime` 的 Host 空入口当浏览器 Runtime。先使用标准 ESM 的 SlotCore 建立自有 Shell；Server Host roster 落地时，通过 DSH Client ModuleLoader 装配 Runtime 与所需 Client 插件，并用真实页面组装测试验证。若上游未来提供标准 ESM Client Runtime，再只替换兼容层加载方式。

其余库应按首个真实消费者引入，不在初始脚手架一次安装 Monaco、图表、拖拽、Markdown、文档解析和全部 Radix package。

## 未来方向检查

关联方向：更多 Adapter、Extension Client UI、Desktop/Server 双宿主、社区后端、Process/Remote Runtime。

保留接缝：React singleton、Client Slot、版本化 Schema、Host Service、Typert Remote、标准 FetchHandler、Repository、语义 Token 和宿主能力 IPC。

避免锁死：不把 Tailwind class 写进 Extension 公共契约，不让组件直接访问 Core 数据库，不让 Electron IPC 成为业务 API，不把社区后端框架带入本地 Runtime。

本次不做：SSR、微前端、完整 UI 沙箱、Tauri/Rust 宿主、第二 HTTP 框架、外部数据库、多前端状态系统和重型 Monorepo 调度。

## 参考取舍

- DSH：参考 React 18 Client packages、对象层、Zustand/Immer、Slot、CSS Modules/Token、Typert Gateway、SSE、WebServer 和 `node:sqlite`；不复制其默认产品信息架构，也不直接修改上游 UI 包；
- Nekro Agent：只参考真实聊天交互和媒体需求，不复用 Python/Vue 历史技术栈或数据格式。
