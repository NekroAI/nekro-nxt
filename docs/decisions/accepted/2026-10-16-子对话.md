# 子对话

状态：accepted（2026-10-16 批准并实施，随 0.6.0 发布）

## 1. 起因

验证扩展候选时，宿主用频道智能体执行 `run_code` 调用候选工具，调用发生在对话轮次之外。DSH 写入 `tool/ptc-dispatch*` 记录时不检查轮次，读回时却要求它们在轮次内，于是会话被判定损坏，整个服务在启动时停在恢复状态。三个验证入口（冷启动恢复、浏览器上报、后台无头验证）都在轮次之外，问题会反复出现。

DSH 只在模型推动的轮次里执行工具，没有让宿主直接开一轮的接口。要让宿主执行的调用落在合规的轮次里，就需要一段单独的对话。

## 2. 决定

| # | 决定 |
| --- | --- |
| C1 | 新对象「子对话」（`sub_conversations`，`cnv_*`）：频道对话下的一段独立对话，是频道对话 DSH 根会话的直接子会话。它不是频道记录：没有平台、绑定与触发方式。记录所属频道与会话期、开启者（`agent` / `host`）、驱动方式（`model` / `script`）、状态、结束原因、结论，可关联创造任务 |
| C2 | 两种驱动：模型驱动由智能体的模型在其中对话；脚本驱动由宿主注册的本机「脚本模型」（`nekro-nxt-script`，不联网、按脚本依次发出工具调用）推动，调用走正常工具管线并落在子对话自己的轮次里，结果经 `tools/result` 取回 |
| C3 | 候选工具的验证改为宿主开出的脚本子对话（标题「验证 工具名」），结束后记为完成或未完成 |
| C4 | DSH 的 `subagent`、`send_message`、`interrupt_agent`、`list_agents` 不再挂载，统一为 `conversation_open / send / close / delete / list`。子对话里只能用 `conversation_send` 向频道对话汇报、用 `conversation_close` 结束自己；子会话禁用的工具在每次组合（含冷恢复）时按当前可见工具重新计算 |
| C5 | 管理员不在子对话里发言；子对话页只读，可结束进行中的、销毁已结束的 |
| C6 | 频道对话结束时其子对话一并结束；重启时尚未完成的脚本子对话记为未完成；模型驱动的在收到消息时由 DSH 冷恢复 |
| C7 | 已结束的子对话按「设置 → 子对话」的保留时长清理（1 / 3 / 7 / 30 天或一直保留，默认 7 天），会话文件与记录一并删除；智能体可以立即销毁自己开的、已结束的子对话 |
| C8 | 对话间传话做成独立机制：本次只开放频道对话与自己的子对话之间。频道之间的通信以后在同一套地址与带来源的消息上实现，届时再定权限规则 |
| C9 | 界面：子对话缩进显示在频道列表中所属频道下方，已结束的折叠为「已结束 N」；子对话页沿用频道对话的页头与时间线；创造任务页列出它的验证对话 |

## 3. 同时做的修复

- 持久化层把编号以 `verify-` 开头的验证子调用改存为可忽略的 `nekro-nxt/verification-dispatch` 记录，保证此前写入方式产生的记录不会再写坏会话；
- 启动恢复时单个会话读不出，只结束那一段会话期（`unrecoverable-session`），其余频道照常恢复；
- 冷启动恢复已验证通过的候选时沿用原验证结果，不再重复调用候选工具。

## 4. 未做

- 频道之间的通信（C8）；
- DSH 侧的会话删除接口：销毁子对话时 NXT 直接删除其会话目录，DSH 提供接口后改用接口。
