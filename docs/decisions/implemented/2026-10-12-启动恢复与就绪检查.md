# 启动恢复与就绪检查

状态：implemented

## 决定

用户确认：启动升级失败时明确进入恢复状态、保留现场，默认不自动恢复整库；核心功能故障影响就绪，模型、连接和辅助功能故障局部提示。

Server 可执行入口在持有数据根锁、确认业务资源全部停止之后，启动只读恢复入口。该入口不打开 Core、不提供登录、业务 API 或恢复写操作，只返回通用失败状态和操作指引；详细错误留在本机进度文件与日志。配置了安全入口时复用现有证书及同端口 HTTP/HTTPS 行为。

同一 Release 已记录的启动失败阻止自动重复执行升级。`--retry-upgrade` 表示管理员明确重试，Desktop 的“重试”只为下一次启动携带该参数；正常取消允许后续启动继续。更换 Release 后可以尝试修正后的实现。默认恢复数据的能力仍由已有桌面恢复按钮和离线 `--restore-upgrade` 命令提供。

`/health/live` 表示进程仍响应。`/health/ready` 同时要求完成启动、Core 可读写、工作区快照可构造。核心快照失败后标记未就绪，后续健康检查会验证快照是否恢复。模型目录、视觉诊断和检索能力异常采用局部不可用结果，不阻断核心工作区。存储写探针由 CoreDatabase 拥有，只更新 `system_settings` 中的 `host/readiness-probe`，不改用户配置或迁移日志；成功缓存三十秒，失败后重新检查。探针不等待其他写事务，结束后恢复原忙等待设置。

## 原因与边界

数据库事务迁移完成后，连接可能已经写入新消息；运行时激活失败不意味着没有新数据。自动恢复整库可能抹掉备份之后的事实，因此保留显式恢复及旧格式保护。

辅助诊断可等待最多两秒，失败不回显上游正文。健康端点不返回本机路径、聊天、凭据或原始异常。恢复页不提供匿名重试或恢复按钮，避免数据库不可用时绕过既有认证。
