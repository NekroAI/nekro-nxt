# 决策：本地凭据与 QQ Connection 由 Server 组合根统一拥有

状态：accepted

## 问题

QQ OpenClaw 的离线 Adapter 已具备 HTTP、Gateway、恢复和失败语义，但此前产品 API 只接收一个不存在实际解析器的凭据引用，Server 组合根也没有创建 QQ Runtime。即使用户提供真实 Client Secret，系统仍只能返回 `needs-credentials`，不能进行真实连接或收发测试。

## 决定

- Web 创建连接时一次性提交 App ID、Client Secret 和主动发送策略；Secret 不进入 Zustand 权威投影、日志或 Core Connection 配置。
- Server 使用 Host 自有的本地凭据目录保存 Secret。目录权限为 `0700`，每个凭据文件为 `0600`，使用同目录 staging、`fsync` 和原子 rename 提交。
- Core Connection 只保存 `credential:local:<random-id>` 引用。引用不可携带路径，解析器拒绝绝对路径、父目录和符号链接。
- `NekroRuntime` 是 Connection Runtime 的唯一生命周期所有者：创建/恢复 `QQOpenClawRuntime`，向 Channel Runtime 注册 Adapter，发布 Gateway 状态，并在 dispose 时等待 Gateway 与 HTTP Transport 静止。
- Gateway resume 继续复用 SQLite `AdapterRuntimeStateStore`；Web Connection 在重启时复用已有记录，不重复创建。
- 接收测试只在真实 Gateway 入站已提交 Channel Event 后通过；发送测试要求先发现真实 QQ Channel，并通过 QQ HTTP Transport 发送明确标记的诊断消息。认证、限流、未知结果和无频道均独立返回，不声称成功。
- 本地文件权限不是加密保险箱。首期单用户 Desktop/Server 以操作系统账号和数据目录权限为信任边界；云 Secret、系统钥匙串、多用户 RBAC 与远程凭据服务不在本次范围。

## 崩溃与恢复

- 凭据文件先提交，随后创建 Connection；Connection 提交失败时删除刚创建的凭据文件。
- Connection 已提交但 Runtime 启动失败时保留 Connection 并标记失败，允许用户看到可操作错误，不回滚已提交事实。
- 重启按已有 Connection 的 credential reference 重建 Runtime；引用缺失或损坏时不启动 Gateway，并明确标记失败。
- Gateway checkpoint 只在入站 Channel Event 提交后推进；停止等待 Gateway 循环退出。

## 验证与外部边界

自动测试使用真实生产组合根、真实 HTTP API、真实 QQ HTTP/Gateway 实现，仅替换外部网络边界。它验证 Secret 不出现在 API/Core、Gateway 入站创建频道、HTTP 发送收到平台 message ID、重启复用 Web Connection 并恢复 QQ Runtime。

真实 QQ 账号仍需用户手工验证通知高亮、平台额度、真实 CDN/上传和断网恢复。没有真实账号证据前，不把 M5 外部验收标记为完成。

## 未来方向与参考取舍

关联方向：更多 Adapter、多设备、Server 长期运行和多账号管理。

保留接缝：Credential Reference、Connection 账号作用域、Adapter Runtime、Gateway checkpoint、结构化失败和稳定 Channel ID。没有把 Secret 写进通用配置，没有把 QQ 特例放进 Channel Runtime，也没有把本机路径变成凭据身份，因此未锁死系统钥匙串、容器 Secret 或其他平台 Adapter。

本次明确不实现：云凭据服务、多用户鉴权、系统钥匙串、凭据同步、Webhook、多账号编辑器和社区扩展供应链。

参考 DSH 的 Credential Reference 与 Host 所有权边界、QQ OpenClaw 的 Token/Gateway 生命周期；拒绝同步明文 JSON 配置、环境变量散落读取和 Adapter 直接访问 Core 数据库。
