# 安装与启动

按看到的现象找对应小节。多数问题的具体原因写在启动窗口的「查看诊断」或服务端日志里，先看一眼再动手。

## macOS 提示“未打开”或“已损坏”

目前的 macOS 安装包还没有经过 Apple 公证，第一次打开会被系统拦下。弹窗里点“完成”（不要点移到废纸篓），然后到“系统设置 → 隐私与安全性”点“仍要打开”。带截图的步骤见[桌面版安装](../install/desktop.md#macos)。

如果提示“已损坏”，或者设置里没有“仍要打开”，删掉旧的应用和安装包，从[正式版下载页](https://github.com/NekroAI/nekro-nxt/releases/latest)重新下载。只放行从官方渠道下载的安装包。

## 桌面版一直停在启动窗口

启动窗口会显示当前阶段，比如“正在备份本地数据”“正在升级本地数据”。升级时要先复制一份数据，数据多的时候需要几分钟，只要进度还在走就耐心等。

如果窗口变成“本地服务未能启动”：

1. 展开「查看诊断」，看失败原因；
2. 按原因处理，常见的是磁盘空间不足（见下一节）或数据目录不可写；
3. 点「重试启动」。

升级出了问题、想回到升级前：点「恢复升级前备份」。恢复后要退出，改用和备份对应的旧版本安装包打开。完整说明见[升级、备份与恢复](../ops/upgrade-backup.md#桌面版)。

## 磁盘空间不足

升级前会把整个数据目录备份一份，需要的空间大约是数据大小再多一成。空间不够时升级不会开始，原有数据不受影响。

- 清理磁盘后重新启动；
- 或者在「设置 → 关于」把升级前备份改到另一个磁盘，或者改为不备份；
- Docker 部署用环境变量 `NEKRO_UPGRADE_BACKUP_DIR` 指定备份位置。

详见[备份位置与保留份数](../ops/upgrade-backup.md#备份位置与保留份数)。

## 打开网页只看到“启动未完成”

这是服务端的恢复页：上次启动失败（多半是升级没完成）之后，服务不会自动再试一次同样会失败的升级，数据和备份都原样保留。

1. 看服务端日志，找到失败原因并处理；
2. 停止服务，在原来的启动命令后加 `--retry-upgrade` 启动一次；
3. 成功后去掉这个参数，恢复平时的启动方式。

需要回到升级前的数据时，按[服务端恢复步骤](../ops/upgrade-backup.md#服务端)操作。

磁盘空间不足导致的失败，清理磁盘之后也需要按上面的第 2 步显式重试，服务不会自己恢复。

## 桌面版连不上远程服务器

切到远程实例时，页面会直接告诉你原因，按提示处理：

| 提示 | 怎么办 |
| --- | --- |
| 无法连接服务器，请检查地址、端口和网络状态。 | 确认服务器在运行、地址和端口没写错、防火墙放行 |
| 管理密钥未通过验证 / 需要管理密钥 | 点「重新认证」，填当前的管理密钥；服务器换过密钥后，旧设备都要重新认证 |
| 服务器 TLS 身份已经变化 | 服务器证书重新生成了（比如换了数据卷）。确认是你自己的服务器后重新认证 |
| 该地址现在指向另一个服务实例 | 这个地址上已经是另一台 NekroNXT，到「管理服务实例」移除后重新添加 |
| 协议版本不兼容 | 把版本较旧的一端升级 |
| 服务器尝试跳转到其他地址 | 反向代理把请求转到了别处，检查代理配置 |

经过反向代理访问时，见[通过公网和 HTTPS 访问](../install/https.md)。

## Docker 容器起不来或反复重启

先看容器日志：`docker logs <容器名>`。

- 提示 `NEKRO_MANAGEMENT_KEY` 至少需要 32 个字符：把管理密钥换成足够长的随机字符串。
- 提示 `NEKRO_TRUST_PROXY` 需要和管理密钥一起设置：经过反向代理时两个变量都要设。
- 出现 `EACCES` 或 `permission denied`：数据目录的属主不对。新版本启动时会自动修正；仍然报错时，停掉容器，对数据目录执行 `chown -R 10001:10001 <数据目录>`。
- 提示这台设备不允许当前用户监听网络端口（常见于安卓设备上的 Docker）：加上 `-e NEKRO_UID=0 -e NEKRO_GID=0`。
- 提示另一个 NekroNXT 正在升级这个数据目录：确实有另一个容器在用同一个目录，等它结束，或者停掉它。

完整的启动参数见 [Docker 部署](../install/docker.md)。

## 端口被占用

Docker 部署时换一个宿主端口，比如 `-p 4961:4960`。桌面版的本机服务会自动换一个空闲端口，重新打开应用即可。

## 更改数据目录卡在“正在校验数据”

复制和校验阶段可以点“取消更改”，原来的数据目录不会被改动。如果窗口没有响应，彻底退出 NekroNXT（Windows 在任务管理器里结束所有 NekroNXT 进程），重新打开后会回到原来的目录。数据目录不能放在网盘或同步盘里。见[更改数据目录](../install/desktop.md#更改数据目录)。

## 关掉窗口后还在运行

Windows 关闭窗口只是收到托盘，macOS 留在程序坞，智能体照常工作。要彻底停止，从托盘或程序坞菜单选“退出”。

想重启服务时，用「设置 → 关于」里的“重启服务”。
