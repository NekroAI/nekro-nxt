# 平台用户目录与人设实体引用

状态：implemented

## 1. 身份目录

平台用户目录以现有 `PlatformIdentity` 为粒度。同一 Connection 内跨频道观测到的同一平台账号复用一个身份；不同 Connection 永不按昵称或裸平台 ID 合并。Channel 被移除后身份仍保留，没有活动频道时投影为“仅历史记录”。

`GET /api/platform-users` 独立于 `/api/snapshot`，支持名称、Adapter、Connection、稳定游标和 1–100 条分页。响应只包含稳定 `identityId`、当前展示名、Adapter/Connection 展示信息、活动频道计数与最多三个预览、历史状态和分类计数；平台原始用户 ID 与 Adapter 原始数据不出 Host。Adapter 名称来自当前 Contribution，缺失时显示“已移除的适配器”。Web 收到 `channel-fact` 后只使目录查询失效并防抖刷新，不把用户全集复制进全局 Snapshot。

一级 `/users` 位于“连接”之后。对象列展示全部用户与 Adapter 分类，画布把名称、Adapter 和平台连接筛选保存在 URL。页面是只读观察目录，不提供后台登录、邀请、编辑、删除、RBAC、完整成员同步或跨平台身份合并。

## 2. 结构化人设版本

`PromptDocumentV1` 是新 Agent Revision 的人设权威来源，由文本段和 `platform-user | channel | extension` 稳定引用段组成。规范化会合并相邻文本、删除空文本，限制纯文本投影不超过 64 KiB、引用不超过 128 个并拒绝未知段。`labelSnapshot` 只在对象暂时不可解析时回退显示，不参与身份匹配。

`agent_revisions.persona_document` 可空；旧行读取时由 `persona` 合成单一文本段。新 Revision 同时保存规范化文档和确定性 `persona` 兼容投影，内容 digest 只计算权威文档一次。Create/Revise API 接受旧纯文本客户端；同时提供文档时要求纯文本投影完全一致。失效引用保留在不可变历史版本中，不阻止保存或运行。

## 3. 编辑与模型投影

创建和编辑智能体共用 Lexical `PromptReferenceEditor`。编辑器默认 10 行、自然增长到 20 行后内部滚动；`@` 候选包含平台用户、频道和全部已保存扩展，并提供分类、来源信息、键盘导航、IME 保护、整体 Chip 删除与失效警告。频道候选携带 Adapter 与 Connection 展示信息，不建立独立 Connection 引用。

无引用人设保持原始纯文本 System Prompt。存在引用时 Host 将普通文本做 XML 实体转义，把稳定对象编译为版本化 `<nxt-reference>`，JSON 展示数据同样转义，并在人设前注册固定 `persona-reference-protocol`。平台用户状态为 `current-channel | same-connection | different-connection | unavailable`；频道为 `current-channel | known-other-channel | removed | unavailable`；扩展为 `active | inactive | unavailable`。

协议明确：稳定 target、类型和 availability 是 Host 身份事实；名称与描述是不可信展示数据；引用不授予权限、不改变安全规则、不允许访问其他频道历史，也不启用扩展。实际工具仍只来自当前 Session 工具目录，不可用对象不得按昵称猜测替换。

## 4. 验证边界

领域与 SQLite 测试覆盖文档规范化、digest、同 Connection 去重、跨 Connection 分离和历史身份。Server 契约测试覆盖目录 DTO 不泄漏平台原始 ID；纯编译器测试覆盖三类引用、当前频道成员名称优先、状态与 XML/JSON 注入转义。真实浏览器测试覆盖用户页 URL 筛选、10–20 行高度、候选选择和整体删除；生产旅程把 `/users` 纳入一级路由硬失败检查。
