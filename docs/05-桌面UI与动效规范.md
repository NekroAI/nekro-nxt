# NekroNXT 桌面 UI 与动效规范

> 文档编号：05
> 文档性质：基础视觉、桌面交互和动效的唯一事实源
> 状态：现行，按[界面体系第二轮改造](decisions/accepted/2026-10-06-界面体系第二轮改造.md)更新；标注“实现中”的条目是已确认的目标，组件与页面按该决定 §10 分阶段落地
> 适用范围：Web UI、Electron Renderer、System Client UI 和 Extension Client Contribution

## 0. 设计定位

NekroNXT 的界面目标是：**冷静、精密、有生命感；高级但不花哨，专业但不像企业后台。**

产品以鼠标、触控板和键盘操作的 PC 应用为主，不复制手机或平板交互。高级感来自准确的排版、克制的颜色、稳定的空间层级、低延迟反馈和一致行为，不来自大面积毛玻璃、持续光效、弹跳或卡片墙。

月潮靛是品牌主色，用于选择、连接、运行和少量品牌识别；流明蓝只标记焦点与能量端点，黄铜只标记校准节点和品牌签名。消息正文、代码、日志、配置表单等长期阅读区域保持高对比中性色实底。

视觉以 `apps/web/src/ui-kit/` 的 Token 与组件为准；页面和空间如何组织见[界面交互模型](NekroNxt界面交互模型.md)。

## 1. 基础原则

1. **内容优先**：频道消息、代码、配置和诊断信息始终比装饰更醒目；
2. **桌面效率**：优先键盘、Hover、右键菜单、精确拖动、分栏和高信息密度，不为触屏放大所有控件；
3. **即时反馈**：按下、选择、保存、执行和失败都在动作发生时反馈，不用无意义等待动画；
4. **空间一致**：面板从其所在方向出现并沿原路径退出；触发器与浮层的空间关系明确；
5. **克制动效**：默认无弹跳、无惯性投掷、无装饰循环；动效只解释状态或空间变化；
6. **用户掌控**：未保存 Draft、危险操作、运行中任务和失败恢复都给出明确结果与撤销/恢复路径；
7. **双主题平权**：浅色和深色都是完整主题，不把浅色主题作为反色补丁；
8. **扩展一致**：System UI 和 Extension UI 使用同一语义 Token、基础组件与动效等级。

## 2. 月潮观测所主题

### 2.1 语义 Token

产品界面只使用 `ui-kit/tokens.css` 中的语义 Token。浅色与深色各自完整定义，不由一方反色推导：

| Token | 用途 | 浅色 | 深色 |
|---|---|---|---|
| `--bg` / `--bg-glow` | 画布底色、概览与资料页顶部的柔光 | `#f3f1ec` / `#e6ebf5` | `#0b1524` / `#15274a` |
| `--side` | 空间内左侧列表的底色 | `#eceef2` | `#0e1a2c` |
| `--surface` / `--surface-2` / `--inset` | 面板、次级表面、内嵌区 | `#fffefb` / `#f7f7f8` / `#f0f1f4` | `#12223a` / `#172a46` / `#0f1d33` |
| `--line` / `--line-2` / `--line-3` | 分隔、边框、强调边框 | 月潮靛 9% / 16% / 26% | 冷白 9% / 15% / 26% |
| `--fg` / `--fg-2` / `--muted` / `--faint` | 正文、次要文字、说明、弱提示 | `#14243d` 起 | `#eef2f8` 起 |
| `--accent` / `--accent-2` / `--accent-soft` / `--accent-line` | 月潮靛：只用于文字、图标、细线与浅底（链接、选中指示条、选中项浅底） | `#3f5b8f` | `#a3bae2` |
| `--focus` | 流明蓝：键盘焦点环 | `#0b73b4` | `#6bc3f4` |
| `--brass` | 黄铜：概览活动图的“现在”标记、品牌签名 | `#b4884a` | `#d8af73` |
| `--ok` / `--warn` / `--bad`（及 `-soft`） | 状态色 | 各自校验 | 各自校验 |
| `--hover` | 行与按钮的悬停底 | 月潮靛 5.5% | 冷白 6% |

月潮靛、流明蓝和黄铜不承担成功、警告和错误语义。主色配文字的对比度用自动化检查验证，不凭肉眼判断。

#### 颜色角色：填充与文字分开

同一种语义色作“填充”（上面要放文字）和作“文字或细线”时取值不同，暗色主题尤其明显：暗色下 `--accent` 是浅蓝，适合文字，但作按钮底色会变成发白的亮色样式。因此填充一律使用填充角色：

| Token | 用途 | 浅色 | 深色 |
|---|---|---|---|
| `--accent-fill` / `--accent-fill-hover` / `--on-accent-fill` | 主按钮、选中计数、开关打开态等带文字或图标的强调填充 | `#3f5b8f` / `#2f4a7a` / 白 | `#4a6aa8` / `#5a7bbb` / `#f4f7fc` |
| `--bad-fill` / `--bad-fill-hover` / `--on-bad-fill` | 危险主按钮、未读与告警角标 | `#b03a30` / `#962f26` / 白 | `#b9483d` / `#c85a4f` / `#fff6f5` |
| `--ok-fill` / `--on-ok-fill` | 已完成步骤、成功图标底 | `#217a4f` / 白 | `#2f8a5c` / `#f2fbf6` |

#### 语义 Token

组件需要的特殊颜色也必须有名字，不在组件里写值：

| Token | 用途 |
|---|---|
| `--scrim` | 对话框、命令面板遮罩 |
| `--knob` / `--knob-shadow` | 开关与切换钮的滑块 |
| `--sh-inset` | 凹陷控件（分段控件槽）的内阴影 |
| `--sheen` | 进行中连线等短暂高光 |
| `--on-toast-action` | Toast 内操作按钮的底色 |
| `--on-identity` | 身份色填充（头像、连线）上的白色标记；两套主题都是中等明度身份色，统一用白 |
| `--identity-sheen` / `--identity-sheen-lg` / `--identity-text-shadow` | 头像的内高光与字形阴影 |
| `--qr-bg` | 二维码底色，任何主题都保持白色以便扫描 |

**规则：组件 CSS 不写颜色值。** CSS Module 中不得出现十六进制颜色、`rgb()`、`white`、`black` 或混入它们的 `color-mix`；颜色、阴影只引用 Token。需要新颜色时先在 Token 中为它命名并分别给出明暗取值。第二轮改造 R2 起由 Stylelint 门禁检查（实现中）。

### 2.2 使用比例

- 中性色承担绝大部分界面面积；主操作按钮使用纯色，不使用渐变；
- 卡片最多一层：面板里不再套卡片，列表行靠分隔线与悬停底组织；
- 装饰只出现在概览的活动图、资料页与工坊页顶部的柔光，以及品牌标识；不使用背景粒子、渐变光斑或长期循环的装饰动画。

### 2.3 状态色

状态色在两套主题里分别校验：

- `ok`：已连接、已通过验证、已送达；
- `warn`：需要用户处理、等待确认、连接不稳定；
- `bad`：失败、异常、危险动作；
- 中性：未知或已结束，不伪装成成功或失败。

状态始终同时用文字或图标表达，不只靠颜色。

### 2.4 智能体身份色

每个智能体有一个身份色相：优先取外观设置中的色相，否则由 ID 稳定推导。身份色只用于该智能体的头像、频道列表与接线中的连线、时间线中轮次的强调线和资料页柔光，不用于状态或主操作。头像为首字（按字形簇截取）配身份色渐变；有上传头像时显示图片。

### 2.5 风险阶梯色

`--risk-0` … `--risk-3` 表示授权风险逐级升高：无额外访问、受限访问、高风险、极高风险。只用于 `RiskLadder` 等表达授权级别的控件，不替代状态色。

| Token | 浅色 | 深色 |
|---|---|---|
| `--risk-0` | `#6b7689` | `#8e9bb0` |
| `--risk-1` | `#3f6fb0` | `#7fa6e0` |
| `--risk-2` | `#a8721a` | `#e9bd68` |
| `--risk-3` | `#b03a30` | `#f08f83` |

### 2.6 平台品牌资产

- 项目标志采用水月荧侧脸头像章，保留银白短发、圆框眼镜、深蓝帽、金色圆环和水母头饰；16–32px 微型版只减少缩放噪声，不另画字母或抽象图形；
- Stable 使用主头像章；Preview 保留同一轮廓，只在右下角增加黄铜—流明蓝—黄铜三节点校准标记，不使用 Beta、Canary 或字母角标；
- Web 提供 SVG/ICO favicon、Apple Touch、PWA、maskable 和 pinned-tab；Desktop 的 Stable/Preview 分别拥有 ICNS、ICO、Linux PNG 图标组、DMG 背景和 NSIS 安装/卸载图；
- macOS DMG 使用 660×420、72 DPI 的珍珠底，不在背景预绘应用或 Applications 图标；Finder 图标中心位于 `(190, 220)` 和 `(470, 220)`。Windows assisted installer 使用 164×314 sidebar 与 150×57 header；
- 安装、升级、备份和恢复使用 `assets/brand/generated/process/` 与 `status/` 的 64px 装饰图标；日常按钮、菜单和运行状态继续使用 ui-kit 与 Lucide；
- 水月荧属于品牌角色，不自动成为产品中的智能体，也不作为默认头像、消息发送者或运行状态图标。人物只进入 README、安装、Release、欢迎、关于和少量大空态/完成页；
- `assets/brand/` 是可公开、可重建的唯一品牌母版，`pnpm brand:export` 同步平台消费物，`pnpm brand:check` 校验尺寸、格式、元数据、哈希和 Stable/Preview 差异。公开构建不得读取 `.local`。

## 3. 排版

- 正文字体 `--font-sans`（PingFang SC、Hiragino Sans GB、Microsoft YaHei、系统字体）；等宽 `--font-mono` 用于时间轴刻度、代码与诊断区的技术值；
- 字号只有 7 档：`--fs-xs` 12、`--fs-sm` 13、`--fs-md` 14（正文）、`--fs-lg` 16、`--fs-xl` 20、`--fs-2xl` 24、`--fs-3xl` 30；最小 12px；
- 组件按**文字角色**取字，不直接组合字号与字重。角色以 `font` 简写 Token 提供：

| Token | 角色 | 取值 |
|---|---|---|
| `--t-page` | 页标题 | 650 / 24px / 1.25 |
| `--t-section` | 区块标题 | 650 / 16px / 1.4 |
| `--t-title` | 列表项、属性名等对象标题 | 600 / 14px / 1.45 |
| `--t-body` | 正文 | 400 / 14px / 1.6 |
| `--t-note` | 说明文字 | 400 / 13px / 1.5 |
| `--t-label` | 表单标签 | 500 / 13px / 1.4 |
| `--t-caption` | 时间、计数等辅助信息 | 400 / 12px / 1.4 |
| `--t-mono` | 技术值 | 400 / 13px / 1.5，等宽 |

- 数字统计使用 `tabular-nums`；列表行中的长名称单行省略并悬停显示全名，标题最多两行。

## 4. 间距、尺寸与密度

### 4.1 间距

间距只用 4px 基准的 9 档：

| Token | 值 | Token | 值 |
|---|---|---|---|
| `--s-1` | 4px | `--s-6` | 24px |
| `--s-2` | 8px | `--s-7` | 32px |
| `--s-3` | 12px | `--s-8` | 48px |
| `--s-4` | 16px | `--s-9` | 64px |
| `--s-5` | 20px | | |

相邻区块的间距只由一方提供：容器用 `gap`，子元素不再叠加外边距。

### 4.2 尺寸

| Token | 标准密度 | 紧凑密度 | 用途 |
|---|---|---|---|
| `--control-sm` | 28px | 28px | 行内小按钮、表格内控件 |
| `--control` | 32px | 28px | 按钮、输入框、下拉 |
| `--control-lg` | 40px | 36px | 主要表单与页头主操作 |
| `--row-compact` | 32px | 32px | 紧凑列表行 |
| `--row` | 40px | 32px | 标准列表行、属性行 |
| `--row-tall` | 56px | 48px | 两行列表项（名称 + 副标题） |
| `--icon-sm` / `--icon` / `--icon-lg` | 14 / 16 / 20px | 同左 | 图标 |
| `--target` | 32px | 32px | 最小点击目标 |
| `--pane-list` / `--pane-detail` | 272 / 360px | 同左 | 工作台的列表栏、详情栏默认宽度 |
| `--reader-width` | 840px | 同左 | 阅读型正文宽度 |

### 4.3 密度

默认“标准”密度；设置 → 外观提供“紧凑”（实现中）。密度通过根元素 `data-density="comfortable|compact"` 只切换控件与行高 Token，间距保持不变；组件不写两套数值。

## 5. 圆角、阴影与表面

- 圆角三档：`--r-1` 8px（输入、下拉、多行编辑器等所有输入表面，统一 `--control` 高度、`--line-2` 边框与 3px `--accent-soft` 焦点环；聊天输入条作为卡片用 `--r-2`）、`--r-2` 12px（面板、行）、`--r-3` 16px（卡片、对话框）；胶囊（999px）只用于 Chip 与分段控件；
- 阴影三档：`--sh-1` 静止表面、`--sh-2` 悬停与浮起、`--sh-3` 对话框、命令面板和 Toast；`--hl` 是表面顶部的 1px 高光；
- 对话框遮罩使用半透明底和轻微模糊；常驻区域不使用毛玻璃。

## 6. 应用外壳

外壳常驻，切换空间只替换主画布：

| 区域 | 内容 |
|---|---|
| 顶栏 | 品牌标识；服务实例（Desktop 中可点开实例切换，浏览器中显示“本机”并链接到关于页；状态栏不再重复）；当前位置（纯文字）；搜索入口（`⌘K` / `Ctrl+K`）；关注铃（数字为需要关注的事项数，点击展开需要关注列表） |
| 导航轨 | 概览、频道、智能体、工坊、接线；设置位于底部。选中块由同一个测量型指示器滑动，不随页面重挂 |
| 主画布 | 当前空间；大多数空间是“左侧对象列表 + 右侧详情”，频道空间另有可开合的检查器 |
| 状态栏 | 本机连接状态、每个平台账号的状态、正在工作的智能体、时钟；每一项都可点击到对应对象 |

服务升级后页面版本不一致时，外壳在画布顶部居中显示“服务已升级”的刷新提示，刷新前保存频道草稿。窄于 760px 时隐藏空间内的左侧列表，只保留当前对象。

第二轮改造中，顶栏不再重复主画布已有的页面标题；状态栏按[界面交互模型](NekroNxt界面交互模型.md) §2 的状态词典取颜色与措辞（实现中）。

### 6.1 页面版式

每个空间入口必须声明以下三种版式之一，页面内不得再嵌套分栏（实现中，R2 起由版式门禁检查）：

| 版式 | 用于 | 结构 |
|---|---|---|
| `ReaderPage` 阅读型 | 没有对象列表的独立表单（添加账号） | 正文限宽 `--reader-width`，居中 |
| `WorkbenchPage` 工作台型 | 设置、工坊、接线、智能体、频道 | 铺满主画布：可折叠列表栏（240–320px）+ 主区 + 可收起详情栏（320–400px） |
| `BoardPage` 看板型 | 概览 | 响应式网格，卡片按可用宽度自动增减列数 |

断点按主画布宽度计算，取 1100 / 1280 / 1440 / 1920：

- 工作台型：1280 以下详情栏默认收起，可手动展开为覆盖层；1100 以下列表栏折叠为可展开的抽屉；
- 阅读型：任何宽度都保持正文宽度居中，窄于正文宽度时两侧留 `--s-4`；
- 看板型：列数随宽度增减，卡片最小宽度不低于 300px；
- 表格在窄宽度按列优先级隐藏次要列，不截断主要列。

#### 主区宽度

切换菜单时页面不能忽宽忽窄、忽左忽右。工作台主区的内容一律从列表栏边缘开始（左对齐），不在剩余空间里居中；页面只从 `MainContent` 的三档宽度里选一档，不自行定宽：

| 宽度 | Token | 用于 |
|---|---|---|
| `readable` | `--reader-width`（840px） | 表单与设置：设置的每个分节、新建智能体、工坊的开始页 |
| `wide`（默认） | `--content-width`（1200px） | 由表格与分组构成的对象页：智能体资料、工坊扩展详情、主从分栏的详情列 |
| `full` | 不限 | 画布：接线板、带侧栏的工坊任务、频道对话 |

页面内部的表单控件组最多与 `--reader-width` 同宽，不再写 640、720 等零散数值。

#### 主从分栏

“点列表项打开详情”的页面（模型供应商、DSH 插件）使用 `MasterDetail`，不整页跳走：

- 未选中时只显示列表，宽度与其他设置分节相同；
- 选中后，主区宽度不小于 1080px 时列表收为左侧 `--pane-master`（360px）常驻、选中项高亮并保持各自的滚动位置，详情在右侧展开；
- 主区更窄时详情代替列表，顶部给出返回；返回后列表回到原来的滚动位置，并把刚才打开的项滚入视野；
- 选中项写在地址里（如 `?entry=`、`?provider=`），可以直达，浏览器后退回到列表。

#### 说明文字

界面第一层只留名称、状态、后果和下一步。用户熟悉后不必每次看的解释（某个设置是做什么的、修改何时生效、字段格式背景）放进 `InfoTip`：`PropertyGroup`、`PropertyRow`、`Field`、`SwitchRow` 的 `tip` 会在标题旁放一个问号，悬停或点按显示。`description` / `hint` 只用于每次都影响判断的内容：当前状态、不可用原因、费用、风险与不可逆后果。

## 7. 组件（`ui-kit`）

产品界面只从 `apps/web/src/ui-kit/index.ts` 取用组件；业务代码不得直接使用原生按钮、输入框或直接导入 Radix（由 `pnpm check:ui-boundary` 检查）。

| 分类 | 组件 |
|---|---|
| 基础 | `Button`（default / primary / ghost / danger / danger-solid，可 `busy`）、`IconButton`（必须有 `label`）、`Pressable`（自定义交互面使用的无样式按钮）、`Chip`、`StatusDot`、`Kbd`、`Spinner` |
| 身份 | `AgentAvatar`（身份色、可选图片、工作中的轨道动画；尺寸 xs 18 / sm 22 / md 28 / default 34 / lg 48，lg 用于对象标题旁）、`MemberAvatar` |
| 选择 | `Segmented`、`TabStrip`、`SelectionList`（列表选中块）——三者都用 `useIndicator` 测量目标并滑动同一个指示块 |
| 表单 | `Field`、`Input`、`Textarea`（可 `bare`）、`Select`（产品自绘弹出列表，`value` / `onValueChange`，不使用浏览器原生下拉）、`Switch`、`SwitchRow`、`SecretInput`（只显示“已配置”，不回显）、`FileChooser` |
| 浮层 | `Dialog`（`media` 为图片与文档预览的大尺寸，`closeLabel` 在标题行显示关闭按钮）、`ConfirmDialog`（确认中保持打开，失败就地显示）、`Sheet`、`Menu`、`Popover`（锚定在触发按钮下的短列表，如关注铃）、`Tooltip`、`InfoTip`（标签旁的问号，悬停或点按显示不必每次看的说明）、`Overlay`（命令面板、全屏编辑一类自定义浮层；`onEscapeKeyDown` 可让内部菜单先响应 Escape）、`toast` |
| 布局 | `Panel`、`Section`、`Banner`（warn / bad 为 alert，info / ok 为 status）、`EmptyState`、`Disclosure`、`Skeleton`、`Stepper`（可标记失败步骤）、`Timeline`、`Gauge`、`Sparkline` |
| 工具 | `cssVars`（传入 CSS 自定义属性） |

### 7.1 第二轮改造新增组件

以下组件替代页面中的零散写法：

| 组件 | 用途与结构 |
|---|---|
| `ReaderPage` / `WorkbenchPage` / `BoardPage` | 三种页面版式，见 §6.1；`MainContent` 的三档宽度与 `MasterDetail` 主从分栏也见 §6.1 |
| `DetailPane` | 工作台右侧详情：标题区（对象图标、名称、状态、主操作）+ 分组 + 底部操作区，可收起；接线、工坊、频道检查器共用 |
| `ObjectHeader` | 对象详情顶部：头像或图标、名称、状态、关键事实与主操作、“更多”菜单；替代资料页的大号英雄区 |
| `PropertyList` / `PropertyRow` | 左侧标签、右侧值或控件、行内说明；标签、控件、说明按网格对齐，行高取 `--row`；替代零散的 `Field`、`SwitchRow` 与自制网格 |
| `DataTable` | 列宽策略、固定表头、行内编辑、行选择，以及空、加载、错误状态；窄宽度按列优先级隐藏 |
| `RiskLadder` | 授权级别：四级递进刻度，每级只写比上一级新增的能力，颜色取 `--risk-0…3` 逐级加深；可展开“手动调整”直接控制各项能力并维护依赖；不属于任何级别时显示“自定义” |
| `SaveBar` | 页面底部的保存栏：“N 项未保存的修改 · 保存”，可放弃修改 |
| `Diagnostics` | 默认收起的诊断区，展示键名、错误码、包名、内部 ID 等技术值，可复制 |
| `EmptyState`（完整形式） | 说明 + 示例 + 入口，不只是一句话 |
| `InlineEdit` | 名称、别名等短字段的就地编辑 |
| `SearchField` / `Toolbar` | 列表与表格的检索、筛选与操作条 |
| `KeyValueCopy` | 可复制的技术值 |

现有组件按 §4 的尺寸档位规格化：`SwitchRow` 标题、说明与开关网格对齐；`SelectionList` 行高与内边距走 Token；`Banner` 严重度与操作区位置固定；`Section` 标题与操作统一布局。

## 8. 领域视觉

- **频道时间线**：成员消息与智能体发言按 5 分钟内连续合并，跨天插入日期分隔；每个智能体轮次在常态下逐行列出工具步骤的可读摘要，点击一步就地展开该工具的详情；打开透视后展开为思考与工具卡片，与步骤详情使用同一种按工具类型排版的内容，并显示用量；未送达的出站消息带重发 / 已送达操作。
- **智能体状态**：空闲为静态；思考中与使用工具时头像外圈出现缓慢轨道动画，并在状态栏列出；等待输入用警示色文字；不可用用错误色与可操作说明。
- **接线板**：平台账号 → 频道 → 智能体三列，连线按智能体身份色渐变；新建绑定时连线描绘进入，工作中的频道连线有流动效果。
- **概览活动图**：最近两小时（不足时为一天）按频道堆叠的消息数柱状图，带数值刻度与时刻，黄铜点与“现在”标记当前时段；计数是离散值，不用平滑曲线（平滑会在零附近下探、读不出数值）。
- **工坊进度**：任务顶部的阶段条依次为生成候选、确认运行、启动、界面验证、保存、启用；失败步骤标红。第二轮改造改为紧凑的水平阶段条（实现中）。
- **系统访问**：使用 `RiskLadder` 表达“基础权限 → 文件读写 → 运行命令 → 完整访问”的递进与风险（实现中），不使用四个并列的分段按钮。
- **身份色**：按对象分配，智能体与频道各自稳定；同一画面内（如概览活动图）不同频道可区分（实现中）。
- **版本**：界面不展示自动递增的版本序号。智能体不呈现版本概念；扩展的保存记录以保存时间区分，内部编号只在诊断区出现。

## 9. 扩展界面

扩展通过 V6 贡献（面板、工具视图、富消息渲染器、页面）进入产品，由统一的 `ExtensionUiRuntime`（`apps/web/src/extension-ui/`）挂载。宿主的 `ContributionFrame` 绘制标题、图标、折叠、加载与失败回退，扩展只渲染内容；每个贡献有独立错误边界。面板按锚点放置：智能体面板进入智能体资料页（完整）与它响应频道的检查器（紧凑），频道面板进入频道检查器，扩展面板进入工坊扩展详情，连接面板进入接线的账号详情与添加账号页。

扩展客户端获得版本化的 `ui-kit@2`：同名组件由产品组件库实现，主题、密度、焦点与 Token 与产品一致。组件与属性清单由 SDK 参考的 `ui.componentProps` 给出，并写入扩展开发技能。`ui-kit@2` 不兼容 `ui-kit@1`：`Tabs`、`Popover`、`Tooltip` 由复合对象改为单个组件，`Select` 改为 `options` / `value` / `onValueChange`，`SidePane` 由 `PropertyList` / `PropertyRow` 取代。工坊验证候选时，会在 `[data-nxt-theme='light' | 'dark']` 子树中分别渲染一次，以覆盖两套主题。

### 9.1 扩展专属页面责任契约

扩展专属页面和动态预览必须使用同一份责任契约。这里的“提供”表示该层由对应所有者统一渲染和验收；另一方不得再补一份相同职责。AI 开发上下文、SDK 示例和运行时错误都必须使用本节口径，不得只写“符合 NekroNXT 风格”“注意留白”等无法执行的要求。

| 层级 | 所有者 | 提供内容 | 另一方不得做的事 |
|---|---|---|---|
| 产品外壳 | Host | 顶栏、导航轨、状态栏、页面的声明式对象列和主画布边界 | 扩展不得遮挡、替换或模拟第二套外壳 |
| 页面视口 | Host | 尺寸、`--bg` 背景、唯一纵向滚动根、稳定滚动条槽和错误边界 | 扩展不得设置 `100vw/100vh`、接管根滚动、覆盖整幅画布或把固定定位元素挂到产品根 |
| 页面内容框 | Host | 顶部、左右和底部安全边距，以及标题和正文共享的内容轴 | 扩展不得在页面根重复设置 `padding`、使用负边距越界或根据宿主绝对尺寸补偿 |
| 声明式对象列 | Host | 背景、宽度、滚动、当前项、Hover、Focus、键盘操作和错误态 | 扩展只提供分组、项目和相对路径数据，不渲染任意对象列 React 或选中样式 |
| 当前视图内容 | Extension | 当前视图标题、说明、业务数据、业务操作和区块顺序 | 不重复应用标题，不创建第二个页面根、对象列或导航外壳 |
| 内容表面 | UI Kit 与 Extension | `PageHeader`、Section、Toolbar、表格、反馈和局部业务布局 | 不复制基础组件状态机，不用任意背景、边框、圆角和阴影制造卡片墙 |
| 局部样式 | Extension CSS | 当前组件边界内的排版、网格和受作用域装饰 | 不修改页面根背景/边距、Host Token、`html/body/:root`、其他页面或 Portal 容器 |

Host 页面内容框使用共享 Page Inset Token，而不是由每个页面复制数值：

- `--page-inset-block-start: 24px`；
- `--page-inset-block-end: 40px`；
- 内容容器宽度不大于 `960px` 时，`--page-inset-inline: 24px`；大于 `960px` 且不大于 `1440px` 时为 `32px`；大于 `1440px` 时为 `40px`；
- 断点按主画布内容容器计算，不按整个窗口计算；浏览器缩放后的 CSS 像素仍使用同一规则；
- `objectPane: hidden` 只撤销对象列和分隔条，页面内容框继续使用上述边距。“全宽主画布”不等于内容贴边；首版不开放扩展声明 edge-to-edge 页面。

背景与滚动所有权固定如下：

- 页面视口背景只由 Host 提供。Extension 页面根必须透明，不能铺满视口渐变、图片、伪元素或另一种背景 Token；
- Section 默认依靠标题、间距和轻微层次组织。只有可独立选择、拖动、拥有明确生命周期或必须与相邻内容区分的对象，才使用 UI Kit 提供的 Surface 背景；
- 页面只有一个 Host 纵向滚动根。代码、日志、表格和资源预览可以在明确边界内使用 UI Kit 的局部滚动，不得形成整页滚动套整页滚动；
- PageHeader、Toolbar、正文首区和主要表格共享同一左右内容轴。组件自己的内部 padding 不得改变这个外部轴；PageHeader 与外层 Stack 只能由一方提供相邻区块间距，不能同时叠加 `margin-bottom` 和 `gap`；
- Portal、Dialog、Popover、Tooltip、Toast 的挂载层、遮罩、焦点和 z-index 由 UI Kit 提供，不受页面内容框裁切。

信息结构的最低要求：

- 对象列标题表示整个应用，主画布 PageHeader 表示当前视图或当前对象；两者相同即不通过；
- 对象列已有的视图切换不得再作为主画布主按钮重复出现。主按钮必须产生业务结果，不以“查看、返回”包装重复导航；
- 概览默认使用紧凑摘要、列表或表格。只有指标确实需要横向比较时使用 2–4 个 UI Kit `Metric`，由 `MetricStrip` 组合成无卡片背景的紧凑数字带；不用等宽大卡片填满首屏；
- StatusBadge 贴合文字内容，不拉伸成无进度语义的横条；同一状态在摘要、表格、筛选和详情中使用同一名称与归类；
- 示例和真实数据都必须内部一致。日期与星期、汇总数量与表格行、筛选结果与状态计数互相矛盾时，视觉链路即使可运行也不通过。

## 10. 操作反馈

- 保存、测试、启用等操作的瞬时结果使用 `toast`：位于状态栏上方居中，最多同时 3 条；成功约 2.6 秒、失败约 5.2 秒后消失，可带一个操作；
- 字段校验靠近字段显示；确认对话框中的失败显示在对话框内，不关闭对话框；
- 持续的状态（连接异常、缺少模型、兼容性隔离）用 `Banner` 留在对应页面，不改成短暂 Toast；
- 同一操作不在正文和 Toast 重复同一结果；
- 错误显示中文原因和建议操作，原始错误码进入诊断区（见[界面交互模型](NekroNxt界面交互模型.md) §1.5）。

## 11. 动效

### 11.1 Token 与实现方式

| Token | 值 | 用途 |
|---|---|---|
| `--dur-1` | 160ms | 颜色、悬停、按下 |
| `--dur-2` | 280ms | 选中块滑动、展开收起、局部入场 |
| `--dur-3` | 420ms | 卡片悬停浮起、较大的入场 |
| `--ease` | `cubic-bezier(0.2, 0.8, 0.2, 1)` | 全部空间动画 |

界面动效全部用 CSS 实现，不依赖动画库。

### 11.2 实现规则

1. **外壳常驻**：顶栏、导航轨和状态栏在切换空间时不重挂、不移动；主画布内容只做 260ms 淡入。
2. **指示块常驻并在文字下层**：导航轨、分段控件、标签和列表的选中块是同一个持久元素，用 `useIndicator` 测量目标几何后以 `transform` 滑动；首次取得几何时直接定位，不从零尺寸长出来；窗口或内容重排时立即对齐。文字始终画在指示块之上，过渡中不消失、不重绘。
3. **局部交互只更新局部**：选择列表项、展开面板、切换透视都只改变受影响区域，不重挂整个页面。
4. **不对含文字的区域使用 View Transitions 命名快照**：快照会盖住实时文字，造成重影和数百毫秒的延迟。
5. **入场与退出**：对话框以 opacity + 位移 + `scale(.97)` 进入，退出更快；`Disclosure` 用 grid 行高度展开，收起后移出焦点顺序；列表与卡片入场按 `--i` 依次错开 45–50ms。
6. **主题切换**：给根元素临时加 `.theming`，让颜色、边框和阴影在 350ms 内过渡，减少动态效果时跳过。
7. **不使用**：弹跳、惯性、对聊天历史或可排序列表做布局动画、长时间大面积闪烁的骨架、阻塞输入的动画；动效不得推迟消息、回执或工具状态的显示。

### 11.3 减少动态效果

设置 → 外观提供“减少动态效果”，打开后根元素带 `data-nxt-motion='off'`，所有动画与过渡压到 1ms；系统 `prefers-reduced-motion: reduce` 时同样压到 1ms。该设置跨刷新保存。

### 11.4 逐帧录屏验收

改动动效、选中块或页面切换时，必须逐帧检查，不能只看静态截图：

1. 用 Playwright 打开页面，通过 CDP `Page.startScreencast` 录下操作前后约 600ms 的全部帧；
2. 把帧拼成按时间排列的拼图后逐张查看；
3. 通过条件：过渡期间文字在每一帧都可见、不重影；没有空白帧或整块闪白；点击后下一帧内出现反馈（指示块开始移动或按下态）；指示块在文字下层且不跳变尺寸。

## 12. 性能与实现约束

- 空间动画只使用 `transform` 与 `opacity`；`Disclosure` 允许 grid 行高度；
- 高频更新（流式输出、轮次状态）只更新对应行，不重渲染整条时间线；消息行保持稳定的根元素，只有新到达的消息淡入；
- 频道时间线贴底跟随时，忽略由跟随逻辑自己触发的滚动事件，图片加载撑高内容后自动保持在底部；
- 接线板连线从 DOM 实测端点绘制，拖线使用 Pointer Events，拖动中禁止选中文本；
- 主题、Token 与组件状态只由 `ui-kit` 输出，业务组件不复制数值。

## 13. 旧 Token 别名（已移除）

第二轮改造 R4 已删除旧组件库与全部 `--nxt-*` 别名。产品页面、扩展 `ui-kit@2` 与扩展页面宿主只使用 §2.1 的 Token；`pnpm check:css-tokens` 以强制模式检查 `apps/web/src` 下全部 CSS Module，颜色只能来自 Token（按对象色相 `--h` 计算的身份色除外），间距只能是 Token 或基于 Token 的 `calc()`。Desktop 实例浮层是独立页面，自带变量，不读取产品 Token。

## 14. 验收清单

实现改动后的像素级验收流程、覆盖范围和否决条件见 `06` §5.1。本清单只规定设计语言必须覆盖的状态组合。局部页面改动按 `06` §5.1 选择受影响的代表场景，不要求每次重跑全部组合：

1. 浅色与深色；
2. 键盘操作、Focus visible、Escape 和 Tab 顺序；
3. Hover、Pressed、Disabled、Busy、Error 状态；
4. 100%、125%、150% 缩放；
5. 主画布宽度 1100、1280、1440、1920，以及 760px 以下的窄窗口；
6. 减少动态效果；
7. 中文、英文、长名称、空内容和错误内容；
8. 扩展贡献注册与卸载后无残留；
9. 动画期间状态更新不丢失、不锁输入，并按 §11.4 逐帧检查；
10. 主操作、正文和状态色达到目标对比度；
11. 真实数据量：数十个模型、数百名成员、数十个频道、两千字设定、长名称与 Emoji。

自动门禁全部为强制：布局审计（`pnpm audit:layout`）在上述宽度 × 明暗下检查横向溢出、文字截断、元素重叠、点击目标小于 `--target` 与空白画布，任一问题即失败；`pnpm check:css-tokens` 检查组件 CSS 只用 Token（§13）；`pnpm check:ui-boundary` 检查空间入口使用三种版式之一；术语检查同时拦截用户可见文案中的版本序号、错误码与配置键名。

## 15. 明确拒绝

- 不复制 macOS 系统设置、iOS 导航和手机手势；
- 不把 Apple 风格等同于毛玻璃、超大圆角和低对比灰字；
- 不使用 shadcn 默认模板、后台卡片墙和全屏指标面板形成产品身份；
- 不让月潮靛或流明蓝吞没内容层级；
- 不把创造状态表现成另一个智能体；
- 不为了视觉效果隐藏真实运行、发送和失败状态；
- 不在暗色主题中出现亮色样式的控件：暗色是独立主题，每个填充都用对应的填充角色。

参考 Apple 设计资料中的即时反馈、空间一致、克制、可访问性和工艺原则；拒绝移动端触屏手势、惯性物理和平台外观照搬。技术实现遵循 `decisions/accepted/2026-08-16-一期技术栈与UI基础设施.md`。

外部参考输入：`https://github.com/emilkowalski/skills/tree/main/skills/apple-design`。本文只吸收适用于 PC Web/Electron 的原则，不继承其触屏交互和示例参数作为项目 API。
