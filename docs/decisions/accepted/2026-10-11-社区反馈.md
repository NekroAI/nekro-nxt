# 社区反馈

状态：accepted（2026-10-11 批准；尚未实施）

用户可以在日常聊天里让智能体把遇到的问题、建议或提问提交到社区，管理员确认后发出；诊断信息由宿主自动附上；NekroNXT 里能看到每条反馈的状态、回复和修复版本。社区端的数据模型、接口、维护者读取方式和网页端写在社区仓库的《社区反馈方案》里，本文只定 NekroNXT 端的行为，两边的接口约定以社区仓库那份为准。

## 1. 场景与目标

- 现在的反馈靠用户自己去 GitHub 提 issue：门槛高、信息靠手填、提交后没有回音。
- 目标：一句话就能提反馈；环境信息自动附上；每条反馈可以跟踪到结果；离开本机的内容用户看得到、控制得住。

## 2. 决定

| #   | 决定                                                                                                                                                                                      |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| N1  | 设置新增分节「社区反馈」，内有全局开关「启用社区反馈工具」，默认关闭。开启要求已登录社区；未登录时开关旁给出登录入口                                                                      |
| N2  | 开启后所有智能体获得三个工具：`feedback_search`、`feedback_draft`、`feedback_status`。提交本身不是智能体工具，是客户端动作                                                                |
| N3  | 默认流程：智能体起草，管理员在客户端确认后发送                                                                                                                                            |
| N4  | 智能体能力新增「免确认提交反馈」，每个智能体单独开启，默认关闭，仅在全局开关打开时显示。开启时需要确认，措辞说明内容会直接发往社区                                                         |
| N5  | 免确认只对管理员从客户端发出的消息触发的那一轮生效；群里其他成员触发的，一律回到草稿等待确认。免确认提交不带对话摘录，每个实例每天最多 5 条                                              |
| N6  | 诊断信息由宿主收集，智能体不能改写；对话摘录由智能体指定消息编号，宿主从本频道的记录里取出并脱敏，智能体不能自行提供摘录文本                                                              |
| N7  | 发送前展示完整的将发送内容；首次启用时展示一次说明并取得同意；设置里可以「查看最近一次发送的内容」                                                                                        |
| N8  | 提交带幂等键（草稿 ID），重试不会产生重复条目                                                                                                                                             |
| N9  | 社区的状态变化回流到本机，进入通知和概览的「需要关注」。智能体通过 `feedback_status` 读取，社区返回的文字按引用的外部内容交给它                                                            |
| N10 | 社区页新增子页「反馈」：待确认的草稿、已发送的反馈、回复与状态时间线，也可以手动新建反馈。没有智能体也能用                                                                                |

## 3. 设置与开关

- **设置 → 社区反馈**：
  - 开关「启用社区反馈工具」，说明写价值和范围，不写机制，例如：“让智能体把问题和建议提交到社区。每条反馈发出前都需要你确认。”
  - 状态行：已登录的社区账号与社区地址；未登录时显示「登录社区」。
  - 「查看最近一次发送的内容」按钮，原样展示。
  - 说明区（默认折叠）：会发送什么、不会发送什么、保留多久、怎样撤回。文案与社区端 §9 一致。
- **智能体页 → 能力**：全局开关开启后出现「免确认提交反馈」。开启要经过确认对话框，列出：内容会直接发往社区；只对你从客户端发出的消息触发的那一轮生效；每天最多 5 条。保存后生效，沿用现有的未保存修改栏。
- 系统设置键 `community.feedback`：`{ version: 1, enabled: boolean, consentedAt?: number }`。智能体能力字段 `communityFeedbackAuto: boolean`，默认 false，关闭时不进入修订摘要，保持已有修订的摘要不变（与 `commandAccounts` 同样处理）。

## 4. 智能体工具与提示词

- `feedback_search({ query, extensionId? })`：在社区已公开展示的条目和我的反馈里查找。返回编号、标题、状态、修复版本、受影响人数。用于提交前查重；命中时建议用户标记「我也遇到」而不是新建。
- `feedback_draft({ kind, target, title, body, conversationRefs? })`：
  - `kind`：`bug`、`suggestion`、`question`。
  - `target`：`nxt` 或 `{ extensionId }`。针对扩展的反馈进入该扩展作者的收件箱。
  - `title`（≤ 120 字）、`body`（≤ 8000 字）：写发生了什么、期望什么、怎么复现。
  - `conversationRefs`：本频道的消息编号，最多 8 条。宿主取出对应消息并脱敏，作为摘录。
  - 返回草稿编号和状态：`awaiting-confirmation`、或免确认时的 `sent` 与反馈编号。
- `feedback_status({ ref? })`：我的反馈的状态、最近回复和修复版本；不带 `ref` 时返回最近的几条。
- 系统提示词增加一段（开启时才出现），草稿如下，实现时按《术语与文案规范》§4.3 复核：

  > 社区反馈已开启。遇到 NekroNXT 或某个扩展的问题，或者用户提出了建议并希望反馈时，先用 feedback_search 看有没有人提过，没有再用 feedback_draft 起草。草稿默认交给管理员确认后发出。正文写清发生了什么、期望什么、怎么复现；版本和运行环境由系统自动附上，不用写。用户没有提出时不要主动提反馈，也不要把聊天里的隐私内容写进去。

## 5. 诊断与脱敏

### 5.1 宿主收集的诊断

- NekroNXT 版本与渠道、宿主类型（Desktop、Server）、操作系统与架构、DSH 版本；
- 启用的平台适配器类型；
- 提交时所在智能体的能力等级与开关（不含凭据和账号）；
- 启用的扩展及版本；针对扩展的反馈附该扩展的版本、权限等级与启用方式；
- 最近的运行诊断条目（兼容性诊断、扩展加载错误、连接异常）的类型与摘要，经脱敏；
- 实例的随机 ID（与匿名使用统计所用相同，不来自硬件或账号）。

契约 schema：`CommunityFeedbackDiagnosticsSchema`，放进 `@nekro-nxt/contracts`，字段与社区端 `diagnostics` 一一对应，未知字段拒绝。

### 5.2 脱敏

由宿主的一个纯函数 `redactFeedbackText` 完成，对草稿正文、摘录和诊断文本统一处理：

- 频道成员的名称与 ID → `成员甲`、`成员乙` 之类的角色占位，同一人在一条反馈里保持一致；
- 平台账号、群号、频道名 → `群 A` 之类占位；
- 用户目录和数据目录的绝对路径 → `<home>`、`<data>`；
- 疑似密钥（常见令牌前缀、`Authorization` 头、私钥块、长随机串）→ `<已移除密钥>`，并在预览里标出；
- 图片与文件只保留「附件一份」，不上传内容。

脱敏后的文本才进入预览和发送。服务端会再扫描一次疑似密钥，命中则拒绝（不是静默改写），此时草稿保持待确认并提示需要处理哪一类。

## 6. 草稿、发送与跟踪

### 6.1 本机数据

两张表（Drizzle 迁移，`pnpm check:drizzle`）：

- `community_feedback_drafts`：`id`（也是幂等键）、`agent_id`、`channel_id`、`kind`、`target`、`title`、`body`、`excerpt`（已脱敏）、`diagnostics`、`state`（`awaiting`、`sending`、`sent`、`failed`、`discarded`）、`requested_by`（`admin-console` 或成员标识）、`auto`（是否免确认）、`error`、`created_at`、`updated_at`。
- `community_feedback_items`：已发送反馈的本机镜像：`ref`（`FB-12`）、`community_url`、`draft_id`、`title`、`kind`、`target`、`status`、`fixed_in`、`unread`、`last_event_seq`、`created_at`、`updated_at`。

### 6.2 流程

1. `feedback_draft` → 宿主脱敏、收集诊断，写入草稿。免确认且触发消息来自管理员客户端时，直接进入 `sending`。
2. 草稿在「社区 → 反馈」出现，概览的「需要关注」增加一项「N 条反馈等待确认」，并按通知设置提醒。
3. 管理员可以编辑标题和正文、勾选或取消对话摘录、查看将发送的全部内容，然后「发送」或「丢弃」。
4. 发送使用已登录的社区账号，以草稿 ID 为幂等键。失败进入 `failed`，保留内容并显示原因，可重试。
5. 成功后写入镜像表，拉取一次详情。

### 6.3 状态回流

- 同步节奏：随每日更新检查一次，加上打开反馈页和刚提交之后各一次；使用 `GET /feedback/changes?cursor=`。
- 新增通知事件 `community-feedback-update`（`NotificationEventKeySchema`），默认开启：社区回复、状态变化、已修复。
- 镜像表的 `unread` 驱动概览的「需要关注」与反馈页角标。
- 已修复且当前版本不低于 `fixed_in` 时，在详情里提示「可以确认是否已解决」，提供「已解决」与「重新打开」。

## 7. 界面

沿用现有的设计系统与文案规范（`docs/01-术语与文案规范.md`、`docs/05-桌面UI与动效规范.md`），使用 `ui-kit` 现有组件，不新增视觉语言。

- **社区 → 反馈**（`apps/web/src/app/community/feedback.tsx`）：主从布局，与「我的扩展」「人设」页一致。
  - 列表：分组「待确认」「进行中」「已解决」；每行是标题、状态标签、对象（NekroNXT 或扩展名）、相对时间、未读点。
  - 详情：正文；「将发送的诊断」折叠区；时间线（`Timeline`）显示提交、状态变化、社区回复、修复版本；底部是回复框。
  - 操作：草稿为「发送」「编辑」「丢弃」；已发送为「追加说明」「撤回」，已修复为「已解决」「重新打开」。
  - 手动新建：页面右上角「新建反馈」，打开与草稿编辑相同的表单。
- **状态标签**：新反馈 中性、需要补充 警告、已确认 与 已计划 强调、已修复 成功、重复 与 不处理 弱化、已撤回 弱化。
- **未登录**：页面顶部 `Banner` 提示登录社区，草稿仍可编辑，发送时要求登录。
- **空状态**：说明可以对智能体说“把这个问题反馈到社区”，以及未开启时指向设置。
- **智能体页**：见 §3。
- 所有可点击控件必须产生真实结果；未实现的操作隐藏。

- `@nekro-nxt/contracts`：`CommunityFeedbackSchema`、`CommunityFeedbackDraftSchema`、`CommunityFeedbackDiagnosticsSchema`、`CommunityFeedbackEventSchema`、`CommunityFeedbackStatusSchema`，以及社区接口请求与响应 schema（与社区端共用同一份）。
- 宿主 API（`HostApiContracts`）：
  `getCommunityFeedbackSettings`、`updateCommunityFeedbackSettings`、
  `listCommunityFeedback`、`getCommunityFeedback`、
  `updateCommunityFeedbackDraft`、`sendCommunityFeedbackDraft`、`discardCommunityFeedbackDraft`、
  `createCommunityFeedbackDraft`（手动新建）、`previewCommunityFeedbackPayload`、`getLastSentCommunityFeedbackPayload`、
  `replyCommunityFeedback`、`withdrawCommunityFeedback`、`reopenCommunityFeedback`、`markCommunityFeedbackAffected`、`markCommunityFeedbackResolved`。
- 快照增加 `communityFeedback: { enabled, signedIn, pendingDrafts, unread }`，供设置页、概览和导航角标使用，旧宿主缺省视为未启用。
- 服务端：`CommunityService` 增加提交、详情、变更游标、回复、撤回、标记等方法；工具放在 `apps/server/src/feedback-tools.ts`，在 `index.ts` 按全局开关注册，与 `notesUpdateTool` 同一方式；脱敏与诊断收集放在 `apps/server/src/feedback-payload.ts`，纯函数，便于测试。

## 9. 边界与取舍

- 免确认提交意味着智能体可以不经你看到就向社区发送内容。限制来自四处：只对管理员本人从客户端发起的轮次生效、不带对话摘录、每天 5 条、发出后可在反馈页撤回。
- 脱敏是尽力而为，不保证所有隐私都能识别；这就是默认要求人确认、预览完整内容的原因。
- 社区端的回复会进入智能体上下文，因此一律标注为外部引用，不当作指令。
- 本期不做截图和文件附件、不做与 GitHub 的同步、不做公开看板。
