# 使用扩展

扩展给智能体和 NekroNXT 增加新能力：智能体可以调用的工具、新的聊天平台、频道检查器里的面板、工具结果的展示方式，以及独立页面。一个扩展可以同时提供其中几样。扩展可以让智能体现场做出来，也可以从 NekroNXT 社区安装。

## 让智能体做一个扩展

1. 在智能体资料的“能力”里打开动态创造；
2. 在它的频道里用平常话说出需要，例如“做一个查天气的工具”；
3. 智能体开始动手后，任务会出现在「工坊」。任务页显示进度、每一次尝试和实际效果预览；
4. 带界面的扩展需要在任务页点击“允许运行”，并保持页面打开直到试运行完成。等待你确认的任务也会出现在「概览」的需要关注中；
5. 试运行通过后，任务页会显示“可以保存”。没通过时智能体会自己接着修，不用再催；
6. 保存成新扩展。智能体还在收尾时，保存按钮会等它完成。

试运行、保存、安装和启用是分开的四步：试运行通过不等于已保存，保存后也还没有启用。

扩展有配置项时，可以在任务页的“测试配置”里填写试运行用的值，你填的值优先于智能体填的。API Key 这类凭据可以选择“设置 → 凭据”里已添加的凭据，也可以单独填写；局域网内的服务地址只能由你填写。这些值只用于试运行，保存成扩展后在扩展详情里重新填写。

要修改已经保存的扩展，在频道里直接说要改什么，智能体会以当前版本为基础开一个修改任务，保存后成为这个扩展的下一个版本。也可以在扩展详情的谱系里选一个版本，点“让智能体在此基础上修改”。

对话结束（重置上下文、换了会话）时，进行中的任务会暂停而不是丢失。在频道里说“继续那个任务”，智能体会把它接到新的对话里；最新候选已经验证通过的，任务页上可以直接保存。暂停 30 天没有继续的任务会自动归档。

## 在聊天里管理扩展

智能体能自己做到哪一步，由智能体资料“能力”里的“扩展自主权”决定：

- **手动**：只开发和试运行，保存、启用等由你在工坊里完成；
- **管理员确认**：保存、启用、切换版本等每一步，智能体都会在频道里发出请求，管理员回复 `/ext approve 编号` 同意或 `/ext reject 编号` 拒绝，24 小时内有效；
- **自主**：只影响它自己的普通操作直接完成，并在频道里留下记录和撤销方法。智能体做出的候选也会直接试运行，不用你去任务页点“允许运行”。

选择“管理员确认”或“自主”后，智能体可以发现和管理本机已保存的扩展，包括其他智能体创建的扩展，并为自己启用或停用。手动档只查看自己创建、使用或正在修改的扩展。共享扩展代码不会复制其他智能体的配置、凭据或私有数据；缺少本机配置时，智能体会提示你先到工坊的扩展详情填写；扩展要求智能体自己的配置时，智能体可以在启用时一起填写；凭据可以启用后再绑定。

带界面的候选试运行时要在浏览器里加载界面并检查。开着任何一个 NekroNXT 页面都可以，不必停在任务页。一个页面都没开时：

- 在“设置 → 界面检查”里下载后台浏览器（无头 Chromium，约 100 MB；服务端镜像已自带），由 NekroNXT 在后台完成检查；
- 没有下载时，候选照常运行，任务页标为“界面未检查”，保存前请先在预览里确认能用。

每次验证候选的工具时，NekroNXT 会在频道下开一个名为“验证 工具名”的子对话，按固定步骤把每个工具调用一次。任务页的“验证对话”和频道列表里都能点开它，查看每次调用的输入和结果。

不是自主模式时，管理员可以在任务页点“允许运行”，也可以在聊天里发送 `/ext run 任务名称` 允许、`/ext reject 任务名称` 拒绝。

不管哪一档，新增高风险权限都要在后台批准；发布到社区、撤回发布、迁移或复制扩展数据，以及会影响其他智能体的操作，都要管理员确认。还可以设置“谁可以让它做扩展”为只有管理员。

智能体也可以修改扩展配置，每次修改都会留下记录。“谁可以让它改配置”默认只有管理员；设为所有人时，群友只能让它改它自己的普通配置项。本机配置、访问地址和需要同意的凭据由管理员确认，扩展标为仅管理员的配置项只能在扩展详情里修改。新配置让扩展无法启动时，会退回原来的配置。

管理员在“设置 → 管理员”里配置：登录这个控制台的人始终是管理员，另外可以从用户里添加平台账号，或者生成认领码，用自己的账号在聊天里发送 `/admin claim 认领码`。群主和群管理员不会自动成为管理员。等待确认的请求也会出现在「工坊」列表顶部。

`/ext` 还可以在聊天里查看和操作扩展：`/ext` 列出智能体的扩展和进行中的任务，`/ext info 名称` 查看版本与同步状态，管理员可以用 `/ext enable`、`/ext disable`、`/ext use 名称 v2`、`/ext revert 名称`、`/ext run 任务名称`、`/ext save`、`/ext continue`、`/ext update`、`/ext publish`。

## 安装与启用

- 带页面或平台的扩展，在扩展详情里安装到本机；
- 给智能体用的工具，在扩展详情或智能体资料页为某个智能体启用。还没安装的扩展会在这时一起安装；
- 扩展申请了权限时，会先请你批准。对整台机器生效的在安装时批准，只对某个智能体生效的在启用时批准。

每台机器上一个扩展只用一个版本。在扩展详情的“当前版本”或谱系里切换，所有用它的智能体会一起切过去，各自的配置在新版本里仍然有效时会保留。切错了可以点“回到上一个版本”。

扩展有配置项时也在扩展详情里填写：“本机配置”所有智能体共用（比如 API Key），“智能体配置”每个智能体各有一份。凭据字段选择“设置 → 凭据”里已添加的凭据，也可以就地新建，或单独填写一个值；本机配置只能选择对全部智能体开放的凭据。每一层配置下方有“配置历史”，列出每次修改的时间、来源和原因，展开可以看到改了什么；“恢复到这一版”会把那一版的配置保存为最新的一版。

## 版本、分支与导出

每次保存都是一个新版本，接在它修改的版本之后，编号按先后为 `v1`、`v2`……；同一个版本被改了两次、各自保存时，第二个写作 `v2·2`。扩展详情的“谱系”把这些版本画成一棵树：实心点是正在用的版本，`#n` 是它在社区上的发布编号。点一个版本可以切换过去、让智能体在它的基础上修改、从它创建分支、发布到社区或导出成 `.nxt-extension` 文件。

分支是从某个版本另起的一个新扩展，可以选择复制原扩展的数据，之后两边分开修改。分支还可以再分支，谱系里能看到整个家族。想保留原扩展、另做一个不同方向的版本时用分支；只是修问题或加功能就直接修改原扩展。

导入入口在「工坊」列表顶部，导入后需要手动启用。V7 之前的旧格式版本标为“格式不受支持”，不能启用或安装。

## 扩展的数据

表情包这类扩展的价值在于长期积累的数据。扩展详情的“数据”显示记录、索引和素材的数量，以及数据格式的版本。

- 新版本改了数据格式时，切换过去会自动升级数据，切换前留一份快照；升级失败会恢复快照并退回原版本。数据已经升级后，切回读不懂它的旧版本时，需要同时恢复一份旧格式的快照；
- 可以随时留一份快照，也可以从快照恢复。每个扩展保留最近 3 份；
- “迁移与导出”可以导出数据（可选连同配置），在另一台机器上导入；也可以从另一个扩展迁入，例如把原版的数据迁到分支。迁移有两种方式：**覆盖**保留目标已有的数据，同一条记录以来源为准；**替换**先清空目标再写入。执行前会显示会新增、覆盖和删除多少条，会覆盖或删除数据时需要输入扩展名确认，并且先留一份快照。API Key 等凭据不会被导出或迁移。

## 处理智能体发出的消息

有些扩展会在智能体的消息发出前加工它，例如翻译、配音、加署名，或者在内容不合适时取消发送；也有扩展只在消息发出后记录。启用这类扩展时会单独确认：能修改或取消消息的算高风险，只读算敏感；扩展声明了「出错时不发送」的，确认页会提示这个扩展出错时消息会发不出去。

被扩展改过或追加的消息，时间线上标出「经 X 处理」或「由 X 追加」。被取消的消息不进时间线，智能体会收到取消原因并可以改了再发；点开对应的发送步骤能看到原来的内容和原因。

同一个智能体启用了两个以上会修改消息的扩展时，扩展列表下方出现「消息处理顺序」，用上移、下移调整；默认按启用的先后。

## 扩展页面

保存后的页面在扩展详情安装后才能打开，入口在顶栏「搜索」（`⌘K`）的“扩展页面”和扩展详情的“打开”。扩展可以把页面放进左侧导航。

页面能读写什么、能访问哪些网址，都在安装前列出。新版本申请了更多权限时，旧版本继续运行，直到你批准新的权限。

## 平台扩展

扩展可以提供一个新的聊天平台。安装后，它会出现在「接线 → 添加账号」的平台列表里。卸载会停止这个平台的收发，账号、频道和聊天记录都会保留，重新安装后自动恢复。

## 社区与官方扩展

「社区」里可以浏览、搜索和安装扩展，打开“只看官方”只列出官方扩展；「我的发布」用来查看自己的发布和审查结果。从社区安装的扩展同样需要手动启用。

本机装过的扩展在列表里标“已安装”，社区有新发布时标“可更新”。读过的列表和详情 5 分钟内直接显示，点“刷新”重新读取；连不上社区时显示上次读到的内容并注明时间。

「同步」列出本机安装和发布过的社区扩展，按谱系比较本机版本和社区最新发布：已同步、社区有更新、本机有修改，或者两边都改了。社区有更新时可以直接更新（作为新版本导入并切换）；两边都改了时，可以让智能体把社区的改动合进本机版本，保留本机，或者改用社区版本。

发布到社区时，这次发布要接在上一次发布之后；如果社区上已经有更新的发布（比如你在另一台机器上发过），先更新或合并再发布。别人发布的扩展不能直接发布新版本，先从它创建分支，再发布分支，社区上会标明它分支自哪里。

官方扩展由 NekroNXT 团队维护，包括掷骰抽签、网页搜索与阅读、图片生成、语音合成、今日运势、节日提醒、RSS 订阅、群管和消息守卫，源码在 [nekro-nxt-extensions](https://github.com/NekroAI/nekro-nxt-extensions)，也可以当作编写扩展的参考。

遇到扩展问题，可以在「社区 → 反馈」新建反馈，或从社区网站的扩展详情页选择「反馈问题」。已有相同问题时可标记「我也遇到」并跟踪状态。作者在网站的「收到的反馈」中查看和处理，详情见[社区反馈](community-feedback.md)。

## 安全

动态创造本身不让智能体读写文件或运行命令，这些要在“能力”里另外打开。平台扩展运行在 NekroNXT 程序里，只安装你信任的来源。

## DSH 插件

“设置 → DSH 插件”可以安装 npm 上的 DSH 插件、npm tgz 包或 DSH 的 `.nxt-extension` 文件。插件装好后默认关闭，每个入口可以选择在本机启用，或者只给某个智能体启用。依赖要运行安装脚本时会逐项请你批准。

插件有配置界面时直接在设置里填；没有的话可以填高级 JSON。DSH 插件自带的网页界面不能在 NekroNXT 里使用，其他功能照常。

从 npm 安装、版本与当前 DSH 一致的 `@deepseek-ai/` 插件是官方插件，详情里标“官方插件”，并列出它获得的服务，例如 agents、sessions。其他插件拿不到这些服务；需要它们的入口显示“缺少服务”，并说明“需要 X 服务，只对官方插件开放”。上传的 tgz 即使同名也按其他插件处理。入口依赖其他插件提供的服务时显示“等待 X 服务”，对方启用后会自动加载。

有些插件会在对话里留下只有它能读懂的内容。只要还有对话含有这些内容，这个插件就不能关闭或移除，否则这些对话将无法恢复。
