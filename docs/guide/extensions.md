# 使用扩展

工具、适配器、Preset、MCP 接入和界面贡献（面板、工具视图、富消息渲染器、页面）都属于同一 Extension 体系，**一个扩展可以同时提供它们**：它在本机有一份运行实例（页面、适配器、界面数据接口），并给每个启用它的智能体提供工具与智能体界面。扩展清单只支持 V7。扩展可以由智能体现场创造，也可以从 NekroNXT 社区安装。

## 动态创造流程

1. 为目标智能体开启动态创造权限；
2. 在该智能体的频道里，用日常语言描述需要的新工具或界面；
3. 智能体开始创造后，任务出现在「工坊」，任务页显示进度、当前候选、各次尝试和真实预览；
4. 含界面的候选需要在浏览器中确认运行并加载界面才能完成验证，验证期间保持任务页打开；等待确认的任务会出现在「概览」的需要关注中。普通智能体第一次运行含界面的候选时，在任务页点击“允许运行”；同一任务的后续候选没有扩大页面、权限或资源风险时会自动继续。审批策略设为完全自动的智能体始终自动运行；
5. Host、Client、工具调用、页面声明和权限全部验证成功后，任务进入可保存状态。界面贡献在浏览器中真实渲染：每个面板按声明的尺寸在浅色和深色下各渲染一次，工具视图渲染摘要和卡片两种形态；渲染出错或横向溢出都会使验证失败。工具和界面数据接口会用智能体提供的验证样例真实调用一次；没有样例时以空输入调用，所以带必填参数的工具需要样例。验证失败的候选会被停止，失败会显示准确阶段和错误，并把结果交回原智能体自动修复，不需要再发送“继续”；
6. 可以把当前候选保存成新扩展，也可以给现有扩展增加不可变修订（适配器 key 不能改变）。只有任务的最新候选通过验证后才能保存；智能体追加了尚未验证的新候选时，保存入口会说明原因，任务页会提供“回到第 N 次”，以相同内容重新运行验证后即可保存。保存时会再用本机运行验证执行一次保存后的产物，失败则不生成修订；
7. 有页面或适配器的扩展在扩展详情安装到本机；工具与智能体界面在扩展详情或智能体资料页为指定智能体启用，尚未安装的扩展会在这时自动安装。扩展声明了权限时先批准：对整台机器生效的部分在安装时批准，只对某个智能体生效的部分在启用时批准。

动态运行、保存扩展版本、安装到本机和给智能体启用是独立提交点。试跑成功不等于已经保存，保存也不等于已经启用或安装。每台机器上一个扩展只有一个当前版本：切换版本会带上所有正在使用它的智能体，各自的配置在新版本仍有效时保留。

候选通过运行验证后，智能体还会收到一次 Host 结果并完成收尾。任务页在智能体回到空闲前提示它正在收尾，不会开放保存；Server 保存入口也会等待该任务的自动续跑静止，再重新核对用户选择的精确候选。收尾期间如果智能体追加了新候选，旧候选保存请求会被拒绝，不能把已过时的页面悄悄写成本地扩展。

每个开发任务和候选都写入本机持久账本，源码位于该智能体的 `workspaces/<agentId>/authoring/`。Host 重启会从精确候选源码恢复仍在进行的任务；无法恢复的任务，以及候选生成后超过 72 小时仍未保存的任务，会明确标记为中断，需要时在频道里让智能体重新运行即可。停止任务会先静止当前 Runtime，删除任务会把源码原子移入受管回收目录后再删除账本，任一步失败都不会留下“界面已删、运行或源码仍失控”的半完成状态。保存使用任务和候选身份，不再由页面猜测当前 Episode 里的某个 Package。

任务摘要中的当前候选始终指向最后一次 Attempt；它通过验证后可以同时成为当前运行版本，因此 `candidateAttempt` 与 `activeAttempt` 可以是同一身份。含界面的候选在浏览器刷新后会从 Host 的精确 active Run 重新加载源码和页面，不重复启动 Host 或审批。页面 CSS 作为候选资源统一预检，动态预览由 Host 自动注入到隔离根，保存时自动接入 Revision 的 Client 构建；用户不需要在动态源码中编写构建期 import。

一个扩展最多提供一个适配器，平台 key 在版本之间不变；同一个扩展还可以给智能体提供配套工具（例如平台管理工具）。安装后平台出现在「接线 → 添加账号」的平台列表中；更新和回滚都显式选择 Revision。卸载会停止该平台收发并移除富消息渲染器，但保留连接、凭据引用、频道和历史；重新安装相同 key 后自动恢复。

专属页面的动态预览在工坊任务页内运行；保存后仍处于未安装状态。用户在扩展详情查看整组权限，批准并安装后，页面可以从顶栏「搜索」（`⌘K`）的“扩展页面”或扩展详情的“打开”进入；扩展页面不自动进入导航轨，只有扩展自己为某个页面声明 `rail`（可选 `order`，越小越靠前）时，安装后才出现在导航轨的内置空间下方；窄屏底栏只放内置空间，扩展页面仍可从搜索与扩展详情进入。页面可以使用声明式对象列或全宽主画布，不能替换导航轨、顶栏、状态栏、Composer 或频道画布。

专属页面默认使用 NekroNXT UI Kit 和语义 Token，也允许语义正确的原生控件。Host 提供页面背景、安全边距、根滚动和对象列。预览中的组件、边距、标题和溢出检查仅提供视觉建议；空白页面、运行错误与权限越界仍使验证失败。

V7 之前保存的旧格式版本标记为“格式不受支持”，不能启用或安装；旧格式的 `.nxt-extension` 文件也不能再导入。需要时从社区获取新版，或让智能体重新创造，再保存为同一扩展的新版本。

页面权限绑定所选 Revision 的精确内容摘要。普通读取、高敏消息/资源读取、非破坏性产品写入和网络 origin 会在安装前完整展示；升级增加权限时，现有 Revision 保持运行，直到用户批准新权限。页面不能删除产品对象、卸载扩展、读取 Credential 明文、访问 SQLite 或宿主路径。扩展状态使用 owner 隔离的受管命名空间；网络请求由 Server 校验获准 origin 和实际公网地址。

扩展可以在包内自带图标（Manifest `icon`，见 [扩展包格式](../../packages/extension-format/README.md)），在工坊、社区和智能体的扩展列表中显示；没有图标时显示名称首字和由扩展身份决定的固定配色。

本地扩展详情列出全部版本，每个版本可展开查看能力与验证记录，并单独导出为 `.nxt-extension` 分享包。扩展声明了配置项时，在详情中编辑：“本机配置”对整台机器生效（例如共用的 API Key），“智能体配置”每个启用它的智能体各有一份。导入入口在「工坊」列表顶部；导入会预检身份、摘要、文件清单和压缩包安全，并在本机重新构建；导入结果默认未启用。同一身份和摘要重复导入是幂等操作，同一身份对应不同内容时拒绝覆盖。扩展详情底部的“删除扩展”会停止全部智能体的使用并卸载扩展，然后把源码移入受管回收目录并删除扩展、修订、验证和诊断；任一步失败都会恢复原状态。

## 社区与官方扩展

「社区」空间连接 NekroNXT 社区：在「发现」中浏览、搜索和安装扩展，打开「只看官方」可只列出官方扩展；「已安装」检查新发布、作者撤回与下架；「我的发布」把本地扩展发布到社区并查看审查报告。发布时可以填写或修改一句话简介、详细介绍（Markdown）、标签和源码地址；扩展详情优先展示这些作者填写的内容，审查结果只显示一行状态与摘要，展开后查看全部发现。社区安装走与本地文件导入相同的检查与确认，安装后不会自动启用。连接测试站等其他社区时，在「社区 → 账号」页面底部更改社区地址。

官方扩展由社区后台认定、官方团队共同维护，发布者显示为「NekroNXT 官方」。第一批官方扩展覆盖掷骰抽签、网页搜索与阅读、图片生成、语音合成、今日运势、节日提醒、RSS 订阅、群管和消息守卫，源码在 [nekro-nxt-extensions](https://github.com/NekroAI/nekro-nxt-extensions)，也是编写扩展的参考样例。

## 安全边界

动态创造本身不授予开发 Shell、文件读写或完整文件访问。Adapter 动态验证使用无网络 Fake Host/HTTP/WebSocket，证明 Host 契约成立，不代表真实平台已经验收。Adapter 仍在 Server 进程内运行，当前安装来源应视为受信任本地代码。

## DSH 兼容

NekroNXT 优先通过 DSH 公开 Plugin、Service、Tool、Provider、Settings、Scope、Bundle 和 Preset 接缝运行能力插件。产品元数据和中文界面只增强体验，不应成为加载 DSH 能力的前提。

“设置 → DSH 插件”支持检查并安装精确 npm 版本、npm tgz 和 DSH `.nxt-extension`。依赖安装默认禁用脚本；只有检测到被阻止的构建依赖时才逐项请求批准。插件安装后处于关闭状态，普通入口由用户选择本机或指定智能体作用域，Bundle 的每个入口独立选择。关闭、配置更新、冷启动恢复和移除均由 DSH Loader 执行，并以官方 Inventory 的真实状态作为结果。

插件 Config 优先使用可序列化 Schema 表单；没有 Schema 时提供高级 JSON。含 `secret` 或 `credential-ref` 的 Config 不兼容这条持久化路径，插件应改用 DSH Settings/Credentials。DSH 原生 WebUI 不在当前产品中加载；检测到 Client UI 时显示说明，不影响 Host 能力。DSH 包只有显式声明 `nekroNxt.hostUi`，并且对应 Host 入口成功启用和完成权限批准后，才发布 NXT 页面；浏览器 Client 故障形成页面诊断，不撤销已经生效的 DSH Host 能力。已安装 DSH 插件可以导出分享包，目标机器按锁摘要联网重装依赖，不携带 `node_modules` 或跨平台原生构建产物。
