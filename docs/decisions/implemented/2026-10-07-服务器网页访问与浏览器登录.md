# 服务器网页访问与浏览器登录

状态：implemented（2026-10-07 用户确认并实施）

## 问题

用户反馈服务器部署没有可访问的网页界面。容器确实托管同包 Web，但安全入口要求设备会话，而建立会话的配对协议只由 Desktop 主进程实现：普通浏览器打开后先遇到自签名证书警告，信任后只得到一段「请先建立设备会话」的 JSON，没有任何登录入口。

## 用户已确认的取舍

1. 保留证书支持，但浏览器可以继续用 HTTP 访问网页界面；非安全连接在页面上提示风险，用户知悉后继续使用。
2. 浏览器登录直接使用现有管理密钥，不新增账号体系。
3. 提供已登录设备列表、可撤销会话，并显示最后活跃时间。

## 决定

### 同一端口同时接受 HTTPS 与 HTTP

安全入口在一个 TCP 监听上按连接的第一个字节分流：TLS ClientHello 总以记录类型 `0x16` 开头，交给使用自动自签名证书的 HTTPS 服务；其他交给 HTTP 服务。两者共用同一套路由与鉴权。Desktop 的 `auto-tls-pinned-v1` 实例描述、证书指纹固定和 HMAC 配对不变；`http://` 不需要任何配置即可使用。

请求是否安全由连接决定：TLS 连接为安全；`NEKRO_TRUST_PROXY=1` 时，另外信任反向代理传来的 `X-Forwarded-Proto: https` 与 `X-Forwarded-Host`。同源校验按实际协议与公开主机比较 `Origin`，代理到内部 WebServer 的 `X-Forwarded-Proto` 也随之如实填写。

### 浏览器登录

- 未登录时，页面请求（GET/HEAD、非 `/api/`、接受 HTML）302 跳转 `/login?next=原路径`；API 仍返回 401，Web 的统一请求函数收到 `authentication_required` 时在普通浏览器中跳转登录页，Desktop 内不跳转。
- `/login` 由安全入口直接返回自包含的登录页（内联样式与脚本，严格 CSP），不加载产品界面或扩展代码，管理密钥只输入到这个页面。非安全连接时页面先显示风险说明，勾选「我了解风险」后才能提交；服务端同样要求 `acknowledgeInsecure`。
- 浏览器在 HTTP 页面里没有 Web Crypto，无法计算 HMAC 证明，因此登录接口 `POST /api/management/login` 直接校验提交的管理密钥（常量时间比较），与配对挑战共享每地址每分钟 10 次的限额。
- 登录成功登记一台「浏览器设备」，名称取自 User-Agent（如「浏览器 · Chrome · macOS」）。设备凭据写入 HttpOnly 的 `nxt_device` Cookie，有效 30 天，页面与扩展脚本读不到；会话只在内存，过期或服务重启后入口用设备 Cookie 自动续开会话。
- Cookie 统一 `SameSite=Lax`，从其他页面的链接进入时仍保持登录；只在安全连接时加 `Secure`，否则浏览器在 HTTP 下不会保存。写操作的保护不变：同源 `Origin` 加 CSRF 令牌，普通浏览器由 Web 从 `nxt_csrf` Cookie 读出令牌附加到请求头。

### 登录设备

- 设备的最后活跃时间按请求更新，每台设备每分钟最多写一次数据库。
- 「设置 → 登录设备」只在经过安全入口时出现（本机直连的 Host 查询会话得到 404 时隐藏），列出未撤销的浏览器与 Desktop 设备、登录时间与最后活跃时间，并标出「此设备」。撤销其他设备立即使其会话失效；「退出登录」撤销本浏览器设备并清除 Cookie。
- 普通浏览器经非回环地址以 HTTP 访问时，底部状态栏常驻「未加密连接」，点击进入「登录设备」；该页同时显示风险说明。顶栏实例名在普通浏览器中显示访问地址，本机访问仍显示「本机」。

## 不在此决定内

- 自定义证书文件与 ACME：需要可信证书时由反向代理提供。
- 多用户、角色与权限：管理密钥代表完整管理权。
- 浏览器设备的服务端过期清理：Cookie 30 天到期后设备留在列表中，可手动撤销。

## 验证

Server 测试覆盖同端口 HTTP/HTTPS、未登录页面跳转与 API 401、风险确认、错误密钥、限流、Cookie 属性、设备 Cookie 续开会话、同源与 CSRF、设备列表与最后活跃、退出即撤销、可信代理与未开启时忽略转发头。浏览器测试覆盖登录设备列表、撤销与退出；生产构建以局域网地址实测 HTTP 登录、风险提示、未加密标记、刷新保持登录与退出后重新跳转登录页，HTTPS 同端口可用。
