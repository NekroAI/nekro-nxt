# 已实施：Handoff 失败降级与最近窗口恢复

状态：implemented

## 结论

DSH 原生 Compaction 继续使用 0.1.1-rc.2 默认策略，NekroNXT 不覆盖其默认 `maxTokens`、阈值或近期尾部保留策略。NekroNXT 自有 Episode handoff 只负责 Revision/Session 边界切换，不复制或重写 DSH Compaction。

Handoff 摘要请求不再设置 NekroNXT 自有 `maxTokens` 上限，仅在提示层建议尽量压缩；请求使用 180 秒取消边界。摘要为空、只产生 reasoning、达到 Provider 结束边界、失败或超时，都降级为结构化 fallback，不阻断新 Episode 和当前消息 Admission。

## 最近窗口

Handoff 持久化 `recent_event_ids_json`，保存旧 Episode 边界前最近的 Channel Event。新 DSH Session 收到一条带有 `nekro-nxt-handoff` 来源的恢复消息，其中分别包含：

- 模型摘要或确定性 fallback；
- 最近频道原文窗口，保留稳定 Event ID 与结构化内容；
- 使用 `conversation_history_search` / `conversation_history_read` 回查更早内容的指引。

当前触发 rollover 的 Event 只通过新的 Admission 注入，不重复放入 recent window。历史原文仍由 Core Channel Event 所有，handoff 只保存来源 ID，不复制第二份领域事实。

## Admission 恢复

Admission 在 Episode rollover 前创建为 pending；handoff 事务提交时，仍处于 pending/claimed 的 Admission 随目标 Episode 一起迁移。运行时恢复还会扫描当前频道中尚未被已完成 Admission 引用、且符合当前 Binding 触发事实的事件，补建批次并按 lane 准入。这样即使进程在 Channel Event 提交与 pending Admission 创建之间退出，也不会永久依赖 Gateway 重放；DSH Session 仍由其公开生命周期负责恢复和幂等核对。

## 后续来源修复

Handoff 摘要输入已进一步收敛为旧 Episode 实际 `logged-to-session` Admission 与该 Episode Outbound，不再读取全频道最近 100 条；上一份 handoff、频道原文和智能体历史出站分区标注，边界锚点按 Event ID 去重。每个 Session 同时获得 Host 权威频道身份，摘要注入明确属于派生记录。完整实现与事故处置见《频道身份与 Episode 交接来源修复》。

## 未来与边界

保留 DSH `BasicCompactionEngine`、`ToolResultPruner`、Session Event Log 和公开历史工具接缝；不自行设置 DSH 压缩上限，不替换官方 Compaction，不把模型摘要当作原始消息事实，也不把提示词当作权限边界。
