# NekroNXT 文档公开边界

## 1. 公开仓库保存什么

公开 Git 仓库只保存能够独立解释 NekroNXT 的内容：

- 产品目标、术语和用户体验；
- 当前架构、公共协议和领域模型；
- Extension、Adapter、Channel Runtime 和 DSH 公共集成设计；
- 一期计划、Decision Notes 和未来方向；
- UI、动效、原型和公开贡献约束；
- 能够在公开环境复现的测试、示例和构建说明。

公开设计可以引用公开项目、公开 Issue 和公开 API，但只记录 NekroNXT 真正依赖的公开契约。第三方仓库的临时提交、相邻本机路径和大段源码调查不属于公开事实源。

## 2. 本地私有资料保存什么

以下内容统一放入 Git 忽略的 `.local/`，不得进入提交、PR、Issue、构建产物、测试、原型、文档、注释或公开日志：

- 私有、企业内或未获公开授权的参考项目名称、地址、提交和源码分析；
- 客户、租户、账号、内部业务、组织结构和产品路线信息；
- 真实入站消息、聊天记录 dump、个人昵称、群名、头像/文件哈希、平台临时 CDN URL、`rkey` 一类资源票据；
- 本机绝对路径、相邻仓库布局和个人开发环境快照；
- Token、Secret、证书、签名、Credential、内部 IP、域名和端口；
- 本地 AI 工作流、个人接管记录和一次性分析提示；
- 生产部署、运维、排障、备份恢复和发布凭据；
- 已被替代但仍需个人追溯的历史调研与归档。

公开专题文档不得链接 `.local/` 的具体资料，也不能要求贡献者拥有这些资料才能理解、构建或测试项目。根 `AGENTS.md` 只保留到可选 `.local/README.md` 的一级路由，使本机私有文档进入同一知识图；该路径不披露索引内容，干净检出缺少 `.local/` 时公开检查仍独立成立。需要拦截个人标识时，把字符串写入 `.local/forbidden-patterns.txt`（Git 忽略）；根检查 `check:public` 会扫描跟踪文件。平台用户内容 CDN 主机名由该检查内置拦截，不把真人真消息写进规则本身。

## 3. 从私有参考提炼公开结论

允许把本地经验转化为 NekroNXT 的原创设计，但必须完成脱敏：

```text
私有来源中的机制
→ 去掉项目名、地址、提交、客户、真人标识和业务背景
→ 用 NekroNXT 自己的对象与约束重新论证
→ 只保留当前项目真正采用或拒绝的结论
→ 写入公开专题文档、Decision Note，或合成后的测试夹具
```

真实平台 payload 只用来理解协议标记。写进仓库的测试、原型和示例必须改写为虚构发送者、标题、文件名和 `*.test` 主机；可以保留公开协议记号（如 `[群聊的聊天记录]`、`[卡片消息]`），不得原样粘贴一次真实入站。真实账号验收留在本机，不入库。细则见 `06-开发与测试规范.md` §5。

“某私有项目这样实现”不是公开设计的理由。公开文档必须让外部读者仅凭 NekroNXT、DSH 公开契约和可验证行为理解决定。

## 4. 推送前检查

每次向公开远端推送前至少检查：

1. `git status --short`：确认没有意外文件；
2. `git diff --cached --name-only`：逐项确认实际提交范围；
3. 搜索私有项目名、本机路径、内部地址、凭据字段、部署细节、真实昵称、入站 dump 和平台用户 CDN；
4. 检查新增图片、压缩包、数据库、日志和二进制元数据；
5. 检查 Git 历史，而不只检查当前工作树；
6. 使用全新目录从待推提交检出并运行公开构建/链接检查。

发现敏感信息进入尚未公开的本地历史时，重建干净公开历史；发现已经推送时，立即轮换相关凭据并清理远端历史，不能只追加删除提交。

## 5. 目录约定

```text
docs/           # 公开、可独立理解的现行事实与设计
docs/archive/   # 冻结的立项快照与过程记录，不是现行规范
.local/         # 本地私有资料，Git 忽略
data/           # 本地运行数据，Git 忽略
```

需要团队内部共享私有资料时，应使用独立受控仓库或文档系统，不通过公开仓库的隐藏目录、分支、Release、Issue 或附件传递。
