# 已实施：M3 同一智能体的创造运行时

状态：implemented

## 结论

一期 M3 已在真实 DSH rc.6 Host/Client Runner 上打通动态创造运行时。创造不是另一个智能体或独立用户模式，而是同一智能体的不可变 Revision 获得相关授权后，可以在自己的 Session 与 Scope 内定义、运行、更新、验证和停止动态 Contribution 的状态。

## 已落实边界

- `dynamicCreation`、`developmentShell` 和 `fullFileAccess` 是三项独立授权；四种关键组合均有测试，不会因为启用动态创造就隐式获得 Shell 或完整文件权限；
- `dynamicCreation` 只挂载 DSH Dynamic Cordis 与 Inspect；`developmentShell` 挂载受 workspace-write 约束的一次性 Bash/FS 工具；`fullFileAccess` 只提升已存在文件能力的策略，不凭空启用 Shell；
- DSH Host 仍要求显式获得绝对 `developmentWorkspaceRoot`，不会把宿主当前目录当隐式工作区；生产 Server 组合根默认将其配置为 `<dataRoot>/workspaces`，再为每个智能体自动创建隔离的 `<agentId>` 子目录，因而普通用户不需要额外环境变量；
- NekroNxt Inspect 只公开当前智能体 Revision、频道身份、授权和扩展生命周期规则，不公开数据库、Session Registry 或其他智能体上下文；
- Dynamic Context 隔离 `agents`、`sessions`、`llm`、`sandbox` 等 Host 私有 Service；动态插件声明注入这些服务时，运行会停止并返回可诊断失败；
- 持久 Extension Host 只获得最小 `tools` facade，`apply()` 不接收真实 Agent Context；
- Client Half 复用 `@deepseek-ai/dsh-client-modules`、`dsh-client-runtime`、`dsh-cordis-client-runner` 和 Cordis Loader；没有自研第二套审批、Slot 或 closure evaluator；
- lockfile 固定的 DSH Client bundle 经官方 Module System 注册与物化，并安装 `@deepseek-ai/dsh-client-web-react` 官方 Renderer，支持 approval、decline、Slot 注册、生产浏览器真实渲染、retract 和清理；
- DSH Client ModuleLoader 是页面单例；产品使用一个浏览器 Runtime，并只协调创造工作台当前选中的智能体。切换智能体先 retract 旧会话清单再加载新清单，避免不同会话可能重复的短 `pluginId` 发生归属碰撞；
- 动态运行、保存为本地 Extension Revision、给智能体启用是三个独立动作。M3 不因一次动态运行而自动保存或 Activation。

## 验证证据

- 两个智能体的动态 Scope 相互隔离，停止后 effect 和 Slot 均清理；
- 三项授权组合、缺失工作区拒绝、workspace-write 与完整文件策略有确定性测试；
- Host Half 的 define/run/update/stop、Client approval/decline、真实渲染和 retract 均使用 DSH 公共包验证；
- 真实创建的“插件链路验证”智能体在单轮对话中自行 Inspect、定义 `nxtp-1`、调用 v1、原地 update 到 v2、再次调用、stop 并通过 `send_message` 汇报；全程没有 Shell、文件访问或进程重启；
- 生产构建 Playwright 旅程从 Creator 审批按钮出发，经真实 DSH Client Runner 加载 Client 源码、渲染 Root Slot，并在 stopped 清单到达后 retract；
- Dynamic 或 Persistent Extension 请求私有 Service 会被拒绝，正常 Tool 注册仍可工作；
- 当前全仓 `pnpm check`、`pnpm test` 和 `pnpm build` 通过。

## M4 接缝与明确未做

M3 保留 Dynamic Package 捕获、源码边界、目标智能体 ID、安全切换点和可逆 Client Contribution，供 M4 的 DraftPackage、ExtensionRevision 与 AgentActivation 使用。本记录不把源码保存、构建缓存、重启恢复或 Activation 声称为 M3 行为。

## 未来方向与参考取舍

关联方向：更多 Extension Contribution、Process/Remote Runtime、社区分发、长期 Job 和智能体自开发。

保留接缝：DSH Scope、公开 Runner、独立权限、稳定 Slot、可替换 Host policy 和动态/持久生命周期分离。没有 Fork DSH、复制 Registry 或向扩展暴露 Core 数据库，因此未锁死未来 RuntimeKind 和社区插件通用性。

本次明确不提前实现：任意 npm 依赖、完整供应链审批、Process 隔离、社区签名和自动发布。

参考 DSH rc.6 的 Cordis Dynamic Host/Client Runner、Inspect、Scope、Sandbox 和 Tool 生命周期；借鉴其公共 Service 边界，拒绝读取私有表、复制 closure evaluator 或以提示词代替权限控制。
