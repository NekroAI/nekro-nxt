# 响应时机与智能响应

状态：accepted（2026-10-31，已实施，尚未发布）

## 决定与理由

群友常把一句话拆成几条发：先 @ 一下，隔几秒再说正事。原来的触发规则只看单条消息：@ 的那条立刻开一轮，后面没 @ 的几条在「提及或回复时」下叫不醒智能体。结果是它要么对半句话抢答，要么想等却再也等不到。只靠提示词让它「先不回」会把人晾着，因为没有任何东西会再叫醒它。

「什么时候该说话」原来散在几处：四种响应方式、定时任务唤醒、平台活动唤醒、扩展入站钩子。这次把它们收成一个模型，再在上面加两样东西：所有响应方式都有的「等对方说完」，以及新的响应方式「智能响应」。

一次唤醒由三件事决定：

- **信号**：强信号是 @、回复智能体、命令、定时任务；中信号是提到智能体的名字或别名、刚和它说过话的人接着说；弱信号是话题和它有关（后续阶段）。
- **回应义务**：必须回，或者可以不回（沿用[消息内容与投递协议](../../03-消息内容与投递协议.md)的回应义务，中信号和定时任务一样只唤醒、不建立义务）。
- **时机**：马上开始、等对方安静一会儿（防抖）、或者在等待中。

响应方式是这三件事的预设组合。

| 行为 | 每条消息 | 提及或回复时 | 智能响应（新增） | 平台命令事件 / 仅观察 |
| --- | --- | --- | --- | --- |
| @、回复、命令、定时任务 | 必须回 | 必须回 | 必须回 | 只认命令 / 不唤醒 |
| 普通消息 | 必须回 | 不唤醒 | 不唤醒 | 不唤醒 |
| 等对方说完 | 有 | 有 | 有 | 无 |
| 提到名字或别名 | — | 不唤醒 | 唤醒，可以不回 | 不唤醒 |
| 注意力窗口 | — | 不唤醒 | 唤醒，可以不回 | 不唤醒 |
| 防抖 | 无 | 无 | 有 | 无 |
| 中信号频率上限 | — | — | 有 | — |

| # | 决定 |
| --- | --- |
| R1 | 触发判断拆成「信号 → 义务 → 时机」三步。现有四种响应方式、定时任务、平台活动、扩展入站钩子（强制回应 / 不回应 / 隐藏）、暂停和本机其他智能体消息的规则都按原语义搬进这三步，行为不变；入站钩子的决定仍然优先于响应方式 |
| R2 | 等对方说完：`finish_channel_turn` 新增结束方式 `waiting-for-more`，参数是安静秒数 `seconds`。等待对象是这一轮里最后一位发言的成员，含义是「等这个人安静这么久再叫我」：等待期间他每发一条消息就重新计时，不开新的一轮、不请求模型；到点以一条宿主事实开启新的一轮，这一轮必须回。秒数被限制在 5 秒和频道的单次上限之间 |
| R3 | 等待的上限：从等待对象这一串消息的第一条算起最多 120 秒，到了就开一轮；被计时器叫醒的那一轮不能再选等待。同一频道同时只有一个等待 |
| R4 | 等待中有其他强信号或中信号到来，照常开一轮；智能体看到全部上下文后可以重新选择等待，但仍计在 R3 的 120 秒里。「每条消息」下，等待对象的消息在等待期间合并处理，不再每条各开一轮 |
| R5 | 等待只保存在宿主进程内存里，重启后丢失；这时等待对象要再说一句才会唤醒智能体。接受这个代价，以后确有需要再持久化 |
| R6 | 新增响应方式 `smart`，界面名「智能响应」。强信号同「提及或回复时」；另外由名字、别名和注意力窗口唤醒，这两类唤醒不建立回应义务，智能体可以用 `no-response-needed` 结束 |
| R7 | 别名放在智能体配置里，所有频道通用；显示名总是算一个。匹配是不分大小写的子串匹配，中文无法按词切分，所以界面提示别名尽量用两个字以上。机器人自己发出的消息、命令、本机其他智能体的消息不参与匹配 |
| R8 | 注意力窗口：智能体被某人用强信号或中信号叫过、或者刚给他回过消息之后，这个人在窗口时长内接着说的话也算中信号。只认这一个人，窗口在他安静满窗口时长后关闭，每次被叫或回复后重新开始计时 |
| R9 | 防抖：智能响应下所有唤醒（含 @）先等发出它的人安静一段时间再开始，期间同一人的消息并进同一轮；有最长等待和最多条数，到了就直接开始。定时任务和命令不防抖 |
| R10 | 中信号频率上限：每个频道在一个时间窗内最多唤醒若干次，超出的只作为上下文；强信号不受限 |
| R11 | 响应时机的参数按频道调整，存在频道绑定上，没填的用默认值。等待（所有响应方式）：单次安静时长 5–60 秒、总共最多等 120 秒，可以关闭。智能响应：防抖 3 秒、最长 30 秒、最多 5 条；注意力窗口 60 秒；中信号每分钟最多 3 次；名字唤醒、注意力窗口可以分别关闭。宿主对每一项设有硬上限，超出的取值被拒绝 |
| R12 | 智能体在被中信号唤醒的轮次里能看到这次唤醒的来源（提到名字 / 接着说），提示词告诉它这类消息不一定是对它说的，不想接话就不回 |
| R13 | 私聊频道绑定时默认用「每条消息」，内置频道维持「每条消息」；群聊默认仍是「提及或回复时」。已有绑定不改 |
| R14 | 运行轨迹里的「结束本轮处理」显示「等对方说完」和智能体写的原因；等待结束的那条宿主事实在频道时间线上显示为「等对方说完」提示；名字和注意力窗口唤醒的来源随这一轮的输入交给智能体 |

## 后续阶段

以下不在本次实施范围，框架为它们留出「信号来源」的位置：

- **话题判断（弱信号）**：用宿主内置语义模型比较最近的消息和智能体的兴趣、频道笔记、刚聊过的话题，足够接近才唤醒（可以不回）。先用本机评测确定阈值；语义模型是可选安装的，没装时智能响应照常工作，只是没有这类信号。
- **注意力窗口的语义筛选**：窗口里的人转去聊无关的事就不唤醒。
- **按兴趣主动插话**：依赖话题判断，单独评测。
- **按内容调整防抖时长**：按字数、末尾标点、「等下」这类词调整。
- **平台「正在输入」信号**：只有部分私聊平台提供，作为额外信号。
- **扩展提供唤醒信号**：在 SDK 里开放信号来源接口。
- **等待持久化**：重启后恢复未到点的等待。

## 实施顺序

1. 信号、义务、时机的统一框架与等待功能（改变的是所有响应方式共有的行为）。
2. 智能响应：响应方式取值、别名、注意力窗口、防抖、频率上限、频道参数和界面。

两步一起发布。
