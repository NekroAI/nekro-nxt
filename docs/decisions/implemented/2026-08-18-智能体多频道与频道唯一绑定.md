# 智能体多频道与频道唯一绑定

状态：implemented

## 决策

一个智能体可以同时拥有多个有效 Channel Binding；一个 Channel 同一时间最多只有一个有效 Binding。把频道绑定给另一个智能体时，系统原子停用该频道原 Binding，并创建或重新启用目标 Binding。

## 数据与运行语义

- 每个频道的消息、Admission、Episode 和 DSH Session 始终独立，不把智能体所绑定的多个频道短期上下文混合；
- 频道换绑只改变后续响应所有权，不删除旧 Binding、Episode 或消息；
- SQLite 使用 `bindings_active_channel_uq` 部分唯一索引约束每个频道最多一个活动 Binding；
- 修复迁移会重新激活被错误“单智能体单频道”迁移停用的其他频道，并在同一频道存在多个历史 Binding 时保留最新一个为活动状态；
- 智能体页面展示全部已绑定频道，“绑定频道”是新增关系，不会替换该智能体的其他频道。

## 验证

- 同一智能体同时绑定 Web 与外部频道后，两者均保持活动；
- 将其中一个频道换绑给另一个智能体，不影响原智能体的其他频道；
- 从错误 schema 版本升级后，被停用的不同频道关系恢复，同一频道仍只有一个活动智能体；
- 产品快照与智能体频道页展示恢复后的全部绑定。

## 未来方向与非目标

关联方向：更多 Adapter、智能体多频道、跨频道长期记忆。

保留接缝：稳定 Binding ID、历史 Episode、显式 `channelId`/`agentId` 和独立 Turn lane。当前约束不会把智能体锁死到单一频道，也不会通过换绑破坏历史。

本次不做：跨频道短期上下文合并、自动消息迁移、批量解绑和隐式跨频道发送。
