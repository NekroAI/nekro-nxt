# 已实施：连接平台目录与通用配置表单

状态：implemented

## 问题

连接页面曾把“添加连接”、Web store、HTTP body 和 Server Runtime 创建方法全部写死为 QQ OpenClaw。点击通用按钮会直接出现“添加 QQ Connection”，系统托管的内置频道详情也错误显示 App ID、Client Secret 和 QQ 收发测试。这与已确认的 `AdapterContribution → Connection` 边界和“多数 Adapter 使用声明式通用表单”的决定直接冲突。

## 决定

- Adapter SDK 增加版本化 `AdapterConnectionDescriptor`，声明稳定 key、用户名称、说明、是否允许用户创建，以及受控 JSON Schema 子集；
- `credential-reference` 只描述凭据槽位，浏览器把原始值放入独立 `credentials` 对象，Host 写入私有凭据存储后才把引用交给 Core；
- Server 快照投影所有已安装 Adapter 描述。`web` 是系统托管且不可创建；`qq-openclaw` 是当前可创建平台，但不再拥有 UI/API 特权；
- `POST /api/connections` 使用通用 `{adapterKey, configuration, credentials}`，组合根按选中的 Adapter 描述校验后分派当前创建实现；
- Web 先选择平台，再按 schema 渲染文本、数字、布尔和凭据字段。平台专属诊断可以继续使用自定义面板，但不能改变 Connection 和凭据语义。

## 验证

- Adapter SDK 测试验证默认值、普通配置与只写凭据分离、缺失凭据和未知字段拒绝；
- Server 快照测试确认 `web` 与 `qq-openclaw` 均来自目录且只有后者允许用户创建；QQ 真实组装测试通过通用 API 创建并验证私有 Secret、Gateway 入站和 HTTP 出站；
- 生产 Playwright 旅程确认对象列「添加平台连接」先出现平台选择，第一步没有 App ID，继续后才显示 QQ 贡献的字段；内置频道详情不再显示 QQ 凭据和测试；
- 根 Vitest alias 补齐 QQ Adapter 源码，避免测试误读旧 `dist` 形成假绿灯。

## 未来方向与参考取舍

关联方向：更多聊天平台 Adapter、动态 Extension 和 Desktop/Server 共用配置界面。

保留接缝：稳定 Adapter key、版本化配置 schema、普通配置/凭据分离、通用创建 API 和可选平台诊断面板。新增平台可以贡献目录和创建实现，不需要修改“添加连接”按钮或复制一套产品表单，因此没有把 QQ 锁进 Core 或 Web Shell。

本次明确不实现：第二个外部聊天平台、任意 JSON Schema 全集、自定义 Adapter UI Slot、在线市场和运行时安装 Adapter。只实现当前已确认字段类型与已有 QQ 消费者。

参考本仓首个 QQ Adapter Decision 已确认的三层 UI 方案；借鉴通用 schema 表单和可选平台诊断，拒绝把 QQ 专属配置继续伪装成 Connection 通用入口，也不提前建设无人使用的平台市场。
