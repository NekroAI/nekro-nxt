# NekroNxt 公开知识路由

本文件是根 [`AGENTS.md`](../AGENTS.md) 的下一层公开索引。先根据任务进入一个领域，再由该领域文档进入具体协议、Decision 或包说明。现行文档描述当前事实；冻结历史只能从[归档索引](archive/README.md)进入。

## 产品、范围与计划

- 想快速确认产品是什么、首版边界和核心对象：读[项目共识](NekroNxt项目共识.md)。
- 修改完整用户路径、页面关系或首次使用流程：从[产品形态与用户旅程](NekroNxt产品形态与用户旅程.md)进入，再按页面动作进入[界面交互模型](NekroNxt界面交互模型.md)。
- 判断当前是否已经计划、还有哪些一期缺口：读[一期开发计划与决策清单](04-一期开发计划与决策清单.md)。
- 设计尚未启动的能力或检查是否锁死未来接缝：读[未来扩展方向](02-未来扩展方向.md)。
- 面向仓库访问者的安装、目录和分发概览：读[根 README](../README.md)。

## 界面、术语与用户文案

- 用户可见实体名称、文案语气和禁用表达：读[术语与文案规范](01-术语与文案规范.md)。
- 页面对象、操作前提、按钮后果和未开放状态：读[界面交互模型](NekroNxt界面交互模型.md)。
- 布局尺寸、主题、组件状态、动效和视觉语言：读[桌面 UI 与动效规范](05-桌面UI与动效规范.md)。
- UI 修改的真实渲染验收从[开发与测试规范](06-开发与测试规范.md) §5.1 进入；相关设计决定由[决策索引](decisions/README.md)路由。

## 消息、运行时与宿主接线

- 消息内容块、通信工具、Asset、模型原始输出和投递边界：读[消息内容与投递协议](03-消息内容与投递协议.md)。
- Server、Web、DSH Host、HTTP/SSE 和静态入口的当前组合：读[接线与 Server 宿主设计](08-接线与Server宿主设计.md)。
- Channel、Adapter、DSH、扩展、持久化和生命周期的细分决定：从[决策索引](decisions/README.md)按主题进入，不扫描目录猜文件。
- 需要查看代码所有者和包级命令：先进入 [Apps 索引](../apps/README.md)或 [Packages 索引](../packages/README.md)。

## 工程、验证与知识维护

- 提交、生命周期、测试阶梯、视觉验收、本地服务、迁移和文档维护：读[开发与测试规范](06-开发与测试规范.md)。
- 公开仓库、本机私有资料、真实样本和发布前泄漏检查：读[文档公开边界](00-文档公开边界.md)。
- 引入外部项目、库或机制并说明借鉴与拒绝边界：读[参考项目复用指南](07-参考项目复用指南.md)。
- 跨包决定的状态、主题和具体文件：从[决策索引](decisions/README.md)进入。
- 原型只用于需求和视觉对照：从[原型说明](../prototype/README.md)进入，不能替代现行产品文档和真实页面。

## 历史与本机私有资料

- 追溯立项快照、过程日记或已被替代的决定：从[归档索引](archive/README.md)进入；默认任务不读取归档。
- 本机存在 `.local/README.md` 时，本地服务、环境、品牌私稿和私有研究从根 `AGENTS.md` 的私有索引入口进入。公开专题文档不链接其具体内容，公开构建也不依赖它。

## 文档图规则

每份受维护文档必须从根 `AGENTS.md` 沿自然任务路由可达。新增文档时把它接到最近的领域索引，并从文档正文链接必要的下游事实源；不得只把文件放进目录。`pnpm check:docs` 检查链接、标题片段和根可达性。

冲突按以下顺序处理：用户最新明确决定 → 现行 accepted/implemented Decision → `AGENTS.md` → 编号协议 → 包 README。发现冲突时修正失真的副本或改为链接，不保留两份独立长描述。
