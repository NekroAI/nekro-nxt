# 决策：可靠性与工程简化整改

状态：accepted

## 决定与边界

保留聊天、连接、智能体配置与客户端偏好；保留 Drizzle 与 Zustand。迁移完整性检查必须发生在事务提交前，历史分页在数据库完成。客户端统一类型化请求和宿主数据缓存，宿主按状态与生命周期所有者拆分。新扩展统一显式 scope，旧源码保留并提供重建入口。视觉建议不代替运行成功条件。工程检查与 CI 去除重复事实和重复执行，相关 main 提交继续自动 Preview，正式发布仍须明确授权。

## 实施状态

阶段 0–6 的实现已完成，按行为分批提交。保留原数据、迁移 journal、扩展源码和客户端偏好，没有执行正式发布。

- 阶段 0–1：迁移、journal 与外键检查在同一 immediate transaction 内提交；失败整体回滚，最新库也检查完整性。历史分页、游标与隐藏事实过滤下推 SQL，Episode 使用关联查询，搜索使用参数化文本折叠与 `instr`。0023 是新增索引迁移，既有迁移不改写。
- 阶段 2：产品动作与 HTTP 传输保留完整类型；宿主数据归入一个 Store，界面偏好单独持有。快照与 SSE 使用 epoch/sequence、重放、单资源在途合并和生命周期代次。提交成功与后续同步分离，绑定同步移动频道行时保留键盘焦点。
- 阶段 3：Session 注册、模型配置、图片上下文、动态创造、持久扩展挂载与运行投影各有所有者；创造和连接操作进入应用服务。快照集中批量读取，HTTP 按领域注册；频道投递、反馈租约和交互意图分离，关闭等待所拥有的任务与资源。
- 阶段 4：新运行格式统一 Manifest V5，scope 与版本分离。V1–V4 只读保留，经显式重建、运行验证生成新 Revision；失败不损失原资料，重复成功重建复用结果。旧页面退出可运行目录，偏好和安装记录保留。视觉几何及 UI Kit 使用改为建议，真实运行、资源和权限失败继续阻断。
- 阶段 5：移除函数名 JSON 门禁和数量基线，DSH 断言改为局部具名例外；可靠的包边界交给 ESLint。源码入口和 TS references 从 manifest 推导，检查不写文件；CSS 类型使用 PostCSS 与选择器解析。按钮检查只给高置信度建议，工程规则允许按需要隔离分支和按影响验证。
- 阶段 6：Node、组件浏览器与生产旅程分组，CI 去除同范围测试和构建重复。Preview 对比最近成功发布与当前提交；平台先保存候选，最终任务串行核对安装包 receipt 和 Server digest，过期任务不发布，失败补偿并清理。Docker 构建上下文保留配置推导依赖的 `scripts/lib`。

## 查询规模与保留限制

本机合成数据测量如下：分页连续读取两页，每页 16 条；搜索分别执行一次命中和一次无命中查询。计时不包含造数，未开启覆盖率插桩。绝对耗时是单次测量，不作为跨机器性能承诺。

| 历史事实数 | 两页读取 | 两次搜索 | 单次无命中搜索期间的事件循环延迟 |
| --- | --- | --- | --- |
| 10,000 | 4.3 ms | 8.2 ms | 9.1 ms |
| 100,000 | 4.0 ms | 99.9 ms | 77.6 ms |

两页共解析 32 个完整消息对象，命中与无命中两次搜索合计只解析 1 个完整对象。无命中搜索仍可能扫描该频道搜索文本并同步占用事件循环；本次没有引入全文索引或异步数据库框架。

旧扩展必须重建后由用户选择新版本，并重新核对权限；重建成功不自动启用。旧源码、配置、版本、安装和页面偏好保留。迁移保留既有 journal 元数据与高水位兼容方式，拒绝超过当前已知迁移的未来记录，不因历史时间或摘要差异重写已发布 journal。
