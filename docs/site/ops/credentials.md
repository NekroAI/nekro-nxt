# 凭据与关联账号

扩展、MCP 服务和智能体的命令常常需要 API 密钥或 token。把它们存在「设置 → 凭据」里，添加一次，各处都能引用，也能随时更换或收回。

## 添加凭据

在「设置 → 凭据」点「添加凭据」：

![添加凭据](shot:ops-credential-add)

- **名称**、**说明**：方便你和智能体认出它是做什么的；
- **值**：密钥本身。保存后只显示已保存，不再显示原值。少于 8 个字符的值没法在智能体的上下文里隐藏，尽量用长一些的密钥；
- **使用方式**：
  - 「仅用于网络请求」（默认，更安全）：扩展只拿到一个占位符，NekroNXT 发请求时才把真值填进去，而且只填给“允许的域名”；
  - 「允许程序读取」：命令和扩展代码能读到原文，需要填一个环境变量名，比如 `WEATHER_API_KEY`；
- 「自动使用」：打开时，可用的智能体直接使用；关闭时，她每次使用前要先申请，管理员批准后才能用；
- **高级 → 可用智能体**：默认全部智能体，可以限定给某几个。

## 智能体缺凭据时

智能体做扩展或运行命令需要某个密钥、而你还没添加时，会发起凭据申请。「设置 → 凭据」顶部会出现申请，点“添加”打开预先填好名称和用途的表单，你只需填值；保存后她会自动继续。

## 用在哪里

- **扩展配置**：带密钥的配置项用下拉选择一个凭据，见[使用扩展](../extensions/overview.md)；
- **MCP 服务**：添加 MCP 服务时同样可以选凭据；
- **命令**：使用方式为「允许程序读取」并填了环境变量名的凭据，会作为环境变量交给可用的智能体的命令。智能体资料页的“能力”里能看到她的命令能用哪些凭据，见[能力与授权](../agents/abilities.md#关联账号和凭据)。

点开一个凭据，可以更换值、调整谁能用，查看使用记录和已同意的智能体；不再需要时删除。

## 凭据不会进入对话

工具返回的结果在交给模型之前，NekroNXT 会把已登记的凭据值替换掉，工具参数里出现凭据值也会被拒绝。所以模型和聊天记录里看不到密钥原文。

「允许程序读取」的凭据，命令里的程序能读到原文。为降低风险：能用「仅用于网络请求」就别用读取；给 token 只开需要的权限；不需要联网的智能体关掉“命令联网”。

## 关联 GitHub 账号

想让智能体用 `gh`、`git` 操作你的仓库，在「设置 → 关联账号」点「关联账号」：

![关联 GitHub 账号](shot:ops-linked-account)

- **填写 token**：建议创建一个只开所需权限、只对需要的仓库开放的专用 token；
- **本机 gh 已登录账号**：这台设备上已经用 `gh` 登录时可选，智能体会获得这个账号在 `gh` 里的全部权限。

账号添加后还不属于任何智能体。到智能体的“能力”里打开运行命令，再在“关联账号”里为她选这个账号，每个平台一个。详见[能力与授权](../agents/abilities.md#关联账号和凭据)。
