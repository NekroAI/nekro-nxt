# 已实施：频道身份与 Episode 交接来源修复

状态：implemented

## 问题与结论

运行时一直以稳定 `channelId` 隔离发送、历史和资源工具，但普通模型上下文只说明“当前频道”，没有明确频道名称、类型、Connection、Channel ID 与 Episode ID。拥有开发工具的智能体直接查询共享数据时可能因此误认当前频道。与此同时，Episode handoff 摘要曾读取整个频道最近 100 条历史，而不是旧 Episode 实际准入和发送的记录；首尾锚点相同时还会重复保存来源 ID。这会把智能体旧回复中的错误判断重新总结，并在后续 Session 中持续传播。

每个根 DSH Session 现在获得一个常驻 `nekro-nxt:channel-context` 系统提示区段，以及无参数只读工具 `nekro_nxt_channel_context`。两者使用 Host 当前 `ChannelRecord`，明确 `channelId`、`connectionId`、频道类型、可用展示名和 `episodeId`。工具不能指定其他频道；发送、历史和 Asset 工具原有的闭包绑定保持不变。动态创造 Inspect 的 `currentContext` 同样投影这份频道身份。

## Handoff 来源

`ChannelHistoryRepository.listEpisodeHistory()` 只投影一个 Episode 的事实：

- 入站必须由该 Episode 中状态为 `logged-to-session` 的 Admission 引用；
- 出站必须拥有相同 `episode_id`；
- 入站、出站与 Episode 的 `channel_id` 必须一致；
- 结果由现有 Core SQLite 事实实时生成，不建立第二份历史或修改 DSH Session 私有表。

摘要输入把 Host 频道身份、上一份派生 handoff、当前 Episode 频道原文和智能体历史出站分区。频道原文是权威频道事实；上一份 handoff 可能不准确；智能体历史出站不代表用户确认。最近 12 条频道原文继续作为独立恢复窗口注入新 Session，不参与旧 Episode 摘要范围，也不复制为新的领域事实。

Handoff 注入文案明确摘要是派生记录，与原文冲突时以原文为准；文件、状态、数量和外部资源按需重新核验。边界锚点按 Event ID 去重，生成时间使用 UTC 绝对时间。没有使用关键词正则拒绝合法文本，也没有把提示词当成频道权限边界。

## 失败与恢复

摘要请求继续不设置 `maxTokens`，使用 180 秒取消边界。只有正常 `stop` 且存在文本时采用模型摘要；超时、异常、空结果、非完整结束或 Episode 历史投影异常都使用确定性 fallback。Channel Runtime 在摘要驱动边界再次兜底，因此摘要失败不会取消 rollover；Core 事务、Session 创建和其他一致性失败仍保持可见失败，不能伪装成成功。

已有 handoff、Episode 和 DSH Session 永不原地改写。受污染的活动 Episode 在部署修复后通过公开 `stopEpisode(..., 'stopped')` 关闭；下一条触发消息创建不携带 handoff 的干净 Session。旧记录只读保留用于审计。

## 验证与边界

- 同频道未准入记录和其他频道记录不会进入 Episode 摘要输入；
- 入站与该 Episode 出站仍按时间进入摘要，出站被明确标记为非用户确认；
- 相同首尾 Event 只保存一个边界锚点；
- 上一份 handoff 作为独立派生分区传递；
- 摘要驱动抛错仍完成 rollover，并持久化确定性 fallback；
- 显式停止后下一条消息创建无 handoff 的新 Episode；
- 真实 DSH 组装验证频道上下文系统提示、只读工具结果、最近窗口和恢复注入。

本次不修改 Core schema，不改 DSH Compaction 默认参数，不限制用户的 Shell、文件或频道用法，不引入长期记忆、向量检索、跨频道短期上下文或独立 summarizer。

关联方向：智能体多频道、长期记忆、更多 Adapter 和智能体自开发。

保留接缝：稳定 Channel/Episode/Admission/Outbound ID、Channel-scoped Tool、DSH System Prompt section、Episode lineage 与历史回查工具。当前实现不把智能体锁死到单一频道，也不阻止未来用独立 Memory Provider 或上游 recall 能力替换历史后端。

参考 DSH 0.1.1-rc.1 的 Session、System Prompt section、Tool 与公开生命周期边界；借鉴来源明确、可逆注册和原日志保持追加式的机制。拒绝读取 DSH 私有 Session 表、复制整份旧 Session、Fork Compaction、全频道历史拼接和用模型自称正确替代外部事实验证。
