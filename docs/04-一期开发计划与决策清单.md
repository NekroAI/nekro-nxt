# NekroNxt 一期开发计划与决策清单

> 文档编号：04
> 状态：核心方案已确认；M0-M4 已实现，M5 离线协议及生产连接宿主已实现；M6 的核心接线、频道消息资源/分页、动态 Client 即时装卸和生产浏览器旅程已完成，QQ 平台行为仍待用户凭据/测试群验收；M7 未开始
> 日期：2026-08-15
> 目标：把当前产品基线转换为可运行的一期垂直闭环，并明确尚未冻结的技术选择

## 1. 一期目标

一期不以页面数量或 Adapter 数量验收，而以两条真实闭环验收：

### 闭环 A：智能体、Web Channel 与本地扩展

```text
创建智能体和首个配置版本
→ 自动创建 Web Channel 与 Binding
→ 通过 DSH 运行并只用通信工具回复
→ 同一智能体启用创造能力
→ 定义、运行、验证动态 Tool/Client UI
→ 保存为本地 Extension Revision
→ 明确启用给该智能体
→ 重启恢复、停用和回退
```

### 闭环 B：QQ OpenClaw 群聊

```text
创建 QQ Connection
→ 发现/产生 QQ Channel
→ 建立 Binding
→ 分别测试接收和发送
→ 群消息可靠入库
→ @、引用或策略触发智能体
→ Tool 运行期间新消息安全注入
→ 通信工具发送文字、Mention、媒体和引用
→ 展示真实平台回执与失败
```

首个外部 Adapter 不再推迟到完整 Local Creator Alpha 之后，而是作为一期第二条垂直切片，与 Channel Runtime 同步验证。Desktop 安装包和 Server 单容器仍在核心 Runtime 稳定后完成。

## 2. 已更新的技术基线

- DSH 当前要求 Node `^22.19.0 || >=24.0.0`、pnpm `11.7.0`；
- DSH 的 npm packages 已公开，但 registry 的 `latest` 目前不一致；抽查包的 `next` 统一指向 `0.1.0-rc.6`，必须以完整精确版本集和 lockfile 接入；
- 当前动态工具为 `cordis_inspect_list`、`cordis_inspect_query`、`cordis_inspect_self`、`cordis_define`、`cordis_run`、`cordis_stop`、`cordis_undefine`；`cordis_run` 使用 `mode: "run" | "update"`；
- 动态 Package 按 Session 拥有，但运行影响不天然限定到该智能体；
- 动态 Package 不持久化，NekroNxt 必须自己实现保存和 Activation；
- 首个外部 Adapter 候选已经确定为 QQ OpenClaw；
- 创造是同一智能体启用相关能力后的状态，不是另一个智能体或用户可见模式。
- 正常聊天中一个 `(channelId, agentId)` 使用一个活动 DSH Session；上下文压力继续使用 DSH 原 Session 压缩，只有长时间断档、不兼容配置变化、人工新建或不可恢复时才交接到新 Session；
- 本地 Extension 一期只持久化不可变源码 Revision 和 Manifest，构建产物作为可删除、可重建缓存；
- Adapter 配置采用通用声明式页面作为基线，并允许通过稳定 NekroNxt Slot 提供平台专属增强。

## 3. 里程碑

### M0：工程基线与 DSH 兼容骨架

- 锁定 Node、pnpm、TypeScript 和 DSH 精确版本；
- 建立根 `dev/check/test/build`；
- 只创建首期真实需要的少量包；
- 建立 `dsh-compat`，集中 DSH import、版本断言和代表性兼容测试；
- 通过公开 Profile seam 离线组合外部 Base/Web Bundle，并从其中使用的公开 package set 启动最小 DSH Runtime；完整 DSH 产品 Bundle 不作为测试进程的最小宿主；
- 验证 Session create/resume、Preset mount、Scope 和 Slot。
- 验证动态 Contribution 在目标智能体 DSH Scope 内注册、更新和 dispose，其他智能体不可见且不可调用；完整 `cordis_define/run/stop` 保存接管在 M3-M4 垂直闭环验证；
- 建立 Fake Adapter、Virtual Clock 和最小场景驱动器，后续 Channel Runtime 不依赖真实时间和平台测试；
- 建立 Client migration registry、冻结 fixture 和 Host upgrade coordinator 接口；
- Spike `node:sqlite + Drizzle`、FTS5、WAL、备份与恢复。

完成证据：精确依赖可重复安装；DSH Bundle 组合、Loader Runtime、Session 恢复、Scope、Slot、React 单例、迁移、双 SQLite 快照和 Fake Adapter 可单独验证。实现记录见 `decisions/implemented/2026-08-16-M0工程基线与兼容验证.md`。

## 4. 建议的最小包边界

首期建议先控制在以下范围，名称可在 M0 Spike 中调整：

```text
apps/
  web/                 # 管理与聊天 UI
  server/              # Runtime 的首个 Host 与后续单容器入口

packages/
  contracts/           # 跨进程/持久边界的类型与验证
  core/                # 智能体、Channel、Extension 领域服务
  dsh-compat/          # DSH 公共 API 薄封装与版本测试
  channel-runtime/     # Admission、Episode、Outbox
  extension-runtime/   # 动态创造、构建、Revision、Activation
  adapter-sdk/         # AdapterContribution 契约与测试套件
  adapter-qq-openclaw/ # 首个外部 Adapter
  storage-sqlite/      # Core SQLite 实现
  test-harness/        # Fake Adapter、Virtual Clock、场景回放
```

如果实现证明 `core/channel-runtime/extension-runtime` 仍高度耦合，可先合并为一个包；不为了目录图强行拆包。Desktop 和 Server 包在 M7 进入，不先创建空脚手架。

## 6. M0 必须形成的验证证据

产品与架构决定已经确认，M0 不重复讨论选项，必须用可运行证据验证：

1. 完整精确 DSH npm package set、lockfile 和 `dsh-compat` 版本断言；
2. NekroNxt Shell 对 DSH Client Service、对象层、React singleton 和 Slot 的最小组装；
3. Core/DSH 双 SQLite 的 checkpoint、备份和恢复状态机；
4. 动态 Extension Host/Client 构建与目标智能体作用域；
5. Client migration 的连续升级、未来版本拒绝和失败保留原数据；
6. Fake Adapter 与 Virtual Clock 能表达重复、乱序、取消和崩溃恢复场景。

## 7. 一期完成标准

- 两条垂直闭环均可从 UI 完成；
- Web 与 QQ 的智能体消息只来自通信工具；
- Channel、Session、内部模型输出和平台发送事实清楚分离；
- 工具期间新消息不取消当前 Tool；
- 动态创造、Shell、完整文件访问分别授权；
- 动态扩展、本地 Revision、Activation 分离；
- QQ Mention、引用、媒体、重放和失败状态有真实证据；
- 重复媒体只保存一个物理 blob，每次接收来源和统计准确；视频作为普通文件不丢失；
- 图片增强按版本缓存，多模态模型可原生或主动读取，文本模型获得增强结果或明确失败；
- Desktop/Server 共用 Runtime 和数据格式；
- 坏扩展和失败迁移可进入恢复模式；
- 根 `pnpm check/test/build` 可验证相关路径。

## 8. 范围声明

### 关联未来方向

更多 Adapter、智能体多频道、Process/Remote Runtime、社区市场、多设备同步、长期 Job、多媒体。

### 当前保留的接缝

稳定 ID、不可变 Revision、Activation、Episode lineage、Adapter capability、Connection 账号作用域、RuntimeKind、MessagePart、Asset/派生内容来源、Outbox 和可重建 Extension cache。

### 没有锁死未来

Channel 事实流不等于 DSH Session Log；Binding 不固定一对一；QQ 不是 Core 特例；本地路径不是扩展身份；源码优先方案不阻止未来追加 artifact/evidence；Desktop/Server 不分叉。

### 本次明确不提前实现
