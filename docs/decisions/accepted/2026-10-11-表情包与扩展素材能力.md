# 表情包与扩展素材能力

状态：accepted（2026-10-11 批准并实施；平台表情包标记与外部嵌入模型尚未实施）

本决定新增官方扩展「表情包」，并为它补齐一组不专属于表情包的宿主能力：图片信息、扩展资源库、工具结果附图、检索索引、本机层模型调用。

表情包的工作方式：
- 智能体在群聊里收藏别人发的表情包，收藏时写下这张图的用途；
- 需要时检索，用视觉确认候选图之后挑一张发出；
- 表情包默认可以在不同群之间流通，群聊特有的截图和私密内容留在原来的群；
- 以前攒下的表情包可以在页面上批量导入，由已配置的视觉模型写好描述；
- 日常运行不需要管理员维护，资源占用要让普通服务器也能承受。

## 1. 场景与目标

- **玩法**：表情包在多个群之间流通，带来"它居然有这张图"的惊喜，是智能体的一大特色。收藏库越丰富，玩法越好。
- **边界**：流出去的必须是通用意义上的表情包。聊天截图、群内信息、私人照片等只在原来的群里用。用户能决定自己的群按哪种方式处理。
- **维护**：长期运行时，管理员不需要定期审核或清理。库的质量在日常使用中自行维持。
- **资源**：默认不增加常驻模型，也不要求额外配置；更好的检索作为可选增强，在界面里一键下载即可使用。

## 2. 决定

| # | 决定 |
| --- | --- |
| S1 | 两道闸门：收藏时由智能体用视觉判断能否流通；使用时搜索结果附上候选图，智能体确认后再决定发不发，并顺手修正或清理。不设人工审核队列 |
| S2 | 表情包按内容去重（内容寻址的 `assetId` 相同才合并），记录在哪些频道出现过。流通状态只有「流通」和「本群」两种：流通的图任何频道都能用，本群的图只在出现过它的频道里用。感知哈希相近的图不合并，评测中它把不同的表情包误并过 |
| S3 | 收紧随手可做，放开要经过视觉判断：智能体和群成员随时可以把一张图改成本群或删除；只有收藏和导入时的视觉判断、以及管理页能把一张图设为流通 |
| S4 | 群聊和私聊都按智能体判断。每个频道可以改为「只在本群用」或「不收藏」 |
| S5 | 检索做成宿主通用能力。默认用关键词索引（SQLite FTS5 加中文分词）；内置小模型 bge-small-zh 作为可选增强，在「设置 → 检索」里按需下载模型与原生推理运行库，不需要离开界面；外部嵌入模型只预留接口 |
| S6 | 收藏时要写「用途」和「配文」。检索质量主要靠这两个字段，不靠更大的模型 |
| S7 | 搜索结果附图时，当前请求上下文里已经看得到的图不重复附上 |
| S8 | 删除先进回收站，保留 30 天，管理页可以恢复 |
| S9 | 扩展专属的规则（流通、来源、频道设置、敏感判断）全部放在扩展里；宿主只提供通用的底层能力 |
| S10 | 本机层可以调用用户在「设置 → 模型」配置好的模型，用于页面发起的批量任务（导入打标）；调整了[扩展形态统一](2026-10-09-扩展形态统一.md)中本机层不调用模型的限制 |
| S11 | 产品文案中"看图"统一改为"视觉"（视觉模型、支持视觉） |

## 3. 和 Nekro Agent 表情包功能的取舍

Nekro Agent 的表情包功能在长期使用中基本不需要维护，关键是它的两道闸门：收藏前要求模型确认看过图；搜索结果把候选图本身放进上下文，并要求模型发现描述不符或混入截图时立即修正或删除。本设计保留这一机制。

| 方面 | Nekro Agent | 本设计 |
| --- | --- | --- |
| 收藏 | 模型自行判断收藏，要求声明看过图 | 保留；收藏时多判断一项「能否流通」，并写下用途与配文 |
| 使用前确认 | 每次搜索都附带全部候选图 | 保留附图，上下文里已经看得到的不重复附（S7）；附图数量可配置 |
| 使用中自我清理 | 模型看到不对的图立即修正或删除 | 保留；新增「改为本群」；删除进回收站（S8） |
| 描述 | 只描述外观，检索时和找图的说法对不上 | 增加「用途」与「配文」，检索质量提升最大（§6） |
| 检索 | 必须配置嵌入模型和向量数据库，维度配错就整个不可用 | 默认关键词，零配置；语义模型可选，不可用时自动退回关键词 |
| 提示词 | 每轮注入"最近收藏的 5 张（带编号）" | 只放固定说明，不随轮次变化，不破坏缓存；编号只出现在工具结果里 |
| 隔离 | 全局一个库，没有边界 | 默认流通，按 S2–S4 留住群内私密内容 |
| 导入 | 无界面 | 页面批量导入图片或 zip，选一个视觉模型写描述并判断能否流通 |
| 管理 | 几条管理员命令 | 管理页：浏览、搜索、分类、编辑、回收站、暂停流通 |
| 文件 | 删除和迁移后留下孤儿文件 | 图片由宿主资源库持有，移出资源库后按宿主规则回收 |

## 4. 宿主能力

下面几项都不包含"表情包"这个概念，以后语录收藏、群相册、抽卡素材、知识库等扩展可以直接使用。接口与声明方式见 [扩展 SDK](../../../packages/extension-sdk/README.md#宿主能力nxt)，SDK 能力等级为 8。

### 4.1 扩展资源库

- `assets.keep` 把当前频道看得到的资源收进本扩展的资源库，`release` 移出，`attach` 把资源库里的资源授权给当前频道并返回可发送的 `assetId`；不在资源库里的一律拒绝，资源库不能成为绕过频道隔离的通道。
- `assets.create(input, { library: true })` 直接生成到资源库。本机层可以列出和移出；页面用 `host.upload` 上传图片或 zip（单张 20 MB 以内），用 `host.assetUrl` 显示原图或缩略图。
- 权限声明为 `assets: { library: { quotaBytes? } }`，默认 2 GiB、上限 32 GiB，同一资源只计一次。授权来源记为 `extension-library`。

### 4.2 图片信息 `image.info`

返回格式、宽高、帧数、字节数和 64 位差异哈希。挂载内可读当前频道看得到的图和资源库，本机层只读资源库。

### 4.3 工具结果附图

- 工具 `output.render` 可以返回 `{ type: 'image', assetId, label }`，只能是资源库里或当前频道可见的资源。
- 宿主按低清晰度把图片放进模型上下文；当前上下文已经看得到的图不重复附上；每次最多 6 张。
- 模型没有视觉能力时只给文字，并说明看不到图。
- 工具返回值不受影响，编排模式的程序照常拿到它。

### 4.4 检索索引 `index`

- 扩展在声明中登记集合：最多 4 个带权重的文本字段、4 个过滤字段（可以多值）；本机层与挂载两层声明必须一致。
- 接口：`upsert`、`delete`、`count`、`query(collection, text, { limit, filter })`，过滤条件是"每组都满足、组内满足一个"。返回编号和分数，不返回原文。
- **关键词检索**：SQLite FTS5，`Intl.Segmenter('zh')` 分词，BM25 排序，带字段权重，不新增依赖。
- **语义检索**：管理员在「设置 → 检索」选择内置模型后，宿主从镜像下载 bge-small-zh（固定版本与哈希）和原生 onnxruntime，后台为所有扩展的索引生成 int8 向量，查询时与关键词结果做 RRF 融合；空闲 10 分钟释放模型。
- **失效处理**：向量按"向量空间"（模型与嵌入文本版本）记录，不同空间不混算；文本变化时按摘要重算。模型未下载、加载失败或正在生成时，查询只走关键词，结果带上原因，查询本身不会失败。
- 数据存放在宿主 SQLite 的独立表里，按扩展和集合隔离。

### 4.5 本机层模型调用 `models`

- `models.list()` 列出已启用且凭据可用的供应商下的模型，标明是否支持视觉；`models.complete` 用其中一个完成请求，图片只能来自资源库。
- 只能在 `permissions.host` 声明 `models: { maxCallsPerMinute, maxOutputTokens }`，批准时提示"使用本机已配置的模型，可以发送图片"。
- 用于用户在页面上发起的任务；智能体挂载里的辅助调用仍用 `llm.complete`（计入智能体用量）。

## 5. 表情包扩展

源码在官方扩展仓库 `extensions/stickers`。

### 5.1 数据

每张表情包一条记录，存在扩展本机存储里；索引从记录派生，随时可以重建。记录包含资源编号、用途、配文、外观描述与标签、流通状态、出现过的频道、收藏者、发送次数与时间、删除时间。

能不能用：未删除，并且流通（且未暂停流通、本频道没有限制只用本群）或当前频道在出现过的频道中；同时满足智能体的「能用的表情包」配置。

### 5.2 工具

| 工具 | 作用 |
| --- | --- |
| `sticker_save` | 收藏当前频道的一张图，写下用途、配文、描述、标签和能否流通。同一张图再次收藏时合并来源、补全文字 |
| `sticker_search` | 按意思检索，返回编号、用途和配文，前几张附图（默认 4 张，可配置 0/2/4/6）。本频道最近发过的排到后面 |
| `sticker_use` | 检查能不能用，授权到当前频道，返回可放进 `send_channel_message` 的图片块 |
| `sticker_update` | 修正文字；流通状态只能从流通改为本群 |
| `sticker_remove` | 移入回收站 |

### 5.3 给智能体的说明

固定静态段，不包含动态内容：什么值得收藏、「用途」写表达什么而不是外观、哪些内容不能流通、发之前先搜索并确认候选图、看到不对的图就修正或清理、有人要求别再发或别外流时照做、不在聊天里说编号。

### 5.4 配置与界面

- **智能体**：收藏方式（看到合适的就收藏 / 有人要求时 / 不收藏）、能用的表情包（所有智能体收藏的 / 只用自己收藏的）、搜索时附图数。
- **频道面板**：收藏（按智能体判断 / 只在本群用 / 不收藏）、使用（库中可用的 / 只用本群的 / 不发表情包）。
- **管理页**（导航轨）：网格浏览与搜索；按全部、流通、只在本群、未写用途、最近流入其他群、回收站分类；编辑文字与流通状态；回收站恢复；暂停流通；批量导入并选择视觉模型，「没写用途」的图可以稍后补写。

导入时模型逐张判断：只有明确是表情包并且可以流通才设为流通，输出被截断或无法解析时按本群处理。

## 6. 检索评测结论

我们用一个约四千张、在真实群聊中积累的表情包库做了检索评测，数据不公开。
- **方法**：66 条按聊天需要写的查询，由多模态模型逐张看图给各方案的前 10 名打 0/1/2 分，以 nDCG@10 为主要指标。
- **评分误差**：一次给评分模型多张图时，它会把编号对错位，所以改为逐张评分。两位评分模型之间的加权 kappa 约为 0.5，因此 0.02 以内的差距视为噪声。

| 方案 | 只有外观描述 | 加用途与配文 |
| --- | --- | --- |
| 关键词 | 0.61 | 0.72 |
| bge-small-zh 加关键词 | 0.66 | 0.74 |
| 外部嵌入模型 1024 维 | 0.68 | 0.71 |
| 外部嵌入模型加关键词 | 0.68 | 0.72 |
| bge-small-zh 加关键词，再由模型从文字候选中挑选 | — | 0.77 |

结论：
- 加用途与配文：+0.11，95% 区间 [+0.05, +0.16]，是唯一明确的大幅提升。
- 加用途与配文之后，关键词、小模型、外部嵌入模型三者之间的差距落在置信区间内，分不出高下。
- 由模型挑选：+0.03，区间 [+0.01, +0.05]。
- bge-m3、Qwen3-Embedding-0.6B 和交叉编码器重排常驻需要 1.5–2 GB 内存，质量也没有超过上面的方案，因此排除。
- 视觉挑选（S1 的第二道闸门）没有单独做检索评测，在对话评测中验证（§8）。

## 7. 维护与安全

| 情况 | 谁处理 | 怎么处理 |
| --- | --- | --- |
| 收进截图、照片 | 智能体 | 收藏时用视觉把关；没拦住的，之后在搜索结果的附图中看到时改为本群或删除 |
| 描述写错 | 智能体 | 搜索确认候选图时修正 |
| 有人不想某张图外流或再出现 | 群成员 | 在对话中提出，智能体改为本群或删除 |
| 某个群整体敏感 | 管理员 | 在频道面板设为「只在本群用」，一次性设置 |
| 出现问题需要立即止住 | 管理员 | 管理页改为本群或删除；打开暂停流通 |
| 删错了 | 管理员 | 回收站恢复 |

- 管理员没有必须定期处理的事项。
- 已经发出的消息不能撤回，界面会说明这一点。
- 群成员不能通过对话把一张图改为流通，避免有人诱导智能体把截图放出去。

## 8. 验证

- **宿主**：资源库的频道可见性、配额与授权；工具附图的上限、去重与无视觉模型时的文字回退；索引的过滤、权重、向量生成与降级；本机层模型调用的限流与图片来源；能力声明的批准摘要包含 `index` 与 `models`。均有单元测试。
- **扩展**：可用性判断、去重合并、只能收紧、回收站、导入打标用内存替身做单元测试；导入验证通过。
- **真实环境**（空白实例、合成图片与公开图片、两个模拟群）：内置模型与运行库在界面中下载完成；导入 8 张合成图约 18 秒，截图被判为本群；对话中智能体收藏表情包并写出用途，拒收照片；在另一个群按意思找到并发出流通的表情包；拒绝发截图；被要求"别在这个群发"时照做。页面在明暗主题与窄屏下截图检查。

## 9. 实施状态

已实施：§4.1–4.5 的宿主能力、「设置 → 检索」、表情包扩展、"视觉"文案统一。

未实施：
- **平台表情包标记**：消息图片段增加 `sticker: true`，由适配器按平台填写（例如 OneBot 图片段的 `sub_type`），作为收藏时的强信号；
- **外部嵌入模型**：需要先在模型配置中支持嵌入模型类型，检索设置中已预留选项位置；
- 桌面版在 Windows 与 Linux 上下载原生推理运行库，尚未在打包产物上验证。
