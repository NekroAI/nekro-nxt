# NekroNxt 术语与文案规范

## 1. 品牌

| 场景 | 唯一写法 |
|---|---|
| 产品名 | NekroNxt |
| 根包名/仓库名 | `nekro-nxt` |
| 所属品牌 | NekroAI |
| 不再使用 | Nekro Harness、Nekro 新平台、Nekro Agent 2 |

## 2. 用户实体称呼

产品面对用户时只使用“智能体”。同一个对象不得根据页面随意改称 Agent、AI 成员、机器人、Bot 或助手。

正确示例：

- 创建智能体；
- 管理智能体；
- 小奈正在使用工具；
- 将此频道交给小奈响应；
- 为小奈启用“网页摘要”扩展；
- 2 个智能体正在使用此扩展。

错误示例：

- 创建 Agent；
- 管理 AI 成员；
- 当前 Bot 在线；
- Agent 配置；
- 给助手安装插件。

“助手”可以出现在具体名称中，例如“开发助手”，但不能作为实体类型。

## 3. 用户术语与内部类型映射

| 用户界面 | 内部 TypeScript 类型建议 | 说明 |
|---|---|---|
| 智能体 | `AgentDefinition` | 长期存在的身份和配置实体 |
| 智能体配置版本 / 配置版本 | `AgentRevision` | 不可变配置快照 |
| 会话 | `AgentSession` | 某配置版本在频道上下文中的运行实例 |
| 频道 | `Channel` | 单一消息事实流 |
| 频道绑定 | `ChannelBinding` | 指定谁响应及触发规则 |
| 平台连接 | `Connection` | 已登录的平台账号连接 |
| 平台用户 | `PlatformIdentity` | 某个平台连接内观测到的稳定用户身份；不同连接不合并 |
| 扩展 | `Extension` | 统一能力包 |
| 扩展版本 | `ExtensionRevision` | 不可变扩展版本 |
| 为智能体启用 / 智能体启用关系 | `AgentActivation` | 智能体对指定扩展版本的引用 |
| 动态包 | `DynamicPackage` | 创造会话中的临时可运行产物 |
| 工具 | `ToolContribution` | 扩展提供的一种贡献 |
| 适配器 | `AdapterContribution` | 扩展提供的消息平台贡献 |

内部类型使用 Agent 是为了与 DSH、生态 API 和英文代码保持一致，不构成产品文案例外。

明确标注为“DSH 原生界面”的兼容区域可以保留上游组件自带的 Agent、Plugin 等原文，因为这些文字属于可执行的第三方 Client UI，NekroNxt 不改写其内部实现。例外只作用于带有该标记的兼容岛：页面标题、入口、警示、错误、fallback 和其他 NekroNxt 外壳文案仍遵守本规范，也不得借此在普通产品界面重新使用 Agent 指代智能体。

## 4. 其他文案约束

- `Revision` 在普通界面写“版本”或“配置版本”，高级详情可附 `r12`；
- `Activation` 使用动作“为小奈启用”，管理页可写“智能体启用关系”；
- `Binding` 写“频道绑定”；
- `Connection` 写“平台连接”或具体账号；
- 一级“用户”页中的“用户”只指平台消息中已观测并持久化的身份，不表示 NekroNxt 后台登录账号；不得把昵称或裸平台 ID 当作跨连接人员身份；
- 由 NekroNxt 自带、独立于外部平台账号的频道统一写“内置频道”。不得写“网页频道”“网页聊天”“本地 Web”或“本地频道”；内部 Adapter key `web` 和 `kind: web` 仅用于兼容实现，不进入用户界面；
- `Extension` 写“扩展”，不混用插件、Skill、能力包；用户动作统一写“保存为本地扩展”；
- `Agent Loop` 只出现在开发文档，产品界面写“思考与工具执行过程”；
- `DSH 原生界面` 是上游 Client UI 兼容标记，不是新的产品实体或第二套扩展类型；
- 状态要说明对象：智能体空闲、平台已连接、频道监听中、工具执行中；不得用一个“在线”混合所有状态；
- 不得在产品壳写死 QQ、Discord 等平台名。选择平台时展示 Adapter 贡献的名称；频道来源、检查器和 Composer 使用该连接的展示名；无名群聊/私聊只写“群聊”“私聊”，可附尾号。开发文档可以写明某个 Adapter 的实现，那不是产品文案。
- Composer 常态只保留一个发送模式短标签、输入框和真实动作。不得同时重复“发给谁”“写在哪里”“对方会看到什么”等同义说明；必须常驻的阻塞原因压缩成一句，补充后果放入可聚焦的信息 Tooltip。
- Tooltip 只补充图标含义、快捷键或已经有短标签概括的发送后果，不能隐藏完成任务所必需的字段、错误或前置条件。
- 管理员从客户端向外部频道发言统一标记为“管理员从客户端发出”；不得写成智能体自己的发言，也不得泄漏内部 `admin-console` 值。

### 4.1 界面文案只说明对象、范围和结果

标题下说明、区块说明、空态和操作提示只保留用户完成当前任务所需的信息：正在操作什么、作用于谁、提交后发生什么，以及真正阻塞操作的前置条件。

产品界面不得自我解说导航结构，也不得把“少进入一个页面”写成产品价值。禁止句式包括但不限于：

- “不会 / 无需 / 无须 / 不需要 / 不必 / 不用”引出的臆测式否定；这类文案往往先虚构用户没有提出的权限、自动操作或页面路径，再自行否决；
- “不删除 / 不影响 / 不改变某个系统外对象”等防御性说明；危险操作只列本产品实际改变的对象和范围，不枚举操作触达不到的外部对象；
- “不需要 / 不必 / 不用 / 无需进入、前往、跳转、打开、切换或离开某个页面”；
- “可在本页 / 当前页 / 这里 / 此处完成”；
- “不需要逐个进入”“逐一打开”等步骤数量比较；
- 用“直接在这里”代替真实操作对象和结果；
- 用“之后 / 以后”代替明确的事件或顺序；需要表达时序时写“保存后”“收到下一条消息时”等可验证事件；
- 用“保持 / 继续 / 仍 / 仍然 / 始终”补充没有对比对象的状态延续；直接写当前状态或实际结果；
- 用“才能 / 才会”转述代码条件；控件缺少前置条件时直接写“请输入名称”“请先绑定频道”；
- 用“重开”描述上下文生命周期；按真实动作写“压缩上下文”“清空上下文”或“开始新上下文”；
- 用“到「页面」”描述导航；统一写“前往「页面」”；“发送到频道”“拖到此处”等非导航语义不受此条限制；
- 用破折号连接本可独立成句的解释，或用 `—` 代替缺失数据；缺失数据写“暂无”“未统计”或“不适用”。

这类缺陷通常来自五种实现视角：担心用户误解而提前辩护、把状态机变化逐句翻译到界面、把禁用条件原样写成“只有……才能……”、为规避遗漏而罗列所有未受影响对象，以及沿用工程口语或占位符。审稿时先删除这些解释，再检查剩余内容是否已经说清对象、动作、真实范围和结果；只有删除后确实缺少完成任务所需的信息，才用具体事实补回。

错误示例：

- 直接为这个智能体选择扩展，不需要逐个进入扩展详情；
- 保存后不必离开当前页面；
- 发现后可在本页绑定。
- 引用用于稳定识别，不会授予权限、读取其他频道或启用扩展；
- 保存后不会自动启用。
- 保存扩展是之后的独立操作；
- 配置仍保持可用，请继续操作；
- 创建智能体后才能启用扩展；
- 压缩并重开；
- 接入聊天平台。到「连接」添加账号；
- 从 NekroNxt 移除，不删除外部平台中的真实频道；
- 缓存占比：—。

正确示例：

- 选择这个智能体可以使用的扩展；
- 保存后立即更新频道绑定；
- 发现后即可绑定给这个智能体。
- 输入 @ 可引用用户、频道或扩展；
- 保存后再选择使用它的智能体。
- 保存扩展需单独操作；
- 基础配置可用；
- 请先创建智能体，再启用扩展；
- 压缩上下文；
- 前往「连接」添加账号；
- 解除绑定并移出 NekroNxt 频道列表；
- 缓存占比：暂无。

`scripts/check-terminology.mjs` 在现有 `pnpm check:docs` 与根 `pnpm check` 中检查上述模式，包括直接 JSX 文本、用户可见属性及其引用的文案变量，以及 Adapter Contribution 提供的平台名称、说明和配置字段文案。Adapter 平台名称不套用产品壳的平台禁词，但其说明仍接受同一套文案模式检查。命中时错误必须指向本节。若受限表达在具体位置承担不可替代的可访问性说明、兼容提示、安全后果、不可逆操作边界或语言内容本身，必须在 `scripts/baselines/user-visible-copy-exceptions.json` 集中添加精确例外：

```json
{
  "file": "apps/web/src/example.tsx",
  "rule": "copy:navigation-self-explanation",
  "text": "需要保留的完整用户可见文案。",
  "reason": "说明该文案在此处不可由对象、范围或结果替代的原因。"
}
```

例外按规范化后的完整文案精确匹配 `file + rule + text`，不得使用文件级跳过、宽泛正则或源码内忽略注释。`reason` 必须可审查；文案删除、改写或不再命中规则后，陈旧例外会使检查失败，必须同时清理。

## 5. 创造状态

- “创造”是同一智能体启用动态创造相关能力后的运行状态，不是另一种用户实体；
- 不创建或展示“创造助手”“创造智能体”等类型名；
- 工作台应直接显示原智能体，例如“小奈 · 已启用创造能力”“与小奈协作创造”；
- 面向用户把系统访问组织为四段快捷预设：“基础权限（Lv.0）→ 文件读写（Lv.1）→ 运行命令（Lv.2）→ 完整访问（Lv.3）”。预设逐级包含左侧能力；展开后仍可逐项控制，组合不匹配预设时显示“自定义权限（Lv.C）”。列表中的轻量 Chip 只显示等级码，完整名称与说明放在悬浮提示中。内部字段继续使用 `fileTools`、`developmentShell`、`unrestrictedFileAccess`，不得把这些实现名泄漏到界面；
- 动态创造是授权能力中的扩展能力子区；子智能体与网页搜索位于“更多能力”，两项互不依赖。不能用“进入创造模式”暗示同时获得系统访问；
- 内部实现可以使用 DSH Preset 组合相关 Tool，但 Preset 名称不得改变用户可见的智能体身份。
