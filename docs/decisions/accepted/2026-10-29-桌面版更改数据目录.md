# 桌面版更改数据目录

状态：accepted（2026-10-29，issue #65）

## 目标

用户在桌面版设置里选择新目录，等待进度完成，就能看到原来的智能体和频道。不需要环境变量、`mklink` 或注销重新登录。Docker 版不提供这个功能。

## 已定的要求

- 同一个磁盘内直接移动；跨盘时先复制并校验，通过后再切换，失败就回到原目录；
- 迁移整个桌面数据目录，迁移后和原来一样，包括实例档案、凭据和本机偏好；
- 目标不能是网络盘或同步盘；
- 旧目录不自动删除，界面给出它的路径，由用户确认后删除。

## 现状里的约束（已核实）

| 约束 | 说明 | 处理 |
| --- | --- | --- |
| 启动时就定下数据目录 | `app.setPath('userData')` 在模块顶层执行，早于单实例锁和 app ready。Electron 的会话、缓存、`safeStorage` 都绑定在这个目录上 | 必须重启应用才能切换。目录指针放在默认位置旁边的独立文件里，由 `desktopUserDataRoot` 在 `setPath` 之前同步读取 |
| 运行中的应用占着目录 | Electron 的浏览器存储（LevelDB）和本机服务的 SQLite 在运行时都被占用 | 迁移在「迁移模式」中进行：应用带标记重启，这次启动把 userData 临时指向一个空的暂存目录，原目录就没有人占用；完成后再正常重启 |
| 会话存储记录绝对路径 | `data/dsh/session-storage.json` 的 `sessionRoot` 是绝对路径，启动时和当前路径不一致就报错（`dsh-session-storage.ts:264`）；重置标记和归档清单里也有绝对路径 | 迁移时改写成新路径 |
| 会话目录名由工作区的绝对路径编码 | DSH 会话目录是 `sessions/--<工作区绝对路径编码>--/<编号>/`，读取时按会话头里记录的工作区路径定位 | 不尝试续接：迁移后，每个频道的下一条消息先整理摘要，再开新会话（与闲置压缩相同的交接方式）；旧会话文件随目录保留，只供查阅 |
| 恢复点里有绝对路径 | 升级恢复点清单的目标是绝对路径，体积约等于两份数据 | 不迁移，留在旧目录；界面说明旧恢复点不能用于新目录，下次升级在新目录生成新的 |
| 凭据加密 | `instance-credentials.json` 用 Electron `safeStorage` 加密，Windows 上的密钥保存在 userData 的 `Local State` 里 | `Local State` 必须一起迁移；同一台机器、同一个系统用户才能解密，这正是迁移的场景 |

## 流程

1. **入口**：新增「设置 → 存储」，显示当前数据目录的路径和占用大小，以及「更改」按钮；升级恢复点设置和旧目录提示也放在这里。只在桌面版的本机实例里显示。用环境变量 `NEKRO_DESKTOP_USER_DATA` 指定了目录时，按钮不可用，说明「数据目录由环境变量指定」。
2. **选择目录**：使用系统的文件夹选择框。选择后立即预检：
   - 目标为空或不存在；新旧目录不能互相包含；
   - 可以写入（写一个探测文件再删掉）；
   - 剩余空间不少于需要迁移的大小再加 10%；
   - 不是网络盘或同步盘：拒绝 UNC 路径和映射的网络驱动器；拒绝 OneDrive、Dropbox、iCloud Drive、坚果云、百度网盘同步目录（根据环境变量、配置文件和路径特征判断）；
   - Windows 上路径长度留出余量（目标路径加 260 个字符以内），会话目录名最长 251 个字符。
   预检通过后显示：迁移方式（移动或复制）、大小、预计时间，以及「迁移期间应用会重启，本机实例暂停」。
3. **进入迁移模式**：
   - 写入迁移记录 `data-move.json`（放在默认位置旁边，记录阶段、源、目标）；
   - 停掉本机服务，等它正常退出；
   - 带 `--nxt-move-data` 重启应用。
4. **迁移**：迁移模式只显示一个进度窗口。
   - 同盘：把数据目录里的每一项逐个重命名到新目录，升级恢复点 `data/backups` 留在原处；
   - 跨盘：
     - 按清单复制，跳过可以重建的内容（日志、扩展缓存、运行环境下载、插件暂存、请求图片缓存、pnpm 缓存、Electron 的网页缓存）；
     - 保留符号链接；
     - 对每个文件核对大小和 SHA-256，对 `core.sqlite` 运行 `integrity_check`。
   - 两种方式都要改写 `session-storage.json` 等记录了绝对路径的文件。
5. **切换**：原子写入目录指针（先写临时文件再重命名），把迁移记录标为完成，然后正常重启，从新目录启动。
6. **完成后**：
   - 「设置 → 存储」显示新目录；
   - 复制的情况下，额外显示「旧目录」的路径、大小、「在文件夹中显示」按钮，以及「我已删除，不再提示」。

## 失败与恢复

- 切换之前的任何失败（复制出错、校验不一致、空间不足、被占用）：删除这次在目标里新建的文件，指针保持不变，正常启动回到原目录，并说明哪个文件因为什么失败；
- 迁移中崩溃或断电：下次启动先读迁移记录。还没切换的，按上一条清理后回到原目录，并提示可以重新迁移；已经写好指针的，按新目录启动；
- 同盘移动逐项重命名，每一项要么在新目录、要么在原处；迁移记录先写下要改写的文件原文，中断后按记录把各项和原文放回原目录；
- 迁移记录本身损坏时，按指针当前指向的目录启动。

## 已定的取舍

- 迁移后一律开新会话，不尝试续接旧会话：简单可靠，代价是丢掉当前会话的完整上下文，只保留摘要；
- 升级恢复点不迁移，两种方式都留在原目录的 `data/backups`；
- 入口放在新增的「设置 → 存储」。

## 实现中的取舍

- 指针和迁移记录放在系统应用数据目录里、默认数据目录的旁边：`<名称>.data-location.json`、`<名称>.data-move.json`。迁移模式使用的空 userData 是 `<名称>.data-move-session`，下次正常启动时删除。
- 启动顺序：环境变量 → 指针 → 默认位置。指针无法读取时不回退到默认位置，提示修复或删除指针文件后退出，避免误开一个空实例；指针指向的目录不存在时（外置盘未连接）同样提示后退出。
- 迁移中断后的恢复不在旧目录上进行：下次启动同样进入迁移模式的空 userData，先恢复原目录，再正常启动。还没进入迁移模式就中断的请求直接作废。迁移进程在记录里写心跳，期间再次打开应用会提示“正在更改数据目录”并退出。
- 剩余空间检查只用于复制；同盘移动不占用额外空间。
- Windows 路径长度：目标路径比原路径长、且会让已有文件的完整路径超过 260 个字符时拒绝。DSH 会话目录名由 DSH 自己截断到 251 个字符以内，迁移后不会续用旧会话目录。
- 复制时跳过的可重建内容与升级备份一致（`logs`、`extension-cache`、`runtimes`、`dsh/plugin-staging`、`dsh/request-images`、`dsh/pnpm-store`），另加 Electron 的网页缓存和 `Crashpad`；同盘移动连同缓存一起移动。Chromium 的单实例锁文件留在原处。
- 数据库检查对复制后的 `data/*.sqlite` 逐个运行 `integrity_check`：主进程不打开数据库，交给随应用打包的本机服务以 `--check-sqlite` 只读检查，不启动服务。
- 网络盘与同步盘识别：Windows 拒绝 UNC 路径和类型为网络的盘符；macOS 读 `mount` 的文件系统类型，Linux 读 `/proc/self/mounts` 和 `statfs` 类型；同步目录看 `OneDrive*` 环境变量、Dropbox 的 `info.json`、iCloud 云盘与 macOS `~/Library/CloudStorage`，以及坚果云、百度网盘同步空间、OneDrive、Dropbox 的默认文件夹名。macOS 开启“桌面与文稿”iCloud 同步后的 `~/Desktop`、`~/Documents` 目前识别不到。
- 迁移后开新会话：迁移在新数据目录写入 `host/data-root-moved.json`，本机服务启动时把当时进行中的对话记进系统设置 `host.data-root-move.pending-rollover` 并删除标记；这些对话各自在下一条消息到来时整理摘要、开新会话，旧对话的结束原因记为 `incompatible-session-storage`。重启不会丢失待开新会话的列表。
- 「设置 → 存储」对所有宿主都显示升级前备份设置（从「关于」移来）；数据目录、旧目录和上次失败只在桌面版本机实例中显示。旧目录在两种方式下都会提示：复制时是完整的原数据，同盘移动时只剩升级恢复点。

## 契约入口

- `apps/desktop/src/data-location.ts`：指针格式、文件位置与启动时的目录解析；
- `apps/desktop/src/data-move.ts`：迁移记录格式、复制与校验、逐项重命名、路径改写、撤销与启动时的恢复判断；
- `apps/desktop/src/data-move-plan.ts`：迁移内容、可重建内容与预检；
- `apps/desktop/src/storage-location.ts`：网络盘与同步盘识别；
- `apps/desktop/src/data-move-mode.ts`、`data-move-window.ts`：迁移模式与进度窗口；
- `apps/desktop/src/data-directory-service.ts` 与 `product-preload.ts` 的 `nekroDesktopStorage`：设置页的桥接接口，只回应本机实例自己的页面；
- `apps/server/src/data-root-move.ts` 与 `ChannelRuntimeOptions.pendingRollover`：迁移后开新会话；
- `apps/web/src/app/settings/storage-section.tsx`：「设置 → 存储」。
