# MCP 服务接入

状态：implemented（2026-10-07 用户确认并实施）

## 1. 用户已确认的取舍

1. MCP 作为无代码扩展，在工坊添加，按智能体启用并审批。
2. 远程服务（Streamable HTTP）和本机程序（stdio）都支持；本机程序只能由管理员在界面添加。

## 2. 模型：扩展能力而不是新实体

MCP 服务是智能体扩展的一项宿主能力 `permissions.capabilities.mcp: { servers }`，每个服务为 `{ transport: 'streamable-http', name, url, headers }` 或 `{ transport: 'stdio', name, command, args, env }`。请求头和环境变量的值可以是文本，也可以是 `{ secret: 字段 }`，引用 `config.schema` 中 `meta.role: 'secret'` 的凭据字段；Manifest 校验引用必须指向凭据字段。

这样 MCP 复用扩展已有的全部机制：不可变 Revision、按智能体启用、启用时的能力审批、凭据存储（值在凭据库，Activation 配置只存引用）、导出分享与导入。没有为 MCP 另建表、另设启用流程或允许 Manifest 不带代码；工坊表单生成的扩展带一个空的 Host 源码，宿主按声明连接服务。

## 3. 连接

扩展的 Activation 挂载到智能体的某个频道 Session 时，宿主为每个声明的服务在该 Activation 的上下文中加载 DSH `@deepseek-ai/dsh-mcp-client`，配置中的凭据引用在此时解析。工具以 `mcp__<name>__<tool>` 出现在模型工具列表，服务说明作为带来源的系统提示段，资源读取由 `@deepseek-ai/dsh-mcp-resources` 提供。

- 不等待连接完成：慢或不可达的服务不能拖住智能体的回合；断线重连、工具列表变化都由 DSH 桥接处理。
- 缺少凭据的服务不连接并写诊断，其他服务照常。
- 停用或删除扩展时随上下文一起断开，本机程序随之退出。
- stdio 的工作目录是智能体工作区（宿主没有工作区根时为用户主目录），环境变量在去除名称含 KEY、PASSWORD、SECRET、TOKEN 的环境后合并声明值。
- 每个频道 Session 各自连接一次：智能体绑定多个频道时，本机程序会有多个进程。共享连接需要跨 Session 注册同一组工具，待使用量证明需要时再做。

## 4. 添加与审批

工坊「添加 MCP 服务」表单填写名称、连接方式、地址或命令与参数、请求头或环境变量（开关决定是否作为凭据）、工具前缀和要启用的智能体。「测试连接」用填写的值临时连接一次并列出工具，不保存任何内容。添加时客户端不发送凭据值；扩展创建后若选择了智能体，走与其他扩展相同的审批对话框，确认后把填写的凭据写入该智能体的 Activation 凭据。

审批摘要：远程服务为敏感项「连接 MCP 服务 name」并显示主机；本机程序为高风险项「在本机运行 MCP 程序 name」并显示完整命令，需要逐项确认。连接目标（地址、命令或参数）变化视为能力扩大，需要重新审批；凭据变化不需要。

只有管理员的工坊表单和导入扩展文件这两个界面动作能带入 MCP 声明。动态创造在定义和保存时拒绝 `capabilities.mcp`，编写参考要求智能体引导用户去工坊添加，因此对话不能让宿主运行新的本机程序。

## 5. 未做与边界

- 单个工具的禁用、连接状态的界面诊断（目前写服务日志）、MCP Prompt 模板与资源订阅、OAuth 授权流程尚未提供。
- 本机程序是宿主进程以同一用户权限运行的任意程序；只应添加可信的服务。Desktop 不预装 Node 或 Python，需要这些运行时的本机服务由用户自行安装。

实现入口：`packages/contracts/src/extension-capabilities.ts`（能力与表单 Schema、审批摘要、能力扩大判定）、`apps/server/src/mcp-servers.ts`（表单转扩展、连接配置、测试连接）、`apps/server/src/host-routes-mcp.ts`、`apps/web/src/app/workshop/mcp-dialog.tsx`。
