# 适配器零知识 Host、活动事实与产品 Slot

状态：implemented

本文是 Adapter Host API、第一方装配、活动事实、运行能力、富消息和产品 Slot 的现行契约。具体平台协议只属于各 Adapter 包；主应用不理解任何平台名称、Adapter key、协议字段或活动名称。

## 1. 决策结果

NekroNXT 的主应用只理解 Connection、Channel、Activity、Capability 和 Host Port：

- `apps/server/src` 只依赖 `@nekro-nxt/adapter-sdk` 和 `@nekro-nxt/adapter-builtin-roster`，遍历贡献集合完成第一方 Adapter 注册；
- `apps/web/src` 只按 Snapshot 中的 Adapter Descriptor 和运行能力渲染，不维护平台映射；
- `contracts`、Core、Channel Runtime 和 Storage 接受开放的 `AdapterActivityKey`，不枚举平台活动；
- `@nekro-nxt/adapter-builtin-roster` 是唯一可以集中静态导入第一方 Adapter 的组合包；
- 具体 Adapter 拥有协议解析、网络、恢复状态、媒体、引用、诊断和账号展示投影，通用 Host 只提供受限服务。

静态门禁禁止主应用导入具体 Adapter 包、按 Adapter key 字面量分支，或出现已知平台名称和旧频道 kind。应用测试使用 `fixture-alpha`、`fixture-beta` 等虚构 Adapter。新增自定义活动只修改 Adapter 或 roster 测试夹具，不修改主应用和通用领域包。

## 2. Adapter Host Contribution V2

Registry 只接受 `apiVersion: 2`，不加载 V1，也不提供双版本兼容层。Descriptor 是产品目录和活动目录的唯一事实源：

```ts
interface AdapterActivityDefinition {
  key: AdapterActivityKey
  scope: 'channel' | 'connection'
  displayName: string
  description: string
  icon?: HostIconName
  triggerable: boolean
  channelKinds?: readonly ('internal' | 'direct' | 'group')[]
}

interface AdapterConnectionDescriptor {
  key: string
  displayName: string
  description: string
  provisioning: 'user-created' | 'system-singleton'
  aliasEditable: boolean
  channelDiscovery: 'host-created' | 'adapter-observed'
  channelKinds: readonly ('internal' | 'direct' | 'group')[]
  diagnostics: { receive: boolean; send: boolean }
  activities: readonly AdapterActivityDefinition[]
  features: {
    processingFeedback?: {
      channelKinds: readonly ('direct' | 'group')[]
    }
  }
  configSchema: AdapterConnectionUiSchema
}
```

Registry 在注册时拒绝以下贡献：

- owner、Adapter key 或活动 key 重复；
- key、Schema、scope 或 Channel kind 非法；
- Connection 活动声明 `triggerable: true`；
- 活动声明的 Channel kind 不属于该 Adapter；
- 处理中反馈包含 `internal` 或 Adapter 不支持的 Channel kind；
- `system-singleton` 允许编辑别名，或不满足系统单例约束。

Host 在挂载 Runtime 前再次校验运行能力必须与 Descriptor 精确对应，避免 Adapter 声明和实际状态漂移：

```ts
interface AdapterRuntimeCapabilities {
  outbound: AdapterOutboundCapabilities
  activities: Readonly<Record<AdapterActivityKey, AdapterCapabilityState>>
  processingFeedback?: AdapterCapabilityState
}

type AdapterCapabilityState = {
  state: 'available' | 'disabled' | 'unsupported' | 'degraded' | 'unknown'
  reason?: string
}
```

`AdapterConnectionRuntime.localChannel` 是可选的内置频道端口。Host 通过 `system-singleton + internal + localChannel` 找到唯一内置实现，自动创建对应 Connection；它不保存或比较具体 Adapter key。Channel kind 统一为 `internal | direct | group`。

## 3. Host Service 与平台实现归属

Adapter 只能通过 `AdapterConnectionHostContext` 使用下列 Connection 作用域服务：

- `channels`：发现频道、更新安全展示名、解析平台频道标识；
- `identities` / `members`：分别维护 Connection 身份和 Channel 成员；
- `messages`：在当前 Connection 和 Channel 内解析逻辑消息与平台消息映射；
- `assets`：受控导入、读取和远程抓取媒体；
- `credentials`：按引用读取只写凭据；
- `state`：保存 Connection 作用域的恢复状态；
- `diagnostics`：发布通用诊断投影；
- `transport`：使用 Host 管理的 HTTP 和 WebSocket；
- `acceptChannelInbound` / `acceptConnectionInbound`：提交两类事实。

平台 Gateway checkpoint、网络测试、媒体上传、Quote 解析、账号摘要和诊断状态都由 Adapter 包实现。Server 不保留平台专用 Bridge、创建方法、选项、状态结构或 API。

## 4. Channel 活动与 Connection 活动

两类活动使用不同提交协议和持久流。

### 4.1 Channel 活动

`AdapterChannelInboundEvent` 必须包含 Connection、Channel 和 Adapter 所有权，活动通过可选 `activityKey` 标识。Host 按 `connection → registry contribution` 验证：

1. Connection 属于该 Adapter；
2. Channel 属于该 Connection；
3. 活动已由 Descriptor 声明为 `scope: channel`；
4. 当前 Channel kind 在活动允许范围内。

验证失败时拒绝提交并发布 Adapter 诊断。成功后活动进入 Channel Event Log，可参与频道检索、历史、Episode 上下文和 Admission 判断。

### 4.2 Connection 活动

`AdapterConnectionInboundEvent` 表示账号、好友关系等不属于具体频道的事实，包含安全 `summary`、可选 actor/subject 身份、时间、去重键和有限 JSON facts。Host 验证活动已声明为 `scope: connection` 后写入 `connection_events`。

Connection Event：

- 按 `(connection_id, dedupe_key)` 去重；
- actor 和 subject 必须是该 Connection 拥有的 Platform Identity；
- 按 `(received_at, id)` 倒序游标分页；
- 只在 Connection 详情和 `connection-fact` SSE 中展示；
- 不创建 Channel 或 ChannelMember；
- 不进入 Episode、Admission、Channel Runtime 或智能体上下文，也没有触发开关。

已经写入 Channel 历史的旧账号事件保持不变，避免破坏逻辑消息、Admission 和 Episode 引用；只有新事实走 Connection Event。

## 5. Binding 与触发规则

具体 Connection 使用 `activityTriggerDefaults` 保存频道活动默认值；默认空数组。Binding 使用 `activityTriggerOverrides: Record<AdapterActivityKey, boolean>` 保存单个频道的例外：key 缺失表示跟随 Connection，`true` 表示强制开启，`false` 表示强制关闭。普通消息仍由 `triggerPolicy` 控制；Channel 活动只有同时满足以下条件才创建 Admission：

- 当前 Adapter 已安装；
- Descriptor 声明该 key 为 `scope: channel && triggerable: true`；
- 活动适用于当前 Channel kind；
- Runtime 能力不是 `disabled` 或 `unsupported`；
- `binding.activityTriggerOverrides[key] ?? connection.activityTriggerDefaults.includes(key)` 为 `true`；
- Binding 不是 `observe-only`。

保存 Connection 默认值或 Binding 覆盖时执行同样校验；实时触发、恢复 Admission 和积压处理也重新读取 Connection、Binding 与当前 Descriptor，不能仅按字符串相等触发。

Adapter 注册或更新后、挂载 Runtime 前，Host 清理该 Adapter 现有 Binding 中不再受支持的活动。Adapter 未安装时保留已有值但视为休眠；重新安装后先校验和清理，再启动 Runtime。

`processingFeedback` 只有在 Descriptor 为当前 Channel kind 声明功能且 Runtime 提供对应状态时才生效。耐久 Lease 属于 Connection 命名空间，在真正的平台调用前持久化，并在 Session 空闲、失败、停机或重启恢复时清理。

## 6. Host API 与 Web 投影

Host Snapshot 透传完整 Descriptor。Connection 状态只使用通用字段：运行状态、凭据状态、`accountReference`、出站能力、活动能力、处理中反馈能力、实现信息和可选诊断结果。

Web 通过 `channel → connection → descriptor` 计算频道设置：

- 只显示当前 Adapter、当前 Channel kind 下可触发的 Channel 活动；
- `disabled` / `unsupported` 不显示，`degraded` / `unknown` 显示 Adapter 提供的原因；
- 没有活动时不显示“频道活动”入口；
- Connection 活动永远不进入 Binding；
- 处理中状态按 Descriptor 和 Runtime 的当前能力过滤；
- 每项显示“跟随连接（当前开启/关闭）/ 始终开启 / 始终关闭”三态选择；
- `observe-only` 禁用活动覆盖。

Connection 详情只显示这个 Descriptor 声明且 Runtime 未禁用的可触发频道活动，并以开关编辑 `activityTriggerDefaults`。修改一个 Connection 不影响同 Adapter 的其他 Connection。

Connection 详情通过 `GET /api/connections/:connectionId/events` 分页读取 Connection Event，并通过 `connection-fact` SSE 接收新事实。该区域只展示摘要、参与者和时间。

用户创建的 Connection 可以删除，系统单例不能删除。删除确认提供“同时删除频道数据”：关闭时将 Connection 归档，停止 Runtime 并从活动产品状态隐藏，但保留凭据引用、Channel、成员、Binding、消息和运行历史；添加连接界面可按原 Connection ID 明确恢复，Host 不根据 Adapter 配置猜测账号。开启时先停止相关 Channel lane，再物理删除该 Connection 范围内的频道、成员、Binding、Channel/Connection Event 和 Core Runtime 记录，并删除凭据；此结果不可恢复。

Adapter 必须在入站时提供安全摘要和可选展示名。Host 不解析平台 ID 前缀，也不猜测频道格式；名称缺失时只按 kind 显示“未命名群聊”“未命名私聊”或“未命名内置频道”。

## 7. 富消息与产品 Slot

公共 `MessagePart` 仍是 `text`、`mention`、`image`、`file`、`audio`、`quote` 和 `rich` 的稳定联合。`rich` 保存必填安全 `summary`、可选 title/source/HTTP(S) 导航目标、受控预览 Asset 和限大小 JSON extension；临时媒体 URL 和原始协议事件不得进入事实流。

产品壳使用独立 Slot Registry，当前 Adapter 槽为：

| 槽 | key | 宿主 fallback |
|---|---|---|
| `conversation.message.rich` | `adapterKey:kind` | summary/title/source/preview 卡片 |
| `connection.adapter.setup` | `adapterKey` | Descriptor Schema 表单 |
| `connection.adapter.status` | `adapterKey` | 通用状态区 |
| `connection.adapter.test` | `adapterKey` | 通用诊断区 |
| `channel.inspector.adapter.sections` | `adapterKey` | 无额外区块 |

Slot 只增强展示，不改变 Connection、Channel、Binding、Credential 和事实模型。Adapter Client 随 Host Installation 挂载，不跟智能体 Binding 走；卸载或渲染失败后自动回退到宿主实现，历史 `parts` 仍可读取。

## 8. 迁移与兼容

数据库迁移执行以下变化：

- `channels.kind = web` 原子转换为 `internal` 并重建约束；
- `event_triggers` 更名为 `activity_triggers`；
- `activity_type` 更名为 `activity_key`，旧值原样保留；
- 创建 `connection_events`、去重索引、时间索引和身份外键。
- `0022_connection_activity_defaults_and_archive` 增加 Connection 默认活动、Channel 关闭覆盖和 Connection 归档时间；旧 `activity_triggers` 原样成为显式开启覆盖，因此升级前行为不变。

本轮不兼容 Adapter Contribution V1。保留现有 Connection、Channel、Binding 和历史消息；只清理当前已安装 Adapter 的无效触发配置，不迁移或复制历史活动事实。

扫码登录由宿主登录会话拥有，Adapter 只声明 `creation.mode`；OAuth 仍可走可选 `connection.adapter.setup` Slot。不允许 Adapter 在主应用里增加平台专用创建页面。远程市场、签名、SBOM 和进程隔离不属于当前实现。
