# 决定：M6 产品 UI 停线整改

状态：implemented

## 背景

当前 Web 已接通智能体、模型供应商、平台连接、频道绑定和真实对话的部分领域入口，但页面仍混合生产事实、演示占位和内部实现文案。现有产品旅程能发现白屏、空按钮和主要请求失败，却不能证明空间布局、浮层层级、信息架构、失败反馈和普通用户文案达到产品可交付标准。

真实页面审查确认的问题不是独立样式缺陷，而是 M6 尚未完成：Host 断线可能仍显示节点正常；运行页含硬编码事件；普通页面泄漏 Revision、Gateway、Session、Package 和技术 ID；基础组件没有统一层级与表单语义；三档桌面视口、双主题和失败状态没有进入交付门禁。

在本整改完成前，暂停增加新的用户可见页面和占位入口。

## 决定

### 1. 产品事实先于视觉

- Web Host 必须显式表达 `initializing`、`ready`、`stale` 和 `error`，首次失败、真实空数据和断线保留旧数据不得显示成同一状态；
- 生产 Store 不内置演示智能体、频道、消息、扩展、运行事件或健康事实；测试 fixture 与生产初始化分离；
- 所有 mutation 返回 Promise，页面统一处理 pending、防连点、失败恢复和成功反馈；不允许 fire-and-forget 或因缺少内部字段静默返回；
- Display Projection 不用内部 ID、Adapter key、平台频道原始 ID 或内部状态枚举作为普通用户展示 fallback。

### 2. app-owned ui-kit 成为唯一基础控件层

- 一期继续使用 React 18、Radix、CSS Modules 与 `--nxt-*` Token，不引入 Tailwind、完整视觉组件库或第二套前端技术栈；
- 当前只有 Web 一个真实消费者，ui-kit 先由 `apps/web/src/ui-kit/` 拥有；Desktop 或 Extension UI 出现第二个消费者时再评估迁入 workspace package；
- 业务页面不得直接导入 Radix 或手写 Button、Select、Switch、Tabs、Dialog、Tooltip 等基础交互；
- Modal 使用动态 layer registry。同层满足 overlay < content < floating；后打开 Modal 的 overlay 高于前一层 floating；
- Dialog 使用固定 header、独立滚动 body 和固定 footer，支持 Escape、焦点回收、关闭按钮、视口高度约束与双向动画；
- Token 覆盖颜色、排版、4px 间距、尺寸、圆角、阴影、层级和 Motion，业务 CSS 不复制基础常量。

### 3. 页面按四种布局模式收口

- Collection：智能体和扩展列表；
- Workbench：连接、创造和运行；
- Conversation：频道目录、消息事实流和检查器；
- Configuration：智能体、模型供应商和设置。

代表页面必须在 1100×720、1440×900、1920×1080，浅色、深色和 Reduced Motion 下成立。宽屏要利用横向空间；窄桌面可以收起次要检查器，但不能裁切或静默丢失核心操作。

### 4. 用户文案设置展示防火墙

- 普通页面只描述当前对象、状态、影响和下一步；
- 内部术语只能在明确的高级技术详情中出现，并默认折叠；
- 无展示名的平台频道使用脱敏且可区分的名称，不显示完整群号或平台原始 ID；
- 错误以稳定 code 映射成产品文案，原始调用链和内部错误只进入日志或技术详情；
- 未实现能力不以一级导航、主按钮或大量“尚未开放”控件占据产品界面。

### 5. UI 交付采用双链路门禁

- 源码链路：所有权、数据状态、mutation、组件复用、文案边界、可访问性和测试；
- 视觉交互链路：真实生产 bundle、关键操作、截图、空间分配、层叠、滚动、主题、视口和失败状态；
- 两条链路任一不通过，不得转用户验收；Console 无错、DOM 存在和 API 成功不能替代视觉结论；
- `pnpm verify:product` 最终串联 ui-kit 边界、术语、组件、领域、构建、产品旅程和代表性视觉基线。

## 实施顺序

1. Host 状态、生产 fixture 分离、可靠 mutation 和安全展示 fallback；
2. ui-kit 语义、动态层级、Dialog、表单、反馈与边界门禁；
3. 应用外壳和四种布局模式；
4. 模型供应商、连接/绑定、智能体、频道会话四条首要用户路径；
5. 扩展、创造工作台和运行情况；
6. 三档视口、双主题、错误态、键盘、层叠和视觉基线收口。

## 完成条件

- 普通页面无内部 ID、DSH/Cordis/数据库实现词或需求讨论文案；
- Host 异常不显示正常状态，所有写操作具备 pending、失败与恢复；
- 所有一级页面具备 loading、empty、ready、error；
- 所有弹层在 720px 高度完整可操作，嵌套 Modal 与浮层顺序确定；
- Switch、Select、Dialog、Tabs 可通过键盘和辅助技术操作；
- 三档桌面视口无裁切、异常留白、核心信息丢失或主任务漂移；
- 浅色、深色、Reduced Motion 和目标缩放下通过真实截图复核；
- 关键旅程经 UI 操作后重新读取 Server 外部结果，不相信页面自称成功。

## 实施结果与验证证据

- 生产 Store 已移除演示智能体、频道、消息、扩展和运行事实；Host 明确区分初始化、正常、旧数据失效和首次连接失败；
- 写操作统一返回 Promise，页面具备 pending、防连点、失败反馈和恢复路径；
- app-owned ui-kit 已统一 Button、Field、Select、Switch、Tabs、Dialog、Tooltip、动态浮层顺序和固定 Dialog 区域；
- 一级导航收敛为“智能体 / 消息 / 连接 / 扩展 / 设置”，创造和运行仅保留上下文直达路由；
- DSH 供应商目录继续作为唯一数据源，Web 只增加产品展示名投影，不维护第二份模型能力目录；
- 静态门禁无临时 allowlist：业务页面不得直接导入 Radix 或原生基础控件，禁止空操作和用户可见内部术语/技术标识回退；
- Playwright 覆盖 1100×720、1440×900、1920×1080，浅色、深色、Reduced Motion、Host 错误恢复、Dialog/Select 层级、Escape/焦点回收和 mutation 失败恢复；
- 真实截图复核修正了 1920×1080 下会话区仅占 720px 的异常留白；
- `pnpm verify:product` 通过：36 个测试文件、161 个单元/组件/领域测试、8 个生产构建浏览器旅程全部通过；
- 使用本机凭据存储中的 DeepSeek V4 Flash 完成真实网页频道回归，Server 外部快照返回智能体消息“对话正常”，投递状态为已发送。

## 未来方向与参考取舍

关联方向：更多 Adapter、Extension Client UI、Desktop/Server 共用 Web、智能体多频道。

保留接缝：React singleton、Radix primitive、语义 Token、Adapter schema、Channel/Binding 分离、Host Display Projection 和 DSH 公共 API。当前 app-owned ui-kit 不妨碍出现第二个真实消费者后迁入共享包。

参考同类桌面 AI 项目的动态 Modal layer、固定 Dialog chrome、ui-kit 依赖边界、可调分栏和双链路 UI 验收。拒绝照搬 Tailwind、React 19、其他品牌视觉、企业后台对象、“助手”术语、390px 移动端要求和外部项目运行依赖。

本次明确不提前实现：移动端导航、完整 DataGrid、第二前端栈、社区市场、复杂动画框架和 Desktop 打包。
