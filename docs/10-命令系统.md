# 命令系统

聊天命令是频道消息之外的显式操作入口，由同一个 Host 执行服务处理平台聊天与 Web 请求；不调用模型来识别命令或代替授权。设置的「聊天命令」分区管理全局策略，频道检查器管理覆盖与成员授权。这里的「命令」不是智能体运行的 shell 命令，也不是 `⌘K` 命令面板。

## 语法与目标

`/命令 参数 --选项 值` 支持 Unicode 名称、别名、单/双引号、反斜线转义、位置参数、`--key=value`、布尔选项与 `--` 结束选项解析。参数按声明的 string、number、integer、boolean、choices、min/max 验证；字符串长度按 Unicode 码点计算。缺少参数、重复/未知选项、类型错误及未闭合引号均返回用法。

单引号和双引号内都支持反斜线转义，例如 `'a\ b'` 得到 `a b`；这与 shell 的单引号规则不同。非布尔选项的值若以 `--` 开头，使用 `--key=--value`；写成 `--key "--value"` 仍会报缺少值。

**谁的命令。** 只识别纯文本。内置频道、Web 和私聊中，`/命令` 直接执行；外部群聊中，默认只有指向当前账号的消息才是命令：消息开头 `@当前账号`（`@机器人 /status`），或平台本身确认提到了本账号（QQ 官方的群 @ 事件、企业微信群回调；这类平台可能去掉 @ 片段，或把 `@名称` 留成文字）。未指向本账号的 `/xxx` 按普通聊天处理，不记失败、不回复。管理员可按频道开启「允许不带 @ 的命令」，此后群里直接输入 `/命令` 也会执行。`@其他成员 /stop`、含引用或附件、代码块都不是命令。`//` 在可识别为命令的位置去掉一个斜杠作为普通聊天，原始入站事实仍保留。

**只拦截认识的名称。** 平台来源的 `/xxx` 只有在名称对应当前频道的已注册命令（内置命令及别名、扩展命令完整名或唯一短名；扩展暂时不可用时仍算）时才按命令处理；其他名称是普通聊天，照常交给智能体，所以路径、QQ 的 `/微笑` 这类表情快捷输入不会被吞掉。控制台输入不认识的命令仍提示「未知命令」。一条消息是不是命令在入库时决定一次并持久保存（执行记录，或因限速被忽略的记录），之后修改设置不会改变历史消息的归类。

这套文本命令与适配器的原生命令事件不同：Binding 的触发方式「平台命令事件」（`triggerPolicy: command`）依据适配器上报的 `facts.command` 触发智能体，不拦截文本，两者互不影响。

## 内置命令

| 命令 | 行为 | 最低权限 |
|---|---|---|
| `/help [命令]` | 当前频道、当前调用者可用的命令、参数、示例 | 普通用户 |
| `/status` | 频道、智能体、响应模式、暂停状态、运行状态 | 普通用户 |
| `/stop` | 只停止当前轮次，保留上下文；之后的新消息仍会触发回应；没有运行中的任务时如实回报 | 频道管理 |
| `/reset` | 停止当前工作并从新的上下文开始；聊天历史、频道说明与笔记保留 | 频道管理 |
| `/compact` | 整理上下文，会中断当前工作 | 频道管理 |
| `/pause`（别名 `/off`） | 暂停当前频道的所有自动响应并停止当前轮次，响应规则保留 | 频道管理 |
| `/resume`（别名 `/on`） | 解除暂停，按当前响应规则恢复；不重跑已停止的任务 | 频道管理 |
| `/ext [操作] [对象] [值]` | 不带参数列出智能体的扩展、进行中的创造任务和等待确认的请求；`info` 查看版本与同步状态。`approve`/`reject` 处理扩展请求，`enable`、`disable`、`use`、`revert`、`save`、`continue`、`update`、`publish` 操作扩展，这些只有管理员能用，新增高风险权限的操作仍要在后台批准 | 普通用户（操作类要求管理员） |
| `/admin [claim 认领码 \| list]` | `claim` 用设置里生成的认领码把自己的平台账号设为管理员；`list` 列出管理员（仅管理员） | 普通用户 |

`/reset` 与 `/compact` 先回一条「正在…」，完成后再回最终结果。

**暂停。** 暂停是频道绑定上独立于响应规则的状态：命令与检查器里的「暂停回应」开关操作同一份，频道标题与频道列表显示「已暂停」。它和触发方式「仅观察」的区别是：仅观察是长期规则，暂停是临时开关，恢复后回到原有规则。暂停期间消息、平台事件、定时任务和扩展唤醒都不再触发回应（普通消息仍作为事实入库，恢复后随上下文进入）；编辑响应规则不会解除暂停；重启后保留；绑定另一个智能体时重置。作用域始终是当前频道，不影响智能体的其他频道或平台账号。

## 权限与防护

帮助始终可用，只展示调用者可执行的命令。平台成员执行需要授权、但尚未被授权的命令时，默认回复一句需要管理员授权；设置「聊天命令」里的「无权限时回复提示」可关闭，关闭后只记录原因、不回复。启用状态按频道覆盖、全局、注册默认值取第一个已设置值；权限不得低于声明的最低要求或全局收紧要求，频道也不能放宽全局已收紧的命令。

**谁能用。** 命令权限分三级：普通用户 < 频道管理 < 管理员。管理员是系统级身份：Web 管理身份（来自已认证管理边缘或可信本地宿主，请求体不能声明身份）始终是管理员，另外是设置「管理员」里列出的平台账号（按连接与平台用户 ID 精确匹配，从用户目录添加或用 `/admin claim` 认领）。管理员拥有每个频道的频道管理权限。频道管理还可以由管理员在 Web 中把某个频道已有成员单独授权，授权只对该频道有效。昵称、消息事实及平台群管理员标志均不授予命令权限。声明为管理员级的命令，频道授权的成员也不能执行；它的权限不能被放宽。

**边界。** 首版不提供 public 命令的成员名单、单用户封禁或跨频道批量授权；公开命令对频道内所有成员开放。未绑定频道只能执行 `/help` 与 `/status`。禁用的命令与执行失败都会如实回复；Web 管理界面能查看每次执行的原因。

**限速。** 平台来源的命令按「频道 + 平台用户」每分钟最多 10 次、按频道每分钟最多 30 次执行；超过的消息仍作为事实保存、仍不进入模型，但不产生执行记录和回复，只做聚合计数并写入运行日志。Web 请求不受限。

## 运行、投递与恢复

入站在同一事务中保存消息事实和命令执行记录，完成识别后立即返回；命令不进入普通扩展入站钩子或模型准入。业务处理器交给后台队列，同一频道按接收顺序执行，最多四个频道并行；处理器返回后释放频道队列，回复在后台按序投递，慢回执不会阻塞后续 `/stop`。慢命令不阻塞同一连接后续消息入库。Web 执行请求共用队列，并等待该命令的执行与回复尝试返回。

命令原文和结果保留在历史；积压、运行中注入和恢复统一排除命令，不产生模型回复义务。管理命令复用 Channel Runtime 的停止、暂停和上下文接口，取得原有串行执行通道后复核绑定代次与授权，避免锁重入。

平台用事件 ID、Web 用客户端请求 ID 去重，同一 Web ID 更换内容或执行者会拒绝。执行记录的状态、命令名、起止时间与恢复标记是独立列，参数、身份、结果与回复在 JSON 中；状态为 pending、running、succeeded、failed、uncertain。宿主恢复把未完成的 running 标为 uncertain 并追加一条结果不确定的终态回复，不自动重跑处理器。启动期间先保存新命令，等待扩展智能体挂载恢复后执行，避免把尚未注册的命令误判为未知。每个频道保留最近 500 条已结算执行的完整内容，更早的只保留列与关联。

**回复。** 一次执行可以发出若干条独立回复，再以终态结果结束：扩展处理器调用 `context.reply(result)` 发送过程回复（每次执行最多 5 条，超出会使命令失败并如实回报），处理器返回值是最后一条。回复使用原 Outbox、Adapter 规划与回执，通过 `commandExecutionId` 与 `commandOrdinal` 关联，Episode 和 agentRevisionId 为空；`(执行, 序号)` 唯一，保证每条回复只规划一次，规划后断电也能从关联找回。已开始发送但没有权威回执的物理投递标为 unknown，不盲目重发。恢复只投递已保存未发送的回复。发送 `/reset` 回执不会重建模型会话。

执行成功和回复失败是两个独立事实，Web 明确展示；已有 Outbox 的失败回复可重发，结果未知或部分发送可标记已送达，均不重新执行命令。Adapter 不在线、无法建立 Outbox 计划时，已保存的结果仍随命令原文显示。

**回复去向。** 平台来源的回复回到原会话。Web 管理员在外部频道执行时，结果默认只在控制台显示，不通过机器人账号发出，时间线标明「只在控制台显示」；命令定义 `consoleReply: 'channel'` 时才同时发送到频道，设置页与输入框都会标出。内置频道没有外部平台，回复照常进入频道历史。

Drizzle 增量迁移保存新系统启用时最大的既有事件 ID，旧事件不追溯执行；迁移保持聊天、旧 Episode、Outbox 及物理回执。该截止点只用于区分启用前的历史，不作为恢复扫描起点。恢复入口只查询带索引的待处理记录，只在首次开放时调度；关闭宿主时取消运行中的处理器，未启动的队列项保留为 pending，供下次恢复。执行期间停用扩展先撤销新调用，再发送取消信号并等待处理器清理。

## 扩展 SDK

Manifest 使用 V7，命令归属智能体层，声明 `requires: { sdk: 9 }` 和 `{ kind: 'command', ...definition }`。Host factory 调用 `harness.registerCommand(definition, handler)`，获得注销函数；声明与实际注册必须完全一致，定义里带默认值的字段可省略。注册属于扩展本机实例，执行与取消按智能体挂载隔离，不依赖 DSH Session，不在每个 Session 的 apply 中注册。一个扩展可注册多个命令，名称/别名不能重复，内置名称（含 `pause`、`resume`、`off`、`on`）保留。

扩展命令有执行时限，默认 60 秒，可在定义里用 `timeoutSeconds` 声明（最长 600 秒）；到时发送取消信号、记为失败并释放频道队列，避免卡住的处理器挡住其后的 `/stop`、`/pause`。内置命令不受此限。

完整名称固定为 `/扩展ID:命令`，短名唯一时可用，冲突返回完整候选名称。处理器收到已验证参数、执行身份、当前频道、AbortSignal，以及 `reply`（过程回复）和受授权约束的 `host.status/stop/reset`；不可通过普通用户命令调用管理能力。返回值是结构化文本、图片或文件，媒体必须是当前频道已授权的 Asset ID，不接受宿主文件路径。

已启用扩展在重配置或停用过程中暂停命令时，保留已提交版本的命令名称、别名和策略，将目录项标为不可执行并给出原因；有权限的调用返回「命令所属扩展暂时不可用，请稍后重试」，不会记为未知命令。重新挂载完成或暂停回滚后恢复执行；停用提交后才移除目录项。

导入隔离验证实际执行命令，管理宿主能力使用合成结果；启用、更新和卸载沿用现有不可变 Revision/智能体挂载流程。运行中的调用持有原 handler，卸载等待它清理；处理器应监听 AbortSignal，不能留下未等待的后台任务。首版通过本地源码包导入命令扩展，参考[可安装回声示例](../apps/server/examples/command-echo/README.md)。

工坊动态创造也可以提供命令（SDK 10 起）：候选在 `nekro_nxt_extension_define` 的 `commands` 里声明，factory 中用 `harness.registerCommand` 注册；预检拒绝内置名称，保存验证按参数定义生成样例真实执行一次，所以处理器不能有副作用。定义的 `minimumPermission` 可以是 `public`、`channel-admin` 或 `admin`。

## Web 与接口

聊天输入 `/` 展示当前频道可执行命令；方向键选择，Tab/Enter 补全，补全后的 Enter 执行。在外部频道里，输入框说明命令只在控制台执行、是否会发送到频道，群聊还会提示成员需要先 `@机器人`。管理命令不受模型供应商不可用、未绑定频道或主动发送开关的输入框限制；执行服务仍按命令规则拒绝未绑定的管理操作。控制台的命令原文只作为本地事实，不作为机器人消息发送到平台。

类型化 Host API 包括目录、执行、读取记录、全局/频道策略、频道设置（是否允许不带 @ 的命令）、频道成员与授权变更，以及频道暂停；`HostApiContracts` 是请求与响应形状的唯一来源。所有管理接口沿用管理边缘鉴权，执行接口重新核对策略、授权及绑定。执行记录随消息快照和 SSE 投影更新，命令结果使用独立来源标记，不冒充智能体发言。

首版不提供正则触发、多步等待与确认、流式输出（过程回复是独立消息，不是编辑同一条）、模型调用命令、Ctrl+K 联动或 Nekro Agent 插件兼容。
