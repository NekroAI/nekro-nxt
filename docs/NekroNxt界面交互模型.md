# NekroNxt 界面交互模型

> 用途：约束产品概念图、交互原型和后续 UI 实现  
> 状态：产品形态设计基线  
> 原则：先定义页面对象、状态和操作后果，再设计控件
>
> 视觉 Token、桌面布局尺寸、组件状态和动效遵循 `05-桌面UI与动效规范.md`。

> 文案铁律：界面中的实体统一称“智能体”。Agent、AI 成员、Bot、助手不得作为同一实体的替代类型名；英文内部类型不得直接显示给用户。

## 0. 旧概念图暴露的问题

旧图不作为后续界面依据，主要问题包括：

1. 把多个外部 Channel 的消息画进同一个对话流，破坏了 Channel 上下文隔离；
2. 页面标题显示智能体，但中央实际承载 Channel Conversation，主要对象不明确；
3. “在线”混淆 Node 在线、Connection 已连接、智能体空闲和智能体正在执行；
4. Composer 中的“能力”和“进入创造工作台”没有明确作用对象和操作后果；
5. “查看”不知道查看消息、运行步骤还是待注入内容；
6. 右侧既像摘要，又能局部编辑智能体，和完整管理页职责冲突；
7. 动态运行、保存插件和给智能体激活没有清楚区分；
8. 没有表达 `AgentRevision` 修改后如何影响已有 Session。

## 1. 全局对象规则

### 1.1 每个页面只有一个主要对象

| 页面 | 主要对象 | 次要上下文 |
|---|---|---|
|智能体首页 |智能体Collection | Node/Space 摘要 |
|智能体创建向导 |智能体Draft | 默认 Web Channel |
| Channel 对话 | Channel Binding | 响应它的智能体|
|智能体管理 | `AgentDefinitionDraft` | 当前 Revision 和活动 Session |
| 频道绑定向导 | Binding Draft | Connection、Channel、智能体|
| 创造工作台 | Extension Draft / Dynamic Package | 目标智能体|
| 本地扩展详情 | Local Extension | Revision 和 `AgentActivation` |

页面标题、主操作和右侧检查器都必须服务同一个主要对象。

### 1.2智能体与 Channel 的关系

-智能体是长期产品实体；
- Channel 是一段消息事实流；
- Channel Binding 决定哪个智能体响应该 Channel；
- 一个智能体可以绑定多个 Channel；
- 一个 Channel Conversation 只显示该 Channel 的消息；
- 跨 Channel 长期记忆可以共享，但短期聊天记录不直接混合；
- 切换左侧 Channel 就是切换中央 Conversation，而不是筛选同一混合流。

### 1.3 Extension 的三个独立动作

```text
动态运行
→ 保存为本地 Extension Revision
→ 激活给一个或多个智能体
```

- 动态运行：临时、可停止、可能重启丢失；
- 保存：源码和 Revision 持久化，但不自动扩大作用范围；
- 激活：指定哪个智能体使用哪个 Revision。

## 2. 状态词典

### 2.1 Node 状态

- 正常；
- 正在启动；
- 需要重启；
- 恢复模式；
- 离线。

### 2.2 Connection 状态

- 已连接；
- 正在连接；
- 认证过期；
- 已断开；
- 异常。

### 2.3智能体运行状态

- 空闲：没有活动 Turn；
- 思考中：模型正在生成；
- 使用工具：Tool 正在运行；
- 等待输入：等待用户问题或审批；
- 已暂停：用户暂停新 Turn；
- 不可用：模型、配置或 Runtime 有错误。

智能体不使用含糊的“在线”表示一切正常。

### 2.4 Channel Binding 状态

- 监听中；
- 已暂停响应；
- Connection 断开；
- 配置错误。

### 2.5 Extension 状态

- 草稿；
- 动态运行中；
- 动态运行失败；
- 本地已保存；
- 已加载；
- 已停止；
- 加载失败。

### 2.6 Activation 状态

- 未激活；
- 已激活；
- 等待安全切换；
- 激活失败；
- 已停用。

## 3. 应用外壳

### 3.1 全局导航

```text
智能体
频道与连接
本地扩展
创造工作台
运行与诊断
设置
```

“首页”可以作为启动概览，但不能与智能体首页重复主任务。若首页只展示智能体，应直接以“智能体”作为默认入口。

### 3.2 左侧智能体树

只在智能体相关页面显示：

```text
小奈
├─ Web 控制台
├─ QQ 用户群
└─ Discord #general
```

- 点击智能体名称：进入智能体概览；
- 点击 Channel：进入该 Channel Conversation；
- `+`：进入“新增频道绑定”向导，不直接创建未知对象；
- Connection 状态不在这里用一个绿点替代，异常时显示明确图标与文案。

### 3.3 右侧检查器

右侧只显示当前对象的摘要、运行状态和少量上下文动作，不承担完整配置编辑。完整修改通过“管理智能体”“编辑绑定”“管理扩展”等明确入口进行。

## 4.智能体首页

### 4.1 页面目标

回答：我有哪些智能体、它们在做什么、从哪里继续使用。

### 4.2智能体卡片内容

- 名称与头像；
- 运行状态；
- 绑定 Channel 数量；
- 当前活动任务；
- 最后活动时间；
- 本地扩展数量；
- 主入口“打开”；
- 次入口“管理”。

### 4.3 按钮逻辑

| 按钮 | 显示条件 | 结果 |
|---|---|---|
| 创建智能体| 用户可管理当前 Space | 打开智能体Draft 向导 |
| 打开 |智能体至少有一个 Web Channel 或 Channel Binding | 打开最近使用的 Channel；没有则创建 Web Channel |
| 管理 | 用户可管理该智能体| 打开智能体管理页 |
| 暂停响应 |智能体有监听中的 Channel | 暂停新 Turn，不取消当前 Tool |

## 5. 创建智能体向导

### 5.1 步骤

```text
身份
→ 模型
→ 工作方式与初始能力
→ 确认
```

### 5.2 默认行为

- 自动创建 Web Channel；
- 默认使用“通用方式”；
- 默认不启用 Bash、动态创造和完整文件访问；
- 可以先跳过外部平台；
- 最终确认前不写入正式 `AgentDefinition`。

### 5.3 按钮逻辑

| 按钮 | 结果 |
|---|---|
| 上一步 | 返回 Draft 的上一段，不丢失输入 |
| 下一步 | 验证当前步骤并推进 |
| 创建智能体| 原子创建 `AgentDefinition`、首个 Revision 和 Web Channel |
| 取消 | 丢弃 Draft，不留下半创建智能体|

## 6. Channel Conversation

### 6.1 页面标题

标题使用 Channel 名称，例如“QQ 用户群”。副标题显示：

```text
由“小奈”响应 · 被提及或回复时触发
```

智能体不是该页面标题，因为中央事实流属于 Channel。

### 6.2 消息流

- 只显示当前 Channel 的平台消息；
- 智能体消息只能来自已成功记录的通信工具调用，并标记发送中、已发送、部分发送、失败或结果未知；
- DSH 模型原始文字和 reasoning 属于后台运行轨迹，不自动画进消息流；
- 文字、Mention、图片和文件均是同一逻辑消息的有序内容部分；
- Tool Card 归属于触发它的智能体Turn；
- 系统事件使用低噪声状态行，不伪装成聊天消息；
- 其他 Channel 的消息只产生全局未读提示，不进入当前流。

### 6.3 新群消息与当前 Tool

Tool 运行时到达的新消息：

```text
3 条新消息已收录
将在当前工具完成后纳入下一步思考
[展开查看]
```

“展开查看”只展开这三条待注入消息，不跳转到运行诊断。

### 6.4 Composer

Composer 顶部或内部必须明确发送目标：

```text
发送到：QQ 用户群（通过 QQ 机器人账号）
```

Web Channel 则显示：

```text
发送给：小奈
```

不放含义模糊的“能力”按钮。附件、表情和明确的发送目标属于 Composer；智能体能力在智能体管理页配置。

Composer 表示管理员本人主动发言，不是智能体的模型输出。它可以复用 Channel Runtime 的发送、媒体和回执能力，但 UI 必须标明实际发送身份。

### 6.5 运行控制

| 按钮 | 显示条件 | 结果 |
|---|---|---|
| 停止当前任务 |智能体正在思考或使用 Tool，且用户有控制权 | 发出控制事件；取消当前模型/Tool；不删除已收录消息 |
| 查看运行详情 | 当前 Turn 存在 | 打开当前 Turn 检查器，区分显示内部模型输出、Tool、通信工具消息、平台回执和待注入消息 |
| 编辑绑定 | 用户可管理 Binding | 打开 Binding 设置，不修改 `AgentDefinition` |
| 暂停响应 | Binding 正在监听 | 后续平台消息继续入库，但不启动新 Turn |

## 7.智能体管理与 Revision

### 7.1 页面分区

- 概览；
- 人设与模型；
- 频道；
- 能力；
- 扩展；
- 记忆；
- 高级。

### 7.2 Draft 规则

编辑进入 `AgentDefinitionDraft`。页面明确显示“有未保存更改”，所有分区修改由同一个底部保存区统一提交。

### 7.3 两种保存结果

| 按钮 | 结果 |
|---|---|
| 保存为新配置 | 创建新 `AgentRevision`；已有 Session 保持当前 Revision |
| 应用到当前会话 | 创建新 Revision；先计算兼容性差异。兼容变化在安全间隙应用，不兼容变化才安排 Episode handoff 与 Session Rollover |
| 放弃更改 | 丢弃 Draft，恢复当前 Revision |

“立即替换运行中 Session”不作为按钮，因为它会破坏工具历史和上下文一致性。

### 7.4 高能力开关

动态创造、开发 Shell、完整文件访问分别设置。开启创造不隐式开启完整宿主文件访问。

## 8. 频道绑定向导

### 8.1 步骤

```text
选择平台
→ 连接账号
→ 选择频道
→ 绑定智能体
→ 测试并完成
```

### 8.2 最终确认内容

- Adapter 与 Connection；
- Channel；
- Primary智能体；
- 触发方式；
- 是否允许主动发言；
- 是否读取绑定前历史；
- 入站/出站测试结果。

### 8.3 按钮逻辑

| 按钮 | 结果 |
|---|---|
| 测试接收 | 验证 Adapter 事件能到达 Channel Runtime，不触发正式智能体|
| 发送测试消息 | 通过目标平台的机器人账号向 Channel 发送明确标记的测试消息 |
| 完成绑定 | 创建 Binding 并开始监听；收发测试均通过时标记为“已就绪”，否则标记为“待验证” |
| 稍后测试 | 保存 Binding Draft 为“待验证”，保留配置且不声称收发可用 |

## 9. 创造工作台

### 9.1 页面主要对象

主要对象是 Extension Draft，目标智能体是上下文。标题示例：

```text
为“小奈”创建能力
```

### 9.2 三栏职责

- 左：Extension Draft、Package/Revision 历史；
- 中：与已启用创造能力的目标智能体对话，以及 Inspect、Define、Run 和修复过程；
- 右：Preview、Validation、Changes、Target 与 Persistence 状态。

### 9.3 状态推进

```text
草稿
→ 已定义动态 Package
→ 动态运行中
→ 验证通过/失败
→ 保存为本地 Extension Revision
→ 激活给智能体
```

### 9.4 按钮逻辑

| 按钮 | 显示条件 | 结果 |
|---|---|---|
| 动态运行 | 已定义、当前未运行 | 仅在选择的目标范围运行 Package |
| 停止动态版本 | 动态运行中 | Dispose 当前动态 Run，不删除 Draft |
| 继续修改 | Draft 存在 | 回到对话并基于当前 Package 创建新 Package |
| 保存为本地扩展 | 验证通过且尚未保存 | 物化不可变 TS 源码 Revision；构建只是可重建验证缓存，不自动创建 Activation |
| 启用给小奈 | 已保存且尚未激活 | 创建 `AgentActivation` |
| 回到上个动态版本 | 存在可运行旧 Package | 停当前 Run，运行旧 Package |

### 9.5 验证标签

首版只显示真实执行结果：

- 构建通过；
- Tool 调用通过；
- Client UI 渲染通过；
- 停止/卸载通过；
- 目标场景通过。

不显示 Verified、Official、签名、SBOM 等尚不存在的社区概念。

## 10. 本地扩展详情

### 10.1 页面目标

回答：这个插件是什么、有哪些 Revision、当前哪些智能体在用、出了问题如何停用或回退。

### 10.2 页面内容

- Extension 名称和 Contribution；
- 当前本地 Revision；
- Revision 时间线；
- `AgentActivation` 列表；
- 加载和错误状态；
- 最近运行日志入口；
- 修改、停用和删除动作。

### 10.3 按钮逻辑

| 按钮 | 结果 |
|---|---|
| 新建修改会话 | 打开创造工作台，以当前 Revision 为基线 |
| 切换到此 Revision | 对选定 Activation 安排安全切换 |
| 停用 `AgentActivation` | 只从该智能体移除，不删除 Extension |
| 停用全部 | 停止全部 Activation，保留源码和 Revision |
| 删除本地扩展 | 仅在没有活动 Activation 后允许；删除前明确列出影响 |

## 11. 按钮命名铁律

1. 动词必须说明对象：用“停止当前任务”，不用“停止”；
2. 保存和生效分开：用“保存为本地扩展”“启用给小奈”；
3. 不使用“确定”代替真实动作；
4. 不使用“查看”而不说明查看什么；
5. 不把权限、能力和运行模式塞进 Composer；
6. 危险动作只在它真正危险时使用警示色；
7. 不可执行的按钮说明前置条件，不能只灰掉；
8. 每个主按钮只产生一种可解释状态变化。

## 12. 本轮概念图清单

1.智能体首页：Collection、状态和入口；
2. 创建智能体向导：默认行为和原子创建；
3. Channel Conversation：单 Channel 流、安全 Step 和运行控制；
4.智能体能力配置：Draft、Revision 和生效方式；
5. Channel Binding 向导：Connection/Channel/智能体/Trigger；
6. 创造工作台：动态、保存、激活三阶段；
7. 本地扩展详情：Revision、Activation 和回退。
