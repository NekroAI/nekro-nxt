# NekroNXT 消息内容与投递协议

> 文档性质：消息内容、模型准入与用户可见投递的唯一事实源
>
> 适用范围：内置频道、外部聊天平台、主动任务、创造工作台中的真实频道发送
>
> 决策记录：`decisions/implemented/2026-08-15-统一使用通信工具发送用户消息.md`

## 0. 核心决定

**智能体自己的用户可见发言必须通过模型可见的通信工具产生。DSH 模型原始输出不自动投递到任何频道。**

内置频道也遵守相同规则，不设置“客户端对话直接显示模型最终文本”的特殊路径。只有通信工具调用成功创建并记录出站意图，才表示智能体尝试对用户发言；只有 Adapter 返回成功回执，才表示平台已接受发送。成功回执可以不含平台消息 ID；企业微信智能机器人等平台只确认请求结果，不能伪造消息 ID。引用、撤回和关系解析只使用实际存在的平台消息 ID。

管理员可以通过客户端 Composer 以该频道绑定智能体关联的机器人账号，向外部平台频道发言。这不是模型调用，群里会看到机器人账号发出的内容；会话中注入系统事实，说明管理员从客户端发出，智能体不得把它当成自己说过的话。该出站仍走 Adapter 投递与回执，并要求连接已允许主动发送。内置频道 Composer 仍是把管理员输入作为入站交给智能体。

DSH Session 中的 `text`、`reasoning` 或供应商提供的其他内容块属于内部运行轨迹，可用于后台观察、诊断和调试，不是频道消息。

这项设计带来三个直接结果：

1. 智能体只学习一套发言规则，不需要区分“最终输出”和“工具发送”；
2. 大段计划、分析或调试文本不会被误发到群聊；
3. 文本、Mention、图片和文件都使用同一条可追踪、可重试的发送链路。

## 1. 统一通信工具

频道发言只暴露 `send_channel_message`。`send_message` 留给 DSH 子智能体控制，不会向频道发言。

模型可以在同一 Turn 中多次调用 `send_channel_message`，先发送开场确认或阶段进展，再继续使用其他工具并发送最终结果；一次成功发送不会结束当前 Turn。频道常驻 System Prompt 只描述真实投递环境和默认沟通方式：普通 `text/reasoning` 对频道不可见，成员在首次成功发送前无法从内部轨迹判断智能体是否已经开始或仍在运行；预计需要多步操作、等待或较长处理时，默认适合先简短确认任务，后续只在有阶段结果、新发现、风险、阻塞或计划变化时同步。智能体人设和成员明确要求可以减少过程消息或只保留最终结果，但不能把普通模型文字解释成已经发送。

```ts
interface SendChannelMessageInput {
  target: { type: 'current' }
  replyTo?: string
  parts: MessagePart[]
  clientRequestId?: string
}

interface SendChannelMessageResult {
  logicalMessageId: string
  status: 'sent' | 'partially-sent' | 'failed' | 'unknown'
  receipts: DeliveryReceipt[]
}
```

`target: current` 指向触发当前 Turn 且策略允许回复的 Channel。不要分别创造 `send_text`、`send_image` 或 Web 专用回复通道。平台特有高级动作可以由 Adapter 增加独立工具，普通内容发送仍经过本协议。跨频道显式 `channelId` 尚未开放，见 `02-未来扩展方向.md`。

模型调用工具时，纯文本 part 同时接受 `{"text":"你好"}` 简写和完整的 `{"type":"text","text":"你好"}`；Host 在工具参数校验后、进入领域层前把无歧义简写规范化为完整 text part。省略 `type` 的媒体、Mention、引用，以及同时携带其他字段的模糊对象一律拒绝。该兼容只属于模型工具输入，公共 `MessagePart`、Channel Runtime、持久事实和 Adapter 契约继续使用严格的带 `type` 联合类型。

智能体可以调用 `asset_create` 把自身生成的内容准备为当前频道可用的 Asset。工具只接受 `encoding: "utf8" | "base64"` 和内容字符串，不接受路径、URL 或宿主文件引用；UTF-8 编码或 base64 解码后的字节最多为 8 MiB，非法 base64、超限内容和其他参数错误都会明确失败。工具复用 Asset Service 的流式内容寻址、大小检查和字节 MIME 检测，成功返回 `assetId`、`byteSize`、`mediaType`。随后智能体可以把该 `assetId` 放入 `send_channel_message` 的 `image`、`file` 或 `audio` part。

`asset_create` 成功后写入当前 Channel 的显式 scoped grant，不写 `ChannelEvent`、`AssetOccurrence` 或普通成员消息。`send_channel_message` 在进入 Channel Runtime 前逐个以当前 Channel 调用 `canAccessAsset(assetId, channelId)`；模型不知道某个 ID 或调用来源不能绕过这项校验，跨频道 Asset 会被拒绝。

## 2. 内容模型

首版公共内容词汇：

```ts
type MessagePart =
  | { type: 'text'; text: string }
  | { type: 'mention'; memberId: string }
  | { type: 'image'; assetId: string; alt?: string }
  | { type: 'file'; assetId: string; name?: string }
  | { type: 'audio'; assetId: string }
  | { type: 'quote'; messageId: string }
  | {
      type: 'rich'
      adapterKey: string
      kind: string
      summary: string
      title?: string
      source?: string
      targetUrl?: string
      previewAssetId?: string
      extension?: JsonValue
    }
```

规则：

- `parts` 是有序数组，可以表达“文字 + Mention + 图片 + 文件”的混合内容；
- `file.name` 是该次消息投递的用户可见文件名；Adapter 上传时必须优先使用它，仅在未提供时才回退到 Asset 来源元数据或平台兜底名，不得因内容寻址 Asset 本身不保存文件名而丢失消息名称；
- Mention 使用 Channel 成员稳定 ID，不用裸 `@昵称` 模拟；
- 图片、文件和音频使用 NekroNXT 资产 ID，不把宿主绝对路径暴露给 Adapter 或模型；
- `quote` 引用当前 Channel 的 `logicalMessageId`，由 Adapter 在平台 ID 与逻辑 ID 之间映射。每条入站、出站、Handoff 最近原文和历史工具结果都向模型使用同一逻辑 ID，不把 `ChannelEventId` 或平台 message ID伪装成频道消息身份；
- `rich` 表示公共词汇不够用的平台内容（卡片、小程序、转发摘要）。`summary` 必填，供频道 fallback 和 `search_text` 使用；`targetUrl` 只保存平台明确提供、使用 HTTP(S) 的用户导航目标，不能拿封面 URL 代替；结构化转发条目放进 `extension.items`，限 64 KiB JSON；预览图必须是 `previewAssetId` 或条目里的 `imageAssetId`，媒体临时 URL 不得直接写入 parts。出站通信工具不发送 `rich`。QQ 官方机器人入站拿不到嵌套消息对象，转发是拍扁文本（`[群聊的聊天记录] === 消息 1 ===`、`[卡片消息]`、`[附件N] URL:`）；适配器解析后再入库，智能体上下文使用 `richPartContextText` 展开条目，不把原始 dump 当正文。
- 内容类型通过 TypeScript 可扩展联合或 DSH declaration merging 增量增加；
- 未知内容必须显式拒绝或按声明策略降级，不能静默丢失。不得把卡片压成字段流水账 `text`。

资产服务负责将 `assetId` 解析为受控字节流、MIME、大小和生命周期。原始字节使用流式 SHA-256 内容寻址，相同内容只保存一个物理 blob；入站消息中的每次引用记录独立 `AssetOccurrence`，而模型生成内容使用独立的 Channel scoped grant。文件名和平台声明 MIME 属于消息或 Occurrence 元数据，不能覆盖 Asset 上从字节验证得到的事实。远程 URL 是否允许、是否下载以及大小限制由 Host 资产策略决定，不能让 Adapter 任意读取本机路径。`fetchRemoteBytes` 默认只接受 HTTPS；协议只提供 HTTP 媒体 URL 时，Adapter 可以为单次读取显式允许公网 HTTP。两种模式都禁止 URL 凭据、重定向、私网、链路本地和元数据地址；DNS 解析后固定已校验地址，并同时校验 Content-Length 与流式读取字节数。返回值只包含字节、声明 MIME 和安全化文件名，不持久化远程 URL。

带 `activityType` 的平台通知是频道系统事实。它可以保留 `senderMemberId` 和 `facts` 中的参与者关系，供触发、检索和模型上下文使用，但 Server 快照必须投影为 `role: system`，客户端不得把参与者显示成消息发送成员。事件涉及的成员、操作者和目标应按语义写成原位 `mention` part，客户端将这些引用显示为状态行中的成员名称，不显示头像、发送者标题或 Mention chip；适配器已经收到的 `sub_type`、持续时间、新旧值和文件信息不得丢弃成“一名成员发生了某事”的泛化摘要。名称不可用时使用中性称呼，不能显示平台用户 ID。

物理去重不扩大权限。Asset 的读取、派生内容和来源查询必须通过当前 Channel Event、Episode lineage、入站 `AssetOccurrence` 或明确的 `asset_channel_grants` scoped grant 证明引用关系；一个频道的 Occurrence 或 grant 不会授予其他频道访问权。详细存储契约见 `decisions/implemented/2026-08-16-内容寻址资源与图片理解.md`。

模型准入投影遇到 quote 时保留原始 `logicalMessageId`，并在当前 Channel 内精确回查被引消息，紧邻展开作者和原始结构化内容。嵌套 quote 只显示下一层逻辑 ID，不递归展开；当前频道查不到时明确说明该 ID 无法读取，禁止跨频道回退或静默丢弃。媒体继续执行当前 Channel 的 Asset 授权、模型输入能力和视觉去重规则。QQ 等 Adapter 无法从平台字段解析引用或无法映射已持久消息时，只发布不含原始 payload 和平台标识的原因诊断。

## 3. 入站多媒体与模型上下文

平台多媒体先成为 Channel 事实，再根据当前模型和已启用预处理能力投影到 DSH Session。Adapter 收到平台资源时必须先将其导入 NekroNXT Asset Service，`ChannelEvent.parts` 只保存稳定 `assetId`、MIME、来源消息和必要展示元数据，不保存 base64、浏览器 object URL、供应商临时 URL 或宿主路径。

准入模型前由 `ModalityProjector` 逐项决定表示方式：

```text
平台媒体
→ Asset Service 内容寻址持久化原件并记录本次 Occurrence
→ ChannelEvent 记录 assetId
→ 检查目标模型 input modalities
→ 原生内容块，或显式预处理产生派生内容
→ Admission 记录原始 assetId、派生结果和投影策略
→ Provider Adapter 在请求时转换为供应商原生格式
```

### 图片

- 模型目录明确声明支持 `image` 时，普通图片与 rich 预览按 MessagePart 原顺序映射为短 Asset 标签和 DSH ImageBlock；相同 `contentDigest` 在当前 Session Surface 只保留一份像素，每次消息位置仍保留文字引用；
- Attachment 引用读取同一个 Asset blob；DSH rc.2 的公开请求图片投影器在 `/data/dsh/request-images` 生成供应商请求缓存，不创建新 Asset、Occurrence 或授权，也不保存 base64 副本；
- DSH 当前附件只接受 PNG、JPEG、WebP 和 GIF，其他格式在准入前显式转码或拒绝；
- 明确 text-only 或缺失 `inputModalities` 的主模型都不接收 ImageBlock，只看到原位置 Asset 标签。缺失声明在 UI 显示“输入能力未声明”，运行时按文本路径处理；
- 文本路径只有在不可变 Revision 配置了明确支持 `image` 的辅助模型时才注册批量图片检查工具；未配置时纯文本聊天继续运行，但图片理解明确不可用。

为历史资源保留 `asset_inspect(assetId)` 元数据工具。图片内容统一使用 `asset_inspect_images({ images, question?, detail? })`，`images` 为 1–20 项的数组，每项包含 `assetId` 和可选 `focus`；单图也使用长度为 1 的数组，不保留单图别名。工具只接受 Asset ID，不接受路径、URL、base64 或 digest，整批完成 Schema、频道授权、Asset、MIME 和附件可读性校验后才执行，任一项失败则不返回部分结果。

视觉主模型的 Tool Result 直接按输入顺序返回必要 ImageBlock，已驻留图片不重复注入，low 到 auto/high 的主动请求可产生一次 `detail-upgraded`。文本主模型通过一次独立 DSH LLM 请求把完整批次交给辅助视觉模型，并只收到经过严格 Schema 校验的结构化观察、比较和不确定性；首次格式错误只做一次不含图片的文本修复。两条路径都保留整批 `question` 和逐图 `focus`，不自动拆批。详细配置、缓存、审计和压缩恢复契约见 `decisions/implemented/2026-08-16-内容寻址资源与图片理解.md`。

DSH 压缩成功后，Host 从当前频道最近 Revision 配置窗口中按 digest 选取不再驻留的最新图片，使用 TokenMeter 缩减到不会立即再次产生压力的数量，再追加一条 DSH-only 恢复消息。该消息不创建频道事实、不显示为新消息、不主动触发回复，并以 `compactionId + policyVersion` 幂等恢复。

### 音频、文件与视频

- 音频首期通过显式 ASR Contribution 生成带时间和来源的文本；只有未来 DSH/Provider 契约支持原生音频后才直接发送音频块；
- PDF 和普通文件通过文档提取、分页读取或索引工具进入上下文，不把文件路径塞进 prompt，也不默认把超大全文一次性注入；
- `video/*` 首期作为普通 `file` 完整入库、下载和转发，不定义专用 video Part，也不声称已经理解。智能体先看到授权元数据和 `assetId`，再决定转发或调用已安装的处理 Contribution；未来可选择 Provider 原生视频，或“抽帧图片 + 音轨转写”的派生投影，两者都引用同一个原始 Asset；
- 原始资产和派生结果是不同事实。重新 OCR、ASR 或解析必须产生带处理器版本的新派生记录，不覆盖原件。

模型输入能力与预处理能力互相独立：模型支持图片不代表 Adapter 能发送图片，Adapter 收到音频也不代表智能体已启用 ASR。Admission 必须记录实际采用的路径，使运行详情能够说明“模型看到了原图”“模型只看到了 OCR/转写”或“资源未能准入”。

DSH 0.1.1-rc.2 当前已实现的是 PNG、JPEG、WebP、GIF 图片附件链路，不是任意文件或视频的通用多模态协议。NekroNXT 通过兼容层复用该图片链路，通用文件则保留在自身 Asset、Admission 和 Tool 契约中；由 DSH 中的智能体根据已启用工具决定后续动作，但不能把“作为文件入库”等同于“DSH 或模型已经能够理解”。

## 4. Adapter 能力与降级

每个 Adapter 必须声明至少以下出站能力：

```ts
interface AdapterOutboundCapabilities {
  text: boolean
  mentions: boolean
  images: boolean
  files: boolean
  audio: boolean
  replies: boolean
  mixedContent: boolean
  maxTextLength?: number
  maxAssetBytes?: number
  acceptedMimeTypes?: string[]
}
```

发送前由 Channel Runtime 根据能力规划物理消息：

- 平台支持混合内容时，尽量保持一个逻辑消息；
- 平台不支持混合内容时，按 `parts` 顺序拆成多个物理消息；
- 一个 `logicalMessageId` 可以对应多个平台 message ID；
- 不支持 Mention 时不得伪造成功，可按明确策略降级为显示文本并在回执中标记；
- 不支持某媒体或超过限制时，在发送前返回可解释失败；
- 部分物理消息成功时返回 `partially-sent`，不得自动整组盲重试造成重复。

Provider 能否理解入站图片与 Adapter 能否发送图片是两种独立能力，必须分别判断。

### 特殊活动与平台互动

撤回、消息回应、戳一戳、成员进退、禁言、管理员、名片、头衔、频道名称、群文件、精华、好友新增、进入会话、卡片操作和消息反馈使用公共 `ChannelActivityType`。活动事件可以携带 `targetPlatformMessageId` 或 `targetLogicalMessageId`；Core 提交时验证目标消息属于当前 Connection 和 Channel。撤回、回应、反馈和精华变化只追加关系事实，不能删除或改写目标消息。

Binding 的 `eventTriggers` 默认空数组。普通 `triggerPolicy` 只控制普通消息；特殊活动只有用户逐项开启后才创建 Admission，`observe-only` 永远不触发。`processingFeedback` 默认 `auto`，表示 Adapter 支持时可在真正触发的群消息上显示临时处理中状态；私聊不发送临时文本降级。

平台互动不走 `send_channel_message`，也不开放 raw Action。Host 只提供语义明确的 `retract_channel_message` 和 `nudge_channel_member`：前者只能撤回当前频道中同一智能体自己的成功投递，后者只能作用于当前频道已知成员。Adapter 可以分别实现处理中反馈、撤回和戳一戳，不需要同时提供全部互动。互动先持久化耐久意图；写入平台后断线或超时记为 `unknown`，不自动重试可见副作用。

## 5. 出站生命周期

```text
智能体调用 send_channel_message
→ 校验目标、权限、内容和 Adapter capability
→ 持久化 OutboundMessageIntent 与 logicalMessageId
→ 规划一个或多个 PhysicalDelivery
→ Adapter 发送
→ 持久化平台回执、失败与 message ID
→ 工具返回结构化结果
→ Channel Conversation 展示已确认状态
```

最小事实对象：

- `OutboundMessageIntent`：智能体希望发送的逻辑消息及来源 Turn；
- `PhysicalDelivery`：针对平台的一次物理发送；
- `DeliveryReceipt`：成功、部分成功、可重试失败、永久失败或未知结果；
- `AssetReference`：本次发送使用的受控资源引用。

Adapter 只执行平台发送，不自行无限重试。重试、限流、幂等和用户可见失败由 Channel Runtime 统一管理。

## 6. 模型原始输出与后台观察

DSH 模型可能产生 `text`、`reasoning`、`tool-call`、`tool-result` 等块。NekroNXT 的解释是：

- `tool-call` 中成功执行的通信工具可以产生用户可见消息；
- 模型原始 `text` 与供应商实际提供的 `reasoning` 只进入 DSH Session Log，不投递给 Adapter；
- 不要求模型供应商暴露私有思维链，也不尝试推断不存在的思维；
- Web UI 应称“内部输出”“工作轨迹”或“模型输出”，不能把它包装成必然真实的思考过程；
- Web UI 是操作后台：会话流和工作轨迹都要能看到内部输出与工具，并与已发送的频道消息区分；
- 内部输出不是业务消息、用户承诺或长期知识事实。

应答型 Turn 必须至少成功调用一次 `send_channel_message`。Turn 第一次抵达停止边界但尚无成功发送时，Host 在同一 Turn 注入一次简短纠正提醒并继续下一 Step；第二次抵达停止边界仍无成功发送时，Turn 以 `unreplied`（未产生回复）投影结束，不再继续提醒，也不得把任何原始最终文本兜底发送。守卫提醒、最终 Turn 边界和工具结果都属于持久 DSH Session 事实，重启后可重建同一结论。已经成功发送的 Turn 即使最后仍产生普通模型文字，也不会再次提醒或重复发送。观察型触发允许合法地零发送；管理员控制台出站注入的是系统事实，不会被识别为应答型频道准入。

回复守卫只在 Turn 准备停止时纠正一次投递事实，不负责中途计时、统计工具次数或自动编写进度。开场确认和阶段沟通由上述环境说明、人设与成员偏好共同引导；Host 不在工具运行期间强制插话，也不替智能体虚构进度。

## 7. 入站与实时群消息的关系

本协议只统一出站，不改变入站安全 Step 规则：

- 新平台事件先进入 Channel Event Log；
- 智能体空闲时，可由触发策略启动 Turn；
- 智能体运行时，普通消息以 `inject()` 或等价非中断机制在下一安全 Step 准入；
- 普通消息不取消正在生成的模型请求或 Tool；
- 停止、权限撤销、系统关停等控制事件可以中断；
- 用户执行“清空并重开”或“压缩并重开”时立即中断当前模型与 Tool；前者不生成交接，后者只从当前 Episode 的 durable history 生成 Handoff；
- 智能体看到新消息后，仍只能通过通信工具对频道发言。

上下文操作只改变 DSH Session / Episode 的工作上下文，不创建新的 Channel Event，也不删除、改写或隐藏既有频道事实。删除智能体和删除频道都不删除 Channel Event、Outbound、Episode、Asset Occurrence 或资源授权：删除智能体默认同时 tombstone 仍归属于它的自动创建内置频道，其他频道只解除绑定；单独删除内置频道或从 NekroNXT 移除外部频道只让频道退出活动产品状态。外部平台再次发现同一频道时复用原 Channel ID 与历史。

每个频道 DSH Session 必须获得 Host 权威的当前频道身份，至少包含稳定 `channelId`、`episodeId`、Connection、频道类型和可用展示名。该身份通过常驻 System Prompt section 与无参数只读工具提供；展示名是可变化数据，稳定 ID 才是共享数据查询和来源校验依据。工具不能接受任意 Channel ID，权限边界仍由 Session 绑定、Channel-scoped Repository 和通信工具执行，不能只靠提示词。

智能体人设使用版本化 `PromptDocumentV1` 保存文本与稳定实体引用。用户可引用平台用户、频道和已保存扩展；Host 只在存在引用时把文档编译为 `<nxt-persona-document>`、转义后的 `<nxt-text>` 与 `<nxt-reference>`，并在其前注入固定引用协议。协议把 `target`、`kind` 和 `availability` 定义为 Host 身份事实，把名称、描述等展示字段定义为不可信数据。引用不授予权限、不读取或混合其他频道历史，也不启用扩展；不可用对象不得按昵称猜测替换。该机制属于 System Prompt 配置投影，不改变 MessagePart、Mention 或频道投递协议。

## 8. UI 语义

Channel Conversation 中的智能体消息必须来自已记录的出站意图，并展示真实发送状态：发送中、已发送、部分发送、失败或结果未知。

Web 投影必须保留 `parts` 的原始顺序，不能先压平成单一字符串再展示。单独的 `text` part 按 GitHub Flavored Markdown 渲染，使用 `react-markdown`、`remark-gfm` 和 `rehype-sanitize`，不启用 raw HTML；外链只允许安全协议并使用新窗口安全属性。连续的 `text` 与 `mention` 作为同一行内联渲染，Mention 显示成员名称 chip，不得把 `mentionedConnectionAccount` 画成独立前缀。图片、文件、音频和引用使用结构化组件，资源 URL 只能由经过 `channelId + assetId` 校验的同源端点生成。入站 Adapter 必须按平台原文位置把 Mention 编进 `parts`，不能先从正文剥离再追加到末尾；机器人账号被提及时既写入 `facts.mentionedBot`，也作为 `mention` part 入库。

会话方向由频道类型和事实角色共同决定：内置频道的成员输入在右、智能体出站在左；外部频道的平台成员在左，智能体出站与管理员控制台出站在右；系统事件独立居中或左对齐为低噪声状态行，不使用消息头像、发送者标题、消息气泡、强调色背景或嵌套富卡片。旧事件只有 `rich` 摘要时，客户端也只显示纯文本摘要。`admin-console` 只增加来源标记，不改写事实角色。

外部群聊的入站消息必须展示成员目录中的发送者名称，不能统一伪装成“你”；结构化 Mention 应显示成员名称，并出现在原文对应位置，不得把内部 `memberId` 或平台 OpenID 当文案。提及机器人账号既是触发事实，也是 `parts` 中的 Mention 和智能体上下文可理解的消息语义，不能只在 Adapter 内部保留一个不可见布尔值，也不能只在气泡开头额外画一颗 chip。成员名称不可用时使用不泄漏标识的中性称呼，身份关联仍以稳定 `memberId` 为准，不能退回昵称反查。

消息列表按频道懒加载事实流：首次进入读取最近 16 条，向上滚动时使用 `(occurredAt, sourceId)` 游标每次读取 24 条更早消息；多取一项判断 `hasMore` 时只丢弃该页最旧的额外项，每个分页边界都不得遗漏或重复事实。全局产品快照不得为了导航预取每个频道的历史。会话和工作轨迹首次进入直接落在底部；离开底部后按频道记住位置，prepend 必须保持当前阅读锚点。历史请求在途时到达的实时频道事实必须在请求结束后合并，不得因对账中而丢弃。距底 80px 内才自动跟随新内容，离开底部时显示「回到底部」；显式回到底部直接定位并立即恢复跟随，不执行会产生中间滚动状态的长距离平滑动画。

图片、音频和文件在消息中使用结构化资源块渲染。单张图片直接显示资源本身，不在图片下重复显示文件名或替代文本；名称只作为无障碍替代文本和预览标题。点击图片或文件在应用内打开资源预览（图片、音视频、PDF、常见文本），不跳转到新窗口；预览对话框提供下载。`rich` part 由宿主用 summary/title/source/预览图画兜底卡片；有安全 `targetUrl` 时整张卡片在新窗口打开该目标，封面只是卡片视觉，不触发资源预览，也不提供下载；没有目标时卡片不可点击。`kind: forward` 展示转发摘要和预览正文，嵌套的真实图片附件仍按资源处理。Web 只能请求经过 `channelId + assetId` 授权校验的同源资源端点，不显示宿主路径，不把资源退化成 `[图片]` 或 `[文件]` 文本占位。外部平台没有提供频道名称时允许保存本地展示名称，但不得覆盖稳定的平台频道 ID 或伪造平台元数据。

消息列、消息行、内容容器和 Markdown 根节点必须允许 flex/grid 子项收缩。普通段落、列表、行内代码、长链接、宿主路径和无空格字符串允许断行；代码块和宽表格只在自身内部横向滚动，不得扩大消息列、`body` 或文档画布的 `scrollWidth`。

频道页画布可在「会话」和「工作轨迹」之间切换，右侧检查器列保持，不随视图卸掉。

- 会话：频道事实流，并穿插当前轮次的内部输出和工具；通信工具发出的话仍是聊天气泡；会话页不放时间轴；
- 工作轨迹：按轮次排列的事件台账，顶部三车道时间轴（内部 / 工具 / 发送）只出现在此视图；点击时间轴片段选中对应行；
- 选中一行后，检查器按记录类型叠放详情，不使用摘要 / 输入 / 输出页签：内部输出展示全文，发送展示发出的内容，工具同时展示输入和输出；每个区域限制高度并在内部滚动；
- 内部输出默认折叠，标注“内部输出”；
- 待注入群消息数量显示在会话流和检查器中；
- 会话检查器分开展示当前 Episode 的预计上下文和按模型请求聚合的缓存分析（有样本时）；缓存区明确最近一次、最近窗口、本次会话和数据覆盖范围，不能把累计缓存读取写成当前上下文缓存。工作轨迹展示关闭区间的耗时，选中行才展示本步用量和首字耗时。不把 DSH 原始 chunk 或占用仪表盘放进消息列。

内部输出与“已发送到频道”的消息必须有明显视觉区分。内置频道 Composer 把管理员输入作为入站交给智能体。外部频道 Composer 以机器人账号把内容发到该频道，并在会话中注入“管理员从客户端发出”的系统事实；连接未允许主动发送时不可执行。Adapter 投递智能体发言时仍然只接受通信工具产生的出站意图，以及上述管理员控制台出站。

## 9. 首版验收

1. Web 与首个外部 Adapter 都只能通过通信工具产生智能体消息；
2. 原始模型文本永远不会自动出现在 Channel Conversation；
3. 文字、Mention、图片、文件及其有序混合能被统一表示；平台卡片以 `rich` 入库，宿主能用 summary 兜底展示；
4. Adapter 不支持混合内容时可确定拆分并保留同一逻辑消息 ID；
5. 失败、部分成功和未知结果不会显示成已发送；
6. 相同 `clientRequestId` 重试不会产生重复业务消息；
7. 工具运行期间到达的新消息不会取消当前 Tool，并可影响下一次发送决策；
8. Web UI 能区分内部输出、工具动作和已发送的频道消息；Adapter 收不到内部输出；
9. 视觉主模型按消息顺序持续收到原图并按 digest 去重；文本或能力未声明的主模型只看到 Asset 标签，且只能通过配置好的辅助视觉模型取得结构化二手证据；
10. 音频、文件和视频不会以宿主路径或提示词标记进入模型上下文，原件与派生内容可追溯。
11. 相同媒体内容无论接收多少次只产生一个物理 blob，入站来源由 `AssetOccurrence` 保持，模型生成内容由 Channel scoped grant 保持，二者都不跨频道泄漏；
12. `video/*` 作为普通文件完整入库；历史图片只通过批量 `asset_inspect_images` 重读，单图也使用数组协议并可携带整批问题与逐图关注点。
13. 群聊发送者、成员 Mention 与提及机器人账号从 Adapter 入站到 Channel 历史、智能体上下文和 Web 展示保持可理解；UI 不泄漏成员或平台内部 ID。
14. 频道历史按需分页，向上加载不改变当前阅读位置，进入频道不会从顶部可见地平滑滚到底部。
15. 图片、音频和文件通过频道授权的资源端点正确渲染或下载，不暴露宿主路径；
16. `asset_create` 只接受受限 UTF-8/base64 内容，复用 Asset Service 并返回稳定 `assetId`、大小和检测 MIME；成功创建不伪造成员消息或污染频道事实流；
17. `send_channel_message` 对每个媒体 Asset 逐项执行当前 Channel 的 `canAccessAsset` 校验，跨频道引用在 Adapter 投递前失败；
18. 纯文本工具输入省略 `type` 时被规范化并真实发送，其他缺少 `type` 或语义模糊的 part 在领域提交前失败；
19. 应答型 Turn 缺少成功发送时只提醒一次，补发成功后正常完成，二次遗漏则持久投影为 `unreplied`，且原始模型文字始终不会被自动发送。
20. 特殊活动默认只记录，只有 Binding 逐项开启后才触发；关系事件不会改写目标消息。
21. 处理中反馈在平台调用前持久化并在 Session 空闲或重启恢复后清理；Host 自己产生的回应回流不进入事实流。
22. 撤回和戳一戳只作用于当前频道授权目标，使用耐久去重意图，未知结果不盲目重试。
