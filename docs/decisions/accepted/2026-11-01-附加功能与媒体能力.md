# 附加功能与媒体能力

状态：accepted（2026-11-01）；五期均已实现（2026-11-02），语音识别按时长计入用量（F9）尚未实现

## 决定与理由

后台浏览器、语义检索模型、编排运行环境（Node）和 GitHub CLI 都是按需下载到本机的程序或模型。它们各有一套状态、接口和设置入口，分散在「界面检查」「检索」、智能体能力和关联账号四个地方。接下来还要加媒体处理（ffmpeg）和语音识别。所以统一成「附加功能」：一个注册表、一个设置页，并通过同一组宿主服务开放给扩展。

起因是让纯文本模型「看视频」这类插件（例如抽帧拼宫格、配台词）。这里做的是通用能力：读取频道里的文件、处理音视频、语音转文字、在受限环境里运行组件程序、存放临时文件和缓存、让模型看清图片、汇报长任务进度。每项都可以单独使用，也可以组合起来用，不为某一个插件设计。

| # | 决定 |
| --- | --- |
| F1 | **能力与提供方式**：服务端的 `AddonRegistry` 管理所有附加功能。一项附加功能是一种能力（如语音识别），下面可以有多种提供方式（如本地 SenseVoice、本地 Paraformer、云端供应商；这台设备的 ffmpeg、下载的 ffmpeg），由用户选择当前使用哪一种。能力声明编号、用途分组（`extension` 扩展能力 / `agent` 智能体命令 / `host` NekroNXT 自身）、名称与简介、谁在使用它；提供方式各自声明名称、简介、资源占用（下载体积、安装后体积、运行时内存，以及速度、语言等差异）、许可证与来源、依赖的其他能力、提供的程序。提供方式的状态统一为：未安装、安装中（含进度）、已安装、失败（含原因）、这台设备不支持；不需要安装的方式（这台设备已有的程序、云端）显示为可用或待配置。来源分为随 NekroNXT 安装、来自这台设备、由 NekroNXT 下载、云端。能力的状态由当前选中的提供方式得出；没选过时，默认用第一个可用的方式。安装位置统一放在 `<数据根>/runtimes/<编号>`，不进备份，迁移数据目录时可以重建 |
| F2 | **接口**：`GET /api/addons` 列出全部能力及其提供方式，`POST /api/addons/:id/providers/:provider/install` 安装，`DELETE /api/addons/:id/providers/:provider` 删除，`PUT /api/addons/:id/selection` 选择当前使用的提供方式（只能选可用的）。变化随快照推送。各组件原来的下载和删除接口一并移除。`capabilityAvailability` 里已有的可用状态改为从注册表得出，智能体页面的「待配置」判断照旧 |
| F3 | **界面**：在「设置 → 智能体运行」下新增「附加功能」页，按用途分组列出能力，每项可以点进详情页。详情页列出这项能力的各种提供方式及其资源占用，可以分别安装、删除、选用，并显示来源、许可证、谁在使用，以及这项能力自己的设置（比如语义检索的开关和索引进度）。只有一种提供方式时不显示选择。删除「界面检查」和「检索」两个导航项，旧地址跳转到对应的详情页。智能体能力页和关联账号页只显示状态，并链接到详情页 |
| F4 | **程序**：附加功能可以提供可执行程序，比如 `ffmpeg`、`ffprobe`、`gh`、`node`。程序有三种用法：智能体运行命令时加入 PATH；按程序声明的常用环境变量名（如 `FFMPEG_PATH`、`DSH_FFMPEG_PATH`）设给 DSH 插件；作为扩展受限命令的执行对象（F7）。GitHub CLI 不再单独处理 PATH，改走这个通用方式 |
| F5 | **工作文件**：新增 `nxt.files`。扩展用不透明的文件编号（`fileId`）在服务之间传递数据，不接触本机路径。临时文件 24 小时后清理；缓存文件按扩展计配额，满了先清最久没用的。接口有写入、分段读取、查看信息、删除、从频道资源取得（`fromAsset`，不复制内容）、转成频道资源（`toAsset`），以及按键读写缓存。声明 `permissions.*.files`，可设临时与缓存配额 |
| F6 | **读取频道资源**：`nxt.assets.read(assetId, { offset, length })` 分段读取字节，`nxt.assets.stat` 读取元数据，可读范围与 `image.info` 相同（当前频道看得到的资源，或扩展资源库）。声明 `assets: { read: true }`。智能体新增工具 `asset_save_to_workspace`，把频道里的文件存进自己的工作区 |
| F7 | **受限命令**：带程序的附加功能为每个程序声明一份命令档案：允许和禁止的参数、哪些参数是输入文件或输出文件（由 `fileId` 和输出名映射到这次调用的工作目录）、强制追加的参数（比如 ffmpeg 只允许读写本地文件）、默认和最长时限、输出上限和并发上限。`nxt.commands.run(profile, args, { inputs, signal })` 在命令沙箱里运行，工作目录是这次调用的临时目录，不能访问网络，只能读取程序本身和输入文件；返回退出码、截断后的标准输出和错误输出，以及输出文件的 `fileId`。声明 `commands: { profiles: [...] }`，属于高风险能力，启用时由用户确认。以后新增程序只需要再写一份档案 |
| F8 | **媒体处理**：`nxt.media` 提供 `probe`（时长、流、编码）、`frames`（按时间点或间隔取帧，可指定尺寸，输出 jpeg、png，或供分析用的 rgb24、gray8 原始像素）、`audio`（截取并转换音频，可指定采样率、声道和格式）、`convert`（在一组常见图片、音频、视频格式之间转换，包括 SILK 和 AMR）。输入可以是 `assetId` 或 `fileId`，输出是 `fileId`。声明 `media: true`。依赖「媒体处理」附加功能，SILK 由内置的 silk-wasm 处理 |
| F9 | **语音识别**：`nxt.speech.transcribe(input, { language })` 返回全文、分段（起止秒数和文字）、使用的引擎与模型。提供方式（F1）：本地 SenseVoice-Small（int8，中英日韩粤，约 0.9 GB 内存）、本地 Paraformer-zh-small（int8，中文，约 0.35 GB 内存），都用 sherpa-onnx 运行、Silero VAD 分段，在独立进程里加载，闲置后释放；云端调用用户在「设置 → 模型」里配置的供应商的 OpenAI 兼容转写接口（`/audio/transcriptions`），在详情页选供应商和模型名。转写前用媒体处理把音频转成 16 kHz 单声道。声明 `speech: { maxCallsPerMinute }`，按时长计入用量 |
| F10 | **语音消息转文字**：智能体能力新增「语音消息转文字」，默认关闭。打开后，语音消息入库时由宿主转写，智能体在消息旁看到 `[语音转写] …`。同一段音频按内容只转写一次。最多等 30 秒，超时或失败时照常唤醒智能体，并附上没能转写的原因。语音识别不可用时开关显示「待配置」 |
| F11 | **图片细节**：工具返回的图片块可以写 `detail: 'high'`。高细节按原图交给模型，长边不超过 2048 像素，计入单次 6 张的上限。声明 `toolImages: { highDetail: true }`。第三方 DSH 插件经管理员在插件详情里允许后，可以通过 `attachments` 提交图片，图片存为当前频道的资源，再交给模型 |
| F12 | **长任务**：工具定义可以声明 `timeoutSeconds`（最长 900）。`execute(args, { signal, progress })` 可以收到取消信号，并汇报进度（一句文字和可选的完成比例），进度显示在频道时间线的工具状态上。宿主服务（F5–F9）都接受 `signal`。没有声明时限的工具行为不变 |
| F13 | **依赖提示**：不新增清单字段。宿主从扩展声明的能力推出它需要哪些附加功能（如 `media` 需要媒体处理，`speech` 需要语音识别），在安装和启用页显示「需要附加功能：媒体处理（未安装）」，并链接到详情页。调用时附加功能不可用，报错写明请管理员到「设置 → 附加功能」安装 |
| F14 | **SDK 14**：F5–F9、F11、F12 一起升一级。新增能力纳入批准摘要、扩大判断、批准指纹和最低 SDK 等级推断；编写参考加上各服务的用法；验证和动态运行提供同一接口，验证时媒体和语音返回固定结果，不消耗资源 |
| F15 | **来源与分发**：先用这台设备已有的程序（PATH 和常见安装位置），没有再下载，我们不托管任何文件。ffmpeg 用 ffmpeg-static 的构建（GPL），从 GitHub 和 npmmirror 下载，固定版本并校验 sha256；sherpa-onnx 从 npm 和 npmmirror 下载对应平台的原生包；模型从 Hugging Face 和 hf-mirror 下载。Docker 镜像用 apt 预装 ffmpeg，语音模型照常按需下载。详情页写明许可证和来源 |
| F16 | **扩展只认能力**：扩展调用 `nxt.speech`、`nxt.media`、`nxt.index` 这类能力接口，不指定提供方式；返回结果写明实际使用的提供方式和模型。新增一种提供方式不需要改扩展，也不需要改 SDK。资源占用大的能力至少提供一种轻量的方式；以后可以在同一能力下继续加，例如语义检索加云端嵌入模型 |

## 组合示例

- 视频宫格：`assets.read` 或 `files.fromAsset` 取得视频，`media.frames` 取 gray8 小图检测镜头切换，再取 jpeg 关键帧，用 `render.svg` 拼图，最后用 `detail: 'high'` 返回给模型；`media.audio` 加 `speech.transcribe` 得到台词。
- 语音回复：语音合成扩展生成 mp3，用 `media.convert` 转成平台需要的 SILK 或 AMR，再用 `files.toAsset` 发送。
- 文档与数据：`assets.read` 读取 PDF、表格或压缩包，在扩展里解析；中间结果放进 `files` 缓存。
- 表情包：GIF 和视频表情用 `media.frames` 取几帧，交给模型标注。
- 智能体自己处理：`asset_save_to_workspace` 存下附件，在命令里直接用 PATH 上的 `ffmpeg`，再用 `asset_inspect_images` 查看结果。

1. 注册表、接口、「附加功能」页，迁移现有四项；

5. `nxt.media`、`nxt.commands`、`nxt.speech`、语音消息转文字、依赖提示，以及用户指南、编写参考与 SDK 说明。

第三期（附加功能部分：F4、F7、F8 的宿主一侧，F15 的镜像预装）：

- `packages/contracts/src/host-api.ts`：`AddonIdSchema` 增加 `media`。

- `apps/server/src/addons.ts`：`mediaAddon`（提供方式 `system`、`download`）；程序声明 `AddonProgram`（`name`、`env`、`profile`），`AddonRegistry.programs()` 列出各能力当前方式提供的程序；`syncProgramEnvironment` 把程序声明的变量（`FFMPEG_PATH`、`DSH_FFMPEG_PATH`、`FFPROBE_PATH`、`DSH_FFPROBE_PATH`）设进服务端进程的环境，DSH 插件在同一进程里运行，从这些变量找到程序；当前方式变化时更新，没有可用方式时删除，NekroNXT 启动前已经设置的同名变量保持原样。
- `apps/server/src/command-account-env.ts`：`programSearchPath`。`DshHostRuntimeOptions.programs` 让每个开启运行命令的智能体的 `PATH` 带上这些程序所在的目录：下载的和随 NekroNXT 安装的放在最前，这台设备上但不在 `PATH` 里的放在最后；命令的读取范围同时保留这些目录。`gh` 改走这条路，关联账号只提供 `GH_TOKEN` 等变量（`GithubCliPort` 只剩 `executable`）。
- `apps/server/src/confined-program.ts`：`runConfinedProgram`、`ConfinedProgramRunner`（共用并发上限，默认 2）、`createProgramSandbox`。不经过 shell 运行宿主程序，套用智能体命令的沙箱：只写这次的工作目录，不联网，在宿主读取范围之外只多读程序目录和输入文件；超时或取消时结束整个进程组。`command-confinement.ts` 的 `dataRootCommandConfinement` 由它和智能体命令共用。
- `apps/server/src/command-profiles.ts`：`CommandProfile`、`FFMPEG_PROFILE`、`FFPROBE_PROFILE`、`prepareCommand`、`CommandProfiles.run(profileId, args, { inputs, workDir, timeoutMs, signal })`，返回退出码、截断后的输出和输出文件。参数是文字、`{ input: 键 }` 或 `{ output: 文件名 }`；只放行列出的选项，每个输入前强制 `-protocol_whitelist file,pipe` 和 `-format_whitelist`（常见音视频与图片容器，不含 `concat`、`hls`、`lavfi`），每个输出前强制 `-fs`；拒绝网址、绝对路径、`..`、会自己打开文件的滤镜（`movie`、`amovie`、`subtitles` 等）和滤镜的文件参数。
- `apps/server/src/media-toolkit.ts`：`MediaToolkit` 的 `probe`、`frames`、`audio`、`convert`，读写宿主路径，运行实例是 `NekroRuntime.media`（命令档案是 `NekroRuntime.commandProfiles`）。SILK 由服务端依赖 silk-wasm 在进程内编解码（QQ 语音按 24 kHz）；图片之间的转换用 sharp，视频转图片和动图走 ffmpeg；当前 ffmpeg 缺少所需编码器时报错写明不能生成哪种格式。
- `Dockerfile`：运行镜像用 apt 安装 `ffmpeg`（Debian 12 的 5.1），作为「这台设备的 ffmpeg」。

实现中的取舍：平台没有可用的命令沙箱时（例如不支持 bubblewrap 和 Landlock 的容器），媒体程序照常运行，参数、白名单、时限和输出上限不变，结果标明 `confinement: 'none'` 并记一条日志。AMR 编码需要带 libopencore_amrnb 的 ffmpeg，Homebrew、ffmpeg-static 的 macOS 构建和 Debian 的 apt 版都没有，这时 `convert` 和 `audio` 报不能生成 amr 文件；AMR 解码不受影响。

第四期（附加功能部分，F9 的语音识别能力与宿主内部接口；`nxt.speech` 和 F10 在合并后接入）：

- `packages/contracts/src/host-api.ts`：`AddonIdSchema` 增加 `speech`；`SpeechLanguageSchema`（`auto`、`zh`、`en`、`ja`、`ko`、`yue`）、`SpeechCloudSettingsSchema`（`provider`、`model`、`language`）、`SpeechSettingsSchema`（`cloud`，以及可用于转写的供应商 `providers`）；接口 `getSpeechSettings`、`updateSpeechSettings`（`/api/settings/speech`，在 `host-routes-addons.ts`，保存云端设置时同时选用云端）。
- `apps/server/src/addons.ts`：`speechAddon`，提供方式依次为 `paraformer-zh-small`（本地 Paraformer）、`sense-voice-small`（本地 SenseVoice）、`cloud`（云端，未配置时为 `needs-config`）。
- `apps/server/src/speech-model-files.ts`：固定版本与 sha256 的 sherpa-onnx 2.0.1 npm 包（整包 tarball，来自 npm 和 npmmirror；npmmirror 不提供这两个包的单文件）、Silero VAD v5（Hugging Face、hf-mirror、sherpa-onnx 的 GitHub 发布）和两个模型。
- `apps/server/src/speech-local.ts`：`LocalSpeech` 下载、校验、删除，安装在 `runtimes/speech/{sherpa-onnx,vad,models/<id>}`；运行环境和 VAD 由两个本地模型共用，删除最后一个模型时一并删除。
- `apps/server/src/speech-engine.ts` 与 `speech-engine-worker.mjs`：`SpeechEngine` 在子进程里运行 sherpa-onnx（`forkSpeechEngine` 用服务端自身的 Node 或以 Node 方式运行的 Electron），一次处理一个请求，闲置 5 分钟后结束进程，取消或超时时结束进程，崩溃后下次请求重新启动；服务端退出时子进程随之退出。分段来自 VAD，每段不超过 30 秒。
- `apps/server/src/speech-cloud.ts`：`SpeechCloud`（系统设置 `speech.cloud`）和 `requestTranscription`，向 `{baseURL}/audio/transcriptions` 发送 multipart 请求（`verbose_json`），地址和密钥来自 `DshHostRuntime.llmProviderConnection`（即 `HostModelSettings.providerConnection`），长音频在 30 秒内最安静处切开分次发送。
- `apps/server/src/speech-service.ts`：`SpeechService.transcribe({ path, language, signal })` 按当前提供方式转写，返回全文、分段、时长、`provider: { id, title }` 和 `model`；不可用时抛出 `SpeechUnavailableError`。WAV 直接读取，其他格式交给注入的 `SpeechAudioDecoder`（媒体处理接入后提供）。`transcribeOnce({ digest, … })` 按音频内容、提供方式、模型和语言缓存结果，存在 `runtimes/speech/transcripts`。`NekroRuntime.speech`、`NekroRuntime.speechCloud` 在 `bootstrap.ts` 组装。
- `apps/web/src/app/settings/addons-section.tsx`：语音识别详情页的「云端设置」（供应商、模型、语言、清除）。

实现中的取舍：现有四项沿用原来的安装目录（`runtimes/node`、`runtimes/gh`、`runtimes/chromium`，语义检索在 `runtimes/onnxruntime` 与 `runtimes/embedding-models`），避免已下载的用户重新下载；新增的能力用 `runtimes/<编号>`。服务端的 Node 只有「NekroNXT 自带」一种，不提供下载。

第五期（F7–F10 的扩展接口、F10、F13、F14 的其余部分、文档）：

- `packages/contracts/src/extension-capabilities.ts`：两层都可声明的 `media: true`、`ExtensionCommandsCapabilitySchema`（`profiles` 取自 `ExtensionCommandProfileIdSchema`，即 `ffmpeg`、`ffprobe`）、`ExtensionSpeechCapabilitySchema`（`maxCallsPerMinute` 1–60，默认 10）；`EXTENSION_COMMAND_PROFILES` 记录每个档案由哪一项附加功能提供，`requiredExtensionAddons(...layers)` 由声明推出需要的附加功能（F13）。批准摘要：媒体处理普通、语音识别敏感（写明音频可能发给所选的语音识别服务）、运行程序高风险，摘要项新增 `scope` 写明高风险能力的范围；新增档案或调高语音次数算扩大。`extension-ui.ts` 的 `requiredExtensionSdkLevel` 把三者推为 14，`packages/extension-runtime/src/permissions.ts` 的批准指纹纳入三者（档案排序后计入）。
- `packages/contracts/src/host-api.ts`：智能体能力 `voiceTranscription`（创建与修改接口）、`capabilityAvailability.speechRecognition`；附加功能提供方式的 `dependsOn`；消息 `inboundHook.hostAnnotations`（`{ label, text }`）。`packages/core` 的 `AgentCapabilityGrantsSchema.voiceTranscription` 默认关闭，只在打开时写进版本摘要。
- `packages/extension-sdk`：`NxtMediaService`、`NxtCommandsService`、`NxtSpeechService`、`NxtMediaInput`（`{ assetId }` 或 `{ fileId }`），两层 `nxt` 都有；编写参考与 README 的宿主能力表。
- `apps/server/src/extension-host-service.ts`：`NxtServiceBackends` 的 `media`、`commands`、`speech`；`mediaService`、`commandsService`、`speechService`。资源输入的可读范围与 `assets.read` 相同；输出经 `withOutputs` 在 `ExtensionFileStore.workDirectory(owner)`（扩展文件目录下的 `work-*`，用完删除，启动时清理残留）里生成，再以 `importPath` 移入临时文件并计入配额，中途失败时删掉已导入的；语音的资源输入走 `transcribeOnce`（按内容摘要缓存），工作文件走 `transcribe`，按绑定每分钟限次。`bootstrap.ts` 把 `NekroRuntime.media`、`commandProfiles`、`speech` 交给已安装扩展和动态试运行（试运行计入它 64 MiB 的文件配额）；`CommandProfiles` 的 `addonTitle` 让不可用时的报错写明要安装哪一项。
- `apps/server/src/verification-media-backends.ts`：保存与导入验证的 `verificationMediaBackends`，媒体返回 1×1 的画面和短暂的静音，命令按档案检查参数后返回退出码 0 和空的输出文件，语音返回固定文字，都不运行程序。
- `apps/server/src/voice-transcription.ts`：`voiceTranscriptionAnnotator`（F10），打开开关的智能体收到的每个 `audio` 块按资源摘要 `transcribeOnce`，一条消息共用 30 秒，超时、失败或语音识别不可用时写明原因；`extension-inbound-hooks.ts` 的 `InboundHostAnnotator` 与 `hostAnnotators` 选项把它排在扩展处理函数之前、同时运行，结果与扩展的决定一起保存一次，没有处理函数也没有标注的消息不保存决定。`packages/storage-sqlite` 的 `inbound_hook_decisions.host_annotations`（迁移 `0060`）。`packages/channel-runtime` 的 `InboundAnnotation`：交给智能体的标注带各自的标签，宿主的在前，扩展的标为 `EXTENSION_ANNOTATION_LABEL`（扩展标注），`index.ts` 按 `[标签] 文字` 显示。
- `apps/server/src/addons.ts`：语音识别的三种方式 `dependsOn: ['media']`，使用方加上语音消息转文字；`host-queries.ts` 的可用状态把 `installed` 与 `available` 都算可用。
- Web：`apps/web/src/addon-status.ts`（`addonUsable`、`addonStateLabel`）；`extension-ui/required-addons.tsx` 的 `RequiredAddons` 显示在 `PermissionApprovalList` 末尾，`onLeave` 在去往附加功能页时关闭批准；扩展详情「能提供什么」的「需要附加功能」行；附加功能详情的「依赖」行（各方式都需要的只在能力下写一次）；智能体能力页的「语音消息转文字」与其下的「语音识别」行；频道时间线在消息下显示宿主标注。
