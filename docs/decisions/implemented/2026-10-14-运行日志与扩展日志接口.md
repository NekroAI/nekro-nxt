# 运行日志与扩展日志接口

状态：implemented

## 决定与理由

日志以当前服务实例为边界，提供独立导航页面、历史检索、实时订阅、临时 Debug 和导出。普通观察和开发排障共用一份列表，通过筛选与详情区分信息深度。插件、连接的当前状态继续由原业务模块拥有，历史日志不反向推断状态。

日志使用独立 SQLite 与工作线程，避免清理、检索及导出占用聊天数据库和主线程；采用独立 SSE，不占用聊天事件的回放窗口。只把成功提交的记录交给实时读者，以持久游标衔接历史和断线补齐。采集有明确容量边界，过量或存储失败优先保持业务运行，并说明记录缺口。

Server 拥有 `logs/` 和 `host/logging.json`。日志数据不进入升级备份，恢复时原地保留，避免回滚抹掉失败现场；保留策略配置正常备份。恢复实现只对明确的 `logs/` 保留目录放行，不扩大其他排除项或未知现场文件的权限。

Cordis 使用公开 `logger.exporter`、Fiber 和插件入口身份接入。NXT 扩展与 Adapter 获得只写、宿主绑定身份的结构化日志接口；SDK 9 对应 NekroNXT 0.6.0。现有扩展继续兼容，使用新接口需要声明新能力等级，不增加单独授权。无法确认身份的 console 输出明确标记为未识别来源。

## 现行契约

新生成的 Host factory 整体采用 SDK 9 环境，不通过搜索源码中的关键词猜测日志使用情况；纯 Client 与已导入扩展保留原有最低等级规则。动态沙箱经已有 `nxt` 服务传递只写日志能力，再呈现 `ctx.logger`，不开放 Cordis 内部对象。
