# 智能体出站处理

状态：accepted（2026-10-29，起因 issue #61；修订[扩展形态统一](2026-10-09-扩展形态统一.md) K9）

## 决定与理由

智能体发出的每条消息都要经过一段「出站处理」。扩展可以在这里读取消息、加工内容，或者取消发送。入站方向已经有 `onInbound`：扩展可以让智能体回应或不回应、对它隐藏消息、给消息加注。出站方向原来只规划了「只读观察」（K9）。只读覆盖不了很多真实用途：把文字转成语音、翻译成频道的语言、按平台转换格式、自动配一张表情包、防止泄密、记录实际发了什么，等等。这些都需要在发出之前碰到内容。审核只是其中一种用法，接口不为它单独设计。

| # | 决定 |
| --- | --- |
| O1 | 扩展在智能体挂载层用 `harness.onOutbound(handler)` 注册出站处理，每个扩展一个，只能在 factory 阶段注册。能力在 `permissions.agent.outbound` 中分三项声明：`read`（读取）、`transform`（加工）、`cancel`（取消），另有 `timeoutMs`（100–15000）和 `onTimeout`（`'send'` 默认放行 / `'cancel'` 超时即取消）。只读算敏感，加工和取消算高风险，启用时逐项确认；声明 `onTimeout: 'cancel'` 时单独提示「这个扩展出错时，智能体的消息会发不出去」 |
| O2 | 范围：只处理智能体通过发送工具发出的消息。管理员控制台消息、命令回复、宿主通知不经过出站处理 |
| O3 | 发出前：在发送工具里、素材校验之后、连发间隔之前执行；被取消的消息不占用连发间隔。扩展收到消息草稿（频道、各消息块、回复对象、引发这次回复的消息编号）和与入站相同的 `nxt` |
| O4 | 返回值：不返回或返回 `{}` 表示原样放行；`{ parts }` 替换整条消息的内容，可以增减文字、图片、语音、文件块，素材必须是当前频道可用的（例如扩展用 `nxt.assets.create` 生成的配音）；`{ followUps: [{ parts }] }` 在这条之后追加消息；`{ cancel: { reason } }` 取消这条，`reason` 会告诉智能体。没有声明对应能力的返回会被忽略并记诊断 |
| O5 | 多个扩展依次执行，后一个看到的是前一个加工后的结果；任何一个取消就停止，后面的不再执行。顺序可以由用户在智能体的扩展列表里调整，默认按启用的先后；只声明读取的扩展不参与排序 |
| O6 | 追加的消息按连发间隔依次发出，它们不再经过出站加工，避免来回触发；发出后同样会通知给声明了读取的扩展 |
| O7 | 超时或抛错时，按该扩展声明的 `onTimeout` 处理：默认当作放行，记诊断和服务日志 |
| O8 | 智能体总能知道实际发出了什么：被加工时，工具结果写明「已发出，内容经 X、Y 处理」并附上最终内容；被取消时写明原因和来源扩展，它可以修改后再发。回复义务按实际是否发出判断，被取消算没有发出 |
| O9 | 发出后：投递有结果后，异步通知所有声明了读取的扩展，内容包括最终的消息块、逻辑消息编号、投递状态和平台消息编号。不阻塞发送；每条消息只通知一次，重启后恢复投递的消息也只在有结果时通知一次 |
| O10 | 处理结果随出站意图保存（经过了哪些扩展、是否改写、取消原因），频道时间线在消息上标出「经 X 处理」；被取消的消息不进时间线，在透视里能看到 |
| O11 | SDK 升一级，新增 `harness.onOutbound`、出站消息类型和 `permissions.agent.outbound` 的校验；编写参考加上出站处理的用法 |

## 用法示例

- 记录与统计：表情包扩展在发出后记下实际发了哪张，替代现在的 `sticker_use`；话题和发言频率统计。
- 加工：Markdown 转纯文本、翻译、敏感词打码、链接换成卡片、统一署名。
- 补充：文字转语音（替换或追加语音）、按语气追加一张表情包、把公式或代码渲染成图片。
- 联动：同步到另一个频道或 Webhook；智能体说到某件事时创建一项扩展任务。
- 把关：防泄密、审核、在静默时段取消并告诉智能体。

## 契约入口

- `packages/extension-sdk`：`harness.onOutbound`、`NxtOutboundDraft` / `NxtOutboundDelivered`（`stage` 区分发出前与发出后，同一个处理函数）、`NxtOutboundResult`；SDK 13。
- `packages/contracts/src/extension-capabilities.ts`：`ExtensionOutboundCapabilitySchema`（`permissions.agent.outbound`）、风险摘要、批准扩大判断与 `EXTENSION_OUTBOUND_SDK_LEVEL`；`extension-ui.ts` 的 `requiredExtensionSdkLevel` 要求声明 13。
- `packages/contracts/src/host-api.ts`：时间线消息的 `outboundProcessing`、智能体的 `outboundOrder`、`PUT /api/agents/:agentId/outbound-order`、工具状态 `cancelled`。
- `packages/channel-runtime`：`SendMessageInput.onIntentPlanned`（规划时关联处理记录）与 `ChannelRuntimeOptions.onOutboundSettled`（每次投递结束，含恢复与重新派发）。
- `packages/storage-sqlite`：`outbound_processing`（按 `episode_id + client_request_id` 唯一，`notified_at` 为发出后通知标记）与 `agent_outbound_orders`，迁移 `0056_outbound_processing`。
- `apps/server/src/extension-outbound.ts`：发出前处理链、追加消息、发出后通知、顺序解析与验证；`bootstrap.ts` 在发送工具的通信端口接入；`channel-message-result.ts` 写给智能体的结果；`channel-reply-guard.ts` 把 `cancelled` 算作未发出。
- 工坊与智能体扩展列表：时间线「经 X 处理」/「由 X 追加」，扩展列表的「消息处理顺序」。

实现中的取舍：只有改了内容或追加了消息的扩展才算「处理过」并显示在时间线和工具结果里，原样放行的只记在处理记录中；没有出站扩展的智能体不产生处理记录；主消息没有发出时，追加的消息也不发；一个扩展一次最多追加 5 条。
